# `tests/` — 谁能判门禁，谁只是人工工具

这个目录里有两类东西，**外观一样，性质不同**。混起来读会把「有文件」当成「有守卫」。

- **门禁夹具**：被 `smoke.sh` 的某个段、CI 步或另一个有根的夹具调用。它们每轮都跑，坏了当场红。
  一个夹具算不算这一类，只认一件事：**有没有执行点**（`section-select.sh --paths` 能给出段号，或
  `smoke.sh` / `workflow-entry.sh` / 另一个有根的夹具里有一处真正的调用）。
- **人工工具**：下面这五个。**它们不在任何门禁段里**（任何段都不调用、CI 也不调用），是发布前或
  排障时**人**跑的取证/审计工具。跑绿了不代表门禁绿，跑红了也不拦合并——它值钱的地方在于它**自己**
  带红侧（把实现/现场弄坏，它必须变红），所以它的结论是一次性证据，不是长期守卫。

判据来由：D201（「不粘锅」代码）与 P353 的普查——19 个夹具当时没有任何执行路径，其中 7 个在修复进
`main` 之后连「一次性证据」都产不出了。P354 按 PM 裁定删掉 13 个（墓碑在 `docs/team/DECISIONS.md`
的同日条），只留下下面五个**可重跑、且守的东西确实贵**的。加新夹具时请顺手回答一句：它的执行点是哪
一段？没有执行点、又不是人工工具的，就不该进这个目录。
