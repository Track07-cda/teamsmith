设计要点（供复验对照）：

- **摘要是数据**：提示词里给出的命令由 teamsmith 渲染，只含 teamsmith 自己生成的路径；worker 只负责把摘要写进
  `.pi/team/state/summary-<agent>-<ID>.md`，然后原样跑那一条命令。`--from-file` 只把文件内容当**一个 argv**，
  不做任何 shell 解释。
- **归一化**：`\r` 删除、换行→空格、去尾部空白，其余字节**逐字节保留**（引号 / `$` / 反引号 / `{agent}` 原样进收件箱）；
  摘要文件缺失或为空 → 非 0 退出且不写收件箱（不会假报「已通知」）。
- **`{summary}` 的兼容语义**：仍是「worker 的摘要」，但渲染成对同一摘要文件的**带引号读取**
  （`"$(cat '…')"`；在 `'{summary}'` 里用单引号安全形态）。工具用老签名（第 5 个参数给文本）调用时，
  文本按「能单引号就单引号、否则 `%q`」强引用成一个词 —— 两条路都不会让文本被 shell 解释。
- **文件名**：`{summary_file}` 由 teamsmith 生成并 `%q` 引用，不接受 worker 提供的路径。

## Decisions and deviations

1. **`{summary}` 的语义**：任务书说「保留可用」但没说保留成什么样。我保留的是**「摘要能到达目标命令」**这个语义
   （渲染成对摘要文件的带引号读取），而不是「把 worker 文本插进命令行」这个实现 —— 后者正是 F1 的漏洞。
   老模板（双引号/单引号/裸三种写法）都能继续工作，且都注入安全；文档 §3 写清了三种形态。
2. **F7 的处置比任务书字面更彻底一点**：任务书说「措辞按 `TEAM_AGENT_CMD` 判定」，我进一步在内置 Pi 路径下
   **完全不给 worker 通知段**（Pi 扩展本来就会自动通知，给额外命令只会诱导重复通知），同时让 dispatch/doctor
   警告「这段配置在 Pi 路径下不生效」。V3.0 的 d6 检查也是按「Pi 路径不该有这一段」写的（照字面只改措辞会仍然报 finding）。
3. **abort 与 warn 的分工**：`TEAM_AGENT_CMD` 的畸形/空白/多行 → **abort**（坏窗口比坏通知严重）；
   `TEAM_AGENT_NOTIFY_CMD` 的同类问题 → **warn + 提示词降级**（M3.0 已有「只警告不阻断」契约，F8 也要求降级而不是阻断）。
4. **换行归一化**：`--from-file` 与内联消息都归一化成单行（收件箱是一行一条）。任务书写「逐字节送达」，我把它实现成
   「除换行/回车/尾部空白外逐字节」并把这条写进文档与测试（含换行的那条摘要单列一行，注明按文档归一化）；
   若要连换行都原样保留，收件箱的多行消息会让 PM 的解析变成两行 —— 这是我不接受的风险。
5. **兼容既有工具调用**：`team_agent_notify_cmd` 保留第 5 个参数（显式摘要文本），文本按「能单引号就单引号、否则 `%q`」
   强引用 —— 既让 V3.0 包里的 a8 检查（看文本里的 `{agent}` 有没有被二次展开）保持有效，又不给注入留口子。
6. **文档里删掉了一个具体例子**：V3.0 的 a9 提取器把文档中任何 `` `{name}` `` 当占位符清单，我原来写的
   `` `{sessionid}` ``（typo 例子）会让契约检查误报。改成不带花括号的措辞（「拼错名字 / 括号里多空格」），
   语义不变。
7. **报告语言**：正文中文、标题用 v1.14.0 起的英文模板（`docs/team/**` 与 CHANGELOG 仍是中文批次的边界）。

## Not verified / risks

1. **真 CLI 端到端没有重跑**：M3.0 用 opencode/codex 实测过 notify 路径；本轮改的是提示词渲染与 `notify` 参数
   解析，我用的证据是「提示词渲染 + 真实 shell 执行那条命令」（`pkg` 的矩阵就是真跑 shell，但没有真拉起模型）。
   PM 若想再要一次真 CLI 证据，`docs/team/reports/M3.0-dev.md` 的脚本可以照抄。
2. **`{summary}` 的三种引号形态之外**：例如 `'--msg={summary}'`（整个参数被单引号包住、占位符不在引号边界上）
   会按「裸值」处理 —— 安全（一个词、不执行）但内容会带上一对外层引号。文档把这三种形态写成 supported，
