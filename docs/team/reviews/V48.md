## 结论

写侧的修法**成立且够用**：**可能启动 server 的客户端**（`new*`/`split*`/`respawn*`/`start*`）才需要没有
`TEAM_*` 命名空间，产品把这一族收进 `team_tmux` 并摘掉整个命名空间后，同一台 server 上**本项目的
`TEAM_*` 一个都不进全局环境**，而本项目的窗口靠**会话作用域 `-e`**（外加既有的启动命令 export）照旧带
身份——这两件事我都在**自己造的现场**上量过（不是复跑作者脚本），并在未修改的 main 上看到泄漏侧。

阻挡项只有一个，且**不在产品代码里**：交付夹具 `skills/teamsmith/tests/tmux-identity-leak.sh` 把
「闸门目录 + `/usr/bin:/bin`」写死进它给子进程的 PATH（第 112/139 行）。写侧修好之后，闸门的
`TEAM_TMUX_REAL` pin 也被摘掉（规范要求摘掉**整个** `TEAM_*` 命名空间），闸门于是必须回落到 PATH 找真
tmux；宿主机 tmux 在 `/usr/bin`（找得到，所以作者与我跑宿主都是 27/0），钉住的门禁镜像里 tmux 在
`/usr/local/bin`（找不到 → 闸门 fail closed 127 → `new-session` 没建成 → server 没有会话就退出 →
`team up` rc=1）。结果是：**这个夹具在门禁镜像里 ✓13 ✗13**，而本项目门禁的既定做法就是在钉住镜像里跑（`localhost/teamsmith-gate:local`，PM 线程 2026-10-02 的配方），本变更的 design 也要求把该夹具挂进 `smoke.sh §32`。修法是两行 PATH 常量（见 F1），产品一行都不用动。

## 发现

**F1（阻挡项，夹具可移植性）· 交付夹具的调用者 PATH 写死 `/usr/bin:/bin`，在钉住的门禁镜像里闸门找不到真 tmux
→ 夹具 ✓13 ✗13。** 机制链每一步都是量出来的：

- 镜像里 `/usr/bin/tmux` **不存在**，tmux 在 `/usr/local/bin/tmux`（`ls -la` 原文见 `logs/container-diag2.log`）；容器 PATH 含 `/usr/local/bin`。
- 闸门真身解析：带 pin `TEAM_TMUX_REAL` → rc=0；**摘掉 pin** + 夹具的窄 PATH → `✗ teamsmith tmux 闸门：PATH 里找不到真 tmux（只找到我自己）` rc=**127**；摘掉 pin + 真 PATH → rc=0。
- 候选树在同一镜像、同一舞台、只是把子进程 PATH 加上 `/usr/local/bin`：`team up rc=0`、PM 起来、**全局 0 / 会话作用域 4**（`logs/container-diag2.log` 的 ③）。
- 把夹具那两行常量补上 `/usr/local/bin` 后（**只改 `cand-gate` 一次性克隆，跑完 `git checkout` 还原，差异 0 行**）：`--all` → **✓27 ✗0**。
- 摘要式申报不成立：交付版本的容器红**不是**环境噪声（main 在同一镜像同一舞台 rc=0；候选宽 PATH 也 rc=0），是**夹具自己**的 PATH 常量。

建议修法（两行，不碰产品）：`SHIM_PATH="$PROD/scripts/shim:$(dirname "$REAL_TMUX"):/usr/bin:/bin"`、`KILL_PATH` 同理；或从 `REAL_TMUX` 的目录推导。**这条要修在挂 §32 之前**——挂在门禁里之后，镜像里的 §32 会天天红（`smoke.sh` 的既定运行环境就是该镜像：PM 线程 2026-10-02 的配方，我这次的容器运行也用它）。

**F2（设计文本已过期，作者已声明，复核属实）· `design.md §1` 仍写着被证伪的规则**：第 36–37 行「只读动词→无所谓；按『只保留 kill 类带身份』这条更简单的规则统一」——实现收窄成「只摘可能起 server 的动词」，而这句话留着会让下一个读者按它去改（§31c ⑪/⑫ 会立刻红）。作者在报告里写明「不动 change 目录，留给 PM」，我核对属实（本分支 `openspec/**` 零改动）。归档前改一句即可。
