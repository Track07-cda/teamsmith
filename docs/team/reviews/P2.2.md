The three facts the implementation is built on:

1. **A symlinked `spec.md` is read through the link.** `file_link_bad`'s archive aborts on the delta's content
   (`probe-cap MODIFIED failed for header "### Requirement: Typo name that does not exist" - not found`) — the
   archiver never notices the symlink, so the gate must not either.
2. **A symlinked `specs/` root is followed.** `root_link_bad`/`root_link_outside_bad` archive aborts on the
   delta's content, so the root link is a discovery root — hence `find -H` (follow command-line links) rather
   than `-L` (which would also walk *inner* directory links into unrelated trees).
3. **Inner directory links are not followed by archive**: `dir_link_outside` archives successfully, i.e. the
   escaping capability dir is invisible to it. Skipping it in the walk matches the archiver; `-xtype f` also
   keeps broken links, links to directories and loops out, and archive ignoring a broken link
   (`broken_link` → archived) confirms that direction.

## 4. The fix

```bash
# skills/teamsmith/tests/spec-lint.sh — change delta discovery
deltas="$(find -H "${d}specs" \( -type f -o \( -type l -xtype f \) \) -name 'spec.md' | sort)"
...
if [ -L "$df" ]; then                                  # a symlinked delta resolves inside the tree …
  tgt="$(readlink -f "$df" 2>/dev/null)" || tgt=""
  [ -n "$tgt" ] && [ -n "$specs_tree" ] \
    && [ "${tgt:0:${#specs_tree}}" = "$specs_tree" ] && [ "${tgt:${#specs_tree}:1}" = "/" ] \
    || continue                                        # … or it is not read at all (escape, §8.1)
fi
```

* `scan_file`/`check_delta` are then called on the link path exactly as on a regular file, so the path and line
  contract is unchanged: `…/specs/probe-cap/spec.md:4: delta-modified-requirement-missing: …`.
* The prefix test is substring-based (`readlink -f`, the repo's existing idiom), not a `case` glob, so a specs
  path containing `[`, `*` or `?` cannot defeat it; the resolved root is computed once per change.

## 8. The escape decision (brief item 1, second half)

### 8.1 What was decided

A `spec.md` whose link target resolves **outside the change's `specs/` tree is skipped, not read**, and no rule
fires. Reasoning, with the archiver as the reference:

* `openspec archive` refuses every such shape with its own path guard —
  `Error: Path is outside the allowed directory: …/specs/<cap>/spec.md` — and
  `openspec validate --all --strict` **fails the same tree first** (`validate` prints the identical error), so
  the project gate (`validate && spec-lint && smoke`) stops before the delta layer is ever the arbiter;
* reading the target would mean the checker parses a file that is not this change's delta — exactly what the
  brief asks not to do — and skipping keeps that guarantee absolute;
* the alternative (a new rule code) would refuse a shape the archiver refuses for a *different* reason and would
  extend the rule-code set enumerated in the active change's delta spec, which is PM territory (`openspec/**`),
  not mine. If the PM wants an explicit code for this class, it needs a spec delta; §11 proposes it as an option.

The 4 escape shapes in §3 are all `validate`-red in every probe I built (absolute escape, relative escape, escape
to inside the change but outside `specs/`, escape to inside `openspec/` but outside the change). That is the same
reachability argument V2 used for its three confound rows, and it is recorded as an observation over five shapes,
not a proof from the CLI's source.

### 8.2 Where that leaves the rc table

Reachable disagreements: **4 before → 1 after** (the 3 closed false greens, plus §8.3). The remaining rc-level
disagreements are all on `validate`-red trees except `root_link_outside_good`.

### 8.3 The one remaining reachable rc disagreement, stated plainly

`root_link_outside_good`: `specs/` is a symlink to a directory **outside** the change, holding an applicable
`ADDED`. `validate` is clean, the gate now reads the delta and passes (correct delta-applicability verdict), and
`archive` **applies the delta** (`Specs updated successfully.`, `+ 1 added`) and then fails its own bookkeeping:

```
✖ Error: The archived delta for 'probe-cap' changed during the final move.
```

That is not a delta-applicability refusal — the archiver accepted the delta and moved the tree afterwards, which
it cannot do when the specs root leaves the change dir. The gate mirrors the archiver's *applicability* verdict,
which is the promise the change spec makes; predicting the archiver's file moves is out of contract. Recorded here
so that "0 reachable disagreements" is never read as more than it is: **0 on the 44-shape matrix, 0
delta-applicability disagreements on the 14-shape symlink sweep, 1 rc-level disagreement of the housekeeping
kind above.**
