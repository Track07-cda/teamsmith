## 4. F1（必修）· git 转义引用的路径名 → 假阳「已合并」

### 现场（判据层）

`git diff --name-only`（默认 `core.quotePath=true`）对非 ASCII / 含 `"` / 含 `\` 的路径输出 C 转义并被
双引号包住；实现把这一整串当成 `:(literal)` pathspec 去 `git diff 分支 main -- …`，于是**这些路径永远
匹配不到**，`still` 为空 → 判成 `merged`：

```
FAIL s11  want=unmerged  got=merged    分支改过的 1 条路径，main 现在的内容就是分支那一版
quoted-name probe: git diff --name-only base s11 = ["\344\270\255\346\226\207.txt"]
FAIL s12  want=partial   got=merged    分支改过的 2 条路径，main 现在的内容就是分支那一版
FAIL s13  want=unmerged  got=merged    分支改过的 1 条路径，main 现在的内容就是分支那一版
control core.quotePath=false on s11: state=unmerged
```

- s11：分支只新增 `中文.txt`，main **没有**这个文件 → 报 `merged`。
- s12（混合）：分支新增 `s12a.txt`（main 有）与 `s12中文.txt`（main 没有）→ 报 `merged`，
  连 ASCII 那半都对不上也一起被吞。
- s13：分支只新增 `we"ird.txt`，main 没有 → 报 `merged`。
- 反向对照：把该仓库 `core.quotePath` 设为 `false` 后，同一条 s11 立刻变成 `unmerged` —— 根因即
  「引用转义没解码 / 没用 `-z` 取原始字节」。这对任何 git 版本都成立（转义是 `--name-only` 的稳定行为）。

### 现场（端到端，PM 看得见）

`02-change-status-e2e.sh` 的 c6：任务 T6 的分支只改一个非 ASCII 路径（`src_中文.txt`），main 上没有它；
报告文件 `docs/team/reports/T6-dev.md` 在分叉点就已在 main（所以 `team_committed_report` 在分支树里
找得到它）。cand 树上：

```
--- c6 (non-ASCII-only change, report on main) ---
change c6 · ready
    T6  apply  dev  wip  已按 squash 合并（内容一致）：分支改过的 1 条路径，main 现在的内容就是分支那一版
  blockers
    （无：全部任务已结束）
```

而事实是：`main: (none)` / `task/T6-demo: src_中文.txt`（`git -c core.quotePath=false ls-tree -r`）。
即**归档前置信号 `ready` 被假阳点亮**；就算报告不在 main，② 文案也会写「已按 squash 合并（内容一致）…
但没有报告」，同样是假话。`pre` 树上同一条 c6 是 `not ready`（祖先判据保守，不会假阳）。

影响面：本仓当前没有非 ASCII 的受版本控制路径（`git ls-files | grep -P '[^\x00-\x7F]'` 计 0），所以
**本仓今天打不到**；但 teamsmith 是随技能发布给别的项目用的通用工具，中文文件名/带引号的文件名在
用户项目里是常态，而这条判据正是归档前置的「所有任务完成」信号。按 P244 要求 1「不能假阳」的原文，
这是一条真缺陷，不是边角。

修法方向（不替作者选）：读路径集合改成 `-z`/`--name-only -z`（或 `-c core.quotePath=false`）拿原始
字节；或对 `still` 用同样的 `-z` 输出计数。修完 s11/s12/s13 应当与 `core.quotePath=false` 的对照一致。
