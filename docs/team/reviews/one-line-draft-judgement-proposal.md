## Findings

1. **判据改成"光标锚定 + 边框配对"**：框不固定在面板底部，所以**上下边框按光标行找**；
   顶部边框必须是**整行等宽规则行**或**spinner 形状行**；**多行候选时取最靠下的那个**——
   否则草稿自己画的分隔线可以冒充边框（V9-A4/A5/A8/A10 复现了"脏框被读成空框"的原始事故）✓
2. **F1 的正解**：**紧贴下边框的那一行按内容读**，**除非**能证明它是框自带的状态行——而"证明"要求
   **两条同时成立**：① 光标**不在**那一行 ② 它的文本**匹配包自带状态行的形状**（Pi 0.87 的布局变化正是被这条覆盖）✓
3. **不许漏看内容行**：必须检查框内**每一行**（不只看光标及上方）——因为"先按回车再打字"或"↑ 取回"的草稿
   会落在光标**下方**（V7-F1 复现了 D20 的原始事故）✓
4. **工作 spinner 行被明确排除**为边框候选，并写明理由（若纳入会把框撑到会话文本上、永远读成忙），
   同时给出"未来 TUI 若把它提升为顶边框"的降级路径（找不到框 → 按现状投递 + 一条告警）✓
5. **代价被写出来而不是藏起来**：在**裁剪长行**的 TUI 上，超长草稿行可能读成等宽规则行、把框撑大 →
   **判定偏向"忙"，绝不偏向"粘进草稿"**（真 Pi 0.85.1 会把内容折在边框宽度少一列处，因此等宽内容行不可达）✓
6. **两处判据同源**（`outbox.sh` 的 `team_input_box_text` 与测试侧 `box-judge.sh`）——这是 P61 明确要求的一条 ✓
7. **MODIFIED 两条 base scenario 一条没丢**（8→13、2→3）✓；`notify-and-inbox` 那条把"停止的座位回退收件箱"与死 pane 的关系也接上了 ✓

## 结论

**ACCEPTED**。apply **高优先级**（投递安全面）：交付后由**不同的人**独立验证（P67 apply → P68 verify）。
