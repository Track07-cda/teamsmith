# P369 · 提案：通知存全文（验收记录）

- 判定: **ACCEPTED**（PM 提案审查）
- author: dev-bob · 受检 `cc47277385` · 审查记录 `docs/team/reviews/notice-fulltext-and-asks-proposal.md`
- 合入: `openspec/changes/notice-fulltext-and-asks/`（proposal/delta/design/tasks）

用户裁定「不要截断，直接传原文」——实测席位的最后消息中位 1952 B、p90 2758、最大 7280，而旧实现截到 150 字，
且同一份截断文本同时进了收件箱行、明细账与敲门载荷。提案的解法：**记录存全文**；只有**预览**截断，且每处自报
`truncated=preview:<shown>/<total>B full=<path>[:<line>]`；`asks=<n>` 用末尾 400 字内的闭集标记识别「这是在问你」；
一个 65536 字节硬上限，超限写 `truncated=hard-limit:…` **且不带 `full=`**——「没有 full=」是「原文在任何地方都不存在」的唯一记号。

**PM 复跑了它的结构性主张**：两个未归档 change 各写一条 MODIFIED 改同一标题，先后归档会静默丢掉前一份的**散文**
（B 归档后 A 的散文从 1 处变 0 处，无报错）。但 `openspec archive` **会拦住**「丢掉当前规格已有场景」的 MODIFIED 块
（逐条点名场景）——所以静默只限散文。这句话要求 apply 时改准。据此确认采纳 append-only（只 ADDED 两条）。
