## 二、判定

设计把我批准的四条口径都落成了可证伪的合同，且比我的要求更细：

- **合并键**四分量（席位／任务／状态类／`awaiting` 集合）＋规范化（集合排序、去重；**字段缺失 ≠ 空集**）；`branch`/`tip`/`uncommitted` 不进键、只更新显示值 → **不存在合成值**。
- **合并行形状**取巧而正确：汇总行 = **最后一条事件的行**、把行首时间戳换成 run 的首事件时间、在字段区插 `×N first= last=`。于是首条事件的行与今天**逐字节相同**（兼容承诺），后续字段自动是最后一条的值。
- **明细兜底**：先明细、后合并判定 → 「`×N` = 该 run 在明细里的记录数」是不变量；上界 2048 事件、只留一代（`notify.log.1`）、轮转头记数；`team inbox <agent> --detail` 只读、不 ack、缺文件或记录不全**点名缺口并非零退出**。
- **叫醒跟着行走**：只有写**新行**才入队 knock；合并的 settle **不叫醒**；knock 的去重身份从「摘要指纹 + 修订戳」换成**行身份**（席位、键、首事件时间）——顺带修掉了今天「两条文本相同但不同的行会互吞」的隐患。
- **既有读者不动**：digest `[2]`、面板尾行、未读计数、`--ack` 都按**行**算；已读行被扩展后仍已读（行数没变）；陈旧判据读最后一条的 `task=`/`tip=`（`last=` 点名它），delta 还把「不得当作当前状态的声明」写进了合同。
- **原子性**：合并只认**尾行**（截尾再追加），「读尾行 → 判定 → 改写」在**每收件人一把锁**内；锚校验不过或写失败一律**追加新行**（fail-safe，绝不重写别人的尾巴）。
- **明确不动**：去重窗口、挂起判定（P236 的 `cwd` 归属）、`[manual]`/`[draft]`/`[nudge]`/pulse 行、敲门的传输机制。

**被否决的替代方案**列了七条（读侧合并、时间窗合并、摘要拼接、只留计数不留原文、计数放 sidecar、穿行合并、把逻辑放 CLI 而不在扩展里消费结果），每条给了否决理由——这份 design 的取舍是清楚的。

1. **语义变化要说给人听**：同类重复轮次（同一任务、同一状态类、同一 `awaiting` 集合）从此**不再叫醒**。这正是本变更的目的，但它是用户可见行为，所以要写进 CHANGELOG：**行上给 `×N` 与首末时间，明细给时间线**；「同类抖动不叫醒」不是「事件消失」。
