## 1 · 1.1 的 `ps` 读数（fork 计数）—— 用**我的**垫片 + **我的**实现变异

**判据**：一次普查只 fork 一次 `ps`（机器级粗筛 `-ww -eo pid=,args=`），不是每个 pid 一次。

命令：`bash scenes/s1_ps_fork.sh`（rc=0，✓10 ✗0；证据 `logs/s1-run.log`）

我的垫片（我自己写的，不是夹具里那个；先写一行日志再 `exec` 真 `ps`）：

```bash
printf 'V44SHIM pid=%s args=%s\n' "$$" "$*" >> "$V44_PS_LOG"
exec /usr/bin/ps "$@"
```

计数方法：`team ps` 在普查开 / 关两种状态下各跑一次，**差值**就是普查该为这一次 `ps` 负责的次数（`team ps` 别的路径若也调 `ps`，会落在差值之外）。

| 读数 | 普查关 | 普查开 | 差 |
|---|---|---|---|
| 我的垫片记到的调用 | 0 | 1 | **1** |
| 其中形态是机器级粗筛 `-ww -eo pid=,args=` | — | 1 | 1 |
| 第二仪器：`bash -x` 里 `+ ps` 行数（独立于垫片） | 0 | 1 | **1** |

- 垫片的**可证伪性自检**：卸掉垫片再跑一次 → 日志 0 行（说明 1 是真读数，不是常量）。
- 真现场：真 `/proc` 上放一个真孤儿（`exec -a pi sleep`，身份指向 scratch 项目），读数不是空跑。
- **我的实现变异** `mutants/mut-one-ps`（我自己写的：把 `team_orphan_candidates` 的粗筛换成逐 pid 的 `ps -o args= -p <pid>`）：

```
--- mutant: ps invocations off=0 on=257（前 3 条）---
    V44SHIM pid=… args=-o args= -p 1
    V44SHIM pid=… args=-o args= -p 1061803
    V44SHIM pid=… args=-o args= -p 1061806
  ✓ named guard “1.1 一次普查只 fork 一次 ps”：候选 → 绿（census delta=1）
  ✓ named guard “1.1 一次普查只 fork 一次 ps”：我的变异（逐 pid 查询）→ 红并点名（census delta=257）
```

即：这条判据**在实现上可证伪**（逐 pid → 257 ≠ 1，日志同时点名退化形态），不是只有夹具手写的变异才红。

**判据本身的边界（如实记下）**：它钉的是「恰好 1 次」，所以是**实现形状**的读数而非合同读数——一个 fork 0 次 `ps`（直接一次性读 `/proc`）的更优实现会被读成红。作为「不许每个 pid fork 一次」的守卫它成立，作为「粗筛必须存在且只有一次」的断言它成立；但不要把它当成「fork 越少越好」的通用判据。
