## 1. 三条修复（逐条）

### 1.1 补丁器不校验命中 → 落空即红

`flip-patch.py` 的判据（全部有独立自检，见 §4）：

| 情形 | 行为 |
|---|---|
| 命中 0 次（M21 事故形状） | `MISS … (nothing written)`，rc=1，文件不动 |
| 命中 >1 次 | `AMBIGUOUS … (want exactly 1)`，rc=1，文件不动 |
| 替换结果与原文相同 | `NO-OP`，rc=1，文件不动 |
| `swap` 三锚点捕获的对象名不一致 | 点名两个名字，rc=1，不猜布局 |
| `swap` 换位后次序没变 | rc=1，文件不动 |
| 正常 | `patched <file> (N → M bytes)`，rc=0 |

补丁器**只报自己做了什么**；破环是否生效另由 flip.sh 在产物上断言（1.2），两者不可互相顶替。

### 1.2 破环点钉在 minify 标识符上 → 改结构锚点 + 产物断言

| 破环 | 旧针（漂移） | 新针（结构） | 落地断言（在剥出的产物上） |
|---|---|---|---|
| F1 hint-after-input | `s.index("kE.hint.map(")` / `")),kE.input.map("`（minify 名 `kE` 硬编码） | `(?P<var>[A-Za-z_$][\w$]*)\.hint\.map\(` ×3 锚点 + `--same-var`（对象名捕获、三处必须同一名） | 产物里前两个锚点必须是 `.input.map(` 在前、`.hint.map(` 在后 |
| F2 clock-frozen | `s.replace("setInterval(GA,1000)", …)`（minify 名 `GA` 硬编码） | `setInterval\(([A-Za-z_$][\w$]*),1000\)\.unref\?\.\(\)`（1000ms **且** 带 `.unref?.()`：只有时钟那只会 unref） | 产物里 `setInterval(<任意名>,1000000000).unref` 出现 1 次、`,1000).unref` 出现 0 次 |

`--same-var` 不是装饰：三个 `.hint/.input/.bottom.map(` 若不再挂在同一个 props 对象上，布局已经变成别的形状，
换位就是瞎猜 —— 直接拒。

**为什么不是"改源码后重建 bundle"**（brief 给的第一选项）：`panel/src/**` 的重建需要 `bun install`
（`skills/teamsmith/scripts/panel/node_modules` 不在仓库里，安装要 registry/网络），验证包必须在离线机器上可复跑。
结构锚点 + 命中数断言 + 产物断言在本机可离线复跑，且漂移时**沉默不会发生**：命中数不对就红。

## 5. 尾部告警的裁决（brief 第 3 条）

PM 抽验时看到的黄字是 `[33m有探针在旧 bundle 上也绿，或翻转不能证伪 —— 见上面的 NOT 行[0m`。裁决：

2. **"旧 bundle 上也绿"分两类，现在都在输出里点名**：
   - **设计内**：`Part A2` 全部 3 条（键位行重钉，见 §3）+ 白名单里的 14 条（inventory 6、visual 7、columns 1），
