## Decisions and deviations

1. **发送 bridge 放在 `scripts/panel/draft-send.sh`（panel 自己的地盘），不是改 CLI。**
   回执契约要求「机器可读的 outcome + rc」，而 `team draft send` 的 outcome 是 shell 变量
   （`TEAM_SEND_OUTCOME`/`TEAM_OUTBOX_RESULT`），跨进程读不到；`cmd-draft.sh`/`outbox.sh` 不在本批授权里。
   bridge 在同一个 shell 里调用**同一个守卫发送函数**（没有复制任何投递语义、没有自己打字），把 token
   打成一行给面板解析——渲染器仍然不碰 PM 的 pane，所有投递仍是守卫的。
   若 PM 更愿意让 CLI 自己吐机器行（E6 §2.5 的 `team draft send --json` 是 v1.1 项），给我一次
   `cmd-draft.sh`/`outbox.sh` 的授权，我把 bridge 的 5 行搬进 CLI 并删掉这个文件。
2. **`team monitor` 新增 `--state-dir`**：面板要写 `state/draft.md`，而 TEAM_STATE_DIR 可能被测试/用户
   指向别处（`TEAM_STATE_DIR` 是 CLI 的解析结果）。显式传参比让 panel.js 猜路径可靠；`--print`/`--json`
   不受影响。
3. **`s` 待命开启的「理由」不写进 `state/draft.md`**（消息草稿不能被理由覆盖）；理由模式下也不提供
   `C-e`（编辑器接力写的就是那份草稿文件，会把消息草稿冲掉）。
4. **键位行加了 `m/f/s`、去掉了 `--no-activity` 的提示文字**：`--no-activity` 功能与文档都没动（26-h
   仍绿），只是底部一行放不下所有旗标。
