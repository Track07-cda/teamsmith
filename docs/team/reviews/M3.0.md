## Decisions and deviations

1. **任务书说的 `team_config_defaults()` 不存在**：默认值实际写在 `common.sh` 的 `team_load_config()` 里
   （配置 source 之后逐键 `TEAM_X="${TEAM_X:-默认}"`）。我把 4 个新键加在那里，没为了对上任务书措辞去重构函数。
2. **`{prompt}` 的实现方式**：定义为窗口 harness 的 `argv[0]`（渲染成 `"$0"`）。派单 harness 是
   `bash -lc "<命令>" "<提示词>"`，所以提示词走 argv 而不是命令行 —— 与原有 Pi 路径同一机制，提示词再长也不会
   撞行长/参数上限。同时把提示词写进 `state/prompt-<agent>-<ID>.md` 供 `{prompt_file}` 与排查使用
   （`state/` 已 gitignore）。这两点都写进了新文档。
3. **【修了一个真 bug】提示词里的 notify 示例参数错位**：`team_build_prompt` 多传了 `$id`，导致渲染出的 notify
   命令把 prompt 文件路径当摘要（codex 实测暴露）。已修 + 加断言（见上）；文档里也把那次 codex 观察改成
   事实描述（是 teamsmith 的错，不是 codex 的怪癖）。
4. **顺手修了第二处真 bug（与 adapter 直接相关）**：`team_monitor_activity` 用 `team_ts_runner` 选运行时，
   而 `monitor.mjs` 是普通 JS —— 在老 node（无 TS 剥离）且没有 bun/tsx 的机器上，活动流会被误判成不可用。
   新增 `team_js_runner`（node|bun|tsx）并在活动流里使用；`team_ts_runner` 仍用于 `.ts` 扩展预检。
5. **roster/say 文案跟随 CLI 名**（`team_agent_cli_name`）：配了 adapter 后不再谎报「pi 在跑」；内置路径文案与
   断言保持原样。任务书第 5 条主要讲 monitor，这里做的是同一类「不因换 CLI 而撒谎」的小收敛。
6. **多写了一个 CHANGELOG 条目（未发布、不动版本号）**：任务书交付物清单没列它，但仓库惯例是每个改动都留一条；
