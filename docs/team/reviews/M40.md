## 交付物

### 1 · 入口解析规则（一处实现，全体共用）

`skills/teamsmith/scripts/lib/common.sh` 的 M40 段 + `scripts/team` 的入口调用：

| 函数 | 作用 |
|---|---|
| `team_dir_roots <dir>` | 从目录推导 `工作树 \t 主工作树`（纯 git，不读任何 `TEAM_*`） |
| `team_identity_resolve [<显式根>]` | 入口身份解析：`--root` 优先于 cwd；成功 → 锁定 `TEAM_IDENTITY_ROOT/MAIN_ROOT/PROJECT`；继承的四件套存进 `TEAM_IDENTITY_INHERIT_*`（**不 export** —— 泄进子进程会让子进程拿父进程的冲突档案判自己的身份） |
| `team_identity_lock_env` | 载入配置**之前**把继承的身份四件套存档后清掉：之后的赋值只可能来自项目自己的配置或目录推导 |
| `team_identity_conflict_pairs` | 冲突判定，每行 `<VAR>\t继承值\t最终值>`。**判据是「同一个项目吗」而不是「同一个路径吗」**（见下） |
| `team_identity_report` / `team_identity_refuse` / `team_identity_observe_only` / `team_identity_gate` | 告警 / 拒绝 / 「只看不改」判定 / 入口闸门 |
| `team_identity_env_prefix [<目标目录>]` | 长驻窗口的身份环境前缀（清继承 + 写目标目录推导出的身份） |

- `team_load_config` 在锁定模式下：身份四件套不进「env 压过配置」的覆盖表，`TEAM_ROOT`/`TEAM_MAIN_ROOT`
  直接取目录推导值（`TEAM_PROJECT`/`TEAM_SESSION` 仍可来自项目自己的配置）。
- `team_find_config` 锁定模式下从**目录推导出的根**向上找配置（不再用继承的 `TEAM_ROOT`）。
- cwd 不在任何 git 仓库里 → `TEAM_IDENTITY_LOCKED=0`，走原有报错路径（行为不变）。

**冲突判据（关键设计决定，brief 留了判断空间）**：`TEAM_ROOT` 的继承值先用 `team_dir_roots` 解析出它的
主工作树，**只有两边主工作树不同**才算冲突。理由：worker 窗口的常规形状就是「env 的 `TEAM_ROOT` 指向主工作树、
cwd 在 agent 工作树里」——按路径比会把每个 worker 的每条 `team notify/report/say` 都拒掉（门禁 32⑤ 钉住）。

**两档处理**（与 brief 的「不一致 → 醒目报错退出」相比更细，理由见「设计决定 §A」）：

| 形状 | 处理 |
|---|---|
| 会改共享状态 / 起进程（`dispatch`、`up`、`pulse up`、`board add/set`、`close`、`say`、`notify`…） | **拒绝**（exit 1），列出被忽略的继承值 + 两条出路 + 显式授权 |
| 纯观察形式（`paths`/`status`/`ps`/`digest`/`inbox`/`board row|ls`/`outbox list`/`pulse status|logs`/`standby status`/`meeting read`/`thread`（读）/`monitor --print|--json`/`__panel-data`/任何 `--print`·`--dry-run`）与 `init|bootstrap` | 按目录解析 + **大声告警**（排障命令拒绝等于把眼睛蒙上；brief 交付物 4 要求这种形状「按 B 解析并打不一致警告」） |

### 2 · spawn 点清洗（长驻进程属于它启动时所在的目标目录）

`team_identity_env_prefix <目标目录>` = 「先 `unset` 身份家族 + 再 `export` 目标目录推导出的身份」。

## 设计决定与偏差（请 PM 重点看这里）

**A · 「观察形式按目录放行并告警」是对 brief 字面（「不一致 → 醒目报错退出」）的细化。** 依据是 brief 自己的
交付物 4：`team pulse up --dry-run` / `team paths` 必须**按 B 解析并打不一致警告**（不是拒），以及用户对事故②的
要求「直接按照 `team up` 运行时的目录来配置 pulse 的目录」—— 只有「看得到 + 动得了（授权后）」才能满足它。
改共享状态/起进程的命令仍然拒绝（与用户认可的 `team up` 护栏同款语义），并且**从不用继承值动手**。

**B · 新增显式授权旋钮 `TEAM_ALLOW_FOREIGN_IDENTITY=1`**（拒绝文案里给出，跑完往 `state/watchdog.log` 落一条审计）。
不这么做的话，「在别处启动的 shell 里按本目录动手」这件事没有任何出口（只能先清环境变量）。

**C · 告警一律走 stderr**（`team_identity_report`）：翻转实验实测，细则行走 stdout 会把机读出口弄坏
（`__panel-data` → 面板 `every block failed (invalid JSON: Unexpected token 'T')`）。这不是翻转的假象，
是实现里的真问题，已修 + 门禁 32① 钉住。

**D · 行为变更（需用户/PM 知情）**：`TEAM_SESSION` 也是身份四件套之一 —— 以前 `TEAM_SESSION=other team …`
能一次性换 session，现在它与项目配置里的 session 不一致时：观察形式按配置的 session 走（告警），改状态的命令被拒。
要换 session 请写进 `.pi/team/config.sh`（`team init --session`）——这也是 `team_session_from` 早就认定的
「explicit = 配置/环境显式指定」的语义收敛。

**E · 残留（不在 brief 的四件套里，未改）**：`TEAM_CONFIG_FILE` 是**显式**定位器（文档化、夹具在用），
仍被信任；若有人把它指到别的项目的配置，`TEAM_PROJECT`/`TEAM_SESSION` 会跟着走（`TEAM_ROOT`/`MAIN_ROOT`/
docs/state 仍是 cwd 项目）。要在文档里点明还是收紧，请 PM 定（收紧需要一个「配置路径 → 项目根」的判据，
目前没有可靠口径）。窗口前缀会 `unset TEAM_CONFIG_FILE`，所以长驻进程不会被继承的定位器带跑。

**F · 身份推导依赖 `git` 在 PATH 里**：`team` 本来也要求 git（`team_is_git_repo`），解析不到时退回改动前的解析顺序，
属于既有的失败模式。

**G · `extension/team-notify.ts` 的根解析（brief 没点名，但是必须改的真回归）**。“身份 = 目标目录”这条一旦用在
worker 窗口上，就会造出「`TEAM_ROOT` = agent 工作树」这个形状，而 notify 扩展的旧 `findRoot` 是 **env 优先**：
它把 root 认成工作树，于是 `worktrees` 前缀变成 `<wt>/.worktrees/`、cwd 不以它为前缀 → `skip settle (not in
worktrees)` → **整个回合通知静默不发**。实测（`notify-probe.sh`，两个真项目 + 工作树里放配置副本的真实形状）：

```
旧实现：ok ① TEAM_ROOT 未设：主工作树收件箱 1 行
         ok ② TEAM_ROOT=主工作树：1 行
         bad ③ TEAM_ROOT=工作树：主工作树收件箱 0 行（通知被静默跳过）
修复后：ok ①②③ 全部 1 行，且三次都确认工作树的收件箱没被写
```

修法：与 team CLI / inbox-watch 同一条原则（cwd 推导优先、env 只在一致时被信任、不一致写一行日志）。
为什么不选「把 dispatch 窗口的身份写回主工作树」（另一个可行解）：工作树里的 `findRoot` 还会被
`session_start` 的重载标记（`state/reload-requested`）用到，而那是主工作树的账本；一致原则比逐个窗口
“绕过”更好维护。门禁把它钉在 13 段（旧实现 → 主工作树收件箱 0 行 → 红）。
