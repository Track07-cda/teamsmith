## 这一版修了什么（用户可感知）

1. **npm 包装也带四个命令入口**（`pkill`/`killall`/`pgrep`/`pidof`）。0.3.0 的 npm 包缺它们，**信号闸门在 npm 路线上等于不存在**（Git 检出安装不受影响）。
2. 图片粘贴真的落盘（新建项目没有容量历史时，降级路径丢失临时根信息，插入的是空路径）。
3. 已 squash 合并的分支不再被报「领先 N」（管道判定在 `pipefail` 下把「找到」变成「没找到」，其中一处只靠 8 字节余量存活）。
4. 长标题流时不再误判「没有接受记录」（同一类管道判定，30/30 误判）。
5. 合法的长门禁不再让等待者超时失败（等待上限原来看一个从没人公布的数字，恒为 0 → 固定 30 分钟；现在跟随持有者心跳）。
6. PM 起不来时诊断说得清（不再出现 shell 的报错与空数字）。

## 这一版修的门禁自身缺陷

- 普通推送跑「地板 + 改动路径」，未知路径仍退回全量；地板按段 key 的稳定哈希切成四片，CI 里一个独立作业断言四片的并集**恰好等于地板**。
- 私有 tmux 锚点随运行消失（外部 `kill -9` 后 2 秒内），socket 目录回收形状修对（此前每轮漏一个空目录，本机曾积到 1233 个）。
- 两处「时红时绿」修根：运行登记的 EXIT trap 武装太晚；`§34b` 最后两处墙钟窗口换成确定性条件。
- 一条**死了两个版本**的断言被救活（红标检查拿带 ANSI 的串比对已去色的文本，永不命中；现在配正向对照）。
- `--keep` 不再泄进夹具自己发起的嵌套运行；`seat-interrupt` 的一个 live 组自 P309 起其实从未跑过（现在恢复）；
- 路由变异矩阵最慢那条臂的预算 900 s → 1800 s（实测 844 s），撞上限时点名「哪条臂、用满多少秒」；
- 一条 82 分钟的段（§61b）以前**对守卫完全不透明**——不交任何进度，被 1800 s 的挂住判据当成挂住停掉；现在矩阵的日志在长就是进度。

## 过程错误（记在这里，因为下一个人会犯同样的）

1. 第一次整套跑完 3h47m 却只留下 `✓4927 ✗13`：日志写进了容器自己的 `/tmp` 且用管道取尾，容器一退现场全丢 → **规则：长跑日志与现场必须落在 bind mount 的宿主路径，不许管道取尾**。
2. 试过「四片并行加速」：在同一台机器上不成立（夹具以默认值、独自运行、干净环境为前提），收到 16 条自家跑法造成的假红 → 已记进 `release-0.3.1-gate-notes.md`。
3. 把临时根挂到容器内 `/logs`，撞上 `tmux-lint` 的「任何含 `logs/` 的路径整段跳过」排除规则，37 个自检夹具全被跳过、一次四小时运行作废 → 盲区已由 P359 修掉（独立验收 V92），但**不在本版**。
