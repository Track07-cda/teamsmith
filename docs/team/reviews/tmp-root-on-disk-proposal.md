## 判定要点

- **默认值**：`/var/tmp/teamsmith-<ns>`（磁盘），`/tmp` 仅作平台兜底；**解析顺序只有一处实现**（"no second implementation of that order MAY exist" ✓）。
- **理由写进了规格正文**（正是我给的数据）：`/tmp` 是 15 GB 内存盘、78% 满、事故时耗尽的是那 3.3 GB 与 inode 表；`/var/tmp` 在磁盘上、228 GB 空闲——**「夹具写 /tmp 花的是 OOM killer 读的同一个池」**。
- **`TMPDIR` 优先于契约键**，且**「pin 被覆盖时打印出来而不是静默」**——比我要求的多一层（我只要解析顺序，它把「静默覆盖」也堵了）。
- 场景里有一条强断言：**默认情形下运行期间**根在 `/var/tmp/teamsmith-<ns>`、**跑完消失**、所有打印它的面都写 `source=default`、**`/tmp` 下不落任何东西**。

## 准入条件（apply）

1. **一个解析函数**（夹具/清扫器/门禁/容器挂载共用）；**余量地板绑定选定的根**并在报错文案里点名它。
2. **红侧**：① 把解析改成各处自算 → 必须红；② 把地板检查指回固定 `/tmp` → 必须红（选定根很空、`/tmp` 很满时不许拒绝）；③ 选定根不可写 → **具名失败**并给修法，**不许静默退回 `/tmp`**。
3. **迁移与回滚**：默认行为变化进 CHANGELOG；`TEAM_TMP_ROOT=/tmp` 可回退。
4. 不变量：夹具隔离/清理/年龄判据不变；不改门禁判定口径。
