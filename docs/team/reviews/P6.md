## 已知边界与记录在案的取舍

1. **纯空白草稿是盲区**（规格 R1 scenario + troubleshooting §3）：只有空格/制表符的草稿判 EMPTY——检测器不知道光标列，保守方向（不拦）会重新引入粘字，选择拦不住但写进规格与文档。
2. **check→paste 仍有残余竞态**（troubleshooting §3）：复检到 Enter 之间人敲进一个字会被一起提交；第二道复检把窗口压到一次 paste 的时长，且「粘贴期间出现草稿 → 不发 Enter → held」已夹具化（12b-h ⑨）。
3. **UNKNOWN 不排队**（规格 R1 scenario）：找不到框线 = 非 Pi pane，按今天行为投递 + 一行警告；排队对非 Pi 目标没有任何意义。
4. **held 不等于丢**：TTL/cap/unconfirmed/draft-raced 都进 `held/` + `HOLDING.log`（hold 时刻、尝试次数、原因），payload 早已 durable（收件箱/nudges.log）；`team outbox flush`/`drop` 是显式出口。
5. **扩展绝不回退打字**：enqueue/flush 失败只记日志并保留收件箱行——宁缺一次敲门，不粘人的草稿。
6. **v3 基线升级未做**（design DG1 的可选项）：tasks 1.1 允许 v2 单独满足要求；没有自带 falsifier 就不上。
