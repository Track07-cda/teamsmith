## 2. 三条必修（FAIL 的实体）

### M1（= F-V27-1）非正规 index/body 让读命令**永久挂住**

- 违反规格：`key-replies` · 「Traversal and nonregular sources are refused」明文要求
  「rejects **without reading the target or blocking on the FIFO**」。
- 证据（4s `timeout` + 我自写的 `LD_PRELOAD` 全路径记录；`pkg/01b-fifo.sh` + `artifacts/01b-fifo/table.txt`）：
  | 场景 | `reply list` / `show` | 最后一步 open(2) |
  |---|---|---|
  | `index.v1` = FIFO | **rc 124（挂住）** | `index.v1 655360`（`O_RDONLY|O_CLOEXEC|O_NOFOLLOW`，**无 O_NONBLOCK**） |
  | `bodies/<id>.md` = FIFO | **rc 124（挂住，含 `--raw`）** | `<id>.md 655360` |
  | 对照：`post` 对 FIFO 索引 | rc4，`index.v1: not a regular file` | 走受保护的打开 |
- 源码定位（`scripts/replies.mjs`）：带 `O_NOFOLLOW` + `fstat.isFile()` 的 `openFileAt()`（207–222）只被写路径用；
  读路径的索引 fd（506/628/683/759）与 `readBody()`（724）缺 `O_NONBLOCK` 与类型判定。
- 影响：CLI 永久挂住（不是报错）；面板有 10s 子进程超时兜底但白等 10s。触发是本地可控的 store 形状。
- 修法（建议）：两处 `openSync` 加 `O_NONBLOCK` → 复用现成 `isFile()` 判定 → 清位；补两条夹具断言
  「rc≠124 且有 `not a regular file` 诊断」。

### M2（= F-V27-2）`team reply list --before <no> --json` **静默丢游标**

- 证据（`pkg/01c-cursor.sh` + `logs/01c-cursor.log`，60 条回复）：
  `reply list --json --before 31` → 第一条 #30（正确）；`reply list --before 31 --json` 与 `--before=31 --json`
  → 第一条 **#60**（静默返回最新页，`next_before` 也回到 11）；文本形态 `--before 31` 正确。
- 根因（读码）：`scripts/lib/cmd-reply.sh` 的 list 分支里 `--json) extra=(--format json) ;;` 是**赋值**，
  把先前解析到的 `--before` 整个丢掉（应为 `+=`）。
- 影响面：按 help/`SKILL.md` 表格推荐顺序调用的读侧会重复读同一页；面板不受影响（走 `__panel-block` 的
  `--before X --format json`，不经过这段）。
- 修法（建议）：改为 `extra+=(--format json)`；补一条夹具把**两种参数顺序**都钉住。

### M3（= F-V27-3）本 change 登记的 §61 在**门禁镜像**里是红的（镜像没有 C 编译器）

- 证据（容器 `localhost/teamsmith-gate:local`，干净 clone @ 冻结 tip；`logs/container-gcc.log`）：
  `gcc/cc/clang/tcc` 全 MISSING；`key-replies.sh --select bounded` → **✓4 ✗1**
  （`IO 计数 shim 编译失败（… gcc: command not found）`）；`--select flip` → **✓8 ✗1**
  （`flip/full_scan：红/绿翻转不对（red_probe=0 green_probe=0）`，同一 shim 的连带）；
  走门禁入口 `smoke.sh --select 61` → **✓21 ✗1**。宿主上同命令全绿（`--select flip` ✓9 ✗0、`--all` ✓168 ✗0）。
- 根因：`ci/Containerfile:61-62` 编译完 tmux 后**故意** `apt-get purge build-essential …`（M47 起），
  所以钉死镜像里永远没有编译器；`.github/workflows/gates.yml` 用的就是这份 Containerfile → **CI 也会同样红**。
- 影响：本 change 唯一在门禁环境里直接判红的点；作者报告里的「§61 ✓1 ✗0」只在宿主成立，
  与「按门禁环境取证」的纪律不符。
- 修法（建议）：按项目既有约定让缺工具**可见跳过并点名**（最小修法），或改用不需要编译器的手段
  （如读 `/proc/<子进程>/io` 的 `rchar/syscr`）；无论哪种，`flip/full_scan` 在 shim 缺席时也必须可见跳过而不是报红。
