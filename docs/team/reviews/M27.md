## 机制：三条规则落在哪一行

```
team_bg_run ── spawn(bash -c, detached, stdio=state/bg/<id>.log)  ── 立刻返回 {id, pid, log}
      │                                            日志有界：裁剪定时器每 2s 检查一次（TEAM_BG_LOG_MAX_BYTES，
      │                                            默认 512KB），超限就地留尾段 + 一行截断标记
      ▼
回合结束（agent_settled）──► state/bg.log: settled-with-unharvested=<n> jobs=<id>:<running|exit<code>>
      │                              未收割的已完作业 → 合并成一条 followUp（triggerTurn）
      ▼
作业退出 ──► 已收割？→ 静默（#689 ①）
            未收割 + agent 空闲 → 250ms 合并窗口后把「这一拍完成的全部」投成一条（#689 ②）
            未收割 + agent 正在跑 → 留给下一次 settled（不插队）
```

- **为什么唤醒要分两条路**：只按 `agent_settled` 投递会漏掉「作业在回合结束后才完成」这一最常见的情形
  （PM 的后台门禁就是这样）；只在退出时投递又会把「同一拍完成的多条」拆成多条消息。两条路共用同一个
  `flushPending`（按 `done && !harvested && !notified` 取集合），所以既及时又合并，且一条通知只发一次。
- **为什么日志要有界**：长门禁可以输出几百 MB，而磁盘是共享资源；上限与截断标记让「产物有界」成为默认。
- **为什么作业是 detached**：PM 的门禁可能跑在会话重启之后；`session_shutdown` 只清 job 表（不杀进程），
  日志与账本留在 `state/` 里可读（代价写在文档里：重启后没人再被唤醒，账本是记录）。
