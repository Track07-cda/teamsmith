  父目录已经是真目录，整条路径就判绿——而正文来自之前 open 的那个 fd。判据与读的对象不是同一个，窗口即此。

  每一段此刻都不是软链」来兜底；上面的数字说明「此刻」正是那个可命中的窗口。

**加固（我给的，已实测）。** 关闭窗口不需要重构：open 一次，用 **no-follow** 的路径身份比对 **fd 身份**：

```bash
      # VERIFIER DEMO PATCH v2：open 一次，再要求「打开到的目标」与「此刻路径指向的东西」同一身份
      text="$( {
        v33_fd="$(stat -Lc '%d:%i' /proc/self/fd/9 2>/dev/null)"
        v33_path="$(stat -c '%d:%i' "$abs" 2>/dev/null)"
        if [ -n "$v33_fd" ] && [ "$v33_fd" = "$v33_path" ]; then
          head -c "$cap" <&9 2>/dev/null | iconv -c -f UTF-8 -t UTF-8 2>/dev/null || true
        fi
      } 9<"$abs" )"
```

- 软链在 open 前：路径的 no-follow 身份是**链接自己**的 inode，与 fd 的目标身份不同 → 丢；
- 软链在 open 后、比较前换上：fd 是原文件的 inode，路径是链接的 inode → 丢；
- 软链在 open 时命中并全程持续：路径身份 ≠ fd 身份 → 丢；
- 安静树上的合法文件：两者同 inode → 照读（E7 控制组、第一轮 91 条静态检查、作者 §28 全绿）。

## 10 F1（阻塞）：目录软链被读穿，openspec 根纪律与「不服务别的 change/archive」被破坏

**合同出处**（delta，MODIFIED `A focused card opens a read-only markdown detail view`）：
"The sources' roots are the reader's own project root: the spec and change sources **read only under the openspec
directory** …"；"MUST NOT serve a file of **any other change or of `openspec/changes/archive/`**"；
"a discovered path that is **a symbolic link** SHALL be refused and named, **never read through**"。

**实现现状**（`cmd-watch.sh`）：叶子判据在各 records 函数里都有（`[ -L "$f" ]` → 进 `refused`、不进发现集），
但 `team_panel_detail_records_spec` / `_change` 直接拼 `$(team_spec_dir_abs)/specs/$id/spec.md`、
`$(team_spec_dir_abs)/changes/$id/<name>.md`，**没有检查路径中间的目录是不是软链**。于是：

```
$ bash probe-reader.sh <frozen clone>       # 容器 + 独立 clone
[probe] 85 ok, 6 failed
[FAIL] symlink-dir: a symlinked change dir does not serve a file outside the openspec root :: escaped, count=1
[FAIL] symlink-dir: the symlinked change dir is refused and named :: None
[FAIL] symlink-dir: a symlinked capability dir does not serve a file outside the openspec root :: escaped, count=1
[FAIL] symlink-dir: the symlinked capability dir is refused and named :: None
[FAIL] symlink-dir: a change dir symlinked to another change serves no file of it :: count=3
        ['openspec/changes/alias/proposal.md', 'openspec/changes/alias/design.md', 'openspec/changes/alias/tasks.md']
[FAIL] symlink-dir: a change dir symlinked into archive/ serves no archived file :: count=1 text='# archived proposal'
[OBS] changes block rows: ['alias','archalias','demo','demo2','other','sym','symdir']
        (symlinked dirs listed: ['alias', 'archalias', 'symdir'])
```

四个形状（都在夹具里复现）：

1. `openspec/changes/symdir -> <树外目录>` → `--source change --id symdir` 返回 `count=1`，正文是
   `# OUTSIDE-DIR-SECRET proposal`（**读穿了 openspec 根**）。
2. `openspec/specs/linkspecdir -> <树外目录>` → `--source spec --id linkspecdir` 同样把树外 spec 当正文。
3. `openspec/changes/alias -> openspec/changes/demo` → `--source change --id alias` 服务 demo 的三个 artifact
   （**服务了另一个 change 的文件**）。
4. `openspec/changes/archalias -> openspec/changes/archive/old` → 服务归档 change 的 proposal
   （**服务了 `archive/` 的文件**）。

**可达性**：不需要手工敲 CLI——面板自己的 changes 块就把这三个软链目录列成了行（上面 `[OBS]`），
用户在**工作页**走到 `symdir` 行按 enter 就打开树外文件。修好之前，预览面不是"只读的三类发现集"，
而是"用 `--id` 命名任意软链目录 + 该目录里有 proposal/design/tasks 或 spec.md"的读取器。

**为什么这比作者的软链红侧更硬**：作者的用例是叶子软链（被 `-L "$f"` 挡住）；一个"解析目标再看是否在允许根内"
的替代实现能过作者那条，却仍会把 `symdir` 判成合法（它的解析结果不在允许根内……只有真的做根前缀比较才挡住）。
换句话说，作者的用例只钉住"看不清"这一层，钉不住"根纪律"。

**修法（示范，非候选改动）**：在发现阶段拒绝任何**组件**是软链的目标，或把候选路径 `readlink -f` 后要求它
