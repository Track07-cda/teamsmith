## 3. The rule, and the measurements it rests on

### 3.1 Two link positions, two reference trees

| link | reference | why (measured, 1.8.0) |
|---|---|---|
| `specs/<capability>/spec.md` → … | the change's resolved `specs/` tree | `resolveTrustedSpecPath` canonicalises both and throws `Path is outside the allowed directory: …/spec.md` when the target lands outside; the error is content-independent (a good ADDED does not help) |
| `specs/` → … | the **change directory** | the archiver *follows* the root link, so the tree itself cannot be its own escape reference; whenever the root leaves the change the archiver applies the delta and then fails `The archived delta for '<cap>' changed during the final move` — never a clean rc=0 |

A `specs/` root link that stays inside the change (`ln -s real-specs specs`, P2.2's `root_link_bad/good`) is
therefore still followed and content-checked, and `ln -s . specs` (root = the change itself) is allowed too — my
probe shows archive **rc=0 and archived** for an applicable delta in that shape (`root_dot_good`), so refusing it
would have been a false red. The `within-or-equal` test is what makes that case pass.

```bash
# skills/teamsmith/tests/spec-lint.sh — helpers, then the change loop
sl_within() { [ -n "$1" ] && [ -n "$2" ] && [ "${2:0:${#1}}" = "$1" ] && [ "${2:${#1}:1}" = "/" ]; }
sl_within_or_eq() { [ "$1" = "$2" ] || sl_within "$1" "$2"; }
sl_escape_violation() { VIOLATIONS="${VIOLATIONS}$1:1: delta-symlink-escape: $2"$'\n'; }

specs_tree="$(readlink -f "${d}specs" 2>/dev/null)" || specs_tree=""
change_tree="$(readlink -f "${d%/}" 2>/dev/null)" || change_tree=""
if [ -L "${d}specs" ] && [ -n "$change_tree" ] && [ -n "$specs_tree" ] \
   && ! sl_within_or_eq "$change_tree" "$specs_tree"; then
  sl_escape_violation "${d}specs" "specs/ root link resolves outside the change directory: $specs_tree"
  continue                                    # the escaping tree is not walked
fi
...
if [ -L "$df" ]; then
  tgt="$(readlink -f "$df" 2>/dev/null)" || tgt=""
  if ! sl_within "$specs_tree" "$tgt"; then
    sl_escape_violation "$df" "delta link resolves outside the change's specs tree: ${tgt:-<unresolvable>}"
    continue                                  # the target is never parsed as a delta
  fi
fi
```

Both operands are `readlink -f` output and the test is a plain prefix + separator check (the repo's existing
idiom), so a specs path containing `[`, `*` or `?` cannot defeat it. One line per defect, always at
`<link>:1` (a link has no parseable content lines; `no-requirements` uses line 1 the same way), with the resolved
target in the detail.

## 9. Decisions and deviations

1. **Root-link reference = the change directory, not the root link's own target.** The brief's parenthetical
   ("or a `specs/` root link whose target resolves outside the change's `specs/` tree") cannot be read literally:
   the root link *defines* the tree, and the archiver follows it (P2.2 §3 fact 2, re-measured). Refusing every
   root link would have been stricter than the archiver and would have made `root_link_good`/`root_dot_good`

   `check_delta`-stripping guard cannot prove it; §16 now strips `sl_escape_violation` for those three fixtures
   and cross-checks the copy's liveness. Keeping them in `SL_RED_FIXTURES` would have made the main guard report
   a false failure.

   table, the escape row's reading, and a superseded banner on §8.1 — the historical reasoning is kept, not
   rewritten silently.
