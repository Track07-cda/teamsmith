**合同怎么说**（delta `specs/verification/spec.md`，ADDED 第 2 条）：

> …its own section guard SHALL be armed with a deadline taken from the ancestor's currently armed section (**the holder

> falling back to its own table budget when that heartbeat is unavailable.

design §3.2 同义：「`heartbeat`：持有者当前武装段的 section-guard 心跳文件路径…**嵌套运行读它**（格式

**实现**（静态证据 `gates/static-heartbeat.txt`）：

也就是说：**记录里的 `heartbeat=` 是死字段**；期限对齐靠的是一个可被任何子孙 `env -u` 掉的继承变量。后果正是这条要求要治的那类：环境里没有它时，嵌套运行**无声**退回自己的表预算（这里 §0 是 60s；全量运行就是它自己的 Σbudget），也就是说它可以远晚于生它的那一段结束，而没有任何一行提示「祖辈心跳没找到」。套件自己的夹具就惯于清掉这个变量（作者 §34b⑧ 的 `p8n_run`/`p281n_run` 里明写 `-u SMOKE_ANCESTOR_HEARTBEAT`），所以这不是假想形状。

```

          （算式：remaining=390s + 60s → cap=450s…）

          （算式：remaining=389s + 60s → cap=449s…）
```

三条证据链：① v0.2.0 没有这条断言、它 §34 ✓48 ✗0；② 候选上 3 次跑出 2 红 1 绿；③ 红/绿两侧的原始 `g.log` 行只差「已跑 10s/11s」。这不是代码正确性问题，但它把门禁变成一条**随机器负载变红的墙上时钟判据**，与项目自己的门禁纪律（「超预算 = 存活检测，不是性能判定：机器再慢也绿」「The gate judges correctness only」）相反。建议：把窗口放宽（如 `remaining=3[89][0-9]s`）或按记录里的 `started` 在运行时算期望值，别钉死一个字面窗口。

**整套门禁**：见 §11（后台运行，结果在本记录末尾补写）。

## 9. 发现汇总（按严重度）

### F1（必修：合同不符，有行为后果）——祖辈心跳不经记录传，靠可清除的继承变量

- 合同：见 §2 的 spec/design 原文。
- 事实：`gate-lock.sh:90` 写的 `heartbeat=` 全仓无人读；嵌套运行只认 `SMOKE_ANCESTOR_HEARTBEAT` 环境变量（`smoke.sh:470`、`section-guard.sh:73`）。
- 行为红侧（B3）：持有者记录公布着一个真实可读的心跳文件，嵌套运行环境里没有那个变量 → 不设期限、10s 内不点名、登记还在（B1 是同样条件的绿侧：变量在 → 3s 到点）。
- 后果：嵌套运行在环境被清（套件自己的夹具就这么干）时**无声**退回自己的表预算，可以跑出「生它的那一段」很远——正是本变更要治的形状；而且降级没有任何一行提示。

### F2（规格字面偏差，影响小，PM 可裁定）——`no_lock=1` 从不写进记录

见 §6：三条 opt-out 路上没有记录文件，`no_lock=1` 只在 stdout；规格与 design 都说 record。

### F3（新引入的夹具抖动红）——§34⑦ 的 1 秒宽窗口

见 §8：同一命令候选树 3 跑 2 红，v0.2.0 无此断言且全绿。

### F4（残余信任边界，越出 brief 三形状的对抗探针）——自带 marker 的伪造仍能覆写/删除真持有者记录

现场（`scenes/g-marker/`）：真 `flock` 持有者（pid 1956764）持锁并写了记录；它的一个子孙继承着 `SMOKE_LOCK_MARKER`（真路径里每个子孙都继承），该子孙把 marker 写成自己的 pid 后跑 `bash smoke.sh`（不带 `--select`，于是锁块就在它自己进程里）：

```
forger own line:  · 全量门禁互斥：持有 …（kind=top pid=1956804 agent=dev worktree=…）
holder record while the forger runs: … pid=1956804 …  ← 记录换了人（它不是 flock 的持有者）
  => the record now names the forger, which does not hold the flock
is the flock lock still held by the real holder? HELD
holder record after the forger exits: <MISSING>
lock after the forger exits: HELD
waiter line: 另一套全量 smoke 正在跑（持有者未知）；本套排队，最多等 1s（…）
G observed: the waiter read 持有者未知 while the real flock holder pid=1956764 was still alive
```

这正是 EXP1 的等待者可见症状（记录被覆写、退出时被删、等待者读到「持有者未知」），现在从「只要继承环境标记」收窄成「要主动写一行 marker」。合同的**规则句**说的是「a run that *merely inherited* the wrapped marker MUST NOT overwrite it」，实现符合规则句；但规则句的**目的**（"so a waiter never reads a process that does not hold the lock and never reads `holder unknown` while the real holder is alive"）仍可被一次有意写触达，而 marker 路径在环境里对整棵子树可见。裁定权在 PM：接受（需要有意写）或收紧（例如不导出 marker 路径、改走非继承通道，或再加一层「本进程真持有 fd」的判据）。

## 10. 观察（都不是判定，记给 PM 与后续席位）

1. **机器锁的 runs 目录会积陈旧记录**：作者交付运行（13:05）留的 `993500.run`（kind=nested、`agent=? worktree=?`、heartbeat 指向已删的临时根）到 14:46 还在，每一个等待者的行里都被打印成「陈旧记录」。规格明确容忍（"the gate MUST NOT remove records it did not write"），但机器锁目录是跨任务共享的，会越积越多。
2. **`team review` 写完持有者记录从不删**：`cmd-review.sh` 里没有一处 `gate_lock_remove_holder`（它的 holder 由 `QUEUE_WRAP` 的 `bash -c` 写，之后 exec 走人）。后果：每次 review 结束都留一条 stale 记录；下一个持有者接手到它写自己记录之间有个小窗口，`gate_lock_cap` 会读这条 stale 记录的 `expected/started`（它不查存活）——窗口内算错上限。影响小，但值得记账。
3. **§34 的一行 stderr 噪音**：`P34_TMUX_LOG` 的 `: >` 在 `mkdir -p "$P34D"` 之前，fresh 临时根里第一次会打一行 `No such file or directory`。**v0.2.0 就有**（同文件同行），不是本变更引入。
4. **上限算式会抬高顶层等待者的上限**：`clamp(remaining+60, W, 4W)` 在持有者公布很小的 `expected` 时把上限顶到 4×W（场景 D2：W=2 实测等 8s，算式与三个数都打印）。这是 D3 的规格行为，只是老文案「wait capped by TEAM_SMOKE_LOCK_WAIT」现在要按 §9b-2 的新算式读。
5. **`team review` 的 `expected` 永远按整套 smoke 表算**：`cmd-review.sh` 调 `gate_lock_expected` 时固定传 `tests/smoke.sh` 与预算表，不管 `TEAM_GATES` 实际跑什么 → 一次 `TEAM_GATES='true'` 的 review 也会公布「129 段 / expected≈9371 / bound≈41486」，让等待者按整套的时间观念等。这是代码阅读结论（我没有跑到真 review 的记录），影响方向是「多等」。
6. **`team review` 自己的排队阶段只认环境标记**：`cmd-review.sh:1087` 用 `SMOKE_LOCK_WRAPPED=1` 判「已由祖先持有」，不做父祖证明。伪造该标记会让 review 跳过自己的排队阶段，但它门禁里的 smoke **仍会**证明祖辈并排队 → 机器仍然串行，差别是那段排队时间会算进 review 的硬超时（M49 的归因形状）。规格的 MODIFIED 条款字面就是这么要求的（"When the environment already records that an ancestor holds the gate lock"），所以我记为观察而非 finding；也没有端到端跑（见 §12）。
