## 根因 2：后台进程组 + tty 读 stdin = SIGTTIN **停住**（不是死锁、不是 CPU 忙等）

最小复现（`/tmp` 私有 socket pane，交互式 shell 里带 `&` 提交后台作业）：

| 形状 | 子进程 stdin | 结果 |
|---|---|---|
| 后台进程组 + 裸 `read` | `/dev/pts/23`（tty） | **STAT=TN —— 被 SIGTTIN 停住**，0% CPU，输出停在 `READER_START`（看着就是「挂死」） |
| 后台进程组 + `</dev/null` | `/dev/null` | 立刻 EOF，跑完 ✓ |
| 前台 + 裸 `read` | tty | 跑完 ✓（前台进程组读 tty 合法） |
| 后台进程组 + `bash -lc 'command -v pm-bare'` | tty | **停住** —— 登录 profile（distrobox 的 `host-spawn`）会碰 tty |

这解释了矩阵的每一格：前台绿（前台进程组）✓、后台窗口 + 裸门禁绿（`tmux new-window -d` 让命令
成为该 pty 的**前台**进程组）✓、后台窗口 + review 包装挂（包装把 review 放进了后台进程组，
`timeout` 只是让它一直挂着，没有 deadline 就永远不回）✗。也解释了为什么「TERM 被忽略」：
进程根本没在跑，它在 **TASK_STOPPED** 状态，收不到 TERM。

**修法**：门禁的 stdin 一律 `/dev/null`（`cmd-review.sh`）。这同时护住了**所有**调用方
（PM 后台化、CI、脚本），不管门禁里有什么子进程会碰 tty。

## Decisions and deviations

- **只改门禁启动行**（`cmd-review.sh`）+ 夹具（`tests/smoke.sh`），边界内没有碰记录格式：
  复验记录抬头、判定词、`gates:` 标记一字未动（F10–F17、F3、F14d 等既有断言全绿）。

  未来新增的 `TEAM_REVIEW_*` 自动纳入，不用改代码。
- **`</dev/null` 而不是 `setsid`/`nohup`**：只切断「读 tty」这一条通路，不改变进程组、不给
