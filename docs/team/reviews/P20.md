## Decisions and deviations

1. **delta spec 的 Kitty scenario 算术修正（12 → 10）**：`alpha beta` 末尾 `ctrl+b`×3 到 index 7（`alpha b|eta`），
   再 `alt+b` 到 index 6（`alpha |beta`），`│ > alpha ` 是 10 列 → `#{cursor_x}` 10；原 scenario 括注的位置
   也描述的是「退一格」而不是三格。夹具同时断言 **legacy 字节复跑落在同一点**（这才是要求里的硬约束：
   两种编码行为一致）。`specs/panel/spec.md` 与 `tasks.md` 的 12 已按实测改成 10，报告在此披露。
2. **理由模式提示不写 `C-o`**：`relayEditor` 在 `mode !== 'message'` 时直接返回（既有规则：理由不写
   `state/draft.md`）。tasks 3.4 字面要求两条提示都点 `C-o`，但把编辑器挂在理由上会是「按了没反应」的死键，
   所以 `composeReasonHint` 只点名 `C-j`（换行→空格）。请 PM 定夺是否要给理由模式也开编辑器。
3. **B4 的 `src/clipboard.ts` 与接线随 B3 提交**（`ab99fae`）：B3 结束时为了保持 bundle 可构建把它一起带了
   进来；B4 提交（`6c7dceb`）带的是它自己的夹具与翻转。功能边界不受影响，但「一批一提交」的干净度有瑕疵。
4. **main worktree 的一次误写（已完全还原）**：B1 开始时我的编辑器把 4 个源文件 + 新夹具写进了主工作树
   （`/home/.../pm-skills`）。发现后立即 `git checkout --` 还原那 4 个文件、删掉主工作树里的新夹具，把改动
   搬到 `.worktrees/dev2`；主工作树现在只剩 PM 自己的 `docs/team/BOARD.md` 改动，未被我触碰。今后所有路径
   都在 worktree 内。
5. **Ink 7.1.1 的两个实测缺陷与对策**（都写进了代码注释）：
   - 满屏帧（无尾换行）时 `useCursor` 的 `buildCursorSuffix` 假设光标在「输出下一行」，实际差一行；而且
     「只动光标」的重绘路径每次还会再漂一行（实测：连按 ← 跨软换行后光标沿屏幕向上走）。对策：main.tsx 用
     一个 **cursor-aware stdout** 在每次 Ink 写入后补发绝对 `CUP`（同一 write 里，连节流帧也覆盖）。
   - 编辑器接力时，按 `C-o` 触发的那次 React 提交会带出一次**节流尾写**，在编辑器打印首行之后擦掉它
     （实测 `EDITOR-ACTIVE` 被面板帧覆盖）。对策：handoff 前 `waitUntilRenderFlush()` + 60ms（>`1000/30`）
     的宽限。
6. **性能口径**：`panel-cpu.sh` 判的是**面板进程均值** <1%（30s 采样的 `pane_delta%` 均值），不是整棵读者树；
   写信+一次粘贴的采样 0.599%。树总计 29.8% 是这 30s 内所有块读者进程的合计，非面板自身。
7. **边界**：未触碰 M40 的地盘（身份/spawn/`extension/team-notify.ts`/`cmd-*.sh` 的 TEAM_* 逻辑）；`smoke.sh`
   只在 28-h 之后追加了 28-h2，§32 未改。
