
夹具：空框 + `MTUI_DRAFT_ON_PASTE=HUMAN_`（粘贴开始的一瞬人打了一个词）；payload 三行 `alpha/beta/gamma`；
`team draft send` 后由人按一次 Enter，然后依次跑 `flush`、`flush --now`、`watch --once`。
`SUBMIT:` 日志就是「落到目标上的投递次数」的硬计数。

| 步骤 | 提交次数 | held/ | 其他 |
|---|---|---|---|
| `draft send`（守卫预检看到空框 → 粘贴；复检发现 `HUMAN_` → 不发 Enter） | **0** | 1（`draft-raced`） | 框被污染：`HUMAN_alpha line one…` 在框里；发送方输出 `queued` |

**裁决：在 `f6a6ec6` 上，V7-F3b 的说法不成立** —— 同一 payload 没有到两次。唯一一次投递来自**人自己的 Enter**

check→paste 残余竞态，也是「draft-raced 终态」这个决定的理由，而不是第二次投递。

同一份探针在同一时序下红绿互斥 —— 因此这不是夹具假象。

- 同一根因的镜像（`V8-N1c`）：光标在框线**上方**、草稿文字在框线下方 → 下边框搜索把草稿的框线当下边框，框线下方的
  文字被排除 → 同样判 EMPTY。
- 后果：**自动化消息粘进人的草稿并一起提交**（D20 的损害本身）。
- 可达性：真实 Pi 已复现（粘贴/输入一行 `─` 即可，Markdown 分隔线、表格/代码块分隔、CJK 输入法都可能产生）。
- 修复方向（供参考，不是本报告的义务）：上/下边框候选要求是**贯穿整框宽度的框线**（而不是任意长度的 `─` 行），
  或者把候选框线行**本身也当内容**、只有与真实边框几何一致时才截断；并给这个形状配一条 falsifier。

### 3.2 `V8-F4b`（中）—— 未确认时不立即进 `held/`，与规格逐字不符

- 规格 R4："when the box then still is not empty the drain SHALL move the entry to `outbox/held/`"；
  实测（Enter 被 TUI 丢掉、框里仍只有 payload）：刚好 2 个 Enter（一次粘贴 + 至多一次补 Enter），但条目**留在活动队列**
  （1 active / 0 held），`held` 只在 `TEAM_DEFER_TTL` 过期后才发生。
- 后果：状态与规格不一致；并给 `V8-F4c` 留下窗口。

### 3.3 `V8-F4c`（中）—— 该窗口 + 人自己的一次 Enter = 同一 payload 到两次

- 形状：夹具丢掉前两次 Enter（第一次排水 + 补的那次）→ 条目留活动队列；**人**按下第三次 Enter 提交了卡在框里的
  payload（第一次到达）；下一次排水看到空框，**又贴了一遍并提交**（第二次到达）。
- 实测提交记录：`V8PROBE-F4-DUPV8PROBE-F4-DUP`（两次）。规格场景 "An unconfirmed delivery is held, not duplicated"
  正是为防止这个。
- 可达性：需要 TUI 丢掉/吞掉 Enter（渲染负载、焦点在覆盖层）。夹具级确定复现；真实 Pi 可达性未证（见 §7）。
  修复方向：未确认且框里只剩 payload 时立即 `hold --reason unconfirmed`（不要等 TTL），或把「人已提交」的确认
  改成与条目绑定的终态。

### 3.4 `V8-N2`（中）—— payload 自己含折叠占位符字样时被误判为「占位符 + 别人的字」

- 形状：payload 是单行 `see [paste #1 +3 lines] and more text`（引用 Pi 的折叠提示，正常文本）。
- 实测：干净框、无人竞速，`draft send` 却判 extra-text → 不发 Enter → 条目终态 `held/ draft-raced`，payload 留在人的框里；
  去掉占位符字样的同一 payload 正常投递一次（阴性对照）。
- 后果：**一条干净的消息被永久扣在 held/**（要人 `drop`/重发），而框里留下一条没人提交的自动消息。
- 修复方向：复检先做「框内容 == payload（去空白）」的逐字判定，**再**走占位符剥除路径；剥除路径只应在
  「框里只有占位符形态」时生效。

### 3.5 `V8-N3`（中）—— 粘贴进行中的中间帧被当成「有人竞速」

- 形状：TUI 已收下大粘贴但只画出半个占位符（`[paste #1 +1`），稳定 ≥ 0.2s（复检的静止判定会停止等待）。
- 实测：判 extra-text → 不发 Enter → 条目终态 `held/ draft-raced`；随后框里显示完整的 `[paste #1 +14 lines]`
  —— 没有任何第二个人参与，payload 却永远不会被自动投递。
- 可达性：夹具级确定复现；真实 Pi 的渲染帧是否会出现半个占位符**未证**（见 §7）。但代价不对称：
  一次误判 = 消息终态卡住，而不是延迟一拍。
- 修复方向：失败帧若与 payload 的前缀或占位符正则的前缀匹配，应继续等静止/重试，而不是直接判竞速；
  或把「疑似竞速」与「确认竞速」分开（前者重试、后者才终态）。

### 3.6 `V8-N4`（低-中）—— 两个折叠占位符都被剥掉 → 「只剩空白」

- 形状：我们的折叠粘贴 + 人同时粘贴的一大段（也是折叠占位符）。
- 实测：复检把所有占位符剥掉后判 only-ours → 放行 Enter → 两条粘贴被一起提交（夹具提交记录
  `[paste #1 +3 lines][paste #2 +14 lines]`；真实 Pi 上会展开成同一条用户消息）。
- 修复方向：占位符数量与 `+K lines` 要与 payload 的行数对齐；多于一个占位符就不是 only-ours。

### 3.7 `V8-N5`（低）—— 提示行不在紧贴下边框的槽位时，装饰行被当成草稿（假 BUSY）

- 手造 pane：提示行在槽位 2（下面还有一空行）→ 判 BUSY（应 EMPTY）。后果只是消息被延迟 hold（方向保守）。
- 可达性：未在任何真实 Pi 形状里看到（真实 Pi 的提示行固定贴在底边框上）；这条是「按槽位排除」这个选择的边界记录。

### 3.8 `V8-N6`（低）—— 只看见 payload 的前缀也算 only-ours

- 手造 pane：框里只有 `V8PROBE-LONG`（payload `V8PROBE-LONG-MESSAGE` 的前缀，其余不在框里）→ 判 only-ours：
  drain 会按 Enter 并把条目当已投递删除 —— 消息没进过 agent 却被记为送达。P6 报告把前缀匹配记为「概率可忽略的取舍」
  （为截断/横滚的 TUI 兼容）；这里补上它的实际后果。
- 修复方向（若今后要收紧）：前缀接受应同时要求「框里没有别的字」且「payload 的粘贴确实发生过」，或只在
  bracket-paste 被 TUI 标记为折叠时才放行。
