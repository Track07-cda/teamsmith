## Blocking findings

1. **The delivery-confirmation semantics are wrong.** A normal `sendMessage` return is not proof that Pi accepted the message, started a model turn or completed work. The current synchronous `try/catch` shape cannot establish the result of the internal asynchronous call. `sent` must not be relabelled `accepted`, and an unknown result must not be shown as delivered or blindly retried.
2. **The mandatory Outbox/spool copy is not justified.** It creates another identity, status and crash-reconciliation authority for every Reminder. The leading hypothesis for rework is Pulse recording a durable `queued` fact in the single Reminder store, existing PM recovery remaining unchanged, and PM's inbox-watch reading that queue for direct Pi delivery. Ordinary Outbox behavior stays untouched. This is a hypothesis to prove, not an accepted final design.
3. **Standby has an unresolved asynchronous race.** Checking Standby before an API call does not cover Pi's deferred execution after the call returns. A correct proposal needs an observable public-API boundary or an honest in-flight/unknown contract; it cannot claim that idle/settled plus a void return closes the race. Cross-process lock paths must not depend on differing `TMPDIR` values.
4. **One authoritative delivery record is required.** The rework must define how intent/unknown and any positive Pi observation relate to the store and watcher journal, including floor compaction, long-held reminders and atomic batch intent. Two journals must not independently decide whether the same Reminder may be sent again.
5. **Secondary feasibility items remain open.** Dynamic tool withdrawal must account for Pi having no unregister API; doctor cannot query another session's in-memory tools directly; terminated history/audit growth needs a bounded retention contract; the prior effort estimate must be revisited after removing avoidable Outbox work.

- **A (PM recommendation): strict ordering.** `standby on` immediately prevents new reminder submission/recovery, then succeeds only after earlier in-flight reminders are proven started or definitely not accepted.
