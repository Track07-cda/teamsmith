## Decisions and deviations

1. **发现了任务书之外的根因并一并修掉**：任务书说「复用 digest 的可行动列表」，代码层确实如此；但真账本的
   实测证明唤醒侧跑的是**进程内存里的旧代码**（窗口 14 号起来，v1.19.0），同函数改动对它无效。不加
   「巡检进程用磁盘上的代码判定」这条，合并后 PM 照样每 15 分钟被假信号叫醒。实现方式是进程自我 `exec`
   重启（不拆窗口、不动 PM、理由留痕），不是给 watchdog 加守护进程 —— 节拍器纪律不变。
2. **其它唤醒理由的核对结果（任务书要求 2）**：未读通知 ↔ digest [2]（同源 `team_inbox_new` + `team_inbox_recipients`）、
   blocked ↔ digest [5]（同源 `team_board_counts`）、「有任务但 agent 停了」↔ digest [5] 建议（同源
   `team_agent_live` + state）—— 全部同源，无口径差异（smoke ③⑤ 逐条钉了）。digest [4]（待收尾）
   **不是**唤醒理由，按任务书「保持现状」不动。唯一**有意**的差异：digest [3] 会把草稿列出来标注、
   并点名被看板跳过的报告（不静默丢），而唤醒计数只算可行动的行 —— 这就是本任务的契约本身。
3. **openspec/** 没动：watchdog spec 目前的「pending」定义没写「待复验 = 可行动列表」这层（它只列举
   唤醒理由的种类）。M9.4 当时也是这个先例（交付先于 spec 补账）。**BLOCKED（spec 补账）**：如果 PM 要
   把「唤醒理由 = digest 可行动列表」与「长命进程不得用过期快照判定」写进 `openspec/specs/watchdog/spec.md`，
   归 PM（openspec/** 是 PM 目录）；本交付只改了代码/测试/文档。
4. **⑥ 的第一版夹具自己带竞态**（已修，见 commit 968ff86）：「先等漂移日志行、再写第二个版本标记」
   赌的是日志行与 exec 之间的窗口（M9.7 修过的同族竞态），FAST 跑 2 次红 1 次。现改成「决策变化」判据
   （基线无待办 → 注入一条永远可行动的规则 → 必然出现「待复验 1」），外加第二个干净夹具仓库避免
   字符串撞车，FAST 连跑 3 遍全绿。
5. **草稿的判定是「太早的信号」而不是「看板裁决」**：它和看板 done 的报告不一样（后者是「已结的事」，
   前者是「还没到 PM 手上的事」），所以处理方式不同——列表里照样点名标注，只是不进唤醒计数。
   `team_report_is_draft` 是这唯一定义，digest 标注与唤醒过滤共用（不再两处各判一次）。
