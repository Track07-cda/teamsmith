### F1（必修）· `flip-p287-name.sh` 的「平铺家族」判据过宽，把带命名空间的合法根判成平铺名

- 位置：`skills/teamsmith/tests/flip-p287-name.sh:48` 的
  `FLAT_RE='^(teamsmith|review)-[a-z0-9-]*\.[A-Za-z0-9]{6}$'`（同文件 `leg0` 判定「命中平铺家族模式」）。
- 机制：`ns = <slug>-<hash8>`，`slug` 是**项目名**过滤 `[A-Za-z0-9_]`（`scripts/lib/common.sh:96`）——
  项目名里没有 `-` 时 slug 就不含 `_`，于是 `teamsmith-smoke-<slug>-<hash8>.<rand>` 落进上面那条
  「`-` 随便吃」的正则里，被当成平铺名。这条假设没有写进规格，规格说的是契约点名的**改动前平铺形状**
  （34c 段用的就是事故那条 `teamsmith-smoke.*`，它对新根零命中）。
- 我在**同一棵树**上只改目录名做 A/B（`env -u TEAM_PROJECT`，`TMPDIR` 各自私有）：

```
[cand]   ns=cand-237fcf6e    rc=1  ✗ leg0：有条目不合规（1 条）
                                   BAD teamsmith-smoke-cand-237fcf6e.MoabMr ← 命中平铺家族模式
[can-d]  ns=can_d-921d6da3   rc=0  ✓ leg0：全部条目点开头或带 ns，且平铺家族模式零命中（13 条）
```

- 第二种暴露方式（同一个 leg0）：调用者环境里 `TEAM_PROJECT` 与检出目录推出来的 slug 不一致时，
  夹具算的 NS 与嵌套运行实际用的 ns 不同，leg0 报「既不点开头、也没有 ns」并 rc=1：


  `pm-skills` → slug `pm_skills`）因为 slug 含 `_` 恰好绿，所以作者与 PM 都没看见。
- 修法方向（留给 apply）：leg0 的「平铺家族」用**事故那条家族形状**（如 34c 的 `teamsmith-smoke.*`）
  或显式排除「名字里带本项目 ns」的条目；同时让夹具的 NS 与嵌套运行实际用的 ns **同源**
  （不要在子进程里 `-u TEAM_PROJECT` 而父进程还在用它），或直接从运行自己写的标记/台账里读 ns。

### F2（记录，不阻塞）· `34b⑫` 是既有的计时类脆弱断言，两棵树同样红

- 候选树：`--select 34,34b` 两次批量都红在这一条（`✓100 ✗1`），单独跑 `--select 34b` 一次全绿（`✓101 ✗0`）。

- 机制（我自己的探针，`ev/probe-34b12b.sh`）：夹具先 `grep -l | head -1` 挑一条 `no_lock=1` 登记，
