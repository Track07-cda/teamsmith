## Finding 1（high）：`team up` 在什么都没启动时说「PM 在运行」

### 新规则（证明，而不是推断）

`running` 只在这两种情况下成立：

1. `state/pm.pid` 存在、pid 活着、**且该 pid 的 cwd 在本项目内**（含 worktree；`team_proc_cwd` +
   既有 `team_cwd_in_project`）；
2. 没有（有效的）pid 记录时，PM 窗口里的进程——**pane_pid 本身或其直接子进程**——命令行中出现配置的
   agent 可执行文件（解析顺序与 dispatch 一致：`TEAM_AGENT_BIN` > `TEAM_AGENT_CMD` 首词 > `TEAM_PI_BIN`，
   按 basename 比对，所以 `bash /path/pi-sleep …`、`node /path/to/pi` 这种 shell/运行时包装也算）**且**
   cwd 在本项目内。

其它一律不叫 PM，也**不得**压制启动：

| 状态 | 含义 | `team up` 行为 |
|---|---|---|
| `foreign:<cmd>` | 占用者 cwd 不在本项目（别的项目/测试残留） | 默认拒绝覆盖，`TEAM_REPLACE_FOREIGN_PM=1` 才动（与既有 smoke 3b 一致） |
| `unknown:<cmd>` | cwd 在本项目内但不是 agent（新建空窗的 `tmux` 瞬态、`sleep`、编辑器…） | **替换它**，并在替换前把 cmd/cwd 打出来（"不是 PM 就不能压制恢复"） |
| `idle:<shell>` | 空提示符 | 照旧 respawn |
| `missing` | 窗口不在 | 照旧（`TEAM_WATCH_REBUILD_TMUX` 语义不变） |

`team_pm_alive` 现在等于 `running:*`；`watchdog-status`/`ps`/`digest`/monitor 面板/`doctor` 都用同一个函数，
所以**没有任何输出面**可以在没有证明时打「PM 在运行」。读命令仍然零写入（M6.1 F28）：`team_pm_state` 只读
`state/pm.pid`，过期条目由启动路径覆盖，不由读命令删除。

### 失效模式（为什么必须这么严）

老规则是「窗口在 + 前台不是 shell」。新建 session 的一瞬间 `pane_current_command` 是 `tmux`（本环境的 shell
会在窗口里 exec tmux/attach），cwd 继承调用者（在项目内）→ 归属校验通过、`team_is_shell_cmd("tmux")` 为假 →
`running:tmux`。于是 `team up` 打印「✓ PM 在运行（tmux）」却不启动任何东西，`watchdog-status` 也照抄；等窗口
真正 settle 成 shell 后又是 `idle`，watchdog 因为「PM 在跑」而只提醒不拉起（smoke 里 `PM 没有被拉起（17 → 17）`
就是这么来的）。这一格已由 11b2 ①b 用 `tmux wait-for` 确定性复现（老代码判 `running:tmux`，新代码判
`unknown:tmux` 且 up 真的启动）。

### 夹具（不依赖开发者的 shell）

11b2 每格都用 fixture 显式造，并读 `state/` 与 `team` CLI 断言：① 整个 session 不存在 → up 必须真启动
（argv 日志出现 `-c`/`@pm-prompt.md`，`watchdog-status` 事先不报「PM 在运行」）；①b `cwd=$REPO` 的 pm 窗口里跑
`exec tmux wait-for …`；② 杀掉记录里的 pid → 不再算存活；③ `cwd=$REPO` 的 `exec sleep 300` → `unknown:sleep`，
up 替换它并启动（只看这一轮新增的 argv）；④ `cwd=/tmp` 的 `sleep` → `foreign:sleep`，up 仍拒绝；④b 手工在窗口
里起的 agent（没有 pid 记录）→ 仍被认成 `running`。

## Finding 2（medium）：TIMEOUT 被记在门禁自己的 124 上

`team review` 现在要求**两条独立证据**才写 `TIMEOUT`：timeout 包装器的退出码（124 = TERM 生效 / 137 = TERM
被忽略后 KILL）**且**实际用时 ≥ `TEAM_REVIEW_TIMEOUT − TEAM_REVIEW_TIMEOUT_GRACE`（默认 2s；timeout 很短时下限
夹到 0）。否则判定 `FAIL`，并把实际用时写进记录（`门禁命令：…（硬超时 1800s，实际用时 Ns）`）与日志：

- 门禁自己 `exit 124`（用时远小于 deadline）→ `FAIL` + 日志明说「这是门禁**自己**返回 124，不是被 deadline
  杀死的」；
- 被信号终止（128+n）→ `FAIL` + 抬头 `· gate killed: SIGTERM`、正文一行、`PM 结论` 一条 checklist，
  **不拿「超时」顶替「被杀」**；
- 真睡过 deadline → `TIMEOUT`（与 F10 一致），记录里同样有实际用时。

verdict 词表保持 `PASS|FAIL|TIMEOUT|SKIPPED|UNKNOWN` 不变（记录解析、digest 待复验、close 的强制通道都依赖它），
所以「被杀」选择记成 FAIL + 信号名，而不是新增一个 `KILLED:` 词（任务书允许二选一，这里选了不破坏既有词表的那个）。
