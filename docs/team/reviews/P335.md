# P335 · 启动失败诊断的两个空答案（验收记录）

- 合入: `f23fad40`（产品 + 报告）；该分支落后 main，`BOARD.md` 与 V71 报告保留 main 版本，`git diff --cached --diff-filter=D` 为空

修的是什么：`wc -c < "$tailf"` 在判存在之前就去读，重定向失败由 **shell** 自己报错（`2>/dev/null` 写在 `<` 之后、尚未生效），而 `wc` 没跑、管道末端 `tr` 仍退出 0，于是 `|| echo 0` 不触发 —— 字节数印成空白。这条失败路径上该文件按构造就不存在（harness 在 CLI 退出后才写尾屏），所以 PM 起不来时第一眼看的诊断文件里同时有「来路不明的 shell 报错」和「一个空数字」。

改法与验证：先判存在再读数；不存在就写明「未写出：harness 还没落这份尾屏」；判了存在之后读失败另有一条具名分支。「只有空白不算抓到」的原分支一个字未动。独立验证自建私有夹具（不启 tmux，用桩替三处现场提问），改前 stderr 131 字节 + 空白数字、改后 0 字节 + 具名句，尾屏存在/空白/空白且窗口仍在三种现场与改前逐字节相同；读数上不再有 `2>/dev/null`、`|| true`、`then :`。

验收者另记一条**不在本次承诺内**的边界：文件存在但不可读时有 217 字节 shell 噪声，改前同样是 217 字节，不是本次引入。PM 判定：**不修**——这是权限异常现场，不是失败路径的常态形状；为它加分支等于给一个不会发生的情形写代码。若将来它真的出现在现场日志里，再按当时证据处理。
