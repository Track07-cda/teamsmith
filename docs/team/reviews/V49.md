## 4 · 授权打断：只对一个 pid，审计一行，读数是打断前的

`--yes` 那一轮（worktree 里先放三个**旧 mtime** 的未提交文件；`dev2` 是旁观席、`dev3` 是另一条拒绝路径的现场）：

审计行（`state/interrupt.log` 第 1 行，逐字）：

```
2026-10-16T03:24:07Z actor=pm seat=dev1 pid=3308084 session_last=2026-10-16T01:24:04Z uncommitted=3 guard=clear reason=V49 授权打断：三处未提交，先落盘再续跑 signal=SIGTERM outcome=gone
```

- **只对一个 pid**：目标在 `SIGTERM` 的有界等待内退出；它的 tick 日志里**恰好一条** TERM；旁观席位的 tick 日志里**零** TERM；旁观席位进程全程活着。
- **恰好一行**：`wc -l` 从 0 到 1（拒绝路径一行都不写，见 §6/§8）。
- **读数是发信号之前的**：`session_last=01:24:04Z` 是打断前读到的 mtime；替身在 TERM 现场把同一个会话文件 `touch` 成 `03:24:07Z` —— 同一个字段在打断后读会变成另一个值，所以这一格**有判别力**（这条判别力正是 §10 红侧②要推翻的东西）。
- **工作树逐字节不变**：打断前后 `find | sha256sum` 全树哈希一致，三个未提交文件打断后仍在且内容不变。
- **理由落位**：线程恰好 +1 条（`from: pm`、带理由）、收件箱恰好 +1 行。
- **回来的路**：输出点名 `team resume --agent dev1`；随后 `resume --agent dev1 --dry-run` rc=0、把 dev1 列成可续跑、点名 `sid=`、`mode=continued`，且渲染出的提示词里有阅读顺序的第二步 `threads/dev1.md`（§7）。

## 5 · 对象证明链与 pid 复用

这一节是任务书里最重的一格，我用了三种现场：

**(a) 端到端：计划读到的 pid 与复验时 pane 里的进程不是同一个**（真 tmux、真进程、真换人）

现场做法：`bin/git` 影子第一次 `status --porcelain` 时撑开 3 秒窗口；后台破坏者等到这个信号就 `tmux respawn-pane -k` 把 dev2 的窗口换成**新进程**（新 pid）。入口读到的是计划时的 pid A，复验时 pane 里是 pid B：

```
✗ interrupt: 复验不过，拒发 —— 窗口里的 agent 进程已经不是计划时那个 pid（计划=3402155 现在=3405468）—— 它不再是那个被证明过的进程
  一个信号都没发；该席位的线程、收件箱与审计日志都没有变。
```

同时成立：审计不增、线程不增、**换上的那个进程没有被碰**（活着）、这一席位**零 TERM**、破坏者确实动过手（`saboteur-done` 在，现场不是自证）。（原始输出：`logs/target-changed.out`；这一格是单独 `--only target` 那一轮的现场。）

**(b) 库层硬目标：启动时刻不一致（pid 被内核回收的形状）**

```
正控制（真启动时刻）：OK
pid 回收形状（伪造启动时刻）：REJECT rc=1 RE=pid 2834920 的启动时刻与计划时不一致（计划=1792121012 现在=1792120952：pid 可能已被内核回收）
```

**(c) 库层：pane 里已经没有那个进程**（计划之后 pane 死了的形状）→ 同一句话拒发；**身份指向别的工作树** → `REJECT id=other-tree`；**本项目自己的进程** → 正控制 `OK`。
