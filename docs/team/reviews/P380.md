**V109 的判定成立。** 两个 resolver 都在匹配**之前**对 npm 的整份输出做了 `tr -d '[:space:]'`：`1.4.0` 与紧随其后的

修法（两处同形，见 diff）：先按**行**挑出「整行只有一个版本号」的那一行（允许行首尾空白），`tail -1` 取最后一条，

```
# 之前（缺陷）：整份输出去空白 → 多行被拼成一个 token
latest="$(printf '%s\n' "$out" | tr -d '[:space:]' | grep -E '^[0-9]+\.[0-9]+\.[0-9]+([-+][0-9A-Za-z.-]+)?$' | tail -1 || true)"
# 现在：先选完整版本行，再只对该行去空白
latest="$(printf '%s\n' "$out" \
  | grep -E '^[[:space:]]*[0-9]+\.[0-9]+\.[0-9]+([-+][0-9A-Za-z.-]+)?[[:space:]]*$' \
  | tail -1 | tr -d '[:space:]' || true)"
```

## Rework 4（V109 第三轮：`pi --version` 的退出码被丢掉，2026-10-27）

**V109 的判定成立，而且是这一串断言里最后一块承重石。** 两条分支原来写的是：

```sh
bash ci/check-pi-version.sh "$PI_EXPECT_VERSION" "$(pi --version)" || exit $?
```

`"$(…)"` 只把**输出**当参数传进去，`pi --version` 自己的退出状态被丢弃。V109 的受控反例：一个打印 `1.4.0` 然后
`exit 42` 的 pi —— 检查器拿到 `1.4.0`、与解析值相等、打印「比较成功」、门禁照常往下跑（rc=0）。这不是「真 Pi 观测到
这样失败」，而是**断言测不到它**：运行时撒谎时门禁不会红。

修法（两条分支同形，`ci/build-image.sh` 同类一并扫）：

```sh
set -u
pi_out="$(pi --version)"; pi_rc=$?
if [ "$pi_rc" -ne 0 ]; then
  printf "::error::pi --version exited %s before the gate ran (the runtime did not report its version; not compared)\n" "$pi_rc" >&2
  exit "$pi_rc"
fi
bash ci/check-pi-version.sh "$PI_EXPECT_VERSION" "$pi_out" || exit $?
```

- 单独读取、**保留**退出码、非零先拒（用同一个码停下，不是换成一个笼统的 1）、点名；只有成功拿到的输出才进比较。
- 没有 `|| true`；不把失败码藏在比较结果后面；比较路径的 mismatch `rc=3` 行为一字未动。
- `ci/build-image.sh`：`observed="$(docker run … pi --version)"` 有同一缺陷（在 `set -e` 下还会**静默**带着那个码退出、
  什么都不说）。现在 `observed_rc=0; observed="$(…)" || observed_rc=$?` 接住原码，非零先拒绝并打印运行时说的话。
