## Findings

1. **它用数据否掉了我的两条建议**（这是我要的对抗性）：
   - **A（负载前提）**：它实测 7 种绿色形态（含 8 worker 的 fork 风暴，`loadavg` 到 **42.4**、满载 32 核），
     而那次红出现在 **load ≈ 11**——**落在绿色带内**，所以**没有任何 `k` 有实测交叉点**；
     在带内取 `k` 只会把"该判的场景"变成"跳过的场景"（而团队日常负载就是 8–11，**恰好在 PM 跑交付门禁时丢覆盖**）。
   - **B（只加预算）**：慢 2.8 倍的机器仍有 **10–40× 余量**，固定加大买不到东西；按负载缩放的固定预算又把 F1 请回来；
     而且更大的预算会让真失败发现得更慢。
2. **它选的 C（预算 + 在"耗尽那一刻"判定）比我的要求更准**：
   - **进度感知的延长**：基础视界耗尽时，若场景**仍在绘制**（掩码捕获在最近 8 轮内变过）→ 最多延长到 **3×**；
     于是"慢但正确"是被**等**出来的（D33 的口径靠等待而不是放松阈值），而**停滞的场景一点不延长**——
     延长永远藏不住静态失败；
   - **顶部归因**：仍在绘制 / **探针**超顶（默认 **120 ms**；实测带 12–34 ms）/ 粗负载闸门超顶（`×2.0` 核，**在实测带之外**）
     → **可见 SKIP**（一行点名 wait、轮数、耗时、M59 现场与读数；计数为 skipped；**fixture 退出 4**，门禁仍 0）；
     静态 + 机器健康 → **红**（带 M59 现场）——**约 40 个状态可达性断言保持武装**（brief 第 3 条的要求）；
   - **入口不判定**：前提行每场景都打印（只读数、不跳过），只有粗闸门在入口跳。
3. **残留风险被写出来而不是藏起来**：静态停滞超过上限**且**外部读数健康（`SIGSTOP`/cgroup 节流的形状）
   仍会红；它试图测这个形状但**没测完**（黑out 脚本的模式太宽、被叫停以保护别人的夹具；此前跑到 `✓70 ✗0` 无超时），
   所以那一行诚实标成 *unmeasured*。**我裁定**：这个残留可接受——缓解是"打印现场 + 粗闸门"，
   而"把无法归因的耗尽一律当 SKIP"会**悄悄解除**那 40 个断言的武装（正是 brief 第 3 条禁止的）。
4. **D37 落地成 ADDED requirement（`verification`）**：只对**自己 spawn 的 PID** 发信号、**拒绝**模式形状与非自己的目标
   （发送前即拒并非零退出）、`SIGSTOP` 必须配 `EXIT/INT/TERM` 的 **CONT** trap（中途被杀不许留下 `T`）、
   整机负载用**自己拥有的**负载进程、实验用私有临时根与私有 socket —— **三条可证伪 scenario** 齐全 ✓
