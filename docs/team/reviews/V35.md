### F2（阻塞）· `init` / `bootstrap` 的旧配置拒绝建议是占位符，不是从项目自身配置推导出的命令

- 现场：`team init --force --task-models … --pm-model …` 在旧配置上 rc=1，`修法` 两条路线都在，但命令是
  `--task-models '<category=provider/model …>' --pm-model '<provider/model>'`（占位符）。`bootstrap` 同形。
- 合同：delta `init-skill` 的场景「The legacy refusal carries a command derived from the project's own configuration」
  把 `team init` 明列为写路径，要求输出**一条**可粘贴的 `team config upgrade-models --task-models '…' --pm-model '…'`
  且类别对**恰好等于**退休键的推导对（含兜底），`--dry-run` 能粘贴执行成功；MODIFIED 要求也写「A write path that
  refuses a project for carrying the retired keys SHALL print the repair advice **derived from that project's own
  configuration**」。
- 推导明确可用：同一份文件上 `dispatch --print` 打印的就是逐字节推导结果
  （`dev=… verify=… default=…` + `openai-codex/gpt-5.6-terra:xhigh`，§2.5），所以 SHALL 适用，不是「推导不出来」的
  退路。设计 §3 明确三处**共用**一张推导表、不许长第二份；init/bootstrap 的硬编码文案就是第二份。
- 证据：`logs/check5.log`（`FAIL c5.legacy.init.refusal` / `c5.legacy.init.once`）；推导对照见
  `logs/check1-migrate.log` 的 legacy dispatch 块。
