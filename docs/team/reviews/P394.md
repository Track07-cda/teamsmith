## Decision required from the user

- **A — accept the transient tail-frame flash.** Teamsmith can proceed without a Pi change, with the honest ~0.1–0.2s boundary and raw-stream tests. This does **not** fully satisfy a strict “the user never sees the marker in Pi” requirement.
- **B — require zero visible marker (PM recommendation).** Pi must support an awaitable/message-update replacement before rendering (the explorer identifies a small public hook/type change), after which Teamsmith can use the same public-API design without provider-specific stream rewriting. This preserves D213's display requirement but depends on separately authorized upstream/Pi work and has unknown cost/timing.

The provider_stream_event mutation remains rejected: it is documented read-only, provider-specific and would require buffering partial marker chunks, creating the response-rewrite framework this project should not own.

PM recommends **B** because the user explicitly required removal from the Pi response, not merely eventual cleanup. A is only appropriate if the user explicitly accepts the measured transient flash.

V115 is independently reviewing message semantics, dedup/recovery, minimal injection and verification. No Propose until V115 is reconciled and the user selects A or B. No implementation, spec/change write, live-team marker test or upstream/Pi modification is authorized.
