## V115 independent review — technical rework required despite settled A

V115 final report `aec614b1` is **NEEDS-CHANGES** and is adopted. D214 has since settled the display choice as A, so its recommendation of B is historical; the remaining blockers are independent of that choice:

1. Pi appends the message and assigns its entry ID **after** `message_end`; `turn_end.messageEntryId` can bind identity, while only final settled state establishes publish eligibility. Startup must not publish every pending intent or bypass a later abort.
2. The existing writer stores no session/entry identity. Identical bodies can be distinct legitimate replies, a latest-page hash scan misses older posts, and an unconfirmed visible write cannot be reconciled by digest. Remove “hash hit = claim / miss = republish”. Unknown writes stay manual; no automatic blind retry.
3. Marker cleanup and publish eligibility are separate. A failed/aborted/non-final message must not publish, but control-marker display cleanup still needs an explicit terminal-state rule rather than leaving it in the final transcript.
4. Syntax/title/content fidelity need product-parser rules, not the probe's global regex: exact final control line, code/fence/quotation conventions, duplicate valid lines, multi-text-block/CRLF/UTF-8, and title derivation that does not consume Magic Context numbering.
5. Directed PM injection, actual identity/root checks, duplicate-load execution rights, custom adapter limits, first-injection restart versus already-loaded extension reload, doctor and update fingerprint must be settled. cwd alone is not PM authentication.
6. Existing key-replies explicitly limits stdin/no session import/no dedup; the future proposal must MODIFY those requirements, not merely add a contradictory marker requirement. Verification must use the actual product parser/writer and raw marker-specific stream checks.
