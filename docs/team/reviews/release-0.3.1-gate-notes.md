# 0.3.1 发布门禁 · 过程账与假红清单（在发布复盘之前）

## 一 · 我的三次过程错误（都记在这里，不藏）

1. **第三次整套（`65e0398b`，容器，串行）跑完 3h47m、134 段全收口，结果 ✓4927 ✗13** —— 但我把容器输出写进了容器自己的 `/tmp` 并用管道只留了尾部，**容器一退，13 条的身份与现场全丢**。留下的事实只有「账本一致：✓4927 ✗13」。规矩已写进项目记忆：长跑日志与现场必须落在 bind mount 的宿主路径上，不许管道取尾。
2. **四片并行跑法在单机上不成立**（我试了，收到 16 条红，其中绝大多数是我自己的跑法造成的）。见第二节。
3. 一次 `--select 0e,0f,0g,0h,0i,4d,36` 被选段器当场拒绝（`4d` 不是合法 key，rc=2）——它没有默默跑半截，这是好事；修成 `...,4,36` 后宿主上 **✓562 ✗0**，即「只在整套里跑」的那 7 段在宿主机上是全绿的。

## 二 · 并行四片产生的假红（不是产品缺陷，是跑法违反夹具的默认约定）

- **`§34d 2.1`「默认路径 → 伴生锁」**：我给每片设了 `TEAM_SMOKE_LOCK=/logs/wK/.gate.lock`，于是伴生锁成了 `..gate.lock.machine`，而断言钉的是**默认文件名** `.teamsmith-smoke.machine`。断言是对的，是我改了默认值。
- **`§31` M28 lint 自检三条**：它把「裸 `tmux kill-server`」种进一棵夹具树再要求检查器抓到；我把 `TMPDIR` 指到了 `/logs`（仓库外），检查器的取样面按仓库/声明路径判定，于是「没抓到」——那是**跑法在仓库外种样本**，不是检查器变弱。
- **`§11b4` P36 七条**：夹具要判断「同 cwd 有活 PM CLI 会话」「`--fresh-pm` 起出的 PM 是不是 running」，而四片共享同一个 `--pid=host` 进程视图，彼此看得见对方的假 PM 进程。

**结论（要写进设计）**：切片并行在 CI 上成立，是因为每片在**独立机器**上；在**同一台机器**上并行跑同一套夹具不成立——这套夹具里有若干断言以「默认值」与「我是独自在跑」为前提。要支持本机并行，得给这些断言加显式的「并行运行」前提，那是另一件变更，不在 0.3.1 里。
