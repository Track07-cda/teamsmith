## 判定

这份提案是**先测机制、再定修法**的范例，且把「假绿」挡在门外：

- **两条决定性事实**都是实测出来的：① server 在启动那一刻把启动者的环境复制进**全局环境**，之后新建对象只继承全局环境（`new-session -e` 只写会话环境）；② **只有建对象的动词能启动 server**（其余动词在没有 server 时 rc=1 且不留 socket，`start-server` 因 `exit-empty` 留不下 server）。于是泄漏只发生在「谁启动了 server」这一件事上——修法因此是「建对象的那次调用不带命名空间」，而不是满地打补丁。
- **被否决的六种做法**里有一条尤其对：把 `TEAM_*` 改成非 TEAM 名字「只是让 `grep ^TEAM_` 看不见，泄漏照旧——**假绿比没有更糟**」。这正是本项目的一贯立场。
- **读侧判据用泄漏自身的指纹**：可归因 ⇔ 调用发生在 tmux 内 **且每个冲突变量的继承值都等于 `tmux show-environment -g` 的值**。它明确拒绝了我任务书里给的那个更宽候选（「cwd 能解析 + 继承身份指向另一个已存在项目」）——理由是那会把夹具/门禁里**显式继承**的外来环境也放行，而规格与 §32③/§32⑧a 要求它拒绝。这个反驳成立，我接受。
- **误判代价写了上下界**：假阴（pane 环境过期）→ 仍拒绝 + 一行 `env -u …` 兜底；假阳需要「每个冲突变量都恰好等于全局环境的值」，夹具形态不会命中。
- **审计面的连带冲突被正面处理**（洗掉命名空间后闸门写不出日志）：给了 A1/A2/A3 三条路，并指出 A3 是「静默的洞」。它还主动记下「第二份 socket 解析不可取」（P188 的教训）。
- **它自己按 D170 分类了本次的断言**：行为类留、**不新增**措辞类断言，且说明行的判定要配行为红侧——与刚裁完的门禁瘦身口径一致。
- 四条红侧、两批拆分、预算行按 `section-guard.sh --budget-check` 的规则填、以及「交付前 `git merge main`」都写进了设计。
