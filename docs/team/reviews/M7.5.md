## 2 · Which side was wrong, and why this fix

- **Detection was wrong.** Both candidates in the brief were evaluated:
  - *(a) bounded poll of the pane*: would wait **through** the flaps, but it still infers the agent's fate from the
    shell's looks — under a churn longer than the bound (see 1.2: busy at +1.356 s with the agent gone since +0.01 s)
    it times out and loses the notice anyway. It reduces the flake, it does not remove the class. Rejected as the
    primary mechanism.
  - *(b) fixture-side polling*: cannot work here. The dispatch is synchronous and prints the notice **once**, at a
    fixed moment; polling the log afterwards can never recover a notice that was never printed (measured: in the
    pre-fix B4 round 1 the log has no notice line at all). The fixture's assertions were reading the log after the
    command returned — there was no fixed sleep to replace in B3 itself.
- **Chosen: the pane harness records the exit event.** `$agent_cmd; printf '%s %s\n' <nonce> "$?" > state/dispatch-<agent>.exit; exec bash`
  is written by the agent's **parent shell** before the pane has to come back to a shell, so the evidence exists the
  instant the agent returns and cannot be affected by shell startup, load, conda hooks or tmux. The dispatch polls
  that record up to `TEAM_DISPATCH_ALIVE_SEC` (same knob, new meaning: *how long to wait for the record*, `0` = don't
  wait), which also makes the fast-death path **faster** (proof→end ≈ 0.26 s instead of ≈ 1.28 s), and it yields the
  **exit code** for free — useful triage for "the agent died instantly" (bad binary/model/provider).
- **Wording follows observed state** (the brief's rule): the notice now says
  `但窗口里的 agent 已经退出（exit code 3）：team roster 会显示「pi 已退出」（续跑：team resume --agent dev）`.
  The claim `（回到 shell）` is gone because we never observed the shell; the still-running case prints
  `窗口里的 agent 还在跑（1s 内没等到退出证据）` instead of silence. Both halves are guarded by assertions.
- Nonce-scoping is kept identical to the launch proof: the record only counts if its nonce matches this attempt's, and
  each attempt `rm -f`s both records. `TEAM_AGENT_CMD` (custom adapters) still skips the observation entirely —
  script adapters exiting quickly is normal.
