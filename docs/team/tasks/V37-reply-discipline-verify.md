## 必须自己做的（不许只复跑作者脚本）

1. **义务的存在**：读 PM 提示词模板、协议 §4b、SKILL 命令表的**成品文字**，确认规则真在（什么时候发 / 怎么发 / 发完再在对话里发同一份 / 同一批可合并 / 只发结论），且**示例命令是当版本可用的形式**（`team reply post --from pm --title … --stdin < …`）——你自己跑一次这个示例命令、断言它被真解析器接受且真发布了一条（槽位 0 → 1）。
2. **常设义务**：协议 §4b 的措辞读出来是「义务」而不是「可选项」（不再只是「当你有一个值得留存的答复时」）。
3. **破坏性对照**（每条破坏→红并点名→还原→绿）：从 PM 提示词模板删掉那段规则 → 断言红并点名那个面；示例命令写成一个不存在的旗标 → 红；删掉命令表那一行 → 红；把 SKILL/协议里的锚点换掉 → 红。
4. **不削弱既有断言**：`key-replies.sh` 既有十二组（`--all`）与 `smoke.sh --select 62` 仍全绿；逐条看 diff 有没有删断言换跳过。
5. **文本/行为边界**（D170）：确认它断言的是「义务的存在」（语义锚点），不是「一字不差的措辞」——若它锁死了具体文字（一改措辞就红），那按 D170 记一条观察；若只到语义锚点，就符合。
6. 容器纪律（钉死容器 + 干净 clone、先看 /tmp 余量）；任何「既有红」同命令对照 v0.2.0。
