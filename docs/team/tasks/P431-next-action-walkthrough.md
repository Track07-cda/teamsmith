# P431 · 只做一次真实数据走查

## 问题

目前判断“谁在等谁、下一步是什么”常要同时读 digest、BOARD、任务书和报告。验证 pulse 首页的一处现有展示能否直接回答这个问题；若只是重新排版陈旧看板，就不做。

依据 D234 与研究候选 A。只写报告，不改产品、面板、规格或 CI。

## 走查方法

1. 只读使用**本项目**真实状态与现有公开命令，不读其它项目会话或文件，不写真实团队状态。
2. 选三类当前或近期真实情形：执行中、等待 PM/独立复验、等待用户决定。每类记录今天需要打开哪些文件/命令才能回答：
   - 当前阻塞在哪；
   - 下一步由谁做；
   - 做什么动作；
   - 依据是否新鲜。
3. 对照 DSH 的“从数据推导阶段”思路，盘点现有 BOARD、seat state、报告、评审、任务书和投递记录哪些已足够，哪些不能可靠推导。**不得为了补齐而发明 run id、事件总线或第二份待办账本。**
4. 给出一个最小展示切片：只改 pulse 首页一个现有区域，说明它替代/删除哪一处旧阅读路径，不新增 dashboard 或设置页。
5. 给出三个反例：状态陈旧、席位已死但记录仍在、报告存在但未验收时，展示必须怎么说，不能猜“正在运行”或“已经完成”。

## 交付

`docs/team/reports/P431-dev2.md`：先给“值得/不值得做”的结论；附真实走查步骤、目前阅读成本、最小切片、数据来源与 freshness 边界。明确哪些推断只是展示建议，不是事实。

本轮不改代码、不建 change、不跑门禁。PM 审阅走查后才决定是否写提案；若证据不足，结论就是不做。
