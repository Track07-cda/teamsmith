# M5.1 · Make magic-context and OpenSpec required dependencies

```
task:   M5.1
agent:  dev
deps:   v1.18.0
```

> Decision (PM, 2026-09-14): **both magic-context and OpenSpec are required dependencies**, not optional. The PM's
> long-lived memory needs magic-context, and spec management / the change workflow is OpenSpec's job — teamsmith
> must not grow a second, rival spec system. This task enforces both and tells the user how to fix a missing one.

## Deliverables

### 1. Config keys (`scripts/lib/common.sh`, `templates/config.sh.tmpl`, `references/config.md`)

| Key | Default | Meaning |
|---|---|---|
| `TEAM_REQUIRE_MAGIC_CONTEXT` | **`1`** (changed from `0`) | missing magic-context is a doctor **failure** |
| `TEAM_REQUIRE_OPENSPEC` | `1` | missing OpenSpec is a doctor failure |
| `TEAM_OPENSPEC_BIN` | `openspec` | CLI resolution (absolute path allowed, same pattern as `TEAM_PI_BIN`) |
| `TEAM_SPEC_DIR` | `openspec` | where the project's OpenSpec root lives |

### 2. `team doctor` (`scripts/lib/cmd-project.sh`)

- **magic-context**: `✓ <version>` / `✗` with an install hint
  (`pi` package `@cortexkit/pi-magic-context`; mention `TEAM_PI_SETTINGS_FILE` for non-standard locations and that
  `TEAM_REQUIRE_MAGIC_CONTEXT=0` downgrades it for odd environments). Keep reading only `settings.json` +
  the package's `package.json` — never credential files.
- **OpenSpec**: binary resolvable → report the version; `$TEAM_SPEC_DIR` exists → report it; missing spec dir →
  fail with `openspec init --tools none` as the fix. Report both as failures when required, and keep the failures
  actionable (one line each, no stack of hints).
- `team paths` should expose both (`openspec_bin`, `spec_dir`, `require_magic_context`, `require_openspec`) so the
  PM and scripts can see the resolved state without guessing.

### 3. Preflight behaviour

- `dispatch`: warn loudly (do not refuse) when a required dependency is missing — the worker can still work, but the
  PM must know the evidence/spec layer is incomplete. Keep the warning to one line, deduplicated per dispatch.
- `bootstrap`: after writing config, check both and print the exact fix command for each missing one.

### 4. Docs (English, and keep the doc invariants green)

- `references/config.md`: the four keys above with honest defaults + the "env beats config" note.
- `references/memory.md`: magic-context is now **required**, not recommended — say what that means in practice
  (team setup fails a doctor check without it) while keeping the "disk wins" rule and the fallback routine.
- `references/bootstrap.md`: `openspec init --tools none` becomes a bootstrap step for a new project.
- `SKILL.md`: update the **Requirements** section (hard deps become bash/git/tmux/agent-CLI **+ magic-context +
  OpenSpec**); leave the rest of SKILL.md alone (a parallel task M5.2 owns the specs section and
  `references/workflows.md`).
- `references/troubleshooting.md`: add two rows — "doctor fails: magic-context missing", "doctor fails: OpenSpec
  missing / spec dir missing" with the concrete fix.

### 5. Tests (`skills/teamsmith/tests/smoke.sh` — you own this file in this round)

- doctor: missing magic-context → **fail** (fake `TEAM_PI_SETTINGS_FILE` without the package) and
  `TEAM_REQUIRE_MAGIC_CONTEXT=0` → warn only (keep the existing tri-state assertions working).
- doctor: missing OpenSpec (fake `TEAM_OPENSPEC_BIN=/nonexistent`, and an empty `TEAM_SPEC_DIR`) → fail; present →
  pass. Use fixtures, never the real machine state, so the suite stays deterministic.
- `team paths` exposes the new fields.
- dispatch with a missing dependency → warn (exit 0) and the warning names the dependency.
- Keep the existing invariant that docs are English and that removed commands are not mentioned.
