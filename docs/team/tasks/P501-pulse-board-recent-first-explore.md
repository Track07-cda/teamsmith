# P501 · 核实看板页按最近更新排序

用户已明确要 Pulse 的看板页按更新时间倒序。保留各状态栏及其位置，每栏最近更新的任务在上；只改变看板页显示，不替换工作页、命令行的顺序，也不为此重排 `BOARD.md`。设计将来与已有明确的「按优先级」选项兼容：它不是这次的默认排序，不改变已批准的优先级求和和同分处理，也不捆绑、放行或解除 P497/V196。

1. 从 `common.sh`/`cmd-docs.sh` 的看板查找和写入、`cmd-watch.sh` 的 board 数据，查到 panel 的 lane、刷新、导航和详情寻址。对照 `openspec/specs/{panel,board-and-status}/spec.md`，标出只需改的现有要求及旧的顺序约定。用已有写入调用列清楚哪些是真的任务更新（新建、状态和负责人实际变化等）；不要用任务编号、整份文件的修改时间或刷新时刻冒充每项更新时间。仓库可能有旧表格、自定义列、重复编号；不要用纯任务编号归并旧行。
2. 判断当前是否已经有可靠、便宜可复用的逐任务时间记录。若没有，给一条首选最小方案，说明跟现有一次行写入如何一致、能否不迁移旧看板、旧任务缺时间如何保留稳定顺序、无变化的重复写入是否不动排序。比较已有 Git 历史或可选时间列等合理备选；不要引进新后台轮询、第二套看板、全库回溯或每刷新为每行启动进程。不编造历史时间，也不把普通通知或成员回合当成任务更新时间。
3. 方案以同栏的具体例子说明：A 创建早于 B，A 后来改状态（最后与 B 同栏）或负责人，A 跳到前面；随后无变化的写入不挪位置；同时间或缺时间有确定顺序。厘清已有滚动（完成和已放弃栏的最近窗口仍先可见）、选中的同一条任务刷新后不串、鼠标/键盘打开的是屏幕所见行；找一个能替换的已有检查覆盖这些关键结果。本单不复现 P497 快速按键失败，只点明任务标签的默认顺序文字和共享代码路径会如何与方案对齐，不扩大此单范围。
