## 问题（有数据）

- smoke：**103 段 / 约 3258 处断言调用**；全套 **13–20 分钟**；**机器锁一套一次**；今天跑了 **77 套全量**。
- 我实测的参照：一次真 Pi 帧夹具 **14.8s**；容器自检 **1.2s**（缓存命中）。
- **完全没有分段耗时数据** → 不知道该优化哪几段、哪些段能安全跳过。

## 要裁决的（写清取舍）

1. **分段计时表**：每段打印 `段号 / 秒数 / ✓数 / ✗数 / SKIP数`，并在末尾给**最慢 N 段**汇总；
   计时**只记录、不判定**（D33：不得变成红线）。
2. **按路径选段**（`team gate --paths …` 或 `smoke.sh --select <set>`）：
   把"改动路径 → 最小段集合"写成**数据**（哪个段覆盖哪些路径，由**计时段 + 段的自我声明**共同产出）；
   **必须**包含一个"**保守兜底**"：任何未标注的路径 → **全套**（宁可多跑，不许漏跑）。
3. **不许降低覆盖承诺**：选段只是"批次内跑什么"，交付/复验/归档仍按 protocol 的里程碑规则；
   并且**报告必须点名"这次没跑哪些段"**。
4. **可证伪**：① 给一个只改 `docs/**` 的 diff → 选段结果为空且**明确说"无需跑"**；
   ② 给一个改 `scripts/lib/outbox.sh` 的 diff → 必须**包含** outbox/投递相关段（列出段号与依据）；
   ③ 未标注路径 → **全套**；④ 计时表与真实耗时的一致性（同一段两次跑差异在噪声内，给数字）。
5. **不许**为了快而放宽任何断言（这条写进 design 的 Non-Goals）。
