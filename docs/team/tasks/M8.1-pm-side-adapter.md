# M8.1 · The PM side adapts too: run the PM under any TUI agent CLI

```
task:   M8.1
agent:  dev

```

> The product claim is "a PM agent that can run on any TUI agent CLI". Workers already adapt (`TEAM_AGENT_CMD`),
> the **PM side does not**: `team up`, the watchdog's restart path and `team say`'s harness all assume Pi
> (`pi -c`, `--session-id`, the `@prompt-file` convention). `references/agent-adapters.md` says so honestly today —
> this task makes the PM side configurable too, with the Pi path **byte-identical by default**.

## Deliverable 1 — PM launch via a template (mirroring the worker adapter's discipline)

New keys (defaults empty ⇒ today's Pi behaviour, unchanged):

| Key | Meaning |
|---|---|
| `TEAM_PM_CMD` | launch template for the PM; same placeholder engine as `TEAM_AGENT_CMD`: `{cwd}` `{model}` `{provider}` `{prompt_file}` `{prompt}` `{skill_dir}` `{extra_args}` (+ `{session_id}` if you keep that concept) |
| `TEAM_PM_BIN` | binary used for existence checks and for the liveness identity check (default: `TEAM_PI_BIN`) |
| `TEAM_PM_RESUME_ARGS` | extra args that try to continue the PM's previous session (Pi: `-c`); **empty** means "no continuity" and must be documented as history loss |

Requirements:

- **Default invariance**: with all three empty, the rendered PM command must be byte-identical to today's
  (prove it by diffing the rendered command string before/after in your report, as M3.0 did for workers).
- The prompt is still written to `state/pm-prompt.md`; `{prompt_file}` expands to its quoted path. `{prompt}`
  (inline) must also work for CLIs that cannot read a file, and must be shell-quoted with the existing helper.
- Unknown/malformed placeholders keep failing loudly (reuse the worker engine's validation; do not fork it).
- `team up`, the watchdog's PM restart, and any other place that currently hardcodes pi must go through the same
  helper (grep for `pi_bin`, `team_pm_pi_args`, `--session-id`, `@` and be exhaustive).
- Liveness must keep working for non-Pi PMs: the M6.5/M7.2 mechanism (recorded pid + cwd inside the project) is
  already generic — make sure the *identity* check accepts the configured `TEAM_PM_BIN`/wrapper and does not
  require the name `pi`. A wrapper script that `exec`s the real CLI must count as the PM.

## Deliverable 2 — a real non-Pi PM run (the only evidence that counts)

In a scratch project, configure e.g. `opencode` or `codex` (both are installed and logged in on this machine) as
the PM CLI and show, with a transcript:

1. `team up` starts it (`team ps`/`roster` show a running PM with `proof=`), and the **prompt file content** is
   actually delivered to that agent (its first action should be a `team digest` per the prompt — show it);
2. the agent can drive the team from there: at least `team digest`, `team board ls`, `team dispatch --print` in
   that session (paste the outputs);
3. **crash + restart**: kill the window, run `team up` again → the PM comes back; with `TEAM_PM_RESUME_ARGS` empty,
   the tool must say plainly that history is not continued (and what to do: `team thread`/`docs/team/**`); if you
   test a CLI with a resume flag, show the contrast;
4. `team watchdog up` in that sandbox does the same restart when pending work exists (one tick is enough).
