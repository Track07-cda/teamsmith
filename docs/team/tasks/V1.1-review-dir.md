```

```

> 这是**独立验证任务**：你的产出是「证据 + finding」，不是改实现。
> PM 派单：`team dispatch verify V1.1 docs/team/tasks/V1.1-review-dir.md`

## 验证证据要求

- 每条 finding 必须带**可复现命令 + 实测输出**（含退出码）。
- **对抗性要求**：不要只跑一遍作者的测试就宣布通过。要主动构造**能让检查失效的输入**
  （例如让文档里出现已删命令的变体写法、或在 review 目录里放只读标记/符号链接/子模块），
  设计成"如果这个不变量是假的，我的测试会失败"的形式。
- 你的测试要写在**你自己的目录**里（建议 `docs/team/reports/V1.1/` 下放脚本），
  不允许复用（import/source）被测者自己的夹具来"证明"它正确。

## 背景

v1.11.3 给 smoke 加了一条文档一致性不变量：**文档/模板里不得再出现已删除的命令**
（`team merge` / `team pr ` / `team gh ` / `team gl ` / `forge.sh`），实现方式是对
`SKILL.md`、`references/`、`templates/` 做 grep，并排除含「已移除/不包装/不执行」等说明句的行。

同时 v1.11.0 起 `team review <ID>` 要求 `--dir <PM 准备的独立 checkout>`：skill 只跑门禁 + 写
`docs/team/reviews/<ID>.md`，**不执行任何 git 写操作**。

这两条都需要独立复核。

## 交付物

1. 报告 `docs/team/reports/V1.1-verify.md`：
   - **不变量 A（文档一致性）**：它在什么情况下会漏报（false negative）或误报（false positive）？
     至少给出 3 个你自己构造的**绕过尝试**（例如：
     `team  merge`（双空格）、`team\tmerge`（制表符）、反引号里的 `\`team merge\`` 之外的形式、
     中文全角、跨行断开的命令、把命令写进 `references/*.md` 的代码块/表格/HTML 注释、
     `templates/*.tmpl` 的占位符里、`SKILL.md` frontmatter 的 description 里），
     逐条说明「当前实现会/不会抓到」并给实测输出。
   - **不变量 B（review --dir 只读）**：验证 `team review <ID> --dir <path>` **不会**修改那个目录里的
     任何 git 状态（`git status --porcelain` 前后一致、`HEAD` 不变、不新建 worktree、不 fetch）。
     另外验证：目录不存在 / 不是 git 仓库 / 是只读目录 / 是 detached HEAD 时，行为是否可预期
     （报错清楚？会不会写出半截证据？会不会误判 PASS？）。
   - **结论**：明确写「不变量 A/B 有效 / 部分有效 / 无效」，并给最小修复建议（**只写建议，不要改实现**）。
2. 复现脚本：`docs/team/reports/V1.1/verify.sh`（可重复运行，自带清理；只读被测仓库/不留下 worktree）。

## 边界（不要做）

- **不要修改** `skills/pi-team/**` 的任何文件（实现与测试都归 PM/ dev）。发现问题写在报告里。
- 不要动 `docs/team/` 下 PM 的文件（除自己的报告目录）。
- 不要在 `pm-skills` 主工作树里留下改动或 worktree；需要独立 checkout 时自己建、结束后删掉。
- 不要 push、不要动远端。
