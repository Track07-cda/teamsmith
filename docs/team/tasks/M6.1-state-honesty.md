> V4.0 attacked the lifecycle and found that in several places the tool's *record* and the *fact* diverge.
> This task fixes the ones where the divergence loses work or reports success for a no-op. Evidence for every
> finding is in `docs/team/reports/V4.0-verify.md` (F-numbers below) with runnable reproductions.

## Findings to fix

### F28 (high) — a read-only status query destroys the durable task record
`team_model_running` calls `team_state_clear` for any agent whose window is gone, and `team ps` calls it too.
Reproduction (PM-verified): dispatch a task → `state/dev.env` has `task=`/`branch=` → kill the window → run
`team ps` → those keys are **gone**; `digest` then reports no pending work and `team resume` says nothing to
resume. A crashed worker becomes invisible, which is exactly the case the tool exists for.

Required: the durable record (`task`, `branch`, `worktree`, …) survives; only the **model-concurrency slot** is
released when a window disappears. Make the distinction explicit in the state layout (e.g. a separate counter
file, or a `running=` key) and say which file is authoritative in `references/config.md`. Read-only commands must
never mutate task state — prove it with a test (state file hash before/after `team ps`, `digest`, `roster`, `paths`).

### F29 (medium) — `board set` reports success for an unknown id
`team board set NOSUCH done` prints `✓ board NOSUCH → done` while the file is unchanged (PM-verified: md5 equal).
Required: unknown id → non-zero exit, no success line, and a message naming the ids that do exist (or telling the PM
to `team board add`). A no-op must never look like a write.

### F1 (medium) — `done` can be set with no verification and no merge
`team board set P1 done` succeeds while the branch tip is not an ancestor of the protected branch and
`reviews/P1.md` does not exist. `references/protocol.md` §8e still describes the *removed* merge wrapper's
transactional behaviour, so the doc promises something the tool does not do.
Required — pick one and make code and docs agree (say which you chose in the report):
 (a) `board set <ID> done` refuses unless the task's branch tip is an ancestor of the protected branch **or**
     `reviews/<ID>.md` exists (with an override flag for the PM, e.g. `--force --reason "…"` that is recorded), or
 (b) §8e and the surrounding docs stop claiming the tool enforces it, and the PM-facing checklist says what to
     check by hand.
 Either way, `done` set through the tool must be traceable: what did it verify at that moment?

### F2 (low) — `close` claims a file that does not exist
`team close P1` prints "复验记录 docs/team/reviews/P1.md 保留" when there is no such record. Report the truth:
either the path exists (print it) or say plainly that no review record was found.

### F5 (medium) — `TEAM_TASK_BRANCH_RESET` is dead config
`common.sh` defines it, `references/workflows.md` documents "after close the worktree returns to
detached@protected", and nothing reads it. Either implement the reset in `close` (git is the PM's job — the CLI
may print the exact `git switch --detach` command it would run, or perform it behind the existing
`--yes`-style authorization) or delete the key and fix the doc. Do not leave a promise with no implementation.
