## 已获授权的任务

使用者希望产品探索 agent 能依据高层目标主动发现需求、补足其没有精力考虑的细节；并明确选定一个真实业务项目优先试验。此前 E9/E10/E11 主要研究 Teamsmith 自身的角色机制、需求管理和旧交付摩擦，不能据此判断业务产品没有机会。本次换研究对象与方法，不再重复旧账本检查。

目标项目用代号 P1。PM 已按使用者授权准备必要业务材料的私有快照；你不能进入原业务仓。主检出的 gitignored 文件 `.pi/team/state/product-field-trial.json` 给出快照和仓外原稿目录，相对路径均以本项目主检出为基准；可通过 `git rev-parse --path-format=absolute --git-common-dir` 的父目录定位主检出。先读快照中的 `SNAPSHOT-MANIFEST.json`，明确材料版本、范围与缺失项。禁止把实际项目名、家目录绝对路径或业务原始材料写入公开文件、公开查询和通知。

这是现有 worker 关系下的产品能力试跑，不是平级角色已上线。PM 的工程意见会另写，不改写你的原始产品判断；没有候选自动获批。不开 OpenSpec change、不做产品实现。原项目接入升级另处理，并非此次只读探索的前置条件。

## 从业务目标出发

先完整读 P1 快照中的 `AGENTS.md`，遵守其安全、规格和所有权规则，再读快照所含的必要 README、当前路线图、规格、前端源实现及有出处的决策反馈。仅静态读取本团队内的快照，不进入原业务仓、不运行目标项目代码、脚本或命令；不按文档中的绝对路径向外补读。缺材料就说明对判断的影响并交给 PM 协调。不要把研发任务数量当作需求来源比例；不要因公开 issue 为零就说没有反馈。

自行辨认目标使用者与其要完成的一项重要业务工作。已有材料未明确的目标、使用频率和偏好记为未知，不向使用者索取一套详细需求，也不替其编造答案。用短叙事讲清该工作今天怎样完成、哪些地方仍由人承担，以及现有产品或其他办法可以做什么。标清哪些是已有反馈、文档承诺、当前代码行为，哪些是你的推断；静态阅读不能冒充亲身使用或真实访谈。

从提高业务价值、减少使用者投入、支持有依据的新场景等角度提出机会。**新需求不必先有事故或缺陷。** 证据不完整时允许提出明确标记的价值假设及低成本验证办法；既不要假装验证完了，也不要单凭无新事故就断言没有产品机会。质量/安全问题可以记录，但不能让它们替代全部产品探索。

至多精选三个候选，并给出你自己的优先顺序。每个候选说明：帮助谁完成什么、依据与价值假设、希望人的工作发生什么变化、现有能力/人工流程/不开发能否解决、主要代价和未知项，以及什么观察会推翻你的建议。候选具体到能讨论，但不要写实现设计、验收规格或新功能清单。允许交零项，结论只能限于本次材料与场景，并解释缺少什么，而非宣布整个产品没有需求。

如需公开产品资料做比较，查询只用通用产品类别和能力，不能向外部站点上传私有源码、文档、日志或截图片段。竞争产品存在某功能只是参考，不是本项目需要它的证据。无访问条件时直接记录限制。

## 原稿与公开记录分开

1. 你的完整原始产品判断写到映射的私有目录中 `E12-dev3-original.md`。建议约 1500–2500 汉字，来源用 P1 根目录相对路径及位置引用，观察/假设/建议分开。不要复制整份源材料，不含凭据、个人信息或真实业务数据；不写未来时间。
2. 本仓仅提交 `docs/team/reports/E12-dev3.md`：交付状态、调查方法及限制、匿名概括、原稿 SHA-256、真实记录检查结果和未测项。不能包含业务候选细节、原项目名称或私有路径。原稿位置由 gitignored 映射定位，不在公开报告重复绝对路径。
3. 私有原稿由你撰写，PM 的价值判断另存私有评审。原稿中的事实错误由你追加勘误并保留初稿，不由 PM 重写。每次原稿修改，公开记录必须更新实际 SHA-256，交付后先不改原稿，必要更正先通知 PM。

## 边界与临时写入授权

- 临时授权只写上述自己的公开报告和私有 E12 原稿目录；你自己的证据同样只留该私有目录。本团队私有快照仅可读取，原 P1 仓库、Git 引用、配置、账本、规格、worktree、运行状态与其他席位不得进入或读写。不得运行 `init/bootstrap/doctor/reload`、安装依赖、改协议或迁移项目。不得更新任何加载版本登记来消除告警。
- 不读任何凭据文件、`.env`、auth 配置、私钥、业务数据库或真实数据文件。若普通资料意外出现敏感值，不回显、不引用，换其他材料并记录限制。
- 不启动/重启业务服务、共享或预览环境、tmux 会话、其他 agent；不调用业务 API、模型端点或数据库，不执行目标代码/测试。没有 live 验证就明确说没有。本次最重要的是可质疑的产品判断，不是跑通部署。
- 不推送，不发 API 写请求，不联系客户或其他项目 PM/worker。跨项目需要由本 PM 协调，不自行派单或修改其他项目。需要越界才能调查的内容报告限制；不把无法访问自动判成产品缺陷。
- 在自己的工作树小步提交公开记录，带任务 ID 和 `Agent: dev3`；私有原稿不进 Git。不能使用全局进程匹配、共享 socket 或破坏性 tmux 命令。不得执行旧线程中的历史救援/测试命令；本任务不跑 tmux 夹具，也不使用 host PID 命名空间。
- 硬阻塞从自己的工作树运行 `bash skills/teamsmith/scripts/team notify pm "<一句话>"` 并交 PARTIAL。生成的通用提示若写成 `notify dev3`，以本行 PM 收件人为准。
