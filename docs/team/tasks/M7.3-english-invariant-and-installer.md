> it is that the invariant lived in a brief instead of in the suite, so it rotted within one release (creed #5).

## Finding 1 — the "English-only" invariant is not enforced, and currently reports a false positive

`grep -rlP '[\x{4e00}-\x{9fff}]' skills/teamsmith/references SCOPE.md` hits `references/protocol.md:349` and `:360`
(both added by M6.2/v1.20.0). Both hits are **inline-code spans quoting real CLI output** (`翻转`, `破坏`,
`不满足（不阻塞合并，但里程碑收口前应补齐）`), which the project deliberately keeps in Chinese (DECISIONS D8: the CLI
surface stays Chinese; only the docs are English).

Required outcome — make the rule precise *and* tested:

- Define the invariant as: **no CJK characters outside inline code spans and fenced code blocks** in
  `skills/teamsmith/references/**` and `SCOPE.md`. Prose must be English; literal CLI strings, command output and
  identifiers quoted as code are exempt on purpose.
- Implement it in the smoke suite (a scanner in the existing doc-invariant section, or your own appended section) —
  strip fenced blocks (``` pairs) and inline `` `…` `` spans, then fail on any remaining CJK, printing
  `file:line: <the line>` for each hit.
- **Flip-test both directions in the suite itself**: (a) inject an English-paraphrase violation
  (`protocol.md`: a sentence with 中文 in prose) into a scratch copy → must be reported; (b) inject a code-span-only
  hit (`` `不满足` ``) → must **not** be reported; (c) the real tree must pass.
- Keep `references/protocol.md` as it is if it already passes under this rule (verify; do not translate CLI strings
  that must stay recognisable). If a hit turns out to be prose, paraphrase it in English.

## Finding 2 — `install.sh` installs the legacy compatibility symlink as a second skill

Reproduction (from the M7.1 report, reproduced with a temp target): the loop `for src in "$REPO"/skills/*/` also
matches `skills/pi-team` (the compatibility symlink), so a fresh install creates **two** entries
(`…/pi-team → …/skills/pi-team` and `…/teamsmith → …/skills/teamsmith`) pointing at the same code — a duplicate
discovery entry with the same skill name, rather than a behaviour difference.

Required outcome: install the canonical `skills/teamsmith` only; **do not** create a second entry from a symlinked
directory (skip symlinks in the loop, and/or install the legacy path only when the canonical name is absent). Add a
guard so this cannot come back: an assertion in the smoke suite that runs the installer against a temporary target
directory and requires exactly one teamsmith entry (and no `pi-team` duplicate). `--copy`/`--link` modes both.
