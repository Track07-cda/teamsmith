> Observed by the PM during the M7.3 review: the gate run reported `✓ 904 ✗ 2`, both failures in the B3 group —
> `B3：agent 秒退被明确说出来（不假装一切正常）` and `B3：给出续跑办法` — while the very same commit produced
> `✓ 906 ✗ 0` twice afterwards (branch and main). The scenario: dispatch starts a fake agent that exits
> immediately; `cmd-agents.sh` is supposed to notice and print
> `但窗口里的 agent 已经退出（回到 shell）：team roster 会显示「pi 已退出」（续跑：team resume --agent dev）`.
> Once the message was missing within the fixture's window; once it was there. That is a timing flake in either the
> detection or the fixture — fix it in the one that is actually wrong, and prove it.

## Required outcome

1. **Reproduce it, with numbers.** Write a small harness (script under `docs/team/reports/M7.5-dev/` or `tests/`)
   that runs *just* the B3 scenario N ≥ 30 times (fake agent that exits immediately, dispatch, then read the
   dispatch output and the roster line) and records how often the exit notice and the `resume` hint are missing.
   Report the counts. If it never reproduces, say so and show the timing you measured (how long after dispatch the
   notice appears, distribution over the runs) — an unreproducible flake still needs the timing measured so the fix
   is grounded.
2. **Fix the cause, not the symptom.** Two candidates to evaluate (pick after the diagnosis, say why):
   - detection: the "did our agent exit?" check samples the pane once after launching; if it samples before the
     shell has come back, it misses the exit. If so, make the check bounded-poll (e.g. poll up to ~2 s for the pane
     to return to a shell after the agent disappears) and make the wording depend on *observed* state, never on an
     assumption;
   - fixture: the assertion reads the log after a fixed sleep. If so, replace fixed sleeps with polling for the
     expected line up to a bound, and fail with the last observed state when the bound is reached.
   Do **not** simply add retries in the assertion without stating which side was wrong — and do not paper over a
   genuine detection gap: an agent that exits must always end up reported, even under load.
3. **Guard it.** Add the deterministic assertion(s) to the smoke suite in a way that cannot flake: bounded polling
   with an explicit failure message that prints the observed pane/log state. If the harness from (1) is cheap, wire
   it into the suite as a small loop (e.g. 5 repeats) rather than 30.
4. **Look next door, cheaply.** If the same fixed-sleep pattern appears in the other dispatch-verification
   assertions you can see (M4.3's B1/B2 and the `proof=spawn` checks), fix them the same way — but keep the diff
   narrow and say in the report which ones you touched and which you deliberately left.
