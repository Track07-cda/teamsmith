# M9.6 · `done` evidence: a committed report is necessary (close the zero-commit hole)

```
task:   M9.6
agent:  (unassigned)
deps:   M9.2 (phase-aware evidence), v1.30.0
```

> Found while probing M9.3: a task whose branch was just created (zero commits beyond the protected branch) passes
> the done evidence — the message even says "代码真的落地了", which is false. Root cause: "branch tip is an ancestor of
> the protected branch" is true both for a merged branch and for a branch that never had any work, and git alone cannot
> distinguish them (`main..tip` counts 0 for both).

## Required

1. For tasks with **no** `phase:` (code tasks), done evidence becomes: a **committed** report
   (`docs/team/reports/<ID>-*.md`, committed — M4.3-C's draft rule) **and** (a PASS/UNKNOWN/SKIPPED review record **or**
   the branch-tip-ancestor rule). The review-record path is unchanged (a PASS implies rigor). The branch path gains the
   report requirement, which is what separates "merged with content" from "created and never touched".
2. The refusal message names which layer is missing (report vs review vs merge), reusing the existing vocabulary.
3. Phase tasks (M9.2) are unchanged — their evidence already requires phase artifacts (a DECISIONS heading, an
   ACCEPTED record, …), which a zero-commit branch cannot fake.
4. Fixtures: fresh branch + no report → refuse, naming the missing report; fresh branch + committed report, no review
   → refuse (still no review/merge evidence); fresh branch + report + review → pass; merged branch + report → pass
   (control); phase task → unchanged (control).

## Boundaries

`scripts/lib/common.sh` (evidence), `scripts/lib/cmd-docs.sh`/`cmd-review.sh` only if the message text lives there,
`tests/smoke.sh` (own section), `references/openspec.md` one sentence if the evidence paragraph lists the rule.
