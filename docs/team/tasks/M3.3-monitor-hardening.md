## F2 · major — unbounded read ⇒ OOM

`monitor.mjs` reads each matched log file whole (`readFileSync`) just to display its tail. Measured: a 256 MB log
took **584 MB RSS**; with a 64 MB heap limit the process aborts (`exit 134`). The watchdog runs this every refresh
for every agent, so a GB-scale log can take down the PM's machine — and the docs promise "graceful degradation …
no crash".

Required outcome:
- bounded memory: read only the tail (e.g. last N KiB, configurable with a sane default and a hard cap),
  never the whole file; handle files that are still being written;
- a file that cannot be read (permissions, FIFO, device, deleted mid-read) degrades to "unavailable + reason"
  rather than crashing;
- assert both: peak RSS stays small for a large file (measure it: `/usr/bin/time -v` or `process.memoryUsage()`),
  and the rendered tail is still correct for a normal file;
- document the bound and the configurable knob in `references/agent-adapters.md` (and the config key list if you
  add one).

## F3 · minor — control characters reach the PM's terminal

A log containing `\033]0;…\007` (window title) / `\033[2J` (clear) is echoed verbatim into the monitor output;
`OSC 52` could even write the clipboard. Display text, not control bytes: strip ANSI/OSC sequences (and other
non-printable control characters except `\n`/`\t`) from activity lines before rendering, in `--once`, live mode and
`--json` alike, and assert it with a log whose content includes title/clear/clipboard sequences.
