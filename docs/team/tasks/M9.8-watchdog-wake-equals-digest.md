# M9.8 · The watchdog's wake counter must be the digest's actionable list

```
task:   M9.8
agent:  dev2
deps:   M9.4（待复验清单让位看板）、M9.5（verify 任务的过期判据）、v1.33.0
```

> 实测（真账本的 digest 头部与 [3] 节并排）：watchdog 的唤醒理由是「待复验 6」，而 digest 的可行动列表是**空**
> （那 6 份报告全部属于看板已裁决/草稿，已被 M9.4 的规则跳过）。结果：PM 每 15 分钟被叫醒一次却无事可做——
> 叫不醒的闹钟和永远清不空的清单是同一个失败模式（M9.4 的判词），只是这次发生在唤醒侧。

## 要求

1. watchdog 计算"要不要叫醒 PM"时，**待复验这一项必须复用 digest 的可行动列表**（同一个函数、同一套过滤：
   看板 done/closed 跳过、草稿标注但不计数、verify 任务按绑定 revision 判）——而不是自己另算一遍报告数。
2. 其它唤醒理由（未读通知、blocked、有任务但 agent 停了）保持现状，但顺带核对它们与 digest [2]/[4] 节的口径一致；
   不一致就统一，并在报告里点名每一处差异。
3. 夹具：① 5 份"看板已 done"的报告 + 0 未读 → **不叫醒**（修复前会叫醒，翻转证据）；② 1 份真待复验 → 叫醒；
   ③ 未读通知 → 叫醒（对照）。全部在沙盒仓库里跑（M7.2 隔离纪律）。

## 边界

`scripts/lib/cmd-watch.sh`（唤醒判定）、`scripts/lib/cmd-status.sh`（若要抽出共用函数）、`tests/smoke.sh`（自己的段）、
`references/workflows.md` 一句话。不动 digest 的显示文案、不动账本。

## 验收

```sh
openspec validate --all --strict
bash skills/teamsmith/tests/spec-lint.sh

TEAM_SMOKE_FAST=1 bash skills/teamsmith/tests/smoke.sh
```
