## Findings to fix (all in `skills/teamsmith/**` unless noted)

### F1 · blocker — worker summary becomes shell code

Today the documented notify template interpolates the worker's own text into a quoted shell string:

```sh
TEAM_AGENT_NOTIFY_CMD='bash {skill_dir}/scripts/team notify pm "{summary}"'
```

so a summary containing `$(…)`, backticks or `"; …` executes (verified: 3 of 6 hostile summaries ran code;
a harmless `"` also silently rewrites the message). "You own the quoting" is not achievable — **the worker
performs the substitution**, not the template author.

Required outcome: **the summary is data, never code.**

- Add a file channel: a `{summary_file}` placeholder for the notify template (teamsmith generates the path and
  quotes it), and `team notify <agent> --from-file <path>` so nothing the worker writes passes through a shell.
- Render the prompt's "notify the PM when your turn ends" section so it never contains worker text: instruct the
  worker to write its one-line summary into the given file (however it normally writes files) and then run a
  **fixed** command with no substitutions, no extra arguments and no quotes.
- Keep `{summary}` working (existing configs must not break) but document plainly why the file channel is the
  recommended default, and make the *rendered* example the safe one.
- Tests: for a set of hostile summaries — `$(touch X)`, `` `touch X` ``, `x"; touch X; echo "`, `it's fixed`,
  a summary with a newline, a summary containing literal `{agent}` — assert (a) nothing executes, (b) the PM inbox
  receives the text **byte-exact**, (c) the PM is notified (non-zero exit only when it really failed).

### F4 · minor — malformed placeholders pass silently

`{ cwd }`, `{cwd }`, `{{cwd}}`, `{cwd'}'` are neither expanded nor rejected: they go into the command line as
literal text, contradicting the documented promise ("a typo must never silently produce a broken window").
Extend the validation so any brace-delimited token that is not a supported placeholder (allowing for whitespace
and doubled braces) aborts the dispatch with the supported list and the config key name.

### F5 · minor — whitespace-only `TEAM_AGENT_CMD` is accepted

`TEAM_AGENT_CMD='   '` renders `cd <wt> &&    `, exits 0, warns nothing, and the window never starts an agent.
Reject an adapter template that is empty after trimming. Also stop silently falling back to `TEAM_PI_BIN` for the
existence check when a custom template is configured but blank.

### F6 · minor — a multi-line template executes its second line

`TEAM_AGENT_CMD=$'<stub> {prompt}\ntouch /tmp/MARK'` really created `/tmp/MARK`. Reject templates containing
newlines (with a message explaining that the adapter is a single command line), or explicitly support them —
pick one and make the docs and tests agree. Rejecting is preferred.

### F7 · minor — the prompt lies when only the notify key is set

With `TEAM_AGENT_CMD` empty (i.e. Pi is still the CLI) and `TEAM_AGENT_NOTIFY_CMD` set, the prompt says the project
"uses an agent adapter, not Pi, so there is no automatic notification" — while the launched CLI *is* Pi and does
auto-notify. Key that wording off `TEAM_AGENT_CMD`, not off the notify key.

### F8 · minor — a broken notify template still yields a "run this" line

With `TEAM_AGENT_NOTIFY_CMD='… {bogus}'` the dispatch correctly only warns, but the prompt then prints an empty/
half command for the worker to copy. When the notify template is unusable, replace that whole section with an
instruction to record the summary in the report instead (and say why).

### Nits (fold in while you are here)

- Document that the template's first word must be a bare executable name (or resolve it properly).
