> **Mission: try to falsify M3.0.** The claim under test is: *"teamsmith's workers can be any TUI agent, and with
> the adapter keys left empty nothing changes for Pi."* Your job is to attack that claim, not to confirm it.
> Findings beat agreement; a verification that finds nothing must show what it tried and why it failed.

## Attack surfaces (cover at least these; add your own)

1. **Command / argument injection.** `{prompt}`, `{extra_args}`, `{summary}` are inserted verbatim.
   - Can a *worker-supplied summary* containing `"` `$(...)` `` ` `` `;` break out of a reasonable
     `TEAM_AGENT_NOTIFY_CMD='bash {skill_dir}/scripts/team notify pm "{summary}"'` and run arbitrary commands
     when the PM/agent runs it? Show the exact summary text and the resulting execution, or show why it cannot happen.
   - Same question for `{extra_args}` and for a task brief whose text lands inside `TEAM_AGENT_CMD` via `{prompt}`.
   - Can a placeholder be split/reassembled (e.g. `{cwd}{cwd}`, `{cwd`…`}`) to smuggle something past the
     unknown-placeholder check?
2. **Placeholder contract vs documentation.** Every token in `references/agent-adapters.md` must be accepted by the
   engine and vice versa (smoke claims this — try to defeat it: `{ cwd }`, `{{cwd}}`, `{CWD}`, `{cwd }`, nested
   braces, `{summary}` inside `TEAM_AGENT_CMD`, `{notify_ext}` outside the launch template).
3. **Default-path invariance.** Independently verify the "empty keys = byte-identical Pi behaviour" claim:
   render the dispatch command with the old code (`main~1`, i.e. `ae49f67`) and the new code and diff; also diff
   `doctor`/`paths`/`roster`/error-string output where the claim is "unchanged". Report the exact diff and whether
   the documented `$PROMPT` → `$0` argv change is behaviour-preserving (test it, e.g. a prompt containing newlines,
   `$`, backticks, quotes, and one longer than the argv limit).
4. **Doctor / dispatch fail conditions.** `TEAM_AGENT_BIN` pointing at a directory, a non-executable file, a
   template whose first word is quoted (`"my agent" run …`), a template that is only whitespace, a template
   containing a newline, `TEAM_AGENT_CMD` set but `TEAM_AGENT_NOTIFY_CMD` empty (should still work), and the
   reverse. Each case: what actually happens vs what the docs promise.
5. **Monitor degradation.** No `node`/`bun`/`tsx` on PATH at all; `TEAM_AGENT_LOG_GLOB` matching nothing; matching a
   directory; matching a binary file; matching a multi-GB file (does it tail or read everything?); `**` semantics;
   `{agent}` substitution. The promise is "graceful degradation and no crash".
6. **End-to-end with a CLI dev did *not* use.** dev's real evidence used both `opencode` (1.18.8) and `codex`
   (0.146.1). Re-run one of them yourself (either is fine, `opencode` is preferred for independence) with **your own
   scenario**, in a scratch repo, and also try the notify path with a summary containing shell metacharacters
   (`"` and `$(...)`) to see what the PM inbox and the shell actually do. Paste: window command, agent output tail,
   commits, report file, inbox line.
7. **Docs truthfulness.** Does anything still claim Pi-only support, or over-claim? Is the "not supported" list in
   `references/agent-adapters.md` (e.g. cross-CLI session resume, PM-side adaptation) accurate? Is `README.md`'s
   "any TUI agent by design" now backed by what actually exists?
8. **Liveness semantics with a custom CLI.** `team roster` / `team say` wording, and what `team resume` does when
   the configured CLI is not Pi (is it documented as unsupported, or does it silently try the wrong thing?).
