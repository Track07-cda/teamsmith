## Findings to fix

### F4 (medium) — "unpushed" is measured against the wrong ref
Reproduction: `ahead` is computed against the protected branch, never against `@{upstream}`; a branch that was pushed
and then squash-merged shows `脏 0 领先 1` under a header that says **未 push**, forever.
Required: measure the push state against upstream when an upstream exists (`rev-list --count @{upstream}..HEAD`);
keep branch-vs-protected as a separate column/label ("ahead of main"), and make the digest's wording match what is
actually being measured. Coordinate with M6.1's `TEAM_TASK_BRANCH_RESET` decision if the two interact.

### F6 (medium) — task ids containing `-` are mis-parsed
`team task API-2 …` → the report `reports/API-2-dev.md` is parsed with `id="${base%%-*}"` = `API`, so the real report
lands in "ignored non-task reports" and never becomes "awaiting verification".
Required: derive the id by matching against known task ids (BOARD rows + `docs/team/tasks/*.md` stems) rather than
splitting on the first `-`; keep the existing heuristics (report heading must match the id, ignored reports stay
visible). Add a regression test with `API-2` and with a file whose stem contains two dashes.

### F21 (medium) — `team version --check` can exit 141 for "you are stale"
The command prints the right message but the pipeline (`sed … | head -14 | sed …`) closes early, and with `pipefail`
the non-zero status propagates; `&&` chains then treat "stale" as a crash.
Required: no SIGPIPE-driven exit codes from a read-only report — restructure or trap it, and add a smoke assertion
that a stale session yields exit 0 with the stale message.

### F23 (medium) — `team reload` promises a watchdog behaviour that does not exist
The output says the watchdog restarts the PM when it sees the marker; nothing reads `state/reload-requested`
(the Pi extension only deletes it after a reload).
Required — choose one and make the other side agree: (a) implement it (the watchdog sees the marker and restarts the
PM session, honouring the restart quota and standby), or (b) delete the claim and print what actually happens
(`/reload` in the session; the marker only suppresses the extension's re-read prompt). State the choice in the report
and cover it with a test.

### F19 (low) — meeting TTL accepts nonsense
`meeting open X --ttl 0` (also `-5`, `abc`) makes the meeting effectively immortal: `is_expired` treats
0/negative/non-numeric as "never expires", `open` neither validates nor warns, and `read` prints `TTL abch`.
Required: validate TTL at open time (positive integer hours; reject or clamp with a message), treat a missing TTL as
the documented default, and make `read` print a sane value. Keep the existing guard tests green.
