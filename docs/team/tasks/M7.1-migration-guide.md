# M7.1 · Migration and upgrade guide (`references/migration.md`)

```
task:   M7.1
agent:  dev
deps:   v1.22.0
```

> teamsmith is published and usable, but a project that was set up with an older version (or with `pi-team`) has no
> single place telling it what to do. Today that knowledge is scattered across `CHANGELOG.md`, `SCOPE.md` and a dozen
> DECISIONS entries. Write the guide people actually need, and make the skill's own doctor/bootstrap able to point at
> it. Docs only — but the doctor pointer is code, so this task needs the usual verification.

## Deliverable 1 — `skills/teamsmith/references/migration.md` (English, ~120–200 lines)

Cover, concretely and honestly (state what is *not* supported):

1. **What is stable, and therefore never needs migrating**: the `team` CLI, `.pi/team/config.sh`, `TEAM_*` variables,
   `docs/team/**` layout, `docs/team/BOARD.md` columns. Say this up front so readers stop worrying.
2. **Renames and their compatibility**:
   - `pi-team` → `teamsmith` (skill directory, `/teamsmith-reload`, the `AGENTS.md` marker `<!-- pi-team:begin -->`);
     what auto-migrates (marker re-render on the next `init`/`bootstrap`, the `skills/pi-team` compatibility symlink)
     and what a project must do by hand (update absolute paths in its own notes/scripts; re-run `team init` if it
     wants the new marker).
   - A short table: old → new, with "nothing to do" where that is the truth.
3. **Removed commands (v1.10 → v1.11) and what replaced them**: `team merge`, `team pr`, `team gh`, `team gl`
   (git/forge work is the PM's, run directly), `team review <ID>` without `--dir` (a PM-prepared independent checkout
   is now required), `team add-agent`/`bootstrap` creating worktrees (now print the command unless `--create`). Each
   row: symptom a user sees (e.g. "unknown command"), the replacement, and the doc to read.
4. **New required dependencies (v1.19.0)**: magic-context and OpenSpec. The exact commands (`pi` package install,
   `openspec init --tools none`), what `team doctor` prints, and the escape hatch (`TEAM_REQUIRE_*=0`) for unusual
   environments — plus the honest note that turning it off loses PM memory / the spec layer.
5. **Behaviour changes that can surprise an existing project** (each with a one-line "what to check"):
   - dispatch now refuses a worktree whose branch is not the task's branch, a brief outside the project, an unknown
     recipient, and a model-limit overrun (v1.21.0);
   - `board set <ID> done` requires evidence (merged tip or a review record) or an explicit force + reason (v1.20.0);
   - a review must run in a clean checkout of the task branch, and the record is bound to that revision (v1.20.0);
   - empty/whitespace tmux targets are refused everywhere (v1.21.0);
   - the watchdog runs as a `watchdog` window in *the project's own tmux session*; `TEAM_SESSION` must match that
     session name (this bit us on 2026-09-14 when the session was renamed — mention it as a real example);
   - long-lived sessions: `--fresh` when changing to a model with a smaller window (v1.22.0).
6. **A step-by-step upgrade recipe** for a project currently on an older version:
   `git -C <skill checkout> pull` → `team version --check` (stale session → `/reload`) → `team doctor` (fix failures)
   → `team init` (re-render the marker block idempotently) → `openspec init --tools none` if missing → add
   `openspec validate --all --strict && bash skills/teamsmith/tests/spec-lint.sh` to the project's `TEAM_GATES` →
   `team watchdog up` → `team smoke`/`bash tests/smoke.sh`. Include the expected output snippets.
7. **Rolling back**: what a project does if an upgrade breaks it (pin a version by checking out a tag in the skill
   checkout; the data under `docs/team/**` and `.pi/team/**` is version-agnostic, so no data migration is ever
   needed). Keep it concrete.
8. **What is deliberately not supported**: PM-side non-Pi agents (only workers adapt via `TEAM_AGENT_CMD`), the old
   Podman/systemd watchdog backends, the removed forge wrappers — link `references/agent-adapters.md` and
   `SCOPE.md` instead of restating.

## Deliverable 2 — make it discoverable (code, small)

- `team doctor`: when the version check finds a stale loaded session **or** the project's `AGENTS.md` still carries
  the legacy `<!-- pi-team:begin -->` marker, print one line pointing at `references/migration.md` (do not add a new
  sub-command).
- `references/bootstrap.md` and `references/config.md`: a one-line pointer where a reader would look.
- `SKILL.md`'s deeper-reading table: add the row.

## Deliverable 3 — tests

- Smoke: a fixture project whose `AGENTS.md` has only the legacy `pi-team` marker → `team doctor` prints the
  migration pointer; then `team init` re-renders it to `teamsmith` and the pointer disappears (idempotent, single
  block).
- Keep the doc invariants green: English only, no active mention of removed commands (the scanner allows
  `removed`/`deleted`/`renamed` contexts — use them).

## Boundaries

- Files you own: `skills/teamsmith/references/migration.md` (new), `references/bootstrap.md`, `references/config.md`,
  `SKILL.md` (deeper-reading row only), `scripts/lib/cmd-project.sh` (doctor pointer),
  `scripts/lib/common.sh` **only** if the marker check needs a helper (coordinate: M7.2 owns `cmd-watch.sh`,
  M2.4-style timing code and the smoke sections around the watchdog), `tests/smoke.sh` (append your section; M7.2
  appends its own).
- Do not touch `cmd-watch.sh`, the meetings code, or `openspec/**`.
- Do not modify `docs/team/**` except your own report. Do not push `main`.
