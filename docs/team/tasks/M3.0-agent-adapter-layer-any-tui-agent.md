> Goal: make the README's claim real — **"Pi today, any TUI agent by design."**
> Today the agent launch path is hard-coded to Pi (binary, flags, notify extension, session logs). This task
> introduces a small adapter layer so a project can run workers with *any* agent CLI, **without changing the
> default behaviour for Pi users**.

## Background (read before coding)

- `skills/teamsmith/scripts/lib/cmd-agents.sh` — `team_pi_args()` builds the flags, `team_cmd_dispatch()` renders the
  window command (`cd <worktree> && <agent-cli> <flags> --session-id <sid> "$PROMPT"`), and `team_build_prompt()`
  renders the worker prompt (already English; it tells the agent to call `$cli notify|say|review` etc.).
- `skills/teamsmith/scripts/lib/common.sh` — defaults for every `TEAM_*` key (`team_config_defaults()`), plus
  `team_pi_pid`/`team_pane_busy` style liveness helpers. Environment variables override the config file.
- `skills/teamsmith/scripts/monitor.mjs` — the activity stream currently reads Pi session JSONL
  (`~/.pi/agent/sessions/**`) and must degrade gracefully for other agents.
- `skills/teamsmith/extension/team-notify.ts` — the Pi extension that appends to `docs/team/inbox/<agent>.md` and
  knocks on the PM window when an agent's turn ends. Non-Pi agents need a different path.
- `skills/teamsmith/scripts/lib/cmd-project.sh` — `team doctor`, `team paths`.
- Existing docs to extend: `references/config.md`, `templates/config.sh.tmpl`, `SKILL.md`.
- **Never break the Pi default**: today's smoke assertions (`--session-id`, `-e team-notify.ts`, `--skill`, `pi`
  resolution) must keep passing unchanged.

## Deliverables

1. **New config keys** (defaults in `common.sh`, documented in `templates/config.sh.tmpl` + `references/config.md`,
   all defaulting to the current Pi behaviour):

   | Key | Meaning | Default |
   |---|---|---|
   | `TEAM_AGENT_CMD` | template for launching an agent CLI in its tmux window | empty = built-in Pi command |
   | `TEAM_AGENT_NOTIFY_CMD` | how an agent notifies the PM at turn end | empty = Pi notify extension |
   | `TEAM_AGENT_LOG_GLOB` | optional log/session files for `team monitor --activity` | empty = Pi session discovery |
   | `TEAM_AGENT_BIN` | optional binary used for existence checks in `doctor`/`dispatch` | empty = resolved from `TEAM_AGENT_CMD` (Pi: `TEAM_PI_BIN`) |

2. **Launch-command builder** in `common.sh`: `team_agent_launch_cmd <agent> <session_id> <worktree> <prompt_file>`
   printing a **shell-quoted, single-line** command. When `TEAM_AGENT_CMD` is set, substitute these placeholders
   (support at least these; unknown `{placeholder}` → `team_die` with the supported list):
   `{cwd}` `{session_id}` `{model}` `{provider}` `{prompt_file}` `{prompt}` (prompt file contents on one line is
   *not* required — define and document whatever you implement) `{skill_dir}` `{notify_ext}` `{extra_args}`.
   When it is empty, produce exactly the current Pi command.
3. **`cmd-agents.sh` uses the builder** for `dispatch` (and `--print`). Keep `team dispatch … --print` readable.
   If `TEAM_AGENT_NOTIFY_CMD` is set, the dispatch prompt must include a line telling the worker to run it at turn
   end (with `{summary}`-style substitution documented), and `dispatch` must warn once if the notify command looks
   invalid.
4. **`team doctor` + `team paths`**: print the resolved adapter — `built-in (Pi)` or `custom: <cmd>` — and make
   `doctor` fail only when the configured binary/command cannot be resolved at all (missing Pi must fail as today).
5. **Liveness/monitor degradation**: `monitor.mjs` (or `common.sh`) must not break when there are no Pi session files
   and no `TEAM_AGENT_LOG_GLOB`; with `TEAM_AGENT_LOG_GLOB` set it shows the tail of the newest matching file as the
   agent's activity. The team status panel keeps working in both cases.
6. **New doc `references/agent-adapters.md`** (English): the contract (launch / notify / logs / liveness), the
   placeholder table, a **worked codex example** and a **worked opencode example**, how to verify a new adapter, and
   what is intentionally unsupported (no attempt to emulate an agent's internal turn events).
7. **`SKILL.md`**: requirements section + a short "Agent adapters" section pointing to the new reference.
8. **Tests in `tests/smoke.sh`** (append to the existing sections; keep the suite green):
   - default path unchanged (existing assertions still pass);
   - custom `TEAM_AGENT_CMD` → `dispatch --print` shows the rendered command with **no leftover `{`**;
   - unknown placeholder → explicit failure (assert the message names the supported placeholders);
   - **flip test**: injecting a bogus placeholder into a sandbox copy must be caught;
   - a **fake non-Pi agent** end-to-end: `TEAM_AGENT_CMD` points at a small script that (a) writes a file and
     commits it, (b) writes the report `docs/team/reports/<ID>-<agent>.md`, (c) calls
     `bash <skill>/scripts/team notify pm "<line>"`; assert the agent window ran it, the commit exists, the report
     file exists and the PM inbox received the line. This is the evidence that the adapter works with no Pi at all.
   - `TEAM_AGENT_LOG_GLOB` set to a temp file → `team monitor --once --activity` shows a tail of it (or, if you
     decide activity rendering stays Pi-only, assert the documented degradation instead — but be explicit).
