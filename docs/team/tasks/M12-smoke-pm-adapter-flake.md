## M12 追加（PM 复验抓到的新抖：26-c，2026-09-16）

`team review` 在你分支上红了一条：`26-c 纯文本：TEAM_MONITOR_UI=text 没有走纯文本路径（ESC=0）`。
我直跑复现：同一条红。但**报错信息骗人**——ESC 其实是 0，红的是后半段的 diff：`--print` 与
`UI=text --once` 两次实时执行之间，容量行（RAM 数值/火花线/可再加 N 个）变了（它们实时读 /proc/meminfo）。
你的运行恰好数值没变所以绿。同一个病在前面那组（--print vs 重定向 --once）也存在，只是更难得罪。

修：26-c 里凡是要 diff 两次执行的断言，夹具都钉 `TEAM_MEMINFO_FILE`（指向你造的固定 meminfo）——
容量守卫的测试钩子本来就在。另外把断言的失败信息改诚实：把「ESC 不符」和「内容 diff 不符」分开报
（现在两条混在一条 else 里，误导了我十分钟）。

证据：钉住后该段连跑 ≥10 次全绿 + 放开钩子变回抖（翻转一次即可）。
