# P428 · 确定性测试替代：只探索一个样本

## 结论先行

本任务只回答“哪一个重测试组值得先改、怎样改才能删掉旧路径而不丢覆盖”。**只写报告，不改产品、测试、规格或 CI。**

依据是用户采纳的研究候选 D。不是再做一次测试瘦身总方案，也不是给现有重型测试旁边另加一套快速测试。

- 研究文档：`docs/team/research/dsh-superagent-reference-study-2026-11-05.md` 第 7 节。

## 要做的

1. **只选一个样本组。** 优先从 `36` 或 `51m` 中选；若证据表明它们都不适合，可选 `61b` 的一个明确子组，并说明为什么不重复 P398。
   选择依据必须是现有日志和源码，不为本任务重跑全量或变异矩阵。
2. 说清这个组验证的**产品行为或测试判据**是什么，时间实际花在哪类工作上。
3. 画清边界：哪些结果只由状态、输入、时间或文件内容决定，可以确定性验证；哪些涉及真实 Pi、tmux、进程身份或窗口行为，**必须保留真实接口测试**。
4. 给出一个最小替代设计，并**点名可删除或停止执行旧重型路径的具体文件、函数、循环或命令**。只新增快速路径而保留全部旧执行，不算本任务成功。
5. 给覆盖映射：现有每个关键判据由什么保留；至少一个“改坏后仍必须按名变红”的反例；样本迁移前后检查的是同一项行为。
6. 用已有日志给出成本账，区分实测与估算。性能数字只作参考，不设性能门禁。
7. 写清最小后续 OpenSpec 提案需要包含什么，以及独立复验者应重跑哪些短命令。
