# M5.3 · Make "every requirement has a falsifiable scenario" a real invariant

```
task:   M5.3
```

> The PM measured what `openspec validate --all --strict` actually enforces, and it is weaker than the project rule:
> deleting a scenario's `THEN`, or deleting the whole scenario (leaving a requirement without any scenario), still
> validates green (`config.yaml`'s `rules` tell the *author* to write scenarios; nothing checks it). This task adds the
> missing check so the gate cannot pass with an unfalsifiable spec.

## Deliverable 1 — a checker, owned by the project

Add a small, dependency-free checker that fails when a capability spec violates the project's spec rules:

- every `### Requirement:` block must contain **at least one** `#### Scenario:` block;
- every scenario must contain at least one `- **WHEN** …` (or `- WHEN …`) line **and** at least one then-line
  (`THEN` / `AND`) — an assertion without a trigger, or a trigger without an assertion, is not a scenario;
- scenario text must not be an empty placeholder (e.g. `THEN it works`);
- requirements/spec files with no content (`spec.md` that is only a heading) fail;
- the checker takes the spec root (`$TEAM_SPEC_DIR`, default `openspec`) and validates `specs/*/spec.md`
  (changes under `openspec/changes/**` are *proposals*: check that each change directory has a `specs/` delta or a
  `tasks.md`/`proposal.md`, and that its deltas follow the same requirement/scenario rules — keep this part tolerant
  if the tool's own CLI already covers it).

Where it lives: prefer a tiny script under `skills/teamsmith/scripts/` (bash or node — pick one, state why) so it is
runnable as `bash skills/teamsmith/scripts/team ...`? **No**: do not grow the `team` CLI surface for this. Ship it as
`skills/teamsmith/tests/spec-lint.sh` (or `.mjs`) and call it from the smoke suite **and** document it in
`references/openspec.md` as the project-level companion to `openspec validate`.

## Deliverable 2 — wire it into the gates

- `TEAM_GATES` in `.pi/team/config.sh` becomes
  `openspec validate --all --strict && bash skills/teamsmith/tests/spec-lint.sh && bash skills/teamsmith/tests/smoke.sh`
  (spec lint is milliseconds; keep the order fast→slow). Update the doc that lists the gate command.
- The smoke suite gains a section that asserts the lint **can fail**: build a broken spec inside a scratch copy
  (delete a scenario's `THEN`, delete a whole scenario, empty spec) and assert the lint exits non-zero for each, then
  assert the real `openspec/` tree passes. Flip-tested in both directions, as usual.

## Deliverable 3 — the specs themselves must satisfy it

Run the new lint over this repo's real specs and fix anything it flags (the PM's audit suggests they are already in
good shape — 45 requirements / 77 scenarios — but do not assume: run it). If a requirement genuinely cannot have a
falsifiable scenario, do **not** invent one: move that statement to `references/**` prose and say so in your report
(this is the rule `openspec/config.yaml`'s `rules` already states).
