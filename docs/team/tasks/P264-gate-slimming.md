## 规则（要逐条判定，不许一刀切）

**留（逻辑类）**＝用户能观察到的**行为与状态**：命令是否接受某旗标、退出码、副作用（写了哪个文件、起了哪个进程）、拒绝是否发生、状态是否恢复、字节一致的机器输出；以及「承诺兑现」类（帮助里的用法行必须被真解析器接受、帮助里没有夹具兑现的承诺不许写）。
**拿掉（文本类）**＝**措辞、排版、语言、术语、概念定义的呈现**：一句帮助/提示/文案必须含哪些词、缩进/行宽/对齐、翻译是否正确、某个概念是否出现在页面上、某种自造词是否禁用。
**边界（重要）**：一条断言**表面上在检查一串字，实际是在代理一个行为**的，算逻辑——例：「渲染出的简报里含通知段」是在验证「简报真的送到席位」（保留）；「这条提示必须写『手改』」是为措辞而立（拿掉）。拿不定主意的**列出来给我裁**，不要自行归类。

## 范围与做法

对象是门禁套件里既有的条目（`tests/smoke.sh` 各段 + `tests/*.sh` 的独立入口 + `tests/routes.sh`），不含产品代码、不改规格（除非你要把一条「文本类」的规格要求按 D170 改写——那样先报我）。

1. **先出分类表（第一步交付物）**：逐段列出每条断言的归类（**留** / **拿掉** / **待定（列给我）**），每条附一句理由与证据指向（断言所在的文件:行）。不许先删再分类。
2. **我复核分类表之后**，你再删：只删我复核后标「拿掉」的；删的同时给每条一个去向（删掉的文本类断言所守护的内容，改由「设计文档 + 评审读最终文本」把关——design/README/`references/` 里若有对应说明，在表里指出来）。
3. **删完跑受影响选段**：`section-select.sh --paths <你改的文件>` 算闭包，跑出的段必须全绿（不许用跳过/删断言换绿）；FAST 与容器各一次，贴结果。
4. **不要削弱**：任何一条断言若被删掉，必须能在分类表里找到它的归类与理由；把「改成宽松」伪装成「瘦身」的一律不许。
