## P14 追加 2（用户界面反馈升级，2026-09-17）：整体视觉语言——卡片边界 + 按钮框

用户原话：「不光是分割线，想卡片的边界，按钮的框之类的都可以包含，界面要美观」。替代前一条追加
（分隔线是它的子集）。视觉规范：

1. **区块 = 卡片**：每个区块有完整边界框，圆角（`╭─ 标题 ──╮` / `╰──╯`，dim 边框色，标题嵌在顶边里）；
   卡片内边距 1 列，卡片间距 1 行/列。焦点卡片（鼠标悬停/键盘选中）边框换强调色。
2. **页脚 = 按钮排**：每个动作是一个"芯片"按钮 `[m 写信] [f 冲刷] [s 待命] [, 设置] [q 收起]`，
   边框或反色区分；鼠标点击目标与按钮视觉边界 1:1（F4 的教训：点击目标必须长在可见元素上）。
3. **页签**：当前页用框/反色标出（`[1 总览]` vs ` 2 工作 `）。
4. **消息输入激活时**：输入行升级成带框输入框（`╭─ 给 PM ─╮ │ ▸ … │ ╰────╯`），焦点态强调色。
5. **降级链（高度/宽度不够时，逐级而不是全毁）**：卡片框 → 只留顶边分隔线（标题嵌线）→ 只留标题行。
   竖屏档默认落在"顶边分隔线"档。紧凑密度默认无框（只有分隔线），舒适密度默认有框。
6. **配色纪律不变**：状态不靠颜色单独表达；边框 dim、内容正常色、焦点/当前页用强调色；
   深浅两套主题各一套对比度达标的调色板。
7. **快照**：四档宽度 × 深浅主题 × 舒适/紧凑，每页一张，逐字节比对；外加"任何一行可视宽度 ≤ 列数"、
   "点击目标全部落在按钮/页签的视觉边界内"两条断言。

## P14 追加 3（用户界面反馈，2026-09-17，截图在案）：会话用量列不许被截

实机截图：agents 表的「会话」列显示 `232k/1…`、`266k/2…`——上下文窗口的余量（`1.0M`/`256k`）被截没了，

1. **会话列定宽保底**：宽度按最宽形态（如 `888k/1.0M ⚠`，含警告标记）+1 列留白计算，任何档位都完整显示；

   才考虑**（实际上永不截；竖屏档宁可砍掉活动列整列也不许截会话列）；
3. 断言：四档宽度下 agents 表的会话值都完整匹配 `^[0-9.]+[kM]/[0-9.]+[kM]( ⚠)?$`（快照里逐字节可见）。

## P14 追加 4（用户界面反馈，2026-09-17，截图在案）：agents 表头与内容错位

实机截图：表头是英文 `state/branch/session`，内容是中文（界面语言是 zh）且状态列内容（`● runni…`）

3. 断言：四档宽度下，表的每一列里"表头单元格"与"数据单元格"的起始列逐行相等（逐列比对）；
   随机内容 fuzz（长分支名/中文任务名/空值）下不出现跨列溢出。
