# P506 · 在项目设置里直接管理标签，不手写配置

用户明确补充：任务标签种类应由项目自定义，普通用户在 Pulse 的「项目设置」操作，不手写配置。先在当前设置面和独立冻结的现有标签候选 `4cbc5bc7` 做只读探索；标签主体 P497/V196 仍停在候选，另由 P505 查键盘，不依赖本任务便可查。后续可并行定方案，必须复用最终通过的标签命令/数据，不能在尚未合入的实现上落代码或改当前设置。

- 建议在「项目设置」只增加一条「任务标签 / Task labels」入口，进入看已有标签并新增、编辑或删除定义；不把整张标签表展开到默认设置列表，不把「给单项任务加标签」混进本次要求。复用现有设置页菜单、列表、表单/保存取消及错误提示；无定义应能直接新增。用简短英文/中文控件文案、操作实例和真实源码入口说明，同时核键盘和鼠标可达性。名称用正常表单字段；颜色优先复用固定调色板或选择控件，权重用直接填数或步进，这是单字段而非手写配置表达式。选色时既有自定义色不得在编辑其他字段时被无声替换。不设计预置标签或另一张高级全表。
- 同一项目标签定义只保留同一真源：名称、颜色、权重和已有任务关系沿用 `team board label` 已审规则；不要把定义复制进 `.pi/team/config.sh` 或偏好页。核现有写入入口能否直接接，项目作用域、非普通任务权限的现有边界、命名冲突、已用标签不可删和修改权重后下一次排序读到新值，不重新决定现有默认/显式排序或允许标签自动影响派单。输入错误用用户语言，不能要求执行命令或手改文件完成正常操作。指出一个已有设置场景如何替换或扩入适用断言，不加新测试套件。
- 交一条首选最小路径和必要的产品取舍，点名现有 `task-labels` 只读 UI 与新变更的衔接以及对原设置精简影响。不要先改旧提案、正式规格或产品、运行 UI、全量或启动模型。只提交 `docs/team/reports/P506-dev2.md`（Git 差异检查和账本检查）；本地留分支、不合并不推送。
