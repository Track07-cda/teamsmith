## 判据（用户 2026-10-16 的第二条澄清，**以这条为准**）

> 「总之就是不希望用户漏掉的回复，希望用户能够看到的回复都要添加。回复 Pulse 的、其他 agent 的不需要算。」

**按读者分类，而不是按话题分类**：

- **属于「给用户看」的回复 → 必须发布**：回答用户的问题、汇报状态与进度、给出结论或裁定、请用户决策、交付与复验的要点摘要——**凡是这条回复是写给用户的，正文就原样发布**（不论长短，也不论话题大小）。
- **不算**：写给 `pulse`/巡检的门控回执、写给其他席位（工人）的派单与协调消息、写给另一个项目 PM 的跨项目消息、以及工具自动生成的回执；这些的读者不是用户。
- **边界判据一句话**：**这条回复的读者是谁**——是用户就必须发布；是系统组件或其他 agent 就不必。

## 现状（我先核过，照这个写）

规则目前写在**三处**：`templates/pm-prompt.md.tmpl`（第 31–35 行：「里程碑落地 / 你做出一项裁定 / 在让用户决策之前」三类触发）、`references/protocol.md` §4b（用法与语义）、`SKILL.md` 的命令表。**触发条件里没有「回答用户的问题」这一类**——短而直接的回答最容易被漏掉，而它们恰恰是用户最想回头找的。

## 要产出什么

一个 OpenSpec change，至少覆盖：

1. **触发条件补齐**：在**三处**把「**直接回答用户提出的问题**」列为**必须发布**的一类（与「里程碑 / 裁定 / 让用户决策之前」并列），并写明判据：**只要这条回复的主要目的是回答用户的一个问题**（无论长短），正文就要**原样**发布到关键回复页，然后在对话里发同一份。
2. **判据要可执行、不靠感觉**：给出「是/不是」的边界（例：对交付与复验的例行回执不算；对「进度怎样」「这个缺陷修了吗」「为什么这样做」这类提问算）。**不要**写成「重要的时候」这种空话。
3. **Pulse 那一侧**（用户说「加到 Pulse 里」）：关键回复页加**一行的说明**（这一页是什么、什么属于它、谁发布），让读者一眼知道这一页是**权威回答**的落点；页面**保持只读**（面板不认聊天流，不能自动检测「用户刚问了什么」——这一条要写成**诚实的边界**，别承诺做不到的自动标记）。
4. **门禁只要「存在性 + 行为」两类**（D170）：① 三处都出现「回答用户的问题」这一类触发（删除或漏写一处 → 红）；② 示例命令必须是当前可用形式（写错 → 红）。**措辞与语气不设断言**。
5. **不变量**：不改 `team reply` 的存储/列表/正文语义、不改面板的只读性质、不改退出码、不新增配置键；不恢复「自称/未经核验」字样（用户已裁定默认信任）。
