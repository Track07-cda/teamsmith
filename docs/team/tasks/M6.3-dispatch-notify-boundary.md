## Findings to fix

### F16 (high) — dispatch never checks the worktree is on **this task's** branch
Reproduction: clean dev worktree on `task/P2-smoke`, then `team dispatch dev P1 <P1 brief>` → exit 0, state records
`branch=task/P2-smoke` for P1, and a later `review P1` can stamp P1 with P2's branch.
Required: compare the worktree's HEAD branch with `team_branch_for_agent <agent> <ID>`; refuse (naming both) unless
they match, or resume the same task (`state task == ID`). Keep the existing refusals (dirty for another task,
protected branch, detached HEAD) intact, and print the exact `git switch` command the PM should run.

### F26 (high) — a worker notification to the PM is invisible when the PM is not running
Reproduction (PM-verified): `team notify pm --from-file <summary>` (the channel `references/agent-adapters.md` and
`templates/config.sh.tmpl` recommend) writes `docs/team/inbox/pm.md`, but `team_pending_counts`, `digest` §[2] and
`team inbox` iterate the **roster** only → “无待办”, and the watchdog never wakes for it. Only the tmux keystroke
delivers, and only while the PM window is running pi.
Required: make `pm` a first-class recipient — count unread lines in `inbox/pm.md` (and any inbox for a name that is
not a roster agent but exists as a file) as pending work, show them in digest §[2] and in `team inbox` (as the PM's
own inbox), and let the watchdog wake on them. Keep the existing dedup and the tmux knock as an *additional* channel,
not the only one.

### F15 (low) — a brief outside the project is accepted and described as "repo-relative"
`team dispatch dev P1 /tmp/outside-brief.md` succeeds and the prompt calls the absolute outside path a
"repo-relative path", while the same prompt orders the worker to stay inside the project.
Required: refuse a brief outside `$TEAM_MAIN_ROOT` (or copy it in first and say so); fix the prompt wording when the
path is not relative.

### F18 (low) — a mis-typed recipient dies silently
`team say devv "…"` writes `inbox/devv.md`, which nothing ever reads: digest/watchdog iterate the roster, so the
message is a dead letter with no visible error.
Required: unknown recipient → non-zero exit and a message naming the roster (or `--any` to force, recorded). A
well-meant typo must not silently lose a message.

### F17 (low) — dedup treats different briefings as duplicates
The extension's key is `agent|summary|last[:60]`, so three distinct settles whose last messages share the first 60
characters collapse into one inbox line.
Required: make the key discriminating (full last message hash, or length+hash), keep the intended suppression of
*repeated identical* settles, and note the behaviour in `references/agent-adapters.md`.

### F27 (medium) — the empty-tmux-target refusal is not centralised
`team_tmux_send_text '' 'x'` really types into the current pane and returns 0 (proven live in V4.0 §90c′), while
`kill-window` / `kill-session` / `respawn-pane` all refuse an empty target. No current caller passes an empty target,
but this is the accident class that killed a PM twice.
Required: move the refusal into `team_tmux_send_text` (and any other tmux wrapper that takes a target) — refuse an
empty/whitespace target with a clear message, and add a smoke assertion that proves it (a probe that must not land).

### F30 (medium, M6.5 follow-up) — startup verification fails for wrapper/script agents

The PM reproduced this while verifying M6.5 (`/tmp/pm-freeze2`): a fake agent that is a shell script ending in
`exec sleep 300` **is** started with the right argv (`--provider … --model … --skill … -c @…/pm-prompt.md`) but
`team_pm_start` then reports

```
✗ PM 启动后 6s 内没在窗口 <sess>:pm 里看到配置的 agent 进程
```

because `team_pm_pane_agent_pid` matches the *process identity* (configured agent binary/argv), and a wrapper that
execs replaces its image. Any `TEAM_AGENT_CMD`/`TEAM_PI_BIN` that is a wrapper script (a common way to pin env vars
or flags) can hit this: the tool then reports a failed start for a PM that is alive.

Required: accept **either** proof —
 (a) the pane's process matches the configured agent binary/argv (keep this), **or**
 (b) the pid captured from the pane immediately after `respawn-pane` (i.e. the process *we* spawned) is alive and
     its cwd is inside this project.
Report which proof was used (`pm.pid` + a `pm.pid.proof=argv|spawn` marker or similar) so `ps`/`roster`/`watchdog`
can show it. Keep the existing pre-start refusal for a foreign process already sitting in the PM window, and keep the
"non-shell is not proof" rule for anything we did not start. Test fixture: a wrapper agent (shell script that
`exec sleep 300`) must be reported as started (proof=spawn), and a foreign `sleep` in the window must still not count.

## Extra deliverable (from the PM): make the OpenSpec step visible in the project protocol templates

Today the skill documents OpenSpec (`SKILL.md`, `references/openspec.md`, `references/workflows.md`, the task/PM
prompt templates) but the **project protocol an agent reads first** does not mention it: grep shows 0 hits for
"openspec" in `templates/AGENTS.section.md.tmpl`, in `templates/PROTOCOL.md.tmpl` and in the rendered
`docs/team/PROTOCOL.md`. A bootstrapped project therefore never learns where the specs live.

Add, in English and matching the existing tone:
- `templates/AGENTS.section.md.tmpl` (the block `bootstrap`/`init` splices into a project's `AGENTS.md`): a short
  "Specs (OpenSpec)" subsection — specs and change proposals live in `openspec/` (required dependency,
  `openspec init --tools none`); before implementing a change read its `openspec/changes/<id>/` proposal and the
  capability spec it touches; `openspec validate --all --strict` is part of the gate; **do not create a parallel
  spec system** in task briefs or docs.
- `templates/PROTOCOL.md.tmpl` (rendered to `docs/team/PROTOCOL.md`): the same rule in one paragraph plus the
  day-to-day commands (`openspec list`, `openspec change show`, `openspec validate --all --strict`,
  `openspec archive -y` after the PM's review record exists), pointing at `references/openspec.md` for detail.
- Keep the marker structure (`<!-- teamsmith:begin/end -->`) intact and the section single — the smoke suite asserts
  that, and re-running `bootstrap` must stay idempotent (it re-renders this block).
