# P507 · 在项目设置增加任务标签入口

P506 `d411b13a` 已接受；沿用 `docs/team/reports/P506-dev2.md`、D271 和已存在的 project settings/标签交互，不重开范围。按 `openspec-propose` 生成 `openspec/changes/project-label-management/` 原生方案、设计、变更规格及任务清单；只写该 change 和本人报告。P497 原版标签与倒序看板接入仍未验过。本方案可与定位并行，但**实施以原标签实现独立验收并合并为前提**；不要改 `task-labels` 或复制它的要求。若 board-and-status 还没有目标要求，明确候选中依赖的原要求标题及将来对齐步骤，不能另造一份并行的定义逻辑；对现有 panel 正式要求给可审的差异。

- 收在「项目设置」的现有入口组，一条 `任务标签 / Task labels` 打开只属于本项目的列表。已有名称、具名常用颜色、数字权重。直接填名称、选择颜色、输入整数，新增/编辑一次保存、取消不写、删除单独确认。既有自定义色可原样保留，不要求写 Hex、配置表达式、文件路径或 CLI。无预置；失败不能报保存成功，坏数据不是无标签。保留目前设置页精简、返回原焦点、键鼠与窄屏，两档文案用普通词。除控件标签、必要错误和删除确认外能少写就少写，不加术语解释或顶级页面。不要把给某项任务贴标签、全表搜索、任意色编辑器、权限或派单功能带进来。
- 列表和写入复用 `team board label` 的同一个项目和定义。不写 `.pi/team/config.sh`、偏好、BOARD 或任务更新时间，不从卡片可选字段猜定义。沿用精确名称、现有的正负整数权重支持（保留全精度、不能用 JS Number 重解释）、改名保留关联、仍在使用时禁止删除。只送实际变化的字段；取消、拒绝后读回状态与草稿，未确认的写入不直接覆盖重试。不新增存储或检查系统。若需提示因重名、非法字段、仍被使用或读写结果不明而不同，只由原命令提供最小结构化结果，不把英文句子或位置当接口，不新增公开子命令。全程用原参数数组传递名称；说明当前同字段并发写入的边界，不为本页建立新的并发架构。成功后得到写入之后的当前标签与看板结果，而不是复用写入之前未完成的读取；以最小现有刷新方式做到，不新增周期查询。默认最近更新、显式权重排序、同分原表序照旧。
- 保留设置精简的已有约定，示例只从三类任务的 10 个可选项变 11，旧设置条目不动。用一个现有 `panel-p21.sh` settings 场景收拢新增检查，先确定具体选择方式及应替换的通用导航断言；在同一私有项目演示不写配置、空表新增、改权重保留色、取消、已用标签拒删和返回，选择最少可证业务差异的真实操作。设置已有编辑/命令/模型记录的有效检查不丢；不抄旧算分、CLI 全量、提醒或看板验证，不加测试框架或跑产品。
