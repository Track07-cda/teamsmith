## 0 · 先说结论（一句话版）

提案把「三次完整 walk」换成「同一份文件判定 + 两次真实单页渲染 + 两次正常对照」，方向对、规模对、delta 也守住了既有场景（见 §5.2）。但当前设计里**替代用例直接调用库里的原语**，而让 `walk` 变红的记账（`finding`/`FIND`）留在走查里 —— 删掉三臂之后，「坏页面会让走查变红」这件事在套件里没有任何证据了（M1）；而且**这套替代用例只在二阶段（§51m）里跑**，提案给的验收命令一条也没执行它，同时它要的独立短入口在 `routes.sh` 无主入口守卫的前提下会复制一整套脚手架（M2）。这两条合起来正是这次改动最怕的形状：**证据被换掉了，但新证据从没在门禁路径上跑过**。

## 1 · 必修项

### M1（必修）替代用例绕过了「页面失败 → 走查变红」的接线，删掉的恰好是这条接线的唯一证据

**证据。** `mr_walk_a` 里让页面内容变红的是三步：逐页 `finding`（`routes.sh:570`、`574`、`581`、`585`、`594`、`604`、`613`）→ `level_fail=1`（同处）→ `622` 把 `level_fail` 汇成 `failed=1`，最后 `639` 才 `return 1`。而 `routes.sh` **根本不用函数的返回码判红**：底部装载是 `if mr_walk_a; then :; fi`（`1972-1974`），红不红只看 `FIND` 计数（`1995-1996`）。设计 §1 的操作表里，库里的操作只承诺「failure status + line diagnostics」，`ok`/`finding` 仍由调用方发 —— 于是两件事同时没了证据：库操作返回失败但走查没发 finding（或没记 `failed`），走查照样绿；而替代用例断言的是库操作的返回，也照样绿。

**反例（可构造，一行）。** 抽取后把 `mr_walk_a` 的逐页判定改成 `mr_judge_page … || true`（或把返回值存进一个没人读的变量）。此时：`team help board` 的列 0 行、`dispatch --ghost-probe` 的多余用法、组级缺页都只在库操作里返回非零，**不发 finding**；`routes.sh walk` 的 `FIND` 仍是 0 → §51 绿；替代用例断言「库操作返回非零」→ §51m 绿（`mr_flips` 的 `ok` 只看用例自己的判据）。全套没有任何一条变红。

**最小修法。**
1. 让「逐页判定 + `ok`/`finding` 记账 + 返回状态」**整体**成为共享操作（不是只把解析原语交出去）；④/⑪ 的用例调用**这一个**函数处理自己的单页输出，所以它断言的失败文本就是共享代码发出的文本。
2. 走查侧只保留两个调用点（逐页判定一次、层级收口一次），把「调用点没把失败转成 `failed=1`」明写为**审查项**（一行 diff 能看住），不声称有测试覆盖它 —— 在「不跑完整 walk」的边界下，这条接线本来就没有便宜的观测点。
3. 在 `design.md` 里把这条残余写进 Risks（现在只写了「findings 不能变成没人理的返回码」，没说它由谁证明）。

### M2（必修）替代用例只在二阶段里跑，验收命令从不执行它；独立的短入口会复制整套脚手架

**证据。**
- `§51` 跑的是 `routes.sh walk control promises refusals`（`smoke.sh:23067`），`§51m` 跑的是 `flips`（`smoke.sh:23120`），而 `§51m` 被 `smoke_meta_begin "51m"` 包着（`smoke.sh:23117`）：默认不跑，只打 `SKIP（二阶 · 默认不跑）`（`smoke.sh:1041`）。`section-select.sh --floor` 里没有 `51m`（实跑：0 命中），`--meta` 里才有；FAST 下 `routes.sh` 自己也会 `skip "flips（FAST 模式…"`（`routes.sh:1988`）。
- 提案给的验收命令是 `bash tests/routes-pages.sh` 与 `bash routes.sh walk control promises refusals`（design「Verification and migration plan」）。**这两条都不进 `mr_flips`**。也就是说：三条臂被改写的那些断言/用例名一旦写错，交付时没有任何命令会跑到它，只能等下一次夜间 meta。
- 独立短入口的代价：`routes.sh` 没有主入口守卫（`set -uo pipefail` 在 `62` 行，环境清理/临时根/trap/计数/`SHIM` 在 `62-190`，全部顶层执行）。一个独立 `tests/routes-pages.sh` 要用 `mr_scratch_tree`（`1553`）、`mr_flip_landed`（`1611`）、`mr_flip_require`（`1634`）就必须复刻或搬走 `62-190` 的脚手架；design §3 只说「reuse the existing scratch-copy/landing-evidence support」，没说这些函数搬到哪 —— 这正是它自己在 Risks 里写的「copied checker would self-confirm」。

**最小修法（推荐）。** 把这份样本做成**同一个脚本里的段**：`bash skills/teamsmith/tests/routes.sh pages`（判定的库仍在 `tests/lib/routes-pages.sh`）。共享的临时根、`SHIM`、计数器、清理、`mr_scratch_tree`/`mr_flip_landed` 全部现成；`mr_flips` 用与其它嵌套臂相同的环境纪律调用 `bash "$here/routes.sh" pages`，断言 rc=0 与三条具名用例行；验收跑**同一条命令**。结果：同一份字节既是门禁路径也是验收路径，不新增入口、不新增脚手架、不新增门禁段，选择策略不变（显式参数，不加进默认段集）。
若坚持独立脚本：`mr_flips` 必须以**子进程**调用它（不是 source），两个调用方的环境由库统一；否则两套环境必然漂移。
同时补一条非空洞判据：入口打印每条具名用例行，用例数少于 3 就非零退出；`mr_flips` 的替代臂**无条件执行**（不许 `if [ -f … ]` 这种可静默跳过的形状），缺脚本就发 finding —— 现成的样板是 `mr_control` 的「控制臂没有扫到任何路径」（`routes.sh:668`）。

### M3（必修）「按名变红」不足以钉住诊断来源，⑪ 可以被遗留的字面量检查冒充

**证据。** `dispatch` 命令页现在有**两条独立诊断**：集合差（`routes.sh:575-582`，输出 `页与清单不一致（页上多出：…）`）和字面量检查（`584-587`，输出 `打印了清单没有的旗标（… --ghost-probe…）`）。两条都点名 `dispatch` 与 `ghost-probe`，而 delta 的场景只要求「fails naming `dispatch` and the extra usage」。

**反例。** 抽取时只保留字面量检查、删掉集合差：`⑪` 的用例仍然「按名变红」（`dispatch`、`ghost-probe` 都在文本里），测试照样绿 —— 但被删掉的正是这条控制要守的规则（页面用法集合 = 清单用法集合），只剩一个特例字面量。`④` 同理：列 0 行会被 `mr_page_usage` 跳过（`489-505`），该页的集合比较**是相等的**，所以 `④` 的失败只能来自解析归属（`397`），用例必须断言这一条文本，不能只断言「失败了」。`⑬` 的坏样本还必须证明它**只因 group 失败**：菜单页/命令页要各自通过同一份逐页判定，否则一个写坏的菜单页会让用例「红得对不上原因」。

**最小修法。** 三条用例各自断言：(a) 具体诊断短语（`列 0 的行` / `页与清单不一致` + `多出` + `dispatch --ghost-probe` / `group 这一级一条都没被判到`）；(b) 正常或还原输入通过且**不发任何 finding**；(c) 打印一行点名被替代的旧臂（`替代④`/`替代⑪`/`替代⑬`），让 §4 的退休映射可以从日志里 grep 出来。`tasks 3.1` 的第二个改坏方向要明确成「删掉集合差」，并断言用例**因为这个**变红。

### M4（必修）verification delta 的计数条款没有可观测对象：它所在的场景跑 FAST，而 §51m 在 FAST 与默认下都不执行

**证据。** delta 的 `The internal checkout loses no existing coverage` 场景是「identical tools and **FAST** settings」+「`TEAM_SMOKE_FAST=1 bash …/smoke.sh`」，但 FAST 下 `routes.sh` 直接跳过 flips（`1988`），`§51m` 连段体都不进（`23117`）。所以「in the affected section, the evidence identifies precisely the three retired executions…」这一句，用这个场景自己的运行设置产生不出来。
另一半：在 smoke 的计数里 `§51m` 只有一行 —— 跑起来是 1 条 `ok`（`23122`，内部的 `✓` 数只印在消息里、不断言），不跑是 1 条 `SKIP`。所以「affected-section pass count」改前改后都是 1，`a lower affected-section count is allowed only…` 这条限定绑定不到任何东西；真正会变的是 `routes.sh` 自己那行 `== 结果 == ✓ N ✗ M` 和逐用例清单。

**最小修法（两句话的改动）。** ①在 delta 里把计数对象定义清楚：「§51m 消息里报告的 routes.sh `✓/✗` 总数 + 逐用例具名清单」，而不是 smoke 的段计数；②在该场景（或新增一句）点名产生前后读数的运行：改前用 M5 里的一条旧臂回执或保留的 51m 记录，改后用 `routes.sh pages`（或 `bash routes.sh flips` 的非 FAST 运行），并写明 FAST 运不产生这份证据。

### M5（必修 · 比例性）一次性 baseline 副本比它要证的事实重，而且它本身变成第二份要被人审「没改坏」的测试代码

**证据。** design §4 + `tasks 1.1` 要求造一份「只保留三段原样臂」的 routes.sh 一次性副本，保存最小 diff，并由独立审阅者确认「baseline bodies and invoked walk remain unchanged」。这实质上是一个一次性选择器（构建 + 评审两道成本），执行面是三次完整 walk（56+56+48 次渲染 + 3 次夹具初始化 + 3 轮 CLAIM）。
而它要证的东西可以静态得到：三条旧臂的**父级断言各自只有一行** `ok`（`1779`、`1923`、`1942`），段内没有别的 `PASS` 增长；嵌套 walk 的断言从不进父级计数（`mr_flip_run` 只存 rc 与日志，`1568-1583`）；运行级基线已有保留记录（`51m` 段 18 通过 / 1 可见跳过，P428 报告 §1 引用夜间日志 L308）。

**最小修法（更简单、同样可证伪）。**
1. **改前只手工复现一条臂**（推荐 ⑪：它的红在聚合日志里看不到，且要点两个名字）：`cp -a` 一份 skill 树 → 用 `routes.sh:1910-1919` 原样 python 片段落变异 → `bash routes.sh walk` → 断言 rc≠0 且日志里有两个名。**不改任何测试源码**，于是没有「副本是否被改坏」的评审义务。
2. ④/⑬ 的改前身份/计数用 `1779`/`1942` 的源码行 + 一行说明（各 1 条父级 `ok`），标明「按源码计，不重跑」。
3. 退休执行量用结构算术：56+56+48 次渲染、3 次夹具初始化、3 轮 CLAIM；标明这是结构不是秒数。
4. 改后照 design 已有的：短入口逐用例清单 + 一次 `routes.sh walk control promises refusals` 前后对照。
如果 PM 要求三臂都实测，就手工复现三条（3 次 walk）——仍然没有改过的测试文件，也没有最小 diff 评审。相应地把 delta 里「comparable pre-change and post-change runs of the three route-page controls」收窄成「改前逐臂断言身份 + 保留的段记录 + 至少一条臂的实际回执」。

## 3 · 任务书七问逐条回答

1. **④⑪⑬ 是否真的删掉三次完整 `walk`。** 计划是删（无夜间/备用/新入口保留）。源码里 `mr_flip_run "$s" walk` 共 5 处：①`1697`、②`1708`、④`1777`、⑪`1921`、⑬`1940`，删后剩 ①②。注意两件事：①**「完整 walk」在 `51m` 里不止三条** —— ③`1758`、⑩`1902` 用 `walk control`（同样跑完整 `mr_walk_a`），⑧`1850` 还有一次裸 `walk`，所以准确的账是 **8 → 5**，delta 的场景把范围限定在「these three controls」是正确的，报告别写成「段内不再有完整 walk」。②删除后真实 renderer、页面枚举与真实 CLI 行为的证据仍在：`§51` 的 `walk control promises refusals` 逐页渲染 + 逐条 CLAIM 未动；①②仍保留「变异 → 完整 nested walk 红」这条机制。**缺的是「坏页面 → 走查红」这条**（M1）。
2. **共享判定是否只有一份、会不会各自演化。** 规则本身不会：设计是「搬」不是「抄」，awk 生成器与清单解析共用一份。两处仍可能分化：①文件样本用的是测试自带的小清单/小页面，生产清单形状变了文件样本可以照样绿 —— 这只能靠 `1.1/3.2` 的**一次性**清单比对（要写明它是一次读取，不是常驻断言）；②抽取边界如果只搬「解析原语」而把记账留在走查里，文件样本与真实走查就不是同一套规则（M1、N3）。
3. **两个 damaged + 两个 normal 够不够防「手写文本自证」；缺失/空文件、renderer 失败与内容失败是否区分。** 够 —— 前提是三条都落实：正常页来自未变异树（N5）、渲染查 rc 与非空（N2）、失败必须是**指定**诊断（M3）。「缺失/空文件 ≠ 页面判过」「renderer 失败/超时不能冒充内容失败」在 delta 与设计操作表里已写明，保持 `570` 的语义即可。
4. **verification 的例外是否严格限于这三项；计数会不会掩盖丢失的覆盖。** 例外文字严格限于三项（dispatch +4、verification +2 个场景，见 §5.2 的 diff 回执），其余既有断言与计数义务逐字保留。计数的问题在**可观测性**（M4），不是范围；而「总数变高但某条旧义务消失」这个方向，需要靠 M3 的「每条用例点名被替代的旧臂」+ `3.2` 的清单比对才查得出来。
5. **比例性。** 按现在的写法不成比例（M5）：一次性副本 + 最小 diff + 评审「没改坏」这三样，都比它要证的事实重，而且它自己就是一份测试代码。替代配方见 M5；四个渲染与两个正常对照**一条都不省**（它们是这次交付里唯一证明「真实 renderer 仍然接入」的东西）。
6. **`tests/routes-pages.sh` 双用途会不会重复执行/变成新框架/和旧臂叠加。** 门禁里不会重复（只要不把它加成门禁段，`mr_flips` 只到一次）。真正的风险是反的：它是第二份入口与第二套脚手架（`routes.sh` 没有主入口守卫），而且门禁路径（`mr_flips`）不在验收命令里（M2）。改成同一脚本的一个段就同时消掉这两点：一个函数、一个入口、一套环境。
7. **任务清单能否直接交给实施者；验收命令是否真实；是否误要求全量/61b。** 大体可以：`bash -n`、`section-select.sh --check`、`routes.sh walk control promises refusals` 都存在，`tests/routes-pages.sh` 在 design 里明确标为未来产物，`3.2` 明确把全量/完整变异矩阵/`36`/`61b` 列为**不跑** —— 没有误要求全量。两处缺口：`1.1` 没有可执行命令（N4），验收不执行 `mr_flips` 路径（M2）；`3.3` 的独立复验同样要跑**同一个**集成入口，否则会继承同一个缺口。
