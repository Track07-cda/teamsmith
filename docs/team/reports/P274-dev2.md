## 摘命名空间的集合：只取「可能启动 server」的那族动词

规范（`specs/pm-lifecycle` 的 ADDED requirement）写的是「**可能启动 server 的那个客户端**必须在没有命名
空间的环境里运行」。所以我只对 `new*`/`split*`/`respawn*`/`start*`（含 tmux 的别名与无歧义缩写）摘掉
`TEAM_*`；其余动词（kill 类、只读类、set 类）**保留**环境。

design §1 的第三个 bullet 曾把只读动词也一并摘掉写作「无所谓的简单规则」。我按那条实现后 **§31c 四条红**
（见下面「自己踩到又修掉的回归」），因此按规范原文收窄：只读动词保留环境，因为

1. §31c ⑪/⑫ 的既有契约要求 CLI 的 tmux 子进程**看得见** `TEAM_SESSION`/`TEAM_ROOT`（`teardown`/`close`/
   `pulse down` 的窗口清理依赖它），而任务书明令这些断言必须仍绿；
2. 只读动词**不可能**启动 server：空 socket 上 `tmux list-windows` 直接报错退出（rc≠0）且**不留 socket**
   —— 夹具 ①f 把这条事实钉成断言；没有 server 就没有可被污染的全局环境。

design 那句「简单规则」因此需要在归档前改成「只摘可能启动 server 的动词」（一句），**我没有动 change 目录**
（写集外），留给 PM。

## Decisions

1. **摘身份的集合 = 可能启动 server 的动词**（`new*`/`split*`/`respawn*`/`start*`，含别名与无歧义缩写），
   而不是「除 kill 类以外全摘」：前者是规范原文，后者被 §31c ⑪/⑫ 证伪（详见上文回归段）。
2. **`kill*` 保留身份**：M67 闸门的 `allowed-owned` 判定绑在 `TEAM_SESSION`/`TEAM_ROOT` 与 cwd 的关系上，
   而 kill 类不可能启动 server。
3. **`-e` 写在 `team_tmux_ensure_session`**（唯一建 session 的入口），只在值非空时追加，空值时 argv 与历史
   一致；本机 tmux 3.7b 实测正常。
4. **A1 的 fallback 放在 shim**（而非每个调用点显式传 pin）：shim 是闸门本体，pin 在不在它都经手；向上找
   `.pi/team` 只做 `[ -d ]` 测试（热路径，不启子进程）。解析不出就不写 —— **可见的例外**，不是静默丢。
5. **夹具不碰默认 socket**：③ 的 `allowed-owned` 判定按默认 socket 形状算（`-u TMUX_TMPDIR`），执行的
   「真身」是 PATH 上的 stub，故真 server 零接触。
