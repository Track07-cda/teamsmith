## 机制（两条机制实测）

### 1. 归属：表头 `# ledger-scan: 60 docs/team/*`

`docs/*` 是豁免类（「门禁不为记账文档开火」），而 `--check` ④ 的老规矩是**豁免类不许任何行在 patterns 列
声明**。所以账本路径的归属写在表头一行，而不是 patterns 列：

```
# exempt: docs/*
# ledger-scan: 60 docs/team/*
```

`--paths` 的认领顺序：patterns 列逐行 → 表头的账本归属模式 → 豁免类（NONE）→ 兜底（FULL）。
9 个账本样例逐条对照（`logs/selector-paths.out`）：

| 路径 | 改动前（`048a0c2`） | 本 tip |
|---|---|---|
| `docs/team/reports/P239-dev3.md` | `NONE`「团队账本，门禁不为它开火」 | `RUN` + `reason=60 ← …` |
| `docs/team/reviews/V9.md`、`tasks/T9.md`、`threads/dev.md`、`inbox/dev.md`、`BOARD.md` | `NONE` | `RUN` + `reason=60` |
| `docs/NOTES.md`、`docs/README.md`（非账本 docs） | `NONE` | `NONE`（豁免类没被拆掉） |
| `notes.txt`（没有行声明、也不在豁免类） | `FULL` | `FULL` |

运行集只有**前导段 + §60**（`--paths docs/team/reports/P239-dev3.md` → `0 0b 0c 0d 60`），不是整套门禁。

为什么不用更短的那条路（把 `docs/team/**` 写进 §60 的 patterns 列）：那样必须把 `--check` ④ 从
「豁免类不许任何行声明」放宽成「除声明过的账本行以外不许」，等于动一条既有断言。表头方案对既有检查
**0 放宽**，只增不断：`--check` 现在是 `ok 8 bad 0 SKIP 1`（第七项是新增的账本归属检查）。

`--check` ⑦ 的四种腐烂都当场点名（`logs/selector-check.out` + §36① 的两条新翻转）：

```
bad: 映射表缺 ledger-scan 头（账本路径没有归属声明处）
bad: ledger-scan 归属模式没有覆盖 docs/team/reports/X.md（改这个路径不会选中它）
```

### 3. 报告模板的固定验收行（`023d85c`）

`skills/teamsmith/templates/report.md.tmpl` 的「Verification evidence」小节里加的是：

```
- Ledger ban (fixed acceptance line — run it **in your own worktree, on your branch's tree**):

  $ bash skills/teamsmith/tests/ledger-ban.sh --names-file "$(git rev-parse --path-format=absolute --git-common-dir)/../.pi/team/forbidden-names.txt"
  ledger-ban: root=… scope=published files=<n> hits=<n> names=ok user=resolved
  $ echo $?
  <rc>

  Paste the real `hits=` and `rc` from this tree. **Running it in the main checkout cannot see files that exist
  only on your branch** (a report you just wrote is simply absent there), so a `hits=0` from the main
  checkout is not evidence that the branch's own ledger is clean.
```

`--names-file` 指到清单那一份（`.pi/team/forbidden-names.txt` 被 .gitignore 挡住、不进任何克隆），否则在
干净克隆里 peer-name 形状会以 `names=missing` **可见跳过**——跳过不是通过，所以固定行带着名单路径。
