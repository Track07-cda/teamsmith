## 1 · 修：读 environ 的失败落成 rc≠0，内核/shell 的报错一个字都不上流

`[ -r "$f" ]`（`access(2)`）与真正的 open/read 不是同一道门。容器 `--pid=host` 下实测一次全扫：

```
$ (容器) for d in /proc/[0-9]*; do [ -r "$d/environ" ] && n=$((n+1)); (tr '\0' '\n' < "$d/environ") >/dev/null 2>&1 || denied=$((denied+1)); done
access_readable=600  read_denied_despite_access=599  example=1014175
```

宿主上也有同形状的进程（非 dumpable 的同 uid 进程，例如 `pid 424`）—— 所以这不是容器独有的洞，容器只是
把它放大到 599/600。

改法（`5291c827`，只动这一处）：

```diff
 team_orphan_read_environ() { # <pid> → 环境文本；读不到 → 非 0
   local f
   f="$(team_orphan_proc_dir "${1:-}")/environ"
   [ -r "$f" ] || return 1
-  tr '\0' '\n' < "$f" || return 1
+  # P366：…读放在子 shell 里、把内核/shell 的报错收进**这条判定本身**：读不到 → rc≠0（身份未知，
+  # 调用方跳过、不猜身份），stdout/stderr 一个字节都不多；读得到时 stdout 与改动前逐字节相同…
+  ( tr '\0' '\n' < "$f" ) 2>/dev/null || return 1
   return 0
 }
```

三个要求逐条对上：① 读不到时 stdout/stderr 各 0 字节（下面两行读数）；② 返回值仍非 0 → 调用方
`envtext="$(team_orphan_read_environ "$pid")" || return 1` 照旧跳过、不点名；③ 读得到时逐字节不变
（同一进程内对照 200 个 pid + 内容面）。
