   （一个 delta 一个任务，天然满足 delta 单写者）。
2. **兜底类别名取 `default`（任务书建议），不取被吸收 P253 文字里的 `code`**：理由写在 proposal 待裁点 2——
   `default` 不假装映射有回退语义；撞名一律拒绝、绝不换名；两处共用同一张推导表。这是与 P253 原文的唯一口径差。
3. **`init`/`bootstrap` 不自动迁移**（任务书让我评估）：保持「`init --force`/`bootstrap` 不是迁移路径」的既有
   承诺，它们拒绝时同时点名 `team up` 与手工事务。理由与替代方案在 design §9、待裁点 5。
4. **`--print` 在旧配置项目上按「预告 + 退 0」**，不打印基于未迁移值的启动命令（不做 guard 投影开关）。
   待裁点 7 给了另一条路及其代价。
5. **自动迁移不受 `--yes`/`TEAM_CONFIRM_WRITES` 约束**（只写本项目自己的配置、先备份、原子、审计、可
   `--no-migrate` 退出）；`TEAM_CONFIRM_WRITES` 的既有语义是远端/共享状态。待裁点 4。
6. **文档面比任务书列的更大一点**：除 `references/migration.md`，还有四处写着「只能走 `team config
   upgrade-models`」的文本会与新行为矛盾（`skills/teamsmith-init/SKILL.md`、`.../references/bootstrap.md`、
   `references/config.md`、`references/workflows.md`），已列进 Impact 与 `tasks.md` §5.2；完整升级 runbook
   仍留给 P255。
7. **「哪些会话用旧版本启动」这一条不做**：今天没有任何按会话记版本的地方（`state/pm-loaded.env` 只是 PM 自己
