## Decisions and deviations

1. **判据落在 `team_change_readiness`（唯一一处），不新开第二套**：`team change status`、归档任务 done、
   digest/面板读的都是它 → 视图与闸门不可能漂开（这正是 P24 设计 §6 的"就绪判据只有这一处"）。
2. **归档拷贝回落**（brief 没点名，但真实时序要求）：PM 归档后活动目录消失，归档任务 done 才跑 ——
   只读活动目录会让第二道闸门永远看不到清单。回落只认 `<archive 路径>/<id>/tasks.md` 或
   `<archive 路径>/<date>-<id>/tasks.md`，不猜别的形状。
3. **只数 `[ ]`，点名前三条**：条数一定给（不静默），逐条点名有界（行宽可控）；`行号「标题」`便于直接跳。
4. **新增四条失锚修复**（上面那一段）：它们就在本包内、且是 P209 翻转对的邻居 —— 留着 4 个 ✗ 会让
   "这个包到底证明了什么"不可读。修复是**重锚**，不是重写语义；`flip-p23.sh` 十对现在全绿。
5. **wording**：文档里写清"清单是 apply 阶段的账，勾选如实归 apply 侧"，并且点名三次同族事故
   （P151 F3 / P175 F3 / P206 F1），让下一个跑归档的人知道这条为什么在。
6. 没有新增 capability / requirement：本 brief 是 `change: -`、`anchor: none (infra)` 的机制修复，
   规格侧没有需要改写的承诺（那条承诺在 `verification` 里已存在：归档前 gate 要绿；清单是它的输入之一）。
