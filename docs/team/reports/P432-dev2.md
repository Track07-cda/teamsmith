### 2.1 成本真正集中在哪

同一份全量日志中，`62/38/51/61/63` 合计 **2914/5080 s＝57.4%**；其中前四项合计 **2687 s＝52.9%**。这五段不是单一行为：例如 §62 有存储正例、九个变异、再嵌套跑一次的缺观测器验证，§51 同时含 routes、完整 help-surface 和重复的配置子组。因此不能按外层 `✓1/✓3` 判断工作很少，也不能把整段时长全记到准备或 renderer 上。

## 3 · 已定位的重复与无效判据

### 3.1 完整故障组被用于证明一个跳过分支（优先 A）

执行链：`smoke §62 → key-replies.sh --all → kr_group_flip`，随后 `kr_group_skip_path` 在 `TEAM_REPLY_NO_PROC_IO=1` 下又调用 `--select bounded,flip`。`flip` 有九臂；只有 `full_scan` 依赖观测器，缺席时 probe 返回 9，其余八臂仍执行各自的坏/恢复树。`flip_probe_no_cursor` 每腿还发布 51 条；`flip_probe_fifo_block` 的坏腿故意等 `timeout 300`。

所以这里不是“同一组有两个必要环境就必须全跑两次”：要证明的差异只有 bounded 读量跳过和 full_scan 具名跳过，其余八臂第二次跑与 `/proc/<pid>/io` 无关。失败分支还以 `bash -x` 再跑整组一次取证（原判定仍失败，不是重试转绿）；这也应随旧嵌套执行退休，保留首轮完整日志即可。

此外，`kr_group_bounded` 在能力检查之前已真实发布 20 条、构造 100000×4096 字节索引并破坏最新槽。缺观测器样本再做这份准备也不是证明“观测器缺席”所需。正常 bounded 中的坏最新/不退回旧标题、权限和实际读量验证全部保留。

### 3.2 同一个帮助入口被重复生成（优先 B）

`help-surface.sh:check_route` 对每个命令比较两次：`help c ↔ c --help`、`help c ↔ c -h`，是 **4 次 CLI**，其中两次 `page en help c` 在同一函数/环境下完全相同。当前 manifest 47 个命令，改成一次取得 canonical 输出再比较两种入口就是 **188→141 次**，三种真实入口一个不减。canonical 留在本次调用的文件里比较，避免 shell 命令替换吞掉尾换行；此处无需跨测试缓存。

同脚本还先为 coverage/invariants 生成英文/中文各 56 页；locale 独立生成“两语言×三组 locale/宽度×56 页”即 336 页。**这两组环境不相同，不能把 448 次页面生成全称为重复。** locale 的 C/C.UTF-8、100/64 格宽度本身就是被验证条件，保留。

`do_flips → flip_case → flip_run → 同脚本 --select coverage` 对局部破坏又生成该树全套页面；此处适合续用 D 的“共享内容判定＋少量真实受损页”。但 `help-surface --flip` 并未由 §51/§51m 的常规命令调用，是显式工具，**不能把它的减少算入每夜 512 s**。claims 的 interrupt 等变异已使用 only-command，不是全部一概重跑。

### 3.3 相同配置子组有两个执行位置（候选 C）

`smoke §33` 无参数运行 `config-cli.sh`；默认组含 `list validate roster`。`smoke §51` 随后又运行同一个脚本的这三个组。同一份全量中这是两次相同断言的执行；不是两份独立 oracle。`routes.sh:mr_promise_roster` 另查的是注册/撤销命令兑现 schema 中的维护承诺，不能因名字也叫 roster 就删除。

建议把这三个组指定给 §51，§33 默认排除它们；`config-cli.sh` 的独立全跑入口仍保留全部组。这样全量由 2→1，单跑 §51/§33 的含义明确；若改变 cmd-config，应保证映射仍选中两段的实际判定。**不建议只删 §51 再加 needs:33**：那会把一个重复子组问题换成单跑 §51 必付完整 §33 的问题。

### 3.4 准备定义依赖被写成整段运行依赖（候选 C）

`smoke.sh` 在 §33 后定义 `P24_ROOT/p24_project/p24_brief/p24_team/...`，12e–12k 复用；表把七段的 needs 都写成 33，理由明确为“helper/夹具由 33 定义”。这些函数与 config-cli 的全套断言没有数据依赖。把定义移到执行前导或一个现有形状的测试助手，只在实际要用时建各自私有项目，可删除这 **7 条 needs 边**；`--select 12e` 等不再为取得函数定义执行 config-cli 全套。全量仍会按正常位置跑 §33，不能把 127 s 当全量净省。

`28→18,26,27`、`38→28`、`63→28,38` 还混有 bundle/测试源/等待助手的真实准备依赖。它们是后续核查对象，不是本轮证明可删除的边；P326 过去删除 58→13c 的依据正是读写依赖而非段名。

### 3.5 相同语义的多个读者，不自动合并

`help-surface.sh:usage_entries/manifest_fragments` 与 `tests/lib/routes-pages.sh` 都读用法块/manifest；前者用于页面与清单对账，后者还承担参数归属、集合差、缺层计数与 finding。它们有重合，但不是可直接相互替换的两个函数。若 B 提取同一条规则，真实路径和文件样本必须调用**同一判定**；不能把独立输入读取也全部换成产品 renderer 的解析器。D/V130 已证明只比一个字面量会漏掉集合差本身。

`key-replies.sh:paths` 同时比较两份 sanitizer 的正则声明哈希和 hostile 输入实际输出；前者只证明实现字面相同，不能证明行为正确。它比缺观测器的重跑便宜得多，适合后续删除字面哈希、由同一输入的实际 CLI/面板输出承担，**不为它单独建 change 或扩展本轮 scope**。

### 3.6 “计数正确”不能冒充“行为正确”

- `kr_group_skip_path` 的 `skips >= 3` 只数 `SKIP`， unrelated skip 可顶数；A 应用三条实际具名理由和结束状态替代它，而不是旁边再加一层。
- smoke §33/§51 的 `grep -c ✓` 仅附在“child rc=0”的说明里，外层并不是只数 ✓ 就过。这是聚合输出，不应误报成假绿；改造前后必须比较子组具名结果，不能只比较外层 `✓1`。
- §14d 的段数、meta-suite 的段收口数是防“根本没执行”的运行完整性检查，作用就是执行记账，不是产品行为断言；保留。
- `help-surface.sh:check_route` 的组页循环会在 finding 后仍打印统一 `ok 每个分组页…`；rc 仍按 FIND 失败，但自述可同时成功/失败。B 内改为只在全组通过后打印该成功行，替换原行，不加新守卫。

## 4 · 四批迁移单元与真实验证底线

下列是候选研究边界，不是新规格或获准实施的验收书。进入 propose 时，把选定批次的行为约定写进现有 OpenSpec capability；不在本报告维护第二份规范。

### A · 关键回复：只验证发生变化的缺观测器分支

- **保留：** 正常 `bounded` 的全部真实文件/内核观察；九个原变异及恢复各一次；缺观测器时不是错误、不是静默通过，而是三个具名诊断加正常结束。现有真实 Pi capture、存储、UI 不变。
- **替换与删除：** 将缺观测器处理本身抽成正常 bounded/full_scan 共同调用的短判定，或在原入口提供仅执行这两条缺席路径的样本。由同一份代码发理由、传播结果；删除 `skip-path` 的完整 `bounded,flip` 子进程及失败后二次整组 trace。不得另复制一份“正确日志”来证明自己。
- **可证明的结构减少：** 九臂中的八个无关变异从“正常环境一次＋缺观测器一次”降为一次，即至少删除八组坏/恢复 probe；其中重复的 FIFO 故意阻塞负例和 no_cursor 的 51 条发布各腿也删除。第二个 100000 槽 bounded 准备退出缺席样本。对依赖观测器的 full_scan 保留一次正常真观察及一次缺席见证。
- **改坏仍红：** 分别去掉缺席诊断、把缺席误算成功、把缺席判成产品错误，具名样本必须失败；令正常 full_scan 真全扫，原内核读量样本仍失败；恢复后正常/缺席都回到各自状态。至少审查两个正常调用点会把结果送到同一退出出口，避免 V130 的“helper 红、父级绿”。
- **最低真实样本：** 原九臂、原 bounded/concurrency/receipts/interrupt、原 reply CLI 与 capture 全保留；本批独立验证只跑受影响正常/缺席子样本及一轮 §62，不重复无关面板全套。
- **风险：** 短样本若只构造日志而不走实际缺席处理，就丢了原证据；如果需要新通用运行框架或产品测试开关，停止该设计。**值得首先提案；没有已测的改后秒数。**

### B · 帮助页：正常入口合并取样，内容变异缩到受影响输入

- **保留：** 每个命令三种真实帮助入口；未知命令/子命令退出码与无副作用；无项目可用；两语言/三 locale-width 组合；claims 的真实写盘/授权/可撤销；§51 routes 全部真实 parser/承诺/修法验证。
- **退休：** 每命令第二个完全相同的 `page en help c`，**47 次**确定可删；局部内容变异的全目录 renderer，逐项改为已取得页面/清单判定＋涉及 renderer 的那一页真调用。先做 group-missing/menu-skips-group 等有直接受影响页的少量样本，不一次改十八个变异。
- **共享判定：** 只提取将被替代的内容规则，正常 coverage 与短样本同调用。保留真实 menu/group/command 的覆盖见证；缺 group 是输入缺层，不可用“文件存在”或默认零 finding 替代。
- **改坏仍红：** 真 `--help` 或 `-h` 返回另一页应失败；关闭组页集合差/缺层 finding，短样本失败；正常页仍过；恢复后回绿。父级必须根据 child rc 与具名结果判定，不只 grep 一个遗留短语。
- **最低真实样本：** `help-surface --select route` 的三入口全枚举、保留完整 locale 组合、受影响的真实受损页和正常页各一次；`routes.sh walk control promises refusals` 不删。D 的 `pages` 仍用原入口，不能重做其脚手架。
- **结构账：** 正常 route 的目标是 188→141，不与 canonical 基线生成混算；变异的总 renderer 量待提案逐条盘点，尚无总节省秒数。**值得提案；显式 --flip 的收益不记进夜间 51m。**

### C · 配置唯一执行位置，移出被借用的准备定义

- **保留：** list/validate/roster、writer/CAS/audit/注入、shape/模型/分组全部具名行为；七个 p24 段的真 CLI、git/worktree 与拒绝不改账本。每个场景仍有自己的可写目录，不共享被上一个场景改过的状态。
- **退休：** 把 list/validate/roster 的 smoke 执行位置收敛到 §51，§33 的 smoke 调用显式跑其余组；删除七条仅为函数定义而指向 33 的 needs。独立 `config-cli.sh` 无参入口仍是全套，不再被两个 smoke 段同时全跑/子跑。
- **改坏仍红：** 分别使 roster 命令成功但不改名单、validate 错误接受、writer 丢注释，仍各由其保留的执行位置报错；去掉 p24 准备的一个必要定义，单选 12e 应失败，恢复后独立单选 12e–12k 都成立。需同时证明从 dirty/missing 前提不能靠别的键补齐。

### D · 模型路由：给纯参数规则一个更小的真实产品调用边界

- **保留：** 31 个同名变异、正常基线/恢复对照；`dispatch/resume/transaction/limits/pm/heal/adopt/updatecheck` 的真 CLI/进程/写盘效果；参数进入实际 Pi 命令那一步的真实接线。
