## What was actually wrong (both flakes are "sample a transition once")

**Target B — §11b3 ⑤ `attempts 行带决策证据（state=…）`.** `make_pm_idle` killed/recreated the PM window,
polled `pane_current_command` until it was a shell, then waited a flat 0.5 s and assumed an empty prompt. A freshly
created pane whose shell is still running a foreground startup command is `unknown:zsh` for `team_pm_state`; the
next `watch --once` records that honestly, and the assertion demands `state=idle`. **Naturally reproduced** (see
below) with the ⑤ tick recording `unknown:zsh`.

**Target A — §11i-D squash heuristic.** The brief suspected a fixed sleep; there is none in that block — the
fixture makes one `digest` call and asserts on it. V3's raw log shows the shape precisely: the fixture's own
`✓ D 夹具：squash 合并进 main` passed, then the digest printed the `领先 main 1` fallback with **well-formed
fields** (no `脏`, no `收尾` line, so `team_git_cols` was fine) and the three squash assertions failed. The old
`✓ D：roster 把 squash 合并与真领先分开显示` was **vacuously true**: the roster legend always contains
`已合并=squash 后的内容已在 main 里`, so it could never notice the digest failure.

## Decisions and deviations

- **§11i-D had no sleep to replace.** The brief said "find the sleeps they ride on"; the real mechanism is a single
  sample of a state that can transiently be wrong. The fix waits for the **digest's own output** (the actual
  condition) with a deadline, prints an ℹ line whenever a retry was needed (so the flake stays visible instead of
  being silently absorbed), and dumps branch tree / main's trees / dirt on timeout.
- **Extra guard fixed in the same fixture** (`d18a460`): the roster assertion was vacuously true; it is now strict.
  This is what made V3's log look self-contradictory (digest failed while "roster found it" passed).
- **`references/troubleshooting.md`**: the brief explicitly allows "a note … if the pattern deserves naming".
  I judged it does (third occurrence of this class) and added one English bullet under §11 "Other known traps".
  It is a PM-owned directory — revert just that commit if unwanted (`git revert a527f3b`).
- **No new failure modes introduced by waiting**: every wait has a deadline and every timeout reports a red with the
  last state/command seen; the assertions themselves were kept wherever they were separate. The flips' *persistent*
  rows above are the proof that a broken implementation still fails.
- **Harness bug fixed, not hidden** (`ddd4795`): the first natural hit was miscounted because `set -o pipefail` +
  `grep -q` makes `sed | grep -q` report 141 when grep exits early; the hunter now scans a clean log file.
- **Deviations from the brief**: none otherwise. Scope stayed `tests/smoke.sh` (+ the authorised doc note).
