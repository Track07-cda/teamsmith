三句话：**变异没有漏抓**（变异树 `RESULT pass=1803 fail=631`、rc=1，红得非常充分），**红的成因只是臂自己的时限**

把预算临时改小之后，超时那条红**点名了臂名与秒数**。

## 1. 改了什么（唯一一处，`task-model-routing.sh` 的 `flip_run`）

```
-    TEAM_ROUTING_TREE=… timeout 900 bash "$here/task-model-routing.sh" --select "$groups" …
-    printf 'CONTROL %s rc=%s log=%s\n' …
+  FLIP_ARM_BUDGET=1800
+  flip_arm_budget_red() { FAIL=$((FAIL+1)); printf 'FAIL flip-%s-arm-budget 臂 %s 用满臂预算 %ss（实跑 %ss）仍未出结果 …\n' …; }
+    started="$(date +%s)"
+    TEAM_ROUTING_TREE=… timeout "$FLIP_ARM_BUDGET" bash "$here/task-model-routing.sh" --select "$groups" …
+    ended="$(date +%s)"
+    printf 'CONTROL %s rc=%s elapsed=%ss budget=%ss log=%s\n' …
+    [ "$rc" != 124 ] || flip_arm_budget_red "$tag" "$((ended - started))"
```

三件事各自对应任务书的一条：

1. **1800 = 实测 × 2。** 注释里写全了依据（变异树 842 s、绿基线 411 s、日期），并明说这条口径与整段 7200 s 相同：
   上界只回答「它没动」，不回答「它慢」。
2. **说明「这是最慢那条臂的上限，不是典型值」。** `flip_run` 只能给所有臂一个值（每条臂跑哪些组由变异体决定，
   耗时差一个量级），所以这行数字被下一个人当成「一条臂的典型耗时」去估总时长就会错——注释里点名了这一点。
3. **超时是点名的红，不再是裸 `rc=124`。** 撞上限时 `flip_arm_budget_red` 打一行
   `FAIL flip-<臂>-arm-budget 臂 <臂> 用满臂预算 1800s（实跑 Ns）仍未出结果 —— 这是「它没跑完」，不是「它红了」`，
   并**计入 `FAIL` 计数**（所以 `RESULT` 与退出码仍然只回答真实失败数，这条红不会被吞）。`CONTROL` 行同时带上
   `elapsed=` 与 `budget=`，事后可用日志本身区分「慢」与「红」。

`smoke.sh` 一条都没动：它数臂用的是 `grep -ac '^CONTROL .*source_restored='`（`smoke.sh:22925`），那行是每条臂
还原后单独打的，与本改动无关；整段的 7200 s 防死等上界也原样保留。

## 3. 变异树（本次要证的）：rc=1，且不是 124，844 s

变异树的造法与 P357 完全相同（`flip_run` 对每条臂就是这套手续）：拷 `scripts references templates extension`
到 scratch、打 `.routing-mutant`、再跑 `tests/lib/model-routing-flips.py <scratch> template-shadow`：

```

  "before": "7abcc32d…", "after": "3ed95685…"}]}

$ TMPDIR=/var/tmp/p358-dev3/tmp TEAM_ROUTING_TREE=/var/tmp/p358-dev3/mut-ts \
    bash skills/teamsmith/tests/task-model-routing.sh --select boundary
RESULT pass=1803 fail=631 selected=boundary      # rc=1（不是 124），844 s（19:43:11 → 19:51:55）
```

`rc=1` 与 `rc=124` 的差别就是本次的全部：**改前**这条臂在满负载机器上会被 `timeout 900` 先切断，于是
`check "flip-template-shadow-red" eq "$FLIP_RC" 1` 拿到 124、判红，而那条红说的是「臂没跑完」；**改后**同一条臂
跑完（844 s / 1800 s = 47 %），变异按名红（`pass=1803 fail=631`），控制断言 `flip-template-shadow-red` 拿到 1、通过。

诚实边界：本轮机器基本空闲（三项串行、无并行门禁），所以 844 s 在**旧**的 900 s 下也能跑完——本机复现不出
那次发布轮的超时。支撑改动的不是「本机超时了」，而是 94 % 对 47 % 的余量差，加上发布那轮整机在跑 134 段
（P357 §3 的原读数）。
