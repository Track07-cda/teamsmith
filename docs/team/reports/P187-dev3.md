## 决定与偏离

1. **「目录在 state 内」用前缀判定（允许目录就是 state 本身、允许 state 内的子目录），不是「必须等于
   `<state>/bg`」**：判据只要求记录留在项目内；把等于当判据会额外拒绝「目录指到 state 内别处」这种
   虽怪但不越界的形态。两侧都取 `realpath`，所以 `/home` 与 `/var/home` 两种拼写、state 目录自身在
   软链下都不算越界（这与 P169 的记录级检查同一口径）。
2. **目录不存在 ≠ 目录越界**：不存在时沿用旧口径（`list` 空视图 rc=0、`stop` 无记录 rc=3），只有解析后
   落在 state 之外（含悬空软链）才 rc=4。理由：新检查的目的是堵越界，不是改变新项目的首次使用体验。
3. **`list` 的越界出口是 rc=4**（而不是「打警告 + 空视图 rc=0」）：brief 要的是读写「同一收口」；
   让读侧静默返回空会让「指向别处」看起来像「没有作业」，而它实际是配置错误。
4. **只动 `cmd-bg.sh` 一个实现文件**：`team-bg.ts` 仍按 `state/bg` 写记录；新检查不改变它的写入路径。
