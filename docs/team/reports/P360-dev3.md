### 2.1 npm 的实测行为改正了任务书里一条预期（且改正了一处判据措辞）

任务书对红侧②的预期是「必须红并点名『指向不是包内』」。**实测不是这样**：`npm i -g` 对**逃出包外**的
bin 目标**直接不建链接、也不打任何 warning**。在私有目录里复现（`/var/tmp/p360/npmprobe`）：

```
=================== bin.pkill = /usr/bin/pkill ===================
added 1 package in 358ms
--- prefix/bin ---
killall -> ../lib/node_modules/teamsmith/skills/teamsmith/scripts/shim/killall
pgrep   -> ../lib/node_modules/teamsmith/skills/teamsmith/scripts/shim/pgrep
pidof   -> ../lib/node_modules/teamsmith/skills/teamsmith/scripts/shim/pidof
team    -> ../lib/node_modules/teamsmith/bin/team.mjs
（没有 pkill 这一行）

=================== bin.pkill = ../../../../../../usr/bin/pkill ===================
added 1 package in 411ms          （同样没有 pkill 这一行）

=================== bin.pkill = ./skills/teamsmith/scripts/shim/signal-gate ===================
added 1 package in 376ms
pkill -> ../lib/node_modules/teamsmith/skills/teamsmith/scripts/shim/signal-gate
```

所以「目标不是包内文件」这个形状，用户看到的症状与 0.3.1 **完全同形**：`prefix/bin` 里没有这个名字，
敲下来落到 `/usr/bin`。这带来两处修改（都在 §3）：

1. 「缺失」那条消息不能把原因断言成「bin 字段没列它」—— 实测里字段列了、npm 只是拒绝链接。改成
   「npm 没为这些名字建链接（bin 字段没列它们，或列的目标不是包内文件）」，事实在前、两种成因并列。
2. 「解析到的不是自己那条 shim」这条分支需要一个**真能到达**的红：npm 会为包内另一个文件建链接（上表第
   三段），所以红侧③用 `signal-gate` 作目标，把这条分支打成红。

## 3 · 我在 PM 的实现上改了什么（三处，各有读数）

PM 的部分（`bin` 补五项、`chk_pack_manifest` 从「恰好一个 bin 键」改成五项、版本六处、CHANGELOG）
**原样留着没回退**。三处改动：

1. **`chk_pack_manifest` 的断言标签**（`install-shape.sh:788`）。PM 把函数语义改成五项，调用处的标签还写着
   「声明面：一个 bin 键（team → bin/team.mjs）」—— 正是本任务要修的那种「宣称与断言不一致」。
   提交 `380f861c`。
2. **`readlink -f` 的 `""` 分支是死代码，而它把悬空链归错类。** PM 的写法
   `resolved="$(readlink -f "$prefix/bin/$t")"; case … "" ) 没有 $t` 里，`readlink -f` 对**不存在的最后一级
   会原样吐出路径**（实测：`readlink -f /var/tmp/p360/rlprobe/bin/pkill` → `/var/tmp/p360/rlprobe/bin/pkill`），
   所以 0.3.1 形状（名字根本不在）永远走不到「没有」那一支 —— 第一次红侧跑出来的就是
   「安装后 prefix/bin/pkill 指向 […/prefix/bin/pkill]，不是这个包里的入口」这句自相矛盾的话；反过来**悬空软链**
   时 `readlink -f` 返回空（rc=1），于是它被报成「bin 字段没列它」。提交 `a856ea71`：先自己判在不在
   （`[ ! -e ] && [ ! -L ]`），再要求解析结果**等于这个包的对应 shim**（两侧都 `readlink -f`，所以指向包内
   另一个文件、指向包外、悬空三种都落进同一支并各自点名）。
3. **缺失与错目标的消息措辞**（§2.1 的两条）。提交 `90942f17`。

三条提交都只动 `skills/teamsmith/tests/install-shape.sh` 一个文件：
`380f861c` 1 行标签、`a856ea71` 判据主体、`90942f17` 一句消息。产品面（`bin` 字段、shim、闸门）一个字节没动。

## 5 · 边界与没测到的

- **registry 一个字节没碰**（发布与 deprecate 归 PM），`npm pack` 只在 `/var/tmp/p360/` 里产出 tgz。
- **没跑全量门禁**：按任务书的写集（`package.json`、`install-shape.sh`、版本六处、CHANGELOG、报告），
  只跑了 `install-shape.sh` 整段（它就是 §39 那一腿的全部内容，115 s）。`smoke.sh` 与 `section-paths.tsv`
  没动。
- **0.3.0/0.3.1 用户的升级路径没实测**：本任务只证明 0.3.2 装出来是对的。旧版本已在 npm 上装不出闸门
  （0.3.0 连 shim 都没有，0.3.1 有 shim 没链接），要用户升到 0.3.2，这一点由 CHANGELOG 与 deprecate 承担。
- **macOS/其它 npm 大版本没测**：`readlink -f`、npm 对逃逸 bin 目标的静默跳过都是在这台机器
  （node v24.19.0 / npm 11.16.0 / Linux）上实测的，别处行为未验证。
