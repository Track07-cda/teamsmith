## 关于 ⑨b 的更正（裁定里那一处假设与实际不符）

裁定说 ⑨b 是「内部树 + 清单里有一条已登记且不在 → 打 SKIP」的正向影子。它不是：`checkout-shape-probe.sh:573` 的 ⑨b 是
**反向控制** —— 内部树 + 合成证据文件**在位**（`docs/team/reports/P222-fixture/pkg/legacy.sh`），断言是
`不以「证据层缺席」为由跳过` 加 `LEGACY …` 打印，即「可裁决时照旧判定」那一侧。改造前**唯一**钉着「打 SKIP」这一侧的是
⑩ po10 的两行（`checkout-shape-probe.sh:746`、`748`，零条清单的树），以及 ⑤b 那条 —— 而 ⑤b 那条命中的其实是 §31 的 M28 那行：
在按探针 mixed 形状搭的私有夹具里跑 `--select 31,58`，那句文案在整份日志里**只出现 1 次**，且那一次是
`SKIP（条件不满足） M28 真树…`，`58 lint` 的 SKIP 行为 0。

所以退役那句许可之后，没有任何断言钉着这条路。按裁定的第二段要求（「保证『至少一条登记且都不在 → 打 SKIP』仍有断言钉着」）
我补了 `po10shadow`：内部树 + 一条落在内部面且不在树里的登记，断言 SKIP 行、证据层文案、整次 run rc=0 三件 —— 即被翻新的
两条断言原文原样保留在真正具备前提的那棵树上。

⑤b 那条与 §31 共用文案的断言我**没有动**（不在授权写集里）。它意味着：探针里 §58「跳过」路径的正向覆盖现在由 `po10shadow`
承担，而 ⑤b 那一条对 §58 其实是同义反复 —— 若要修，把它的期望串改成只在 §31 那行出现的文字（例如带上 `M28 真树`）即可；
