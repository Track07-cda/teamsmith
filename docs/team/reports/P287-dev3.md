## 设计要点（给复核用，完整版在 design.md）

**归属**（brief 第 1 条）：① 工作根与每运行标记带**项目命名空间** `teamsmith-<kind>-<ns>.XXXXXX`
（`ns = <slug>-<hash8>`，与 P122 已写进 run 台账头的 `repo=` 同源：同一个项目的所有 worktree 得同一个 ns）；
② 互斥换到**点开头、同行同目录的机器级伴生锁**（`…/teamsmith-smoke.lock` ⇒ `…/.teamsmith-smoke.lock.machine`），
发布路径原样保留为**兼容声明**（P287 之前的写入者只取它；顺序固定：发布路径 → 伴生锁，所以新旧版本之间仍串行）。
实测 A+C 是这条选择的地基。

**察觉**（brief 第 2 条）：① 取锁时记下**自己持有的那个文件**的身份（`fd` 能读就读 `dev:ino`，否则记路径并如实写
`source=path`）；② 运行期间由**同一个** M33 哨兵（0.2s 轮询、证据在 `$TMP` 之外、一条点名行、安全点停跑、退出码 2）
多看一条前提 —— 伴生锁还在不在、还是不是那个文件；**删 =「已不在」，换 =「已被替换（两个身份）」**，
两种都停跑且绝不给出对代码的判定；发布路径的丢失**只印不停**（互斥完好，丢的只是与旧版本串行）；
③ 等待者改有界轮询，能看出「我等的那把变了」并印两个身份；④ **入场检查**：新运行拿到锁后核对活登记的**身份**，
有活运行记着另一个 inode ⇒ 点名它 + 两个身份 + **不跑套件**（「本套没有运行」）。③④ 与 ② 互补：②让持有者有界时间内停，
④让新来者不加入。**no-unlink 纪律**写进合同：持有者绝不删除/改名自己持有的锁文件（删掉还有等待者阻塞在其 inode 上的
锁文件，正好就是事件那条机制本身）。

**两条红侧 + 反向对照**（brief 第 3 条，设计与翻转旋钮在 proposal tasks §3.3/3.4/3.5/4.2）：① 删锁 ⇒ 有界时间内
点名 + 证据 + 退出码 2 + 无结果行；`--break=no-lock-guard` ⇒ 不点名也不停（红）；② 换锁（unlink+新建 / `mv` 覆盖
两种形状）⇒ 文案是「已被替换」且带两个身份；③ 反向：正常跑与串行两套都不许出现锁身份行、持有者不许删自己持有的锁
（inode 前后相同）；④ 入场检查的 shadow（`--break=no-entry-check`）必须让第二套照跑。**不许**把锁去掉、也**不许**
把「删了锁文件」当成通过（本变更的选择是停止 + 留证据 + 运维重跑，不做自动重取/修复）。

## Decisions and deviations

1. **任务书头部 `change: -`，本任务建了新 change `gate-lock-external-deletion`**：brief 的 1–4 条要的是「新场景走新变更」，
   而 D184 的处置也明说「不塞进 P281 的返修」。change id 与任务书文件名同根（`P287-gate-lock-external-deletion`）。
2. **偏离 brief 括号里的建议一支（D1）**：brief 说「锁文件的名字带项目身份（**或**把锁放进本项目自己的状态目录）」，
   提案裁**都不取**，改「互斥留在机器级、换成点开头的伴生锁」。理由：这把锁保护的是**机器**（一套全量自己就能把 32 核压到
   loadavg 20+，P255 §2.2；协议 §9b-2 与 perf/panel 的负载前提都建立在这条上），按项目名切会让两个项目/两个检出
   静默并发 —— 正是 M23/P255 量过的那族；而「够不着 vs 够得着」的真正判据是**点开头 + 换出平铺家族**（实测 A/C），
   不是项目名。若 PM 仍要「项目级锁」，design §2 的备选 ① 写了要连带改哪些判定（六条 scenario 的方向不变）。
3. **新增 D2（兼容声明）**：发布路径保留、先取它后取伴生锁。不保留就等于在升级窗口里**新开**一个静默并发窗口，
   与本变更目的相反；它的代价（发布路径是命名规则唯一的平铺例外、被删只印不停）如实写进要求与诚实边界。
4. **顺手扩了 `--lint` 的作用域（D6）**：为写 ns 规则必须改这条检查，同时发现**7 个直接落在临时根上的模板**今天

   这条是**发现**，不是 brief 明写的要求；若 PM 裁「只加 ns 规则、不动作用域」，按 proposals D6 的备选执行。

## Findings（不是本变更范围，但复核时值得知道）

1. **性能套件那把锁**（`teamsmith-perf.lock`，同一平铺家族、同一 `$TMPDIR`）有同样的分裂面，而它的后果是
   **静默的错误测量**（两套 perf 互相测量却都报自己的数）—— 比门禁那次更糟。提案按 D4 推荐「一并走同一实现」
   （同一份库的第二个调用点）；若 PM 裁「留给下一批」，这条按 finding 记在报告里。
2. **`review-<ID>` 检出仍在别人的 `rm -rf /tmp/review-*` 射程里**：它是检出、不是活运行，且 P122 已拒绝未证明的候选，
   所以本变更不动它（名字写在 `SKILL.md`/`references/workflows.md`/`references/migration.md` 三处）。
3. **`TMPDIR` 覆盖造成的互斥分裂**（P255 r4/r5 的残留）本变更不关：换了 `TMPDIR` 的运行取的是另一对文件，彼此不可见
   （连察觉都没有）。写进诚实边界，不新增第二个解析规则。
4. **本机平铺家族有 111 个历史条目**（含两把锁文件），本变更不清理它们；只保证**新**的活运行不长在那个形状上
   （历史残留照旧靠 `tmp-hygiene.sh --sweep` 与运维）。
5. **`--status` 今天看不见家族外的平铺模板**（D6 那 3 个）：它们既不是候选也不在清单里，扩大作用域后才会被列出来。
