## 射程与边界（改后）

**纳入**（两侧同源，逐词 argv）：

- 命令链：一次调用里 `;` 分隔的**每个**动词都扫；任一是破坏性 → 整条破坏性，且**逐条**要求目标是本项目自己的
  命名对象（例：`kill-session -t myown ';' killw -t other` 拒绝，`… ';' killw -t myown` 放行）。
- 别名：`killp` = kill-pane、`killw` = kill-window（tmux 命令表的第二列）。
- 前缀：`kill-s` → 有歧义（kill-session + kill-server）→ 按破坏性对待；`kill` 同理；`kill-servers` **不**是破坏性
  （不误伤）。
- 全局位：`-L/-S/-c/-f/-T` 分开写、`-Lx/-Sx` 粘连、组合簇（`-uf /dev/null`）、开关（`-2 -8 -C -D -l -u -v -V -N`）、
  `--`、闸门自己的 `--teamsmith-allow-destructive`；认不出/缺值 → uncertain → 按破坏性对待。
- 套件前置的壳：`tmux …` / `\tmux` / `"tmux"` / `command tmux …` / **`builtin command tmux …`**（P186 F1）。

**仍在射程外**（与 M36/M41 的既有边界一致，本任务不扩大）：绝对路径 `/usr/bin/tmux …`（不经 PATH、也不经壳函数）、
`env tmux …` 或 `bash -c 'tmux …'` 这类子进程（按 PATH 解析，由运行时闸门管）、`$(…)` 里的调用（同理）。这些在
`skills/teamsmith/scripts/lib/tmux-argv.sh` 与 `tests/lib/tmux-iso.sh` 的文件头都写明了。

## 两条设计选择（brief 要求说明）

**`builtin command tmux` 为什么用壳层包装、而不是塞进共享分类器**：`builtin`/`command` 是 **shell 的前缀**，不是 tmux 的
argv —— 分类器只看得到 argv，运行时闸门又是一个**独立进程**（经 PATH 到达），两者都永远看不见这个前缀。能看见它的
只有「与调用同处一个 shell」的那一层，也就是套件里的壳函数（P180 已经为 `command tmux` 这么做过）。所以共享分类器
负责「argv 里有什么动词」，壳层负责「这次调用到底有没有走到 tmux」。运行时侧对应的射程不是壳，而是 PATH：`/usr/bin/tmux`
这类绝对路径绕开 PATH，也就绕开了闸门（既有边界，见上）。

**`kill-s`/`kill` 这类歧义前缀按「破坏性」对待**：tmux 允许无歧义前缀，`kill-s` 同时指向 `kill-session` 与 `kill-server`；
分不清就按危险的那边处理（与 M67 原有的 `ambiguous` 一致，也符合「认不出不装懂」）。私有 socket 上照旧放行，
默认 socket 上要求证明目标是本项目自己的命名对象。

## 留给 PM 的判定点

1. **口径**：`kill-s`/`kill` 这类歧义前缀按「破坏性」对待（默认 socket 上要求证明目标归属，私有 socket 上放行）。
   这与 M67 原有的「多候选 = ambiguous」一致；若希望改成「按最严重的候选处理」，只需动共享文件一处。
2. **`builtin()` 壳**：套件现在覆盖 bash 的 `builtin`（只拦 `command`，其余按名字原样执行）。这会把套件里所有
   `builtin <名字>` 的写法纳管；`builtin command -v/-V` 走查询口语义（rc 与真 bash 一致）。
3. **`env tmux` 透传**：非破坏性调用不再用 `builtin command tmux`（那会被壳拦住），改用外部 `env tmux`（不经壳函数，
   仍是 PATH 解析，语义与 P180 之前一致）。若将来要连 `env tmux` 也纳入前置，那是另一条边界（子进程形态）。
