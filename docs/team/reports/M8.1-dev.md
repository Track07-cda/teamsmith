## TL;DR

- **The PM is an adapter now, and the Pi path did not move.** Three new keys (`TEAM_PM_CMD`, `TEAM_PM_BIN`,
  `TEAM_PM_RESUME_ARGS`) are empty by default; with all three empty the rendered PM launch command is
  **byte-identical** to the pre-M8.1 expression (proved two ways: an in-suite golden string and a before/after diff
  against the branch base, `docs/team/reports/M8.1-dev/invariance.sh`).
- **Same engine, not a fork.** PM templates are validated and expanded by the worker engine
  (`team_agent_placeholders`/`team_agent_expand` gained a `pm` kind); unknown, malformed (`{ cwd }`, `{{cwd}}`…),
  blank and multi-line templates fail loudly with the same messages, naming `TEAM_PM_CMD`.
  `{notify_ext}`/`{summary}` stay **worker-only** and are rejected on the PM side; a `{resume_args}` in a **worker**
  template is still rejected (worker semantics unchanged).
- **The prompt still goes through a file and an argv, never the command line**: it is written to
  `state/pm-prompt.md`, `{prompt_file}` is its quoted path, and `{prompt}` is the window harness' `argv[0]`
  (`"$0"`) — the same contract workers already have.
- **Liveness identity now resolves the PM's own binary.** `team_proc_is_agent_bin` used to match the **worker**
  adapter's executable inside the PM window (so a project with `TEAM_AGENT_CMD=codex …` and a Pi PM could not
  recognise a hand-started Pi PM, and `bash` could pass by accident); it is now `team_proc_is_pm_bin`
  (`TEAM_PM_BIN` > first word of `TEAM_PM_CMD` > `TEAM_PI_BIN`). A PM whose CLI is not called `pi` counts, and a
  wrapper that `exec`s the real CLI is carried by the spawn proof (`proof=spawn`).
- **Restart honesty**: with a custom CLI and `TEAM_PM_RESUME_ARGS` empty, `team up`/the watchdog say
  `这次启动**不延续** PM 的历史上下文` and point at `docs/team/**` + `team inbox`; with resume arguments configured
  (and `{resume_args}` in the template) they say `续跑：…`. Arguments configured but not referenced by the template
  are reported as `lost: … 没有 {resume_args}` instead of silently doing nothing.
- **Real non-Pi PM run (the evidence that counts)**: `codex` as the PM CLI in a scratch project — started by
  `team up` (`cli=codex`, `proof=argv`), the briefing was delivered (its first action was `team digest`), it drove
  `team board ls` + `team dispatch --print` from that session, a killed window was restarted by `team up`, the
  resume contrast continued the codex session, and `team watchdog up` + one patrol tick restarted it with pending
  work. Transcripts in `docs/team/reports/M8.1-dev/live-codex/`.
- **Rework after the PM's rejection (4/4 closed)**: a **bare executable name works now** (the first word is
  rendered as the absolute path `team_pm_bin_path` resolved — the PM's `codex` case starts with `cli=codex`,
  `proof=argv`); a failed start **leaves a diagnosis** (`state/pm-launch-failed.log`: exit code, rendered command,
  resolved binary, normalized window output) and no longer takes the window with it; the **worker side has the same
  hole** and it was measured — dispatch reports `✓ dispatched` while the CLI never runs (out of bounds here, flagged
  as a follow-up in §3.5.3); smoke fixtures for all of it. See §3.5.
- **Numbers**: acceptance green (`openspec validate` 8/8, spec-lint 45 req / 77 scenario, full smoke **✓1102 ✗0**,
  fast smoke **✓836 ✗0**); new smoke section 6i = **124 assertions**; flips: drop the `-c` default → **✗2**,
  identity back to the worker adapter's bin → **✗1**, fake continuity → **✗1**, no bare-name substitution → **✗2**,
  old `tail -30` capture → **✗5**, no harness capture → **✗4**, restored → **✗0** (§3.4, §3.5.5).

The suite keeps a **literal** golden string for the same thing (section 6i, first assertion): the reference is
written out by hand instead of being taken from the implementation, so a change *inside* the helper cannot make the
comparison pass on both sides — flip evidence below exercises exactly that.

Template mode uses a window harness (`exec bash -lc '<inner script>' "$(cat <prompt_file>)"`):
the inner script `cd`s to the main worktree, writes `$$` to `state/pm.pid.spawn` (the spawn proof, before `exec`),
then `exec`s the expanded template. The briefing is `$0` inside it, which is what `{prompt}` expands to; the
prompt is quoted as a single word, never shell-interpreted, and does not appear in the command line at all.

#### 3.5.1 退回点 1 — a bare executable name must work (the defect)

Reproduced first, exactly as the PM did (caller `PATH` = the interactive one, `bash -lc` = the window's shell):

```
$ bash -lc 'command -v codex'   →  NOT-FOUND-IN-LOGIN-BASH        # the window's shell cannot see it
$ bash -c  'command -v codex'   →  <home>/.bun/bin/codex   # the caller's shell can
$ TEAM_PM_CMD='codex exec {prompt}' TEAM_PM_BIN=codex team up
✗ PM 启动失败：6s 内既没看到配置的 PM 进程，也没等到我们 spawn 的 pid 写盘       # before the fix
```

**Fix chosen: substitute the first word with the absolute path that `team_pm_bin_path` resolves** — rather than
prepending the binary's directory to the window's `PATH` — for three reasons: (a) the binary that is started is
exactly the binary the liveness identity check looks for (no "ran A, checks B"); (b) it does not put a directory such
as `~/.bun/bin` at the front of the window's `PATH`, where it would shadow same-named `node`/`npm` shims; (c) the
template-mode command then has the same shape as the built-in Pi branch (absolute path in the command). A first word

#### 3.5.2 退回点 2 — the failure diagnosis must not be killed

Required: capture the window's last lines into `state/pm-launch-failed.log` *before* anything cleans up, and name
that path in the error. Implemented — and reproducing the PM's case exposed **a second defect** in the capture itself:

1. **The window survives.** The CLI now runs inside a subshell (`( … exec <cli> )`), so a CLI that exits immediately
   leaves the pane at a prompt with its own error on screen instead of taking the window with it; the spawn proof is
   still the pid that `exec`s into the CLI. The next `team up`/watchdog tick sees the idle prompt and replaces it.
2. **`capture-pane` returns the whole screen, not the interesting lines.** The CLI's error sits in the first lines and
   the rest is blank; the original "last 30 lines" (`tail -30`) therefore threw the only signal away, and the
   diagnosis looked like "the window printed nothing" — this is exactly what the assertion
   `诊断里有窗口最后几行（CLI 自己的报错）` kept catching. The capture is now normalized
   (`team_pane_tail_normalize`: drop blank lines, 300 chars/line, first 30 non-blank lines + a truncation note),
   both for the harness capture and for the launcher's re-capture.

## 4. What a non-Pi PM does not get (explicit)

- **No turn-end notification, no auto-nudge event of its own.** `TEAM_AGENT_NOTIFY_CMD` and the Pi notify extension
  are worker features: a worker tells the PM when its turn ended. The PM is the recipient; teamsmith has no "the
  PM's CLI finished a turn" event. A non-Pi PM is started/restarted by `team up` and by the watchdog's pending-work
  check and reads `team inbox` itself. (Typing into the PM window when it is alive — `team notify pm`, the watchdog
  nudge — still works for any CLI, because that path only checks that the pane is busy, not which CLI runs.)
- **No guaranteed session continuity.** With `TEAM_PM_RESUME_ARGS` empty a restart is a **fresh** session, and the
  tool says so and names the durable handoff (`docs/team/**`, `team inbox`, `team digest`) instead of implying a
  continuation. Continuity is the adapter's business: `resume --last`, `--continue`, `--session <id>`, `-c` — set it
  in `TEAM_PM_RESUME_ARGS` **and** reference `{resume_args}` in `TEAM_PM_CMD`.
- **No model/CLI compatibility guarantee.** `{model}` comes from teamsmith's registry; a CLI that does not know that
  model fails inside the CLI (that is why the live example above does not pass a model at all).
- **No `{notify_ext}`/`{summary}` and no extra keys beyond the three**: the PM template set is
  `{cwd}` `{session_id}` `{model}` `{provider}` `{prompt_file}` `{prompt}` `{skill_dir}` `{extra_args}`
  `{resume_args}`; the worker-only placeholders are rejected, and `team doctor` still only checks the **worker**
  adapter (the PM CLI is checked at start time by `team up`/the watchdog).

## 5. Decisions and deviations

- **`{resume_args}` is an addition to the placeholder set.** The brief lists the PM placeholders without it, but the
  key it asks for has to be usable by a template; a placeholder is the only way to place `resume --last` before the
  prompt (its position is CLI-specific). It is PM-only: worker templates that use it still fail as unknown, and the
  suite pins both directions.
- **`team_proc_is_agent_bin` → `team_proc_is_pm_bin` (+ a generic `team_proc_cmdline_is_bin` core).** The old name
  resolved the *worker* adapter's executable while only ever being called for the PM window — a latent mis-detection
  this task had to fix anyway ("the identity check … does not require the name `pi`"). No worker behaviour depends
  on it (grep: only the PM liveness path called it).
- **`cmd-agents.sh` needed no change.** I grepped the PM window paths: the say/notify path addresses the PM window by
  name, guards on `team_pm_alive` and `team_pane_busy`, and never assumes Pi (the `team_tmux_send_to_pi` **name** is
  historical; I added a comment saying so instead of renaming a helper used by the meetings code, which is out of
  bounds). So the file is untouched this round.
- **Template mode runs the CLI through `bash -lc '<script>' "$(cat <prompt_file>)"`** instead of putting the prompt
  in the command line: the 4 KB TTY line limit, the `{prompt}` contract and the worker harness all point the same
  way, and the spawn proof still records the pid that `exec`s into the agent.
- **Report/pre-flight failures happen before anything is replaced**: `team_pm_check_launch` (template) and
  `team_pm_check_bin` (executable) run before `state/pm.pid.starting` is written and before `respawn-pane`, so a
  broken config cannot leave a half-started pane or a stale "starting" marker.
- **Not changed (out of the brief's boundaries, flagged for the PM)**: `templates/config.sh.tmpl` (the generated
  project config) does not mention the three PM keys yet — a new project's config comment block lists the worker
  adapter only; `cmd-project.sh`'s `doctor` still checks `pi` and the worker adapter. Both are reasonable
  follow-ups, neither blocks this task.
- **Rework decisions** (details and reproductions in §3.5): **substitute** the template's bare first word with the
  resolved absolute path instead of prefixing the window's `PATH` (started binary == identity-checked binary, no
  shim shadowing, same shape as the built-in Pi branch); keep the failed CLI's window alive in a subshell so its own
  error survives; **normalize** `capture-pane` output (drop blank lines) because "the last 30 lines" of a
  mostly-blank screen is *nothing* — that was the second, hidden defect behind the PM's first one; make `team up`
  exit non-zero when the PM did not come up (called out separately in §3.5.2 because it is beyond the four points).
- **The worker side is deliberately untouched** even though the probe shows it has the same bare-name hole and hides
  it behind a `✓ dispatched` line: the brief's boundaries say worker adapter semantics are out of scope. The fix is
  a two-line reuse of `team_pm_subst_first_word`; see §3.5.3 and §7.

## 6. Known risks / not verified

- The live run used `codex` only. `opencode` is described in the same docs but I did not run the PM-side scenario with
  it (the brief said "e.g. `opencode` or `codex`"). The smoke's fake non-Pi PM covers the mechanism generically.
- The real-run evidence is a transcript from one machine/session (paths under `/tmp/m81-live/` and
  `~/.codex/sessions/…`); the reproducible part is the smoke section 6i, which repeats all four scenarios
  deterministically against a fake non-Pi CLI.
- `TEAM_PM_CMD` is not shell-agnostic by design: the pane shell parses it (POSIX single quotes are emitted by
  `team_squote`, and the template itself is the author's shell command). A template that relies on bashisms will
  fail if the pane's default shell is `dash` — same rule as the worker adapter.
- The watchdog restart path is covered both by the smoke (fake PM) and by the live codex run, but the *quota*
  interaction is only asserted in the smoke (`pm-restarts.log` = 1 line per real restart).
- The failure-diagnosis path is verified against a CLI that exits immediately. A CLI that dies after a *while* (or
  one that clears the screen on exit) is covered by the same mechanism (the harness captures at the CLI's exit
  moment, and the launcher re-captures with a bounded retry), but the smoke does not simulate a long-running CLI
  that redraws.
- The worker-side hole (§3.5.3) is a **real, unfixed defect** in this branch's scope report: dispatch can report
  `✓ dispatched` for a worker adapter it never started. It is not a regression of M8.1 (the code is unchanged) but
  it should get a task before that behaviour ships as "adapters work".
