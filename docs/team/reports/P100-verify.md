## 4. findings（逐条 + 判读建议）

**F1（口径，需要 PM 判读）· A3 的「锁路径不可创建」形状没有「加锁失败」这句措辞。**
任务书 A3 的字面期望是：`锁路径不可创建（例如父目录只读）→ 措辞是「加锁失败」而不是「排队超时」。
交付行为（§30③，父目录 `chmod 500`）是 M23 的既有降级：`注意：锁文件 %s 建不了 → 不做排队（…见 M23）`
+ 照跑套件，**不是**「加锁失败」；「排队/加锁失败：flock 没能把本套跑起来」只在 `flock` 起不来（rc>1，
§30①）时出现。两条路径都**没有冒充「排队超时」**、都可见、都不静默。
我核过 P66 的 diff：`fe08dd20` 只改了 `skills/teamsmith/tests/smoke.sh`，逐字保留了这条 M23 分支——
所以这是「任务书举例 vs 既有 M23 语义」的口径差，不是 P66 改坏。**建议 PM 判读**：若坚持任务书字面，
需要单独的 apply（把这支改成硬失败并配门禁断言）；若接受 M23 降级，建议把 A3 的举例改成「flock 起不来」
那一支，并注明「锁文件建不了 = M23 已有降级（不排队，照跑）」。

**F2（边界，不可达于真 flock）· 一个「直接返回 1」的坏 flock 会被读成排队超限。**
§30②：假 flock 在**探锁**与**排队**两步都直接 `exit 1`（不写 marker）→ 父进程按「没 marker + rc=1 = 排队超限」
判决 exit 2。真 `flock -w` 只在**超时**时返回 1（§34b⑤ premise + §40 的真形状对照），rc>1 的失败被 §30① 的
分支兜住；所以这条二义性在真 flock 上不可达。记录备查，不建议动手。

**F3（正向反证）· marker 写入是「子进程真的跑过」的唯一证据——删掉它真红会被误报。**
§20②：对交付树做 2 行 scratch 变异（只删 marker 写入，其余逐字节相同），同一个 `exit 1` 的子进程就被
误报成「排队超限（exit 2）、本套没有运行」。这正是 A2 要防的方向（真红 ≠ 排队超限），也说明 §34b④ 的
反例断言有载荷。记录为正向证据。

**F4（机理）· P94 的 141 只在写端输出 >管道缓冲（64 KiB）时确定性复现。**
§80④：`BEGIN` 版 560 KiB 写端 + `tail -n 0` + `pipefail` → 141；小输出的同一管道是调度竞争（本次实测 0）。
这解释了任务书为什么用 560 KB，并把「配置语义（不打印）」与「管道中止」分开。记录备查。
