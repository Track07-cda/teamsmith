## 结论（先说包里的实际行为）

- `npm pack` 出的 tgz 现在携带四个入口：`skills/teamsmith/scripts/shim/{pkill,killall,pgrep,pidof}`，
  每个 672 B、mode 755 的**普通文件**。从该 tgz 装进隔离 prefix 后，gated PATH 里四个名字都解析到安装包的
  shim 目录。0.3.0 正式包（`npm pack teamsmith@0.3.0`，只读复核）里这四个名字**一个都没有**，装完后
  `command -v` 全部落到 `/usr/bin` —— 与 `docs/team/reviews/release-0.3.0.md` 的记录一致。
- 判定与记录仍然**只有一份**实现（`signal-gate`）。四个入口是字节相同的 6 行 wrapper，各自把自己的名字作为
  第一个参数交给它；没有第二份 gate、没有 postinstall、没有运行时修补器，也没有四份判定。
- gate 恢复了已归档的 selector 契约（`boundary#Signals go to a recorded pid…`）：`pkill`/`killall` 除单个
  `--help`/`-h`/`-V`/`--version` 以外一律 exit 64；`pgrep` 只放行 `-g N`/`-P N`（N 为 `[1-9][0-9]*`）与
  `-fc P`、`-f -c P`、`-c -f P`（P 非空且不以 `-` 开头）；`pidof` 只放行同一个信息词。
  `-g`/`-P` 是**输出 PID 列表的诊断查询**（结果不是任何记录过的身份）、`-fc` 一族只出个数 —— 两者都不授予
  信号权限。其余形态 exit 64、
  stdout 留空、不解析也不执行真身。放行形态保留真身的 argv、stdout、stderr 与退出码并记 `act=pass`；
  `pgrep`/`pidof` 忽略旧的 `TEAM_SIGNAL_REAL`（它通常钉在 pkill 上），只在**闸门目录之外**按自己的名字解析，
  不会被路由到信号工具上。
- 入口名不授予任何放行：四个名字走同一套判定。wrapper 形态下 `basename "$0"` 是 `signal-gate`，历史软链形态
  （老检出、第三方副本）仍按 `basename "$0"` 认名字；两种形状都只用来决定「哪个工具被拦」。
- 随之必须一起修的一处实现细节：入口变成普通文件后，PATH 扫描里「跳过自己」不能再靠
  `readlink -f` 等于 gate 路径（wrapper 是另一个文件），改成**跳过闸门目录** —— 这正是 spec 里
  「resolve its own name outside the gate directory」那句话。

  而且入口名不授予任何放行（四个名字同一套判定）。

  （不改版本/依赖/脚本生命周期）。
- **性能**：没有动任何 `timeout` 一类墙钟上限。对照 P316 已验收分支的 `signal-gate.sh` diff（只读）确认它在
  「保留写失败」「FIFO」两腿把 `timeout 10` 放宽到 `timeout 300`；本任务没有碰那两处，也没有新增墙钟上限。
- 新增夹具断言全部落在**现有两个夹具**里（signal-gate 的段 + install-shape 的 pack/flip 段），没有新增套件、
