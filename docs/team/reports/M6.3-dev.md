## F26 · PM 现在到底被哪条通道叫醒（明确回答）

两条通道，**主通道是收件箱 + 巡检待办**，tmux 敲门只是 PM 正好在跑时的附赠：

```bash
# 现场：session 与 pm 窗口都在，但里面是空 shell（= PM 没在跑）
$ team notify pm --from-file summary.md
! PM 不在运行：消息只落收件箱（watchdog 会把 PM 拉起后读到）
✓ notified pm: worker summary awaiting the PM
  inbox/pm.md: - 2026-09-14T15:28:13Z [manual] agent:pm · worker summary awaiting the PM

$ team watchdog-status | grep -E 'PM |待办'
!   PM              未在跑（空提示符）；有待办时看门狗会拉起它（team up 手动）
  待办             未读通知 1          # ← 修复前这里是「无」

$ team watch --once
✓ watchdog: 有待办（未读通知 1）但 PM 没在跑（idle:zsh）→ 已拉起
  PM 是否真被拉起：args=[--provider deepseek --model deepseek-flash --skill … -c @…/pm-prompt.md]

$ tail -1 inbox/pm.md
- 2026-09-14T15:28:15Z [watchdog] agent:pm · PM 会话曾停止（状态 idle:zsh），watchdog 因有待办（未读通知 1）而用 pi -c 拉起它并注入开场提示词
```

即：`notify pm` 先落 **durable 收件箱**（PM 不在跑也丢不了）→ `team_pending_counts` 把它算成「未读通知」
→ watchdog 的 ③c 分支把 PM **用 `pi -c @pm-prompt.md` 真正拉起来**，并回写一条说明。smoke 的
11b step 8 把这段做成了 live 断言（`已拉起` + `pm-args.log` 增长）。PM 在跑时，`notify` 仍然会往窗口
打字（这条没变），但即使那次打字失败/被 TUI 吃掉，收件箱这一行也已经进了待办。

## 决策与偏差

1. **F18 同时管 `notify`**（任务书只点名 `say`）：两者都是「往 inbox 文件里写字」的通道，同一个打字错误
   在 notify 上同样是死信。拒绝文案与 `--any` 语义完全一致。
2. **F26 顺带修了 ack 基线失效**：`inbox/pm.md` 被清掉重建（比 ack 时更短）时，旧实现 `total - acked < 0`
   会让新消息**永远不可见**——这正是我给 11b 写 live 夹具时踩到的。现在 `files 被截短 → 基线失效 → 剩下的行
   重新展示一次`（`team_inbox_new/since` 同步），并有一条 smoke 断言钉住。
3. **smoke 的 TS runner 探测加了 `$HOME/.bun/bin/bun`**：这台机器 node 无 TS 剥离、bun 不在 PATH，
   于是第 13 节（notify 扩展）**一直是被静默跳过的**——F17 在这里将没有覆盖率。现在断言标签会打印
   `runner=…`，扩展开关的翻转证据（3 行 vs 1 行）真的跑起来了。这属于测试自身诚实性，不是产品行为变更。
4. **修了 smoke 里一处粘连的断言**：`|| bad "dispatch --print 失败"assert_has …` 被 bash 当成一个词，
   `--session-id` 那条断言从来没执行过（测试自己谎报覆盖）。拆开后断言真的在跑并通过。
5. **夹具必须建在规范分支上**：F16 之后 `dispatch` 会拿工作树分支与 `team_branch_for_agent` 对照，
   所以 smoke 的 T1.1/T1.2 夹具改用 `canon_branch()`（用实现自己的函数算），不再手写 `task/T1.1-smoke`。
6. **11b step 6 的夹具确定性**：F26 让「pm 未读」也进待办后，那一拍的告警可能因「同一批待办静音」而消失
   （告警按 sig 去重是有意设计）。夹具现在显式 `kill-session` + 把 `_watch last_sig` 打旧，
   确保这一拍确实走到「session 丢了 → 请人工 up」分支；断言意图没变。
7. **F30 的 spawn pid 走 `state/pm.pid.spawn`**（由 pane 里的 shell 在 `exec` 之前写自己的 pid），
   而不是去赌 `respawn-pane` 那一瞬间的 `pane_pid`（M6.5 已证明那一刻可能还报 tmux）。判据仍是
   任务书的 (a) 或 (b)：**没有写 pid 的进程永远走不到 (b)**，所以「别人放的 sleep」照旧是 `unknown`。
8. **`team_pm_pid_clear` 同时清 `pm.pid.proof`**：证据标记跟着 pid 记录一起作废，不会留下旧 proof 冒充新 PM。
9. **模板改动保持 marker 结构单份**：只替换 `<!-- teamsmith:begin/end -->` 内的段落，`bootstrap`/`init`
   重跑幂等（smoke 既有的「只一份」断言 + 新增内容断言都通过）。
10. 未提交 CHANGELOG（不在任务书「files you own」里，版本号归 PM）；未碰 `openspec/**`（规格由 PM 在修复落地后更新）。
