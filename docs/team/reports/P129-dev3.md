## Flip evidence

1. **公开路径红→绿（同一个 150018 B 帧、同一个 needle）**：修前树 rc=1 且点名 `缺 [P129-LONG-NEEDLE]`
   （needle 就在 pane 末行里）→ 当前树 rc=0 且放出帧首行就是 needle（§1 前两条 + 后两条）。
2. **影子精确命中**：`--break=pipeshadow` 把谓词换回旧写法 → 同一个真实命中 rc=1，自检汇总
   `✓16 ✗1`，唯一那条红就是 `✗ 长帧命中被判成没出现`；不 shadow 时 `✓17 ✗0`。
3. **26 站点逐站红侧分辨力**：把任一站点的新管道换回旧管道，该站点的检查就会红 —— 因为旧形状在
   `long_hit` 上的 rc 全部 ≠ `rc_present`（26/26，见 §2 表）；「新形状错」与「锚点腐烂」计数都是 0，
   绿不是靠放宽判据得来的。
4. **归因没放松**：`pipeshadow` 下只有长帧命中那一条红（`✗ 1`），预算/归因函数逐字节未动，两条活体
   M59 行为（超时现场 + SKIP 归因）仍按原语义输出。

## Decisions and deviations

- **合成 capture 而非真 tmux**：本仓库的红线是任何 tmux 复现都不许落到默认 server 上（历史事故：一天
  三次）。复验包用 PATH shim + shell stub 喂同一份字节，形态与夹具的 `tmux capture-pane -p -S -` 输出
  一致；真实 tmux 行为由 PM 的 `--select 53` / FAST 门禁覆盖（§53 自带真 `pty_wait_frame` 两向）。
- **站点数 27 vs 26**：P127 报告写「27 处」，按行点算 diff 是 26 个行级站点；p21:652 一个站点里有两条
  `printf|grep -q` 管道，所以管道级是 27 条。本表按 26 个站点逐站点列，p21 那站把两条都跑到了
  （`short_hit` 旧 rc=1→新 0）。
- **引擎只走公开路径**：引擎里 4 条谓词调用不单独做「旧/新管道」对照，而是由 §1 的公开路径 +
  `pipeshadow` 影子覆盖（`_pty_has_all/_pty_has_any` 的四个分支在自检的 17 条里两向都跑到）。
- **一处有意的语义差异（新写法更忠实的部分）**：生产者写出一段输出**之后**才死、而死之前已把目标
  内容写出来了 —— 旧写法报「缺席」，新写法报「在场」。26 个站点的问句都是**内容在不在**（containment），
  完整性由别处独立把关（`rc2`/`rrc` 显式判、探针 `PROBE-…-END`、落盘 capture 上的 `assert_has`），
  没有站点在条件里用生产者 rc 当完整性信号；`fail` 输入（生产者立即失败、零输出）两版都报缺席。
- 复验期间 main 前进到 `c3c7cd80`（P126，`config-cli.sh`）；本任务受检的 14 个文件在两版之间无差异。
- 没改任何实现文件；只写了报告目录与本分支的复验包。
