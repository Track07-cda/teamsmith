### The invariant exactly as implemented

**Rule**: `skills/teamsmith/references/**` and `SCOPE.md` contain no CJK ideographs (U+3400–U+4DBF, U+4E00–U+9FFF,
U+F900–U+FAFF) **outside fenced code blocks** (``` / ~~~ pairs) and **inline code spans** (`` `…` ``). Quoting the real
Chinese CLI output strings is intentional (D8: the CLI surface stays Chinese); prose must be English. Every hit is
printed as `path:line: <the line>`, relative to the repo root, so a reader can grep the file directly.

**Deliberate boundaries** (each one is in the code comment next to the scanner):

- Full-width punctuation (U+FF00–U+FFEF) is **out of scope**: `config.md` / `workflows.md` use `｜` (U+FF5C) as the
  vertical bar inside tables and sample output to avoid clashing with markdown table syntax. That is typesetting, not
  "the docs turned back into Chinese".
- Stripping is line-based: fence state spans lines (the fence lines themselves are blanked too), inline spans are
  matched on one line. An unbalanced backtick therefore *under*-strips and makes the check **stricter**, never weaker
  (fail-closed).
- 4-space indented code blocks are **not** exempt — the brief's rule names fenced blocks and inline spans only. The
  real tree has none containing CJK; if one ever appears, it is reported (and the rule can be widened deliberately).
- Implementation is one `perl -CSD` pass. `perl` is a new dependency of the *suite* only (the shipped scripts still
  have none). If `perl` is missing the section reports a hard red — a rule that silently skips is the same rot we are
  fixing here.
- `references/protocol.md` was **not touched**: its two raw hits (`翻转`/`破坏` in §9c, `不满足（…）` in the warning
  sentence) are inline-code-only and the brief says not to translate strings that must stay recognisable. Verified,
  not assumed — see the raw/scanner outputs below.

### Installer change

`for src in "$REPO"/skills/*/` also matched `skills/pi-team`, the symlink kept for old projects' absolute paths, so a
fresh install produced two discovery entries whose `SKILL.md` both say `name: teamsmith` (link mode: two symlinks;
copy mode: the symlink copied along as `pi-team -> teamsmith`). Install now `continue`s on a symlinked entry with a
one-line explanation. `--uninstall` keeps iterating symlinks on purpose so the target of an old duplicate is removed.

## Decisions and deviations

- **Section number 18** and everything in one block at the end of the suite, so it is pure addition (the diff has no
  deletions): M7.2's edits to `cmd-watch.sh` / watchdog paragraphs / its own smoke section cannot collide textually.
  If M7.2 also appends a section, the PM can renumber mine.
- The scanner is `perl`, not `grep -P` + a stripper, so there is one dependency instead of two and no "silently skip
  because `grep -P` is unavailable" hole (the existing M4.1 check has that hole; I did not change it).
- The full-width-punctuation exclusion (documented above) is my call: including U+FF00–FFEF would have made the gate
  red on `config.md`'s `｜` table separators, i.e. it would have forced a PM-owned paraphrase of files this task does
  not own, for a character that is not a Chinese word.
- `install.sh` skips *symlinked entries* (not "the entry named pi-team"): the alias is a compatibility artifact by
  definition, and a future real skill would be a real directory. Verified against a scratch repo with a second
  `dummy-skill`: 2 real dirs → 2 entries, alias skipped.
- Nothing else was touched: `cmd-watch.sh`, `cmd-project.sh`, the meetings code, `openspec/**` and `docs/team/**`
  (except this report) are untouched; `references/protocol.md` needed no paraphrase (verified, not assumed).

## Findings (found while flipping my own guard — both were defects in *my* test, fixed and re-verified)

1. **The guard wrote into the repository.** The uninstall fixture did
   `ln -s teamsmith "$T/m73-install-link/pi-team"` on the target produced by the *broken* installer, where `pi-team`
   is a symlink to the real `skills/pi-team` (→ the real `skills/teamsmith` directory). `ln` then **descends into that
   directory** and creates `skills/teamsmith/teamsmith -> teamsmith` in the source tree — a self-referential symlink
   left untracked exactly when someone is testing the fix direction (observed twice, mtime-verified; it is also why
   the flip run left junk in the worktree). Fixed by building that fixture by hand with `rm -rf` first, and pinned by
   a new assertion: the `skills/` listing is snapshotted on entering section 18 and compared on exit, so any scratch
   file left in the tree is a red assertion rather than a silent untracked artifact.
2. **"Exactly one entry in the target" would have failed the day a second real skill ships.** It now asserts
   `entries == number of non-symlink skill dirs in the repo`, `teamsmith` discovered exactly once, no duplicate
   discovery names, and no `pi-team` entry: strict today (1 == 1), still correct later.
