| 场景 | 候选控制路径 |
|---|---|
| 显式目录不存在、不是目录或不可写 | `team_tmp_root_prepare` 报原有诊断并返回失败；调用点在创建 `reviews/`、写日志及取锁之前。`--no-gates` 或未配置检查时不新增准备要求。 |
| 正常取锁，检查退出 0 或 1 | 取锁循环结束时记下排队用时；同一 shell 在实际执行子命令前后计算运行用时，不计入场检查或清理持有者记录。`gate_rc` 保留真实退出，按既有规则分别记 `PASS`、`FAIL`，而不是 `queuecap`。祖辈已持锁及无法启用排队的路径也只量命令运行，排队显示仍按各自原有格式。 |
| 持锁者未释放、确实等满上限 | 等待循环设 `lock_cap_hit=1` 并跳过子命令。这个标志是 `queuecap` 的唯一来源；仍记录排队用时和持有者、`ran=未跑`，以 `FAIL` 退出，不判 `TIMEOUT`。 |
| 互斥异常 | 入场冲突仍以 `gate_rc=2` 拒绝执行，判 `FAIL` 并保留 `mutexbroken`，不写数值运行时间。运行后存量锁身份复核发现丢失时，保留运行时间但改判 `FAIL` 并标 `mutexbroken`；两者均不记排队超限。既有入场拒绝报告显示未重做：计时行的 `ran=?s` 与通用门禁行仍按原格式输出，终端明确打印未跑。 |
| 真实硬超时 | 保留原 GNU `timeout` 包装参数及“包装器返回 124/137 且运行用时贴近限时”的判定；只把计算用时的输入换为本次命令的起止时刻。 |
