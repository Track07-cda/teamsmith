## 为什么用看板旁的一份文件

- **不加可选列。** 做标签列仍得统一处理表头、列宽、不同语言、转义及首次补全全部旧行，并与现有 `set/assign/add` 共写 `BOARD.md`；上面的列数与插入点判据不同，已是实际冲突。若改放任务书头，无任务书的 `board add` 行又不能贴标签；把权重写进每一行也会让一次改权重变成批量改行。
- **选 `<账本目录>/task-labels.tsv`（默认 `docs/team/task-labels.tsv`）。** 一个普通 UTF-8 文件，两类记录：`label / 名称 / 颜色 / 权重` 与 `task / 任务 ID / 标签名称`；用 tab 分隔，通过 CLI 以带引号的自然名称操作，不要求输入内部编号。名称在项目内唯一，正常空格和中文都可用，tab、换行和终端控制字符不作名称。可用现有 Shell/AWK 一次解析，不为旧看板或标签读路径添加运行时依赖。它是持久项目资料，可随账本单独检查和提交，不放进 `panel.conf`、项目设置或易丢的运行状态；使用命令不自动提交或发送远端。若后来把该文件提交到公开库，它会如同看板一样可见。
- **谁读写。** `board label` 负责写定义和关联；定义与关联在同一文件，用同一写入入口锁住一次读改写、在同目录完整替换并按项目现有持久写法同步。变更限定于相关记录，保留其它记录，不排序或重写原 Markdown、任务书、项目配置。旧项目第一次看不建文件，普通看板按原顺序；首次 `define` 才建立文件，首次 `add` 只给存在于看板的 ID 增加关联，无需任务书。不存在的 ID 或未定义的名称不会被顺手创建。找不到文件是未启用标签；已有文件读不了或格式有错时，标签命令说明问题，Pulse 仍显示看板但标明标签不可用，不以全零假装读成功。
- **谁算分。** 共用的只读标签解析与评分一次读定义及关联、按任务 ID 对不同名称去重并求和，不保存分数、不认颜色大小。CLI 排序列表与 Pulse 看板消费同一份分数；以分数降序及原始行位置为第二项。历史重复 ID 共享标签，但显示仍是两行；文件里不为两行各计一遍权重。改权重之后下一次 CLI 读、下一次 Pulse 刷新即用新值，既不用重贴标签，也不改行序。后续巡检先按既有事实找出值得提醒的任务，再从这个只读评分入口按 ID 取分；不要从画面取，也不改本轮巡检、待命、唤醒或恢复。
- **改名和删除。** 重命名在同一次写入里改定义及关联，不改其他标签或任务；若 Pulse 正选旧名称，名称不存在时回到“全部”，而不是继续显示空结果。颜色改动不改变筛选或分数。删除已用标签时，建议报出受影响 ID 并不落盘，PM 用同一 `remove` 明确解除后删除，避免一次误删无声地重排多项任务。手动删除一条看板行不从标签文件生成幽灵任务；旧关联仍按原 ID，重新用该 ID 会重新关联。手工改号或复用前先解除旧关联；旧行已删也可用 `remove` 清掉原 ID 的既有标签，不增设清理命令。

## PM 怎么用

以下为候选命令，不是现有命令；颜色与权重都是项目示例，不随安装附送。`Docs` 表达类别，不提高排序；省略权重即零。建议用整数分，不预置轻重等级。

```sh
team board label define 'Security vulnerability' --color '#d1242f' --weight 8
team board label define Bug --color '#bf8700' --weight 3
team board label define Urgent --color '#8250df' --weight 5
team board label define Docs --color '#0969da'
team board label ls
team board label add T2 Bug Urgent
team board label remove T2 Urgent
team board label edit Bug --weight 6
team board label edit Docs --name Documentation --color '#1a7f37'
team board ls --label Bug --sort priority
team board ls --sort priority
```

`board ls` 无选项保持原 Markdown、提示与顺序；显式排序是跨状态的列表，带标签名称和分数，显式筛选选一个名称即可。Pulse 第 4 页仍按状态分栏；复用现有选择控件的键盘和鼠标方式，在看板页一行放“标签”和“排序”，不放进项目设置，也不保存成项目配置。默认是全部标签、看板顺序；选择“优先级”只排栏内，历史栏也从高分起看，切回看板顺序则恢复历史栏从最新看。筛选不隐藏状态栏，只改变各栏显示的卡片和该栏可见结果数。普通卡片行不加一列；标签名称和色块出现在筛选选项及已有的任务详情，详细标签可随详情滚动，无任务书也可看标签。没有颜色的终端仍看得到名称；颜色只画色块，不承担筛选或区分任务含义。

```text
看板              [标签：● Bug ▾] [排序：优先级 ▾]
待做 2
› · T2 修复离线草稿恢复
  · T9 修正通知数量
进行中 0

Enter 打开 T2
详情 T2
标签    ● Bug   ● Urgent          优先级 8

```

草图是下列对照中 `Bug=3` 且移除 `Urgent` **之前**的两个界面。色块的实际颜色由项目定义；整行卡片标题的可用宽度不变。第一版不增加图形编辑入口：已有任务详情是只读，CLI 可以一次贴多个标签，做两套写入不缩短这条最短路径。CLI 写后在 Pulse 可用现有 `r` 查看，或等原有刷新，不另建通知通道。
