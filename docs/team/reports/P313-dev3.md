## 2. 根因与修法

旧形状（`section_guard_begin` 的超时注入）：

```
bash -c 'log="$1"; trap "" TERM; while :; do date +%s >> "$log"; sleep 0.2; done' _ "$stuck_log" &
```

三处缺失正好是三条泄漏条件：忽略 TERM（看门狗只能等 KILL 升级）、从不看父进程（套件被 KILL -9 时它被
reparent 到 init 继续跑）、没有上限（没人管也永不停）。而它写的 `$SG_RUN_TMP/fixture-stuck-<n>.log`
随 run 临时根一起被删 → 「已删除但仍被持有」的块一直不释放；每被打断一次就多一个持有者。PM 现场：
78 个、11.98 GB、2 天以上。

新形状 `bounded_spin <interval> <cap_s> <cap_bytes|-> <log|-> [<parent>]`：

- `trap '_bs_on_term' TERM`（`BOUNDED_SPIN_TERM` 可挂一段「留证据」的片段，`touch` / `order` 两个
  stub 用它）；只有 `BOUNDED_SPIN_IGNORE_TERM=1` 才忽略 TERM，注释里写明「只有那个形状本身是被测对象
  时才允许」；
- `while _bs_parent_alive "$parent"; do …; sleep "$iv"; done`（僵尸父按「不在」算）；
- 每轮判 `SECONDS - t0 >= cap_s` 与「已写字节 + 这一行 > cap_b」，到点 `_bs_exit "到点（…）"`；
- 写目标 `[ -e "$log" ]` 不成立 → `_bs_exit "写目标已不在（…）"`（直接对准 PM 的场景）。

超时注入那一处的 cap = `SG_BUDGET + 120`（**永远大于该段自己的预算**，正常运行不会被它截断），字节上限
按上限秒数推算（64 B/s + 64 KB，比心跳真实写入速率约 55 B/s 宽）。它**响应 TERM**：夹具里没有任何
`trap "" TERM` 的心跳了。段 0f 因此不再断言「现场记了升级」（那条断言的措辞还是 P110/F1 已经退掉的
错误归因），而是反过来断言「现场**不**记升级」—— 谁把 `trap "" TERM` 放回夹具，这条立刻红；
「真要升级时现场照写」的那一面由自检的 F1 夹具（P110，段 0e 内）负责（§3.3 是原始红与修法）。

### 2.1 交付前在真机上发现并修掉的两处（同一天）

跑 `--status` 时读到 0，但机器上实际有一个旧形状的孤儿（`/var/tmp/p314-before/…` 那份副本的基线运行，
ppid=1、已跑 50 分钟、持着 2 个已删 fd）。两处都不对：

1. **扫描面太窄**：只扫「解析出的根 + `$TMPDIR` + `/tmp`」，而验证者把仓库副本放在 `/var/tmp/<副本>/` 下，
   它的运行根不在任何一条扫描面里。现在扫「解析出的根 + 它的基（`/var/tmp`）+ `$TMPDIR` + `/tmp`」，
   「可归属」改成**路径里任何一层**是本项目的运行根（`teamsmith-*-<ns>.*`），副本目录套着也认得出来。
2. **建议太松**：只按「本项目 ns」归属，会把**别的席位正在跑的夹具**也列成「建议结束」。现在只有同时满足
   **父进程已不在**（被打断的运行留下的孤儿）才给建议；父链还在的持有者单独一行说明「活着的运行在用它们，
   不建议」。自检里三个持有者形状（孤儿 / 活着的 / 别家的）分别断言。

真机复测（§3.4）：`合计 1 个进程 · 8834 B`、`其中父进程已不在 … 1 个进程`、`--sweep` 只点名那一个孤儿、
并且**没有**发信号（跑完它仍然在，pid 2904613）。那个孤儿我没有动 —— 它属于另一份副本的运行。

## 8. 返修（V58 独立复验后 · 2026-10-18T13:40Z）

### 8.1 F1：`[suggest-kill]` 计划行只印 argv（没有路径，路径还被截断）

**缺陷**：计划行依次是 pid / 字节 / 已删文件数 / 「父进程已不在」/ argv，而 argv 被 `cut -c1-140`。两条后果
都在真机上出现过：`exec sleep` + fd 那种持有者 argv 里**一个路径字符都没有**；有路径的那种在 140 字节处
被截在中间。操作者要「按路径确认这是不是我们那次的夹具」时，这一行给不了。

**修法**：目标路径在扫描时本来就已经读到（`fpath[]`，按 inode 去重），只是没按 pid 记下来。现在记进
`_HO_PID_PATHS`，计划行第一栏就是 `目标：<完整路径>`；一个 pid 持有多个已删文件时逐个续行印全；argv 移到
下一行，只用于形状识别（不再承担「说清目标是谁」）。同时把 `--status` 的归属措辞改成 `_ho_path_ours`
实际检查的东西（删除目标所在路径里**有一层**是本项目的运行根 `teamsmith-*-<ns>.*`，不是「路径里带 ns」）。

**红侧（`--break=heldpath`）**：把计划行退回 argv-only 的旧形状。自检的 ① 号持有者本来就是 `exec sleep 60`
+ fd 的形状（argv 里没有路径），而且它的目标文件现在套在一串长目录名下
（`run-tmp-a-very-long-dir-name-for-the-v58-path-clause/fixture-stuck-1.log`），所以一条断言同时覆盖
「argv 里没有路径」与「长路径被截断」两半：
