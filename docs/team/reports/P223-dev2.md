## 一句话结论

**根因既不是"收集步到得太晚"，也不是"容器已经停了"。** 容器停了照样能带出现场：P214 那两次红带出来的锁文件，本身就是从**已停止**的容器里 `docker cp` 出来的（我这次本地复刻同样如此，`cp rc=0`）。

### ② `--keep` 是在哪里丢的（定位链，每步可复核）

1. 工作流的 gate 步是 `bash skills/teamsmith/tests/smoke.sh --keep </dev/null`；而工件的现场族是 0 → `--keep` 没生效。
2. §40 收尾打的是"没保留"分支 → 收尾时 `TEAM_TMP_KEEP` 为空。
3. `smoke.sh` 里 `TEAM_TMP_KEEP=1` 唯一的设置点在参数解析之后、**建根之前**；而全量门禁更早处（拿机器锁那一段）已经用 flock 起了持锁子进程 re-exec 自己（`SMOKE_LOCK_WRAPPED`）——**建根与收尾都在那个子进程里**。
4. 参数解析 `shift` 掉了 `--keep`，子进程收到的是过滤后的参数（`--select` 走 P98 的过滤副本那条路同理）→ 子进程 `KEEP=0`。
5. 于是父进程设的 `TEAM_TMP_KEEP` 只作用于它自己（它不建根），子进程收尾时把根收干净。

（这就是任务书里"①还是②"之外的第三种：不是收集太晚、也不是容器停了，是现场在门禁自己手里就没了。）

## Decisions and deviations

**先回答任务书 grant 里点名要先说明的一条：为什么必须动 smoke 的现场目录逻辑。** 症状的根因就在那里：`--keep` 是 smoke 自己的开关，而它在被 flock 的 re-exec 换进程时丢掉了 —— 收集步拿不到现场，不是因为它去晚了，而是因为**现场在门禁自己手里就没了**。所以不动 smoke 这段逻辑，任务书给的两条路都修不到根上：
   - **"容器还在时先 `docker cp` 到宿主暂存目录"**：这次的第一条负向证据正是在此——改前的根在 gate 步**退出时就已经被收掉了**，容器还在也拿不到；何况"趁容器还在"本身就是竞态（失败发生的那一刻容器就已经在退场）。
   - **"smoke 在失败时把现场族复制到约定位置"**：那是再开一条旁路（多一份拷贝逻辑、多一个可能静静失败的地方），而且工作流本来就写着 `--keep`、说的是"把现场留下"——把 `--keep` 修回它字面的意思，比再加一条侧面通道稳（D39 那两次挂载实验已经证明"另加一条通道"在 runner 上反复翻车）。

两条合起来才是这次的交付：**门禁真的按 `--keep` 留下现场 + 收集步自证真的带出来了**。


1. **`--keep` 的修法选"在拿机器锁之前 export"，而不是"把 `--keep` 也塞进 `"$@"`"**：后者要走过滤副本那条路（P98）才能抵达子进程，而过滤副本会重排参数，多一处"参数必须原样穿过"的暗约定；export 的形态在本文件里已有先例（`SMOKE_CALLER_HAD_TMUX`，注释写着同一个理由）。同时删掉原来"建根之前"的那处 export，免得同一件事两个位置。
2. **收集步的判断逻辑搬进 `ci/collect-scene.sh`，工作流那一步只剩一行**：理由与任务书"能本地跑影子实验"一致 —— YAML 里的内联 shell 没法在本地当命令跑，也没法被别的实验复用。收集面没有扩大：前缀表逐字保留原来的四个（`teamsmith-smoke. panel-p21. config-cli. pty-wait-selftest.`），另加三个点名的现场日志名（它们原本就在现场根里、只是没被点名）；整份 `/tmp` 仍然不收（D39 的 ELOOP 教训），打包仍走 `tar`（只记录软链、不跟随）。
3. **锁文件不再算"现场"**：`teamsmith-smoke.lock`/`.holder` 与现场根同前缀，照旧进产物（保持原行为），但**不计入阈值** —— P214 那两次红里唯一活下来的恰是它，把它算成现场等于什么都不判（自检 C3/C4 钉住）。
4. **gate 绿时不收集**（`--gate-outcome success`）：绿跑没有要带出来的东西，省得白拷上 100 MB 的现场根；容器照旧收掉。这是新增行为，写在脚本与工作流注释里。
5. **新增文件放在 `ci/`**（授权面含 `ci/**`；`ci/` 就是"门禁怎么跑"的家，`ci/Containerfile` 同类）。`section-select.sh` 的路径表没有声明它 → `--select <该路径>` 走 FULL 兜底（既有机制）；我没改那张表（那是 PM 的段落账本）。
6. **改 `section-budgets.tsv` 是必需的**：表头公式与 `--budget-check` 都要求 `band = max(host, container, ci)`、`budget ≥ max(ceil(band×4), 60)`；段变长而不重填就自相矛盾（运行时还会多一行"超过实测带"的 ⚠）。
