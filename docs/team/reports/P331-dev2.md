## 二 · 结论链：缺的是一份历史，不是一条通路

1. `writePasteFile` 的目录由数据层给（P309 的规矩：只有一份解析器 `team_tmp_root`，面板侧不二次解析），
   载体是 **capacity 块**的 `temp_root`。
2. `team_panel_capacity_json`（`cmd-watch.sh:831-871`）把「没有 `capacity.log`」判成**整块降级**：JSON
   照常打印，函数 `return 1`。
3. 数据层对非 0 退出的块**丢弃 payload** → `data.capacity` 不存在 → `temp_root` 为 `undefined` →
   `writePasteFile` 返回 `null` → `pasteClipboard` 回 `{kind:'none'}` → 草稿不动、不落文件、不报错。
4. 而 `capacity.log` 是**巡检拍写下的历史**（`cmd-watch.sh:552-556`），`team init` 不写它、也不起巡检。

**「新建项目为什么可以没有 capacity.log」**：那份日志的语义是「这个项目被巡检过多久」，它的缺席是**新**，
不是**坏**；产品对它的缺席有明确定义（容量块渲染 `—`）。缺陷不在「新项目没有历史」，而在**把一条与历史
无关的事实（临时根）挂在一个会因为缺历史而消失的载体上**。

## 六 · 理由框断言（OWNERSHIP 临时明授，仅此一条）

`panel-b2.sh` 的 `B4 理由行里有图片路径` 原来是 `assert_has <capture> "$file"`：逐行 `grep -F` 整条路径。
夹具里这条路径 **156** 字符，面板 120 列、草稿框可用 **116** 列（`columns - 2` 边框、`- 2` 提示符），
所以产品把整条路径**折成两行画出**：

```
│ > why/var/tmp/teamsmith-pm_skills-deb708fe/teamsmith-panel-b2-pm_skills-deb708fe.alU6pM/clipboard/tmpdir/teamsmith-pas
│   te-db6e66d9-3887-4cde-b263-d94afaf4cb51.png
```

改法（只改这一条的读取）：按**理由框自己那几行**重建完整文本 —— 标题行之后连续的 `│ ` 行，去掉托盘前缀
（`│ `、首行提示符 `> `、续行缩进）后按画出的顺序拼成一行，止于第一行别的东西；框外的行不进这段文字，所以
别处的路径顶替不了。然后仍用 `assert_has` 找**整条**路径；路径为空时这条直接红（不再是 `grep -F ''` 通真）。
断言仍是「完整路径出现在理由框里」，没有放宽；其它场景一行没动；没有接门禁；那 76 个 `sleep` 没碰。
