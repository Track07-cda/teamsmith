## 2. Phase → evidence as implemented

| `phase:` | New route (in addition to rule ① review record / ② merged branch tip) | Refuses when | Message says |
|---|---|---|---|
| `explore` | a `DECISIONS.md` **heading entry** naming the task id → prints `PM 接受记录 …（标题点名 <ID>）`; **or** `reviews/<ID>.md` with `判定 PASS/UNKNOWN/SKIPPED` → prints `复验记录 …` | no entry and no record; `FAIL`/`TIMEOUT` record; an id mentioned only in a body line | which route was found; on refusal both paths plus the ③ hint |
| `propose` | `reviews/<change>-proposal.md` with `verdict:`/`判定:` `ACCEPTED` | missing record, `NEEDS-CHANGES`, an unrecognisable verdict, or a brief without a `change:` line | the exact record path and the verdict it found |
| `apply` | *(unchanged)* rule ① / rule ② | — | `apply 与代码任务同规则（①/②）；没有额外的阶段证据` |
| `verify` | rule ① — the task's review record | no record | the record path and the phase route |
| `archive` | a directory `openspec/changes/archive/<change>` or `<date>-<change>` | no such directory (another change's archive does not count) | the archive path it looked in |
| *(none / `-` / unknown)* | **only** rules ①/② — byte-identical messages, no ③ line | anything a phase task would now accept | unchanged |

The invariant the brief calls the most important one is enforced structurally: `team_task_phase` returns empty for a
missing, `-`, or unknown value, and both callers skip the whole phase block when it is empty.

## 5. Decisions and one deviation from the handed-over implementation

- **Deviation (gap fix): an explore acceptance must be a `DECISIONS.md` *heading* entry.** dev's version grepped the
  whole file, so any task id mentioned anywhere — including old entries' bodies, which mention ids constantly —
  accepted an explore task. That is a widened guard in the direction that matters. The check now looks only at
  heading lines; the smoke fixture pins the body-mention refusal, and both reference docs say "heading entry". The
  tool's success line says `标题点名 <ID>` and the refusal tells the PM what to write.
- **explore's second route** is a `reviews/<ID>.md` record with `PASS`/`UNKNOWN`/`SKIPPED`; `FAIL`/`TIMEOUT` is not an
  acceptance (consistent with the review-verdict vocabulary the brief asks to keep).
- **propose refuses without a `change:` line** instead of guessing which proposal review belongs to the task.
- **unknown `phase:` = no `phase:`** (case-sensitive, the five documented values); the refusal message then contains
  no ③ line at all — the control fixtures assert that no "阶段" hint leaks.
- **`apply`/`verify` add no phase-specific route** beyond rules ①/②: the brief says `apply` is unchanged and `verify`
  is "a review record for the task id", which rule ① already is.
- **Report path**: dispatch says `M9.2-dev2.md`; the brief says `M9.2-dev.md` (written for dev). I followed the
  dispatch and left the brief untouched.
- Commits: dev's four (`feat`/`test`/`docs`/`test`) are unchanged; mine add `fix(teamsmith) … heading entry`, two
  `docs(team)` package commits, and this report. This report is a docs-only addition under `docs/team/reports/`,
  which no gate scans; the acceptance commands were run on the delivered branch (`validate` 8/8, `spec-lint`
  45/77, full smoke `1202 ✓ / 0 ✗`, fast smoke `916 ✓ / 0 ✗`).
