## 结论

两处都按 P323 点名的原因修好了，红侧仍然可证伪，产品契约一个字没改。

1. **34c 的回收探针不再继承外层的 `--keep`。** CI 的 gate 步永远带 `--keep`，它被落成 `TEAM_TMP_KEEP=1`
   （`smoke.sh:161`），原先原样传给了 `p287c_run` / `p287n_root_live` 起的两个探针；产品按契约保留探针
   自己的根，于是「主人退场 → 根被回收」每次 CI 必红。修法是两个 `-u`（`smoke.sh:16975`、`:17106`），
   写法与仓里三个既有嵌套夹具一致（`:1774`、`:18963`）。实测：修前 `--select 34c --keep` =
   `rc=1 ✓48 ✗1`（同一句具名红）；修后带 `--keep` = `rc=0 ✓49 ✗0`，不带 `--keep` = `rc=0 ✓49 ✗0`；
   把 `TMP_ROOT_BREAK=noreap` 还给探针的回收路径 → 同一条断言再红（`rc=1 ✓48 ✗1`），树字节不变。
2. **失败现场从一个显式临时根收，gate 与 collector 用同一个值。** 收集步原本拷容器的 `/tmp`、按 P287 之前
   的平铺前缀匹配，真实现场（写在 `$TMPDIR/teamsmith-smoke-<ns>.XXX/` 里）一个字节也进不了产物。现在
   workflow 定义 `TEAM_CI_TMP_ROOT=/var/tmp/teamsmith-ci-tmp`（`gates.yml:54`），gate 步把它当容器 `TMPDIR`
   并在跑门禁前 `mkdir -p`（`:95`），收集步用 `--tmp-root` 收同一个值（`:114`；脚本 `ci/collect-scene.sh:49`、
   `:91`）。族前缀改成带 ns 的 `teamsmith-<kind>-`（`:39`），本次运行的现场日志随族进产物，锁文件既不算
   现场也不进产物。实测（固定镜像 + 一次性容器）：同一次失败现场，旧脚本 = `rc=1`、暂存里只有容器 `/tmp`
   的 `node-compile-cache` / `tmux-build.log`；新脚本 = `rc=0`、1 个族、tgz 里 128 项（80 个文件 + 48 个
   目录），含 `.teamsmith-tmp` owner 标记与现场里的真文件。

## 5 · 边界（观测到的 / 未观测到的）

- **容器内这一次跑的是选段，不是全量。** `--select 34c` 的 `✓49 ✗0` 只覆盖 #0/#0b/#0c/#0d/#5；全套门禁、
  FAST、31 臂变异、发布套件都没跑（任务书禁止）。所以「workflow 的 `TMPDIR` 接线在真 CI 上正确」这件事的
  端到端证据要等合入后的第一次真运行。
- **整套门禁现在都看得见 `TMPDIR` 了，这个副作用没有全量测量。** 我能点名的相关处：三处 `source=` 断言都在
  嵌套运行里，其中两处显式 `env -u TMPDIR`（`smoke.sh:18715`、`:18719`），一处钉自己的 `TMPDIR` 并要求
  `source=tmpdir`（`:18973-18977`）；`tmp-hygiene.sh:1580/1602` 对 `/var/tmp/teamsmith-` 的断言只在那条
  两块都不设的腿上；tmux socket 路径只会更短（`/var/tmp/teamsmith-ci-tmp/…` 对 `/var/tmp/teamsmith-<ns>/…`）。
  剩下的段没有逐个读过——按任务书，CI 分层与范围属于 P322/P325。
- **容器运行缺 `--pid=host`。** 本机 rootless podman 直接拒绝（`Error: containers not creating Cgroups must
  create a private PID namespace: invalid argument`，三种组合都试过），而 CI 是 rootful docker。34c 选段
  不需要那个 POSIX 角（§10c 的 SIGTTIN 形状没有被这次运行覆盖）。
- **镜像用的是本机已有的 `localhost/teamsmith-gates:p223`**（与 `ci/Containerfile` 同一条钉住链，2026-10-03），
  任务书禁止重建；它比当前树早约两周，34c 选段在里面全绿，说明它足够跑这一段，但它不是 CI 明天会构建的那份。
- **`podman cp` 跑在宿主上，所以暂存目录必须在宿主可见的路径。** distrobox 里的 `/var/tmp` 宿主看不见
  （`statfs …: no such file or directory`；`cp rc=125 … could not be found on the host`），于是暂存与那次
  一次性克隆放在 `$HOME/tmp/p324-*`；运行产物仍按任务书写 `/var/tmp/p324-*`。两者都已清理。
- **括号：一次「2 个族」的采集是我自己的操作痕迹。** 为放软链我先 `podman start` 再 `podman exec`，而
  `start` 会把容器原来的命令再跑一遍（又建了一个根 `…nDqsUh`），所以那次采集打了 2 个族。真现场证据取
  第一次采集（1 个族、128 项）。这不是 gate 或收集步的行为。
- **三个非 `smoke` 的前缀没有在真现场里被观测到。** `panel-p21` / `config-cli` / `pty-wait-selftest` 的新名字
  来自 `tmp_root_create` 的 kind（`tests/panel-p21.sh:66`、`tests/config-cli.sh`、`tests/lib/pty-wait.sh:367`），
  `--select 34c` 不跑那些段，所以它们的族在这一次现场里不存在。
