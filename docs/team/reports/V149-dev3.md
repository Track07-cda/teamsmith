## 2. 周期提醒语义

- 活动中同 key 同请求：`spec.md:8` “A project-scoped active key SHALL return the existing ID and fixed due for the same normalized request”，
  场景 `:13-17`（concurrent/delayed retry 返回同一 ID 与首个 due，且只有一条 active）；design:31 写明“在重算相对期限之前先比 key”，
  与 landed `remind-store.mjs:624-641` 的顺序一致（先 key 判定，后算 due）。
- 观察后释放、再同 key 得新单调 ID：场景 `:31-35`（GET 新 ID、新 due，旧的那条不再触发）；design:31 “Periodic use means arranging the next one-shot Reminder with the same key after each observed wake releases it; that create receives a new monotone ID.”
  V129:53 实测相位边界：`unknown` 仍占 key，`observed`/`cancelled` 之后释放、两次复用都得到新 id。
- 无 key 的相同正文不猜重：去重只在“active key”条件句下发生（spec:8），`spec.md:8` 的 create 承诺是“a stable non-reused ID”，
  design:31 只描述 equal-key 请求；landed 代码也只有 `if (key.key)`（`remind-store.mjs:626`）这一条去重分支，
  没有正文比较。规范按唯一读法成立；未单列 scenario（见 SUGGESTION，不阻塞）。
