## 检查器的规则（稳定规则码，smoke 逐条断言）

| 规则码 | 何时红 |
|---|---|
| `no-specs` | `specs/` 下一个 `specs/*/spec.md` 都没有（查不到东西的绿灯不是绿灯） |
| `no-requirements` | 主 spec 文件没有 `### Requirement:` 块（例如只剩标题） |
| `requirement-without-scenario` | 一条 requirement 没有任何 `#### Scenario:` |
| `scenario-without-when` | scenario 没有 `WHEN` 行（有断言、没触发） |
| `scenario-without-then` | scenario 没有 `THEN`/`AND` 行（有触发、没断言） |
| `scenario-placeholder` | `WHEN`/`THEN` 文本为空或空洞（`THEN it works`、`… as expected` 等） |
| `change-incomplete` | `changes/<id>/` 里既没有 `specs/` delta、也没有 `proposal.md`/`tasks.md` |
| `delta-requirement-without-scenario` | `ADDED`/`MODIFIED` delta 的 requirement 没有 scenario |

退出码：`0` 干净（并打印 file/requirement/scenario 计数）、`1` 有违规（每条一行 `path:line: rule: detail`）、
`2` spec 根不可用（没有 `specs/`）。`changes/` 是提案：`REMOVED`/`RENAMED` 允许无 scenario，
`changes/archive/` 是历史、直接跳过（proposal 与 delta 的完整性由 OpenSpec 自己的 CLI 兜底）。

**为什么用 bash + awk**：门禁、smoke、`team` 本身都是 bash，规则是行式的（标题 + 列表项），awk 足够且不引入新运行时；
本机 node 没有可用的类型剥离，引入 node 会为「多一个运行时」付出成本而没有收益。

## 决策与偏离

1. **没有把任何 requirement 挪去 prose**：真树 45 条 requirement 全都能给出可证伪的 scenario，唯一的问题是
   `board-and-status` 那个 scenario 把触发写进了 GIVEN 从句（已补 WHEN，语义不变）。没有发明新 scenario。
2. **多修了一条 lint 抓不到的 scenario（请 PM 重点看这条）**：`memory-and-deps/spec.md` 的
   「An invalid spec fails the project gate」原本声称 `openspec validate --all --strict` 会在 requirement 缺 scenario 时
   非零退出 —— 这正是本任务的前提所否证的事实（上面「前提复现」里 CLI 是绿的），也就是说这条 scenario **写的是假的**。
   我把它改成由门禁里的 spec-lint 步骤拒绝（`THEN bash …/spec-lint.sh exits non-zero…`），WHEN 里点明 CLI 单独不抓。
   这超出了「只修 lint 报出的东西」的字面范围，但留着它等于门禁自带一句假承诺；若 PM 认为该由另一张单处理，这是一处 4 行回退。
3. **文档位置**：按 Deliverable 1/2 的明确要求改了 `references/openspec.md`（新增小节）与 `references/workflows.md`
   （gate 清单补一行），并更新 `.pi/team/config.sh` 的 `TEAM_GATES` 与注释。`SKILL.md:136`、`AGENTS.md:108`、
   `templates/*.tmpl` 里「openspec validate 是 TEAM_GATES 的一部分」仍然为真（只是不完整），且模板是给别的项目用的
   （那些项目没有 `spec-lint.sh`），故未动 —— 是否要在 SKILL.md/AGENTS.md 里点名 spec-lint，请 PM 定。
4. **`AND` 也算 then 行**（按任务书原文）：因此「删掉 THEN 但留下 AND 续行」是合法的（仍有一条可证伪的断言）。
   独立包把这条当成显式的宽容用例断言下来，避免后人把它当漏报。
5. **delta 的规则码**：delta 的 requirement 缺 scenario 时单列 `delta-requirement-without-scenario`（第一版借用了
   主 spec 的码，smoke 夹具当场抓出来并已修）。
6. **未修、但报备的既有问题**：全量 smoke 在第 11d 段会往 stderr 打一行
   `skills/teamsmith/tests/smoke.sh: line 1824: team_dim: command not found` —— 该函数在 smoke、common.sh 里都不存在，
   **main 上同一行同样如此**（不是本分支引入），走的是「keep 窗口不存在」的跳过分支，不影响结果（全量仍 777/0）。
   它在 M4.3 正在编辑的段落里，且属别人的文件范围，我没有顺手改；请 PM 决定给 dev。
