## 选择与理由（brief「要做什么」第 1 条的二选一）

**选 (a)「让它真幂等」**，三条理由：

1. **语义对**：这份记录的名字就是「本会话加载的是哪个版本」。版本号、skill 指纹、安装方式、会话 id 都没变时，
   时间戳本来就不该刷新——(b) 等于承认「再跑一次会有变化」，把声明改成描述一个不该有的行为。
2. **读它的地方按内容读**：`team version --check` 与 `team doctor`（`cmd-project.sh:319`）读的是 `VERSION` 与 `HASH`，
   `AT=` 是这份记录自己的元数据，没有任何调用方拿它当「上次跑的时间」用（全仓只有 `cmd-update.sh` 写它、
   `cmd-project.sh` 读版本与指纹）。
3. **断言的牙保住了**：(b) 要在夹具里把这个字段**指名放行**（brief 自己也这么要求），夹具那半的活与 (a) 一样多，
   而 (a) 之后连「这个字段也不许被重写」都还能断言（见下）。

选 (a) 之后 `mark-loaded` 的三种行为都不变：`--version <X>` / `--session-id <S>` 显式换值时照旧重写并盖新 `AT=`；
文件不存在时照旧创建；**只有「什么都没变」这一支不再碰文件**，那一支的文案改成
`✓ 本会话 skill 版本未变化：<ver>（指纹 <hash>；保留 pm-loaded.env 里记录的时间）`。写盘那一支的文案与字段顺序
（`VERSION` / `DOC_VERSION` / `HASH` / `SKILL_DIR` / `INSTALL` / `AT` / 可选 `SESSION_ID`）逐字未变。

## 探针的确定性：为什么是两半（brief「要做什么」第 2 条）

原判据是「第二次跑前后状态指纹逐字节相同」，它有一处靠运气的地方和一处失明的地方：

| 盲区 | 后果 | 这一半怎么堵 |
|---|---|---|
| 两次调用**跨过一次调用里写下的时钟值** | 落在同一秒就绿、跨秒就红——同一棵树宿主绿、容器红（P290 的现象） | 第二次调用前 `sleep 1.1`：比较落在后一秒，重写必然改字节 |
| 字段**没人指名**（表里没有它） | 只靠指纹比较，重写落在同一秒里仍然看不见 | 同上（间隔是按**类**堵，不按字段） |

两半的分工（免得复核时把哨兵当成唯一机制）：

- **哨兵 + 指名表**：`IDEMPOTENT_TIME_FIELDS=( [mark-loaded]=".pi/team/state/pm-loaded.env:AT" )`。第一次跑后把这个
   字段的值改成 `sentinel-not-a-clock`，第二次跑要求**连哨兵一起**逐字节不变——「字段被重写」一定看得见，**且与两次
   跑之间过了多久无关**（不需要等）；表里指名的字段第一次跑后**不存在**也算 finding（声明过期，不许静默放行）。
- **1.1s 间隔**：哨兵只管**已经指名**的字段；今天没指名的时钟字段在「同一秒」里仍然隐形，所以第二次调用前固定等
   1.1s——重写落在后一秒，字节必然不同。代价实测：声明 `idempotent` 的 20 行里 **18 行真跑探针**
   （`smoke` / `perf` 走有界窗口、`merge`/`pr`/`gh`/`gl` 是拒绝式只读面），≈ **+20s**，且只在完整门禁的 `claims` 段
   （FAST 档不跑 `claims`；§51 的预算是 5200s、band 1300s，不受影响）。

**否掉的两条口径**：

- **「比较时剔除已声明可变字段」**（brief 括号里的备选）：它让探针对**它本该抓的那种重写**失明——被剔除的字段改成
  任何值都算绿。改用哨兵之后这个字段是**可以断言不变**的（(a) 之后它确实不变），没有理由放弃。
- **给产品注入时钟 / 在夹具里遮 `date`**：产品没有可注入的时钟；用 `PATH` 垫片改 `date` 的返回要跟着实现
  `-u +%Y-%m-%dT%H:%M:%SZ`、`+%s`、`-d …` 各种形状，产品里换个参数就变成误判。1.1s 间隔是同一个目的、不碰产品、不猜参数。

**这条间隔不是装饰**：把「无变化不重写」的守卫去掉（回到 P290 的形状）**并且**把指名表清空（假装没人指名）之后，
**只剩**这 1.1s 能抓住它（红侧 ⑱，见下）。

**诚实边界**：间隔只能覆盖「跨秒才变」的值。按小时/按天变的值在两次调用之间通常不变，这类东西这条间隔看不见——
今天没有这样的命令（另外 17 条 idempotent 命令在间隔下全绿）；将来若出现，做法是**给表加一条**（指名 + 哨兵），
而不是把间隔越拉越长。

### F1（必修）· 记录在、但没有 `AT=` 行时不再静默失败

根因是 `skills/teamsmith/scripts/lib/cmd-update.sh` 里「读既有 `AT=`」那一行用裸赋值接了一个
「没命中就返回 1」的 `grep`，在 `scripts/team` 的 `set -euo pipefail` 下把整个 CLI 带走。改法与相邻
一行对称：

```diff
     stored_core="$(grep -v '^AT=' "$f" 2>/dev/null || true)"
-    stored_at="$(grep -s '^AT=' "$f" | head -1)"
+    stored_at="$(grep -s -m1 '^AT=' "$f" 2>/dev/null || true)"
```

语义上「没有可保留的时间」等于「没有记录」：走写盘分支把全字段补回，不是错误。0 字节记录同理。

### O1（一并修）· 幂等臂也判退出码：「第二次失败且不写盘」不再算绿

`probe` 原来只看第二次跑前后的字节。V46 的 m3（第二次跑打印成功文案却以 rc=1 退出、一字不写）
因此判绿——「失败」被当成了「幂等」。现在两次跑的退出码都进判定，rc 也打进探针输出：

```

  ✓ claims: mark-loaded 幂等：第二次跑退出码与第一次一致（rc 0 → 0）
```

判据写成「第二次 == 第一次」而不是「都必须为 0」：夹具里 `gh`/`gl`/`pr` 这类命令在没有远端时
本来就以非零退出（只读拒绝），要求全 0 等于把它们判红——那是假的，不是更强的。段标题里
「断言效应，不看退出码」随之改成实情（`（断言效应；幂等臂另判两次退出码一致）`）。

### O2 / O3 为什么不改

- **O2（哨兵可以被「写回原值」的实现骗过）**：这条吊住的是文件字节，而声明本身（`idempotent`）
  说的就是「再跑一次不会有任何变化」。一个把值原样写回的实现，对调用方的效果与不写盘逐字节
  相同；要区分「有没有走写盘路径」得在产品里插桩或看 mtime，前者是替产品做实现假设，后者在
  同一秒内不可靠（正是 P290 的坑）。留着这条边界比加一个会误判的探针好。
- **O3（容器与宿主的 `INSTALL=` 不同）**：`team_skill_install_kind()` 走 `git -C "$TEAM_SKILL_DIR"`，
  容器里只挂载 worktree（`.git` 是文件、指向挂载外）所以是 `copy`，宿主是 `git`。这是两个环境
  各自内部一致的属性，不是缺陷；幂等判定拿它当核心字段之一，两边各自稳定（下面的宿主/容器
  5+5 同判就是证据）。跨环境比对 `pm-loaded.env` 时先看这一行即可，夹具里不动它。
