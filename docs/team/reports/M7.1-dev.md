## Decisions and deviations

- **Guard change in 14b (smoke)**: the brief says the removed-command scanner "allows `removed`/`deleted`/`renamed`
  contexts". It did not — the exemption list was Chinese-only (`已删|已移除|不再|废弃|历史`), so an English guide that
  honestly documents the removals could only pass by smuggling Chinese words into it. I added the English framing
  words (`removed|removal|deleted|renamed|legacy|no longer`) and **kept the existing requirement** (the same line must
  also quote the command in backticks), then added flip tests in both directions: a framed English mention must not be
  reported, an unframed one ("Then reopen it with \`team gh\` pr view 12.") and a framed-but-unquoted one
  ("We removed team gl in v1.11.0…") must be. The Chinese words stay.
- **No `common.sh` change**: the marker/staleness judgement lives next to `doctor` in `cmd-project.sh`
  (`team_migration_reasons`); nothing else needs it today.
- **The pointer is conditional, not always-on** — the brief's wording, and it also keeps `doctor`'s output stable for
  clean projects (no churn in every other project's expectations).
- **Extra, not requested**: `tests/flip-m7.1.sh` (independent red→green package — the pattern the PM used for
  M6.5/M4.3) and the CJK check inside section 17.
- **Scoped CJK check**: section 17 checks the three references files this task delivered, not the whole directory —
  see Finding 1 (a pre-existing violation outside my boundary). The smoke comment names the reason and the repro
  command, so this is a deliberately scoped guard, not a silently narrowed one.
- **Timings in the guide are described, not quoted**: measured 1m41s (full) / 40s (fast) here while the PM and dev2
  were both running; the skill's own docs quote idle-machine numbers. The guide says "tens of seconds idle, minutes on
  a loaded box".

## Findings (things found in the code/docs; not doc problems)

1. **`references/protocol.md` breaks the M4.1 English-only invariant — on `main`, not in this branch.**
   `grep -rnP '[\x{4e00}-\x{9fff}]' skills/teamsmith/references` currently returns two lines: `protocol.md:349`
   (the flip-evidence keywords `翻转`/`破坏` as they appear in the review code) and `protocol.md:360` (the verdict
   string `不满足（不阻塞合并，但里程碑收口前应补齐）`). Both are quotes of real CLI strings, added by M6.2/v1.20.0,
   i.e. **after** M4.1's "zero output" acceptance run of that grep. So the documented invariant is currently false and
   only lived in a brief, not in a test. `protocol.md` is PM-owned; the fix is either paraphrasing those two strings
   in English or extending the invariant's exemption list deliberately. Section 17 covers the files this task
   delivered rather than turning the suite red on someone else's file.
2. **Release tags stop at v1.20.0.** `git tag` has v1.14.0…v1.20.0, but v1.21.0 and v1.22.0 (the current version) are
   untagged, while the rollback recipe in the guide tells people to pin a tag. The guide therefore says "recent
   releases are tagged" and keeps the release-commit fallback; tagging at release time is the PM's call.
3. **`install.sh` installs the compatibility symlink as a second skill.** `for src in "$REPO"/skills/*/` also matches
   `skills/pi-team`, so a fresh install creates both entries (reproduced with a temp target):
   `软链 /tmp/…/pi-team → …/skills/pi-team` and `软链 /tmp/…/teamsmith → …/skills/teamsmith`. Both point at the same
   code, so this is a duplicate discovery entry (same `name: teamsmith`) rather than a behaviour difference — but it
   is PM-owned (`install.sh`) and cheap to fix (skip symlinked entries, or only install `pi-team` when the canonical
   name is missing).
