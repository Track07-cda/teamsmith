## 2. 现有路径实际做了什么

### 2.1 要保留的行为

`openspec/specs/dispatch/spec.md:879-932` 的 `The printed route is a route that works` 约定：清单声明的每条用法必须出现在相应帮助页、页面的旗标由它自己的命令解析器接受、不能静默漏掉用法或一个帮助层级。列 0 反例及层级覆盖场景见同文件 L956-962、L1041-1045。

三个样本的现有判据：

| 样本 | 注入的损坏 | 真正决定红绿的输入与输出 | 源码事实 |
|---|---|---|---|
| ④ | `cmd-help.sh` 为 `board` 渲染一条列 0 的 `board add <ID> [--allow-dup]` | 页面行的缩进与命令归属；失败必须含“列 0 的行”，不能默默跳过 | `routes.sh:1765-1783`；解析判定 L391-407；页面调用该解析器 L606-613 |
| ⑪ | `dispatch` 的命令页追加 `dispatch --ghost-probe`，清单不变 | 清单声明的用法集合与页面用法集合不相等；失败必须含 `dispatch` 与 `ghost-probe` | L1909-1927；集合比较/诊断 L574-589 |
| ⑬ | 清单移除全部 `group` 行，命令行仍在 | 已读取页面清单中没有 `group`，即使菜单与命令页正常也必须点名缺失层级 | L1930-1945；页面生成 L469-487；最终层级检查 L620-623 |

这三项都不是“旗标真的被命令接受”的判断：④是无法归属的**页面行**，⑪是清单与页面**声明不一致**，⑬是某一级**没有读到**。具体旗标是否有效仍归 `mr_probe_claim`，不能把两个问题合并。
