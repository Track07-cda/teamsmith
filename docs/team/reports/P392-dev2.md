## 实现交接中需要保留的判断

- `design.md` 决策 1–3 指定 `cmd-agents.sh` / `outbox.sh` 的最小接缝：移走重复的 caller watch probe，将原 say 目标检查移到真正直发前；fresh `kind=say` 的默认意图不传播到后续 drain；已选 watch 的本次处理使用局部 watch-only 参数，路由消失或写入失败不能换道盲打。依据是 P390 `ec78b6c622ad`、PM `reviews/P390.md` 与当前 `team_send_guarded` 的 force-before-watch 顺序，故不能只改 `now=1`。
- `design.md` 决策 4 保留原 `forced.log` 字段顺序及一次直发尝试一行。旧 force 的 tmux best-effort、snapshot 等待及可能的第二次 Enter 不升级为成功或自动排队保证；正常 watch 也只确认持久交接，真实模型 receipt 另取 request/event/frame 证据。
- 仅选择一个有源码依据的有界错误修正：watch 初次 enqueue 无条目时，当前 helper 设 `offline`，say catch-all 会谎报 agent 退出并走 offline append；新路径应返回真实非零持久化错误，不声称不存在的 queue/inbox 成功。定位和失败注入验收见 `design.md` 决策 3 / delivery-guard 的 initial-persistence 场景，不扩展为全局恢复重写。
- `design.md` 决策 5 列出旧测试迁移表：smoke `12b`/`42`/`44`、guard-matrix、delivery-truth、watcher/help/real-Pi fixtures。旧 say 草稿保护用例改走真实 protected draft/notify/explicit queue，保留原断言和 mutation；不是把所有旧红侧改为允许粘字。任务 5.1 另列三项 scratch mutation：删除默认直发意图、force 移到 watch 前、恢复公共 parser flag，每项具名红及恢复绿。
- `design.md` 决策 6 列出 `SKILL.md`、config/troubleshooting、command/help strings 的当前承诺修正，并要求 PM 与 P391 排序共用 SKILL 面。OpenSpec 对已有 capability 的 Purpose 不做 delta 合并，后续获授权归档时 PM 还需单独把 delivery-guard 的旧通用 Purpose 限定到 protected senders；本轮没有改 canonical spec。
