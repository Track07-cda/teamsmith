```js
const writableGroups = () => new Set([process.getgid(), process.getegid(), ...process.getgroups()])
function foreignWriter(mode, gid, groups) {
  if (mode & 0o1000) return ''                 // sticky (system temp) protects entries the caller does not own
  if (mode & 0o002) return 'is other-writable'
  if ((mode & 0o020) && !groups.has(gid)) return 'is group-writable outside the effective groups'
  return ''
}
```

## Decisions and deviations

1. **外来组那条红侧用「进程组集合」而不是「真把目录 chgrp 到别的组」**：非 root 无法把目录 chgrp 到不属于自己的组。
   产品判定比较的是 `stat gid` 与 `process.getgid()/getegid()/getgroups()`，所以夹具把后三者暂时收窄为 `{0}`
   （目录仍是本机自己的组），断言器只认「拒绝 + 点名目录 + 点名规则」。这是同一个判定的等价输入，不是放宽。
2. **doctor 的读取顺序**：`inspectRuntime` 在读 `runtime.json` 之前先跑 `root`/`state` 的同一套祖先判据
   （ENOENT 仍然当作「还没注册」，不当作拒绝）。这样「磁盘上还留着上一份 runtime.json」时，拒绝仍然是
   第一结论 —— 见 `real-project.sh` B 段最后一条断言。
3. **不动扩展**：`extension/team-reply.ts` 一行没改。它把 `e.message` 原样写进 stderr，判据修好后
   `[team-reply] disabled: unsafe directory ancestry（…）` 自带目录，不需要第二套格式化。
4. **不动 spec**：任务书 `deltas: -`；`openspec/specs/key-replies/spec.md` 的 requirement 只要求
   「拒绝 unsafe directory ancestry」，没有钉死判据的白名单，收窄后仍然满足（仍然拒绝他人可写与外来组）。
5. 报告的时间行：`time:` 取写入这一行时的 `date -u`（就是本行上那个值），不是预计值。
6. **没有推远端**：PM 04:07Z 说「推分支」，但派单头（本仓 `TEAM_VCS="local"`）明确写「本仓库是 local 模式，不要 push、

   `task/P415-safe-dir-own-group` 上（tip `3802756b`）。远端 `public` 确实存在，所以这是一次**没有执行**的授权，
