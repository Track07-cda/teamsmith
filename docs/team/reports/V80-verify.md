
③ 与 ① 之间**没有秒数**：持有者从「拿到锁」活到「等待者被回收」，等待者多慢都在这段里。

### 1.2 `flock --close` 的语义由我自己证（四个探针，`/var/tmp/v80/probe/`）

| 探针 | 做法 | 读数 |
|---|---|---|
| T1 互斥 | 持有者在跑时，另一个进程 `flock -n -x f -c true` | `BLOCKED` —— 锁真的被持有者握着 |
| T2 锁 fd | `flock --close -x f bash -c 'ls /proc/self/fd'` 里数锁文件 | `0` —— 子进程**不**持有锁 fd |
| T3 对照 | 同一条去掉 `--close` | `1` —— 普通子进程确实继承（证明 T2 的 0 是 `--close` 造成的） |
| T4 时序 | 先让别人按住 2s，再起 `flock --close` 的探针，记子进程第一句的时刻 | 启动 `1792510700.983`、子进程第一句 `1792510702.785`，**Δ=1.802s** —— 只在锁到手那一刻才跑 |

T2 与 T4 合起来的意思是：`hold-ready` 出现 ⇒ 锁被 flock **父进程**握着，且那个父进程不是等待者的祖先
（它是本段的子进程，等待者是本段另一个子进程里的前台命令 —— 兄弟关系）。这正是本节要的「活着但不是祖辈」。

## 3. 问题三：「挂住」必须点名，且不因机器慢而出现

### 3.1 挂住（底层真的不完成）

破坏（`exp-new-hang`，只多一行）：在夹具持有者之前先让**另一个**进程按住锁 40s，于是
`flock --close` 的父进程 30s 内根本拿不到锁、`hold-ready` 永不出现（这就是「底层不完成」，不是「慢」）：

```diff
+flock -x "$P281_LOCK" sleep 40 &   # V80 hang side: someone else keeps the lock
 flock --close -x "$P281_LOCK" bash -c ': > "$2"; …' …
```

读数（`✓125 ✗1`，rc=1，79s）：

```
  ✗ 34b⑨ 没等到持有者拿到 TMP/p281/lock（30s 上限）→ 下面三条读数无效（这是「挂住」，不是「慢」）
  ✓ 34b⑨ 锁被活着但不是祖辈的进程持有 → 证明不成立 → 照旧排队（exit 2）
  ✓ 34b⑨ 证明不成立时不放行（不打印嵌套行）
  ✓ 34b⑨ 它照旧排队并撞上限
== 选段结果 ==  ✓ 125  ✗ 1
```

三件事都成立：**只**红这一行、它**点名**「没等到什么」（锁路径 + 30s 上界）、而且**没有**笼统超时；
行为读数照旧绿（锁确实被按着，只是「已经拿到」的证据没来）。作者 M1 的形状一致。

### 3.2 慢 ≠ 挂住（同一候选，放慢到旧窗口的 4 倍）

| 运行 | 前导加时 | 结果 | 说明 |
|---|---|---|---|
| `iso-new-5` | +5s | `✓ 125 ✗ 0`（50s） | 与修前那个 5s 窗口等长 |
| `iso-new-20` | **+20s** | `✓ 125 ✗ 0`（63s） | 旧窗口的 4 倍，⑨ 三条仍绿 |

20s 还能绿，本身就是「持有者不参与计时」的行为证据：如果锁在等待者到达前被放掉，等待者会 exit 0，
⑨ 第一条必红 —— 它在 +20s 下仍绿，说明持有者确实活到等待者被回收（§1.1 的 ③）。

## 8. 边界与没做的

1. **没跑整套门禁、没进容器、没抢机器级门禁锁**：按任务书只跑 `--select 34b`（选段自己打印了没跑的 130 段）。
2. **只在 `/var/tmp/v80/` 里造破坏**：主检出与我的工作树都没有被任何人改动；受检树 `tree-new` 的
   `git status --porcelain` 为空，`smoke.sh` 的 blob 与 `32c40ed9:` 那份逐字节相同（所有破坏都在副本里）。
3. **持有者放行轮询的 120s 上界是唯一静默的口**：耗尽时持有者自己退出、`wait` 返回，不会有断言因此红。
   它只在「本段自己没走到写放行那一行」时才可能耗尽（那时段子已经死了，后面的断言也不会跑）。要我把
   它也变成一行 `bad` 的话是另一处改动，本次没动。
4. **失败的代价从 5s 变成最长约 120s**：等待者若真挂住，本段会在 `wait "$P281_REALHOLD"` 上等到持有者
   那个 120s 轮询到期（实测挂住那一遍整段 75s）。这不是判据问题，是「挂住时要等多久」，记在这里。
5. `openspec validate` 需要 `$HOME/.bun/bin` 在 PATH 里（§6 末）。
6. 我跑完的残留进程：`ps` 里没有我留下的 `sleep 30/40/120` 或 `flock`（批尾那行打印为空）。
