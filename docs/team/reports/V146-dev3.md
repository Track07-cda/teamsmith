## WARNING

### W1 · 净化用无边界替换，兄弟路径被改写成不存在的路径

`team_review_ledger_display()` 对整行执行 `${line//"$main"/<main-root>}` 与 `${line//"$home"/<home>}`，不判断路径
边界。任何以 main root 为**字符串前缀**的另一个路径都会被截断。真实复现（隔离项目，真实 `team review`）：

```
$ team review T1 --dir "<main-root>-extra/checkout" --branch task/T1-v146
- 独立 checkout：`<main-root>-extra/checkout`
真实路径: <main-root>-extra/checkout
```

这不是假想形状：本项目 PM 的复验 checkout 位于 `…/pm-skills-ledger/team/reviews/<round>/checkout`，main root 是
`…/pm-skills`，所以每次真实复验都会在公开记录里写出一条从未存在过的 checkout 路径。公开账本扫描仍 `hits=0`
（它不再含绝对路径），但“可审计”变成了“写着一条走不通的路径”。

建议：按路径段落替换（只替换 `"$main/"` 与作为完整 token 的 `"$main"`；HOME 同理），或对落在 HOME 下的路径统一用
`<home>/…` 一类占位，确保替换后的字符串仍是可解析的路径而不是拼接残片。修复后应在 §10 加一条“兄弟前缀”场景。

### W2 · 红侧判据可以为“记录没生成”或别的断言失败而假过；绿侧依赖 checkout 在 HOME 之外

红侧代码（`skills/teamsmith/tests/smoke.sh:5949-5953`）只按 `review_record_ledger_clean` 的返回码分支：

```
if review_record_ledger_clean >"$TMP/p440-review-red.log" 2>&1; then
  bad "P440 review 红侧失效：恢复绝对路径写盘仍通过账本路径断言"
else
  ok "P440 review 红：恢复绝对路径写盘 → 断言红（…）"
fi
```

而该函数的第一条就是 `[ -f "$rec" ] || { printf 'missing record\n'; return 1; }`。把记录移走后直接运行作者函数：

```
$ review_record_ledger_clean      # 记录不存在
missing record
rc=1
```

同一函数在一条**没有绝对路径**、只是少了锁显示行的记录上也返回 1（`lock path was not sanitised`）。两种都会进入
`else ok`，所以红侧证明的不是“写盘路径被恢复成绝对路径”，而是“记录不满足十条断言中的任意一条”。作者本次的真实
输出恰好是 `absolute main root remains`，但这层判据本身不能区分。

绿侧同样有夹具位置前提：函数要求 `独立 checkout：\`$REV_WT\`` 原样出现。用 HOME 下的 checkout 跑同一个真实 review，
记录按规则遮成 `<home>/…`，作者断言即红：

```
- 独立 checkout：`<home>/.cache/v146-verify/checkout-home`
作者断言（独立 checkout 原样保留）: FAIL
```

烟测夹具的 `REV_WT` 在 `$TMP` 下（`TMPDIR=/var/tmp`），所以现场绿；但 TMPDIR 一旦落在 HOME 下，或 PM 用
`$HOME/.cache/pm-skills-reviews/…` 做复验，这条断言就会因环境而红——它不是被验行为的分叉，而是夹具路径假设。

建议：红侧在判定前显式要求 `[ -f "$rec" ]`、变异体 review `rc=0`、记录判定为 PASS，并把翻转点收窄到
`grep -qF "$REPO"` / `grep -qF "$HOME"`；绿侧改为断言**显示形态**（例如 checkout 在 main root 之外时原样、在 HOME
之下时为 `<home>/…`），或在夹具里显式准备两种 checkout 形状。
