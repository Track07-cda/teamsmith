## 2. §41 ④：等待循环在 `pipefail` 下一次都没有 break

旧写法 `roster | grep -q '在跑' && break`：`grep -q` 命中即退，`bash team roster` 还要接着写，写端吃 SIGPIPE，
管道状态变 141，`&& break` 一次都不成立。P316 把上界从 20 提到 1000（6 s → 300 s）之后上界正好等于被等对象的寿命
（本段假 agent 是 `sleep 300`），于是循环白转到窗口自己关闭。

改法与 P326 在 11c 的范式一致：先落一整份输出（连同它自己的退出码），再用 bash 内建匹配；上界只防死等，并且必须
短于被等对象的寿命（200 × 0.3 s = 60 s，被等对象 300 s）：

```diff
-  P55_W=0
-  while [ "$P55_W" -lt 1000 ]; do
-    P55_RENV bash "$SKILL_DIR/scripts/team" roster 2>/dev/null | grep -q '在跑' && break
-    sleep 0.3; P55_W=$((P55_W + 1))
-  done
+  P55_W=0; P55_WMAX=200; P55_ROSTER=""; P55_RRC=0; P55_HIT=0; P55_T0="$(date +%s)"
+  while [ "$P55_W" -lt "$P55_WMAX" ]; do
+    P55_ROSTER="$(P55_RENV bash "$SKILL_DIR/scripts/team" roster 2>/dev/null)"; P55_RRC=$?
+    if [ "$P55_RRC" -eq 0 ]; then
+      case "$P55_ROSTER" in *'在跑'*) P55_HIT=1; break ;; esac
+    fi
+    sleep 0.3; P55_W=$((P55_W + 1))
+  done
+  if [ "$P55_HIT" != 1 ]; then bad "P55 ④ 夹具前提：…没等到「在跑」（挂住）…"; fi
```

三点都改了：命中不再靠管道状态（`case` 是内建）；CLI 自己的退出码非 0 时不算命中；耗尽不再是静默的「慢」，而是一行
点名的红。

不依赖 tmux、不占门禁锁的机制复现（「首行就命中、之后还有多段慢写」的假生产者代 `team roster`，各跑 3 次）：

```
$ bash old.sh            # 旧形状：producer | grep -q '在跑' && break
OLD hit=0 rounds=40      ×3        # 40 轮全部耗尽，一次都没 break
$ bash rc-probe.sh       # 旧形状的管道状态
pipeline rc=141          ×3
$ bash new.sh            # 新形状：落变量 + case
NEW hit=1 rounds=0 rc=0  ×3
```

**改后绿**见 §4 的 A/B；**红侧**（把等待改回「永不 break + 1000 轮上界」的变异树）见 §4 的 D。

### 3.4 §36③ 的红标检查：从死断言到有正向对照的断言

旧代码（两版都一样死）：

```bash
sed 's/\x1b\[[0-9;]*m//g' "$TMP/p98-nest-run.log" | grep -E '^#[0-9]+ ' > "$TMP/p98-close-lines.txt"
grep -qF -- "$SMOKE_RED_MARK" "$TMP/p98-close-lines.txt"     # SMOKE_RED_MARK 自带 ANSI，文件已被去色
```

`SMOKE_RED_MARK` 是 `  \033[31m✗\033[0m`（`smoke.sh:307`），而文件已经过 `sed` 去色，所以这条 `grep -F` 永远不命中，
`bad` 分支不可达 —— 收口行就算真的带了红标也会报绿。改法：

```bash
P98_RED_PLAIN="$(printf '%s' "$SMOKE_RED_MARK" | sed 's/\x1b\[[0-9;]*m//g')"
printf '%s带红标的合成行\n' "$SMOKE_RED_MARK" | sed 's/\x1b\[[0-9;]*m//g' > "$TMP/p98-mark-control.txt"
… 若 ! grep -qF "$P98_RED_PLAIN" 对照文件 → bad「匹配器是死的」
… 否则若 grep -qF "$P98_RED_PLAIN" 收口行文件 → bad「收口行带了门禁红标」
… 否则 ok
```

三个现场 × 两个匹配器（用同一段代码文本跑，不是复述）：

| 现场 | 改前（ANSI 串 vs 去色文件） | 改后（去色串 + 正向对照） |
|---|---|---|
| 干净收口行 | ok | **ok** |
| 收口行里夹了真红标 | **ok ← 假绿（死断言）** | **bad（点名「收口行带了门禁红标」）** |
| 匹配器退回旧形状（把 `P98_RED_PLAIN` 换回 `SMOKE_RED_MARK`） | — | **bad（点名「匹配器是死的」，正向对照没命中）** |

正向对照的作用正是把「仪表死了」和「现场干净」区分开：没有它，退回旧匹配器时第一行仍然是绿。
