机制探针（同一私有 socket，逐个动词）：`new-session` 建 socket 并把**启动者环境**写进全局环境；
`new-session -e TEAM_PROJECT=third` 只写**会话**环境（全局环境不变）；
`kill-session`/`kill-window`/`has-session`/`list-sessions`/`display-message`/`send-keys`/`respawn-pane`/
`split-window` 在无 server 时全部 **rc=1 且不建 socket**；`tmux start-server` 单独跑 rc=0 但**留不下
server**（`exit-empty`）。这三条决定了「只有建对象调用能启动 server」与「先起一个干净 server 不存在」。

## Decisions and deviations

1. **delta 落到两个 capability**（提案裁定点 1，推荐并已按此落笔）：`pm-lifecycle` 两条 ADDED +
   `boundary` 一条 MODIFIED。理由：任务书写的是 `specs: pm-lifecycle`，但「闸门日志恰好一行」这条合同
   本身写在 `boundary#The gate's actions are logged…`；按评审清单第 7 条，取代它必须是 MODIFIED，
   不能在新要求里另说一套。**这是相对任务书 `specs:` 行的一处范围外扩，请 PM 在提案评审里裁。**
2. **审计面必须在提案里解决，不是顺手带过**（裁定点 C）：写侧「洗掉命名空间」与既有「每次过闸门恰好
   一行」直接冲突；三条路（A1 闸门按 cwd 解析日志目标 / A2 只洗身份族保留四个 pin / A3 接受洞）都写清了
   代价。推荐 A1，因为它是唯一同时满足「全局环境零 `TEAM_*`」「日志无洞」「不引入第二份 socket 解析」的。
3. **归因判据选了「值就在 server 全局环境里」**，而不是任务书里另一个候选「cwd 能解析出项目 + 继承身份
   指向另一个已存在的项目」：后者会把 `smoke.sh` §32③/§32⑧a 那种**显式继承**也放行，而规格与门禁要求
   它拒绝。误判的代价与兜底（假阴=过期副本仍拒绝，兜底是既有 `env -u` 一行 + doctor 只读残留行；
   假阳需要「冲突的每个变量的继承值都恰好等于全局环境的值」同时成立）写在 design §2。
4. **本阶段没碰 `smoke.sh` 与两张 tsv**（裁定点 D）：`tests/smoke.sh`、`tests/section-paths.tsv`、
   `tests/section-budgets.tsv` 此刻有在飞写者（P251/P261 在写、P264 排队），提案按「新增独立夹具
   `tests/tmux-identity-leak.sh` + apply 阶段接入 §32 并按实测重填预算行、补 §32 patterns 的
   `common.sh`」落笔，把「增量选集今天不含 `common.sh`」这个缺口写进 design §4，不静默。
5. **没做的事**（守 propose 边界）：没有改 `scripts/**`、`shim/**`、`templates/**`、`references/**`、
   `SKILL.md`；没有动 `docs/team/**` 里除本报告以外的任何文件；没有合并、没有推送（local 模式）。
6. **两个 apply 批次**（design §6）：写侧+审计（apply-1）、读侧+doctor（apply-2），同分支串行（都动
