- **按裁定做完的两点**：① inbox 的逐字节比对去掉，理由写进代码（append-only，由每次回合结束的收尾钩子写）；

  仍比「state 除遥测之外的一切」，活项目长跑还会被 `notify.log` / `notify-knock.log` / `notify-dedup`
  判红 —— 它们和 inbox 是同一次收尾写入的（A1 的 diff 就是这三条）。所以比对范围落到
  `state/key-replies/**` 一处，`KRG_TELEMETRY_ERE` 那张排除表随之整张删掉（净减 42 行，没有新增守卫层）。
  若你要的只是"摘掉 inbox、其余照旧"，把比对路径改回 `.pi/team/state` 并在表里补三条 notify 即可，
  但那样下一次 `team dispatch`（写 `dispatch-*.spawn`/`prompt-*.md`）还会再红一次。
- **代价（明说）**：「夹具误用真根跑了一次 `team notify`」这种形状不再由本守卫抓 —— 它的痕迹落在 inbox 与
  投递账本，按裁定出界。这条家族的独立一道仍是 `smoke.sh §26-l`（按夹具特征串扫真实账本）。
- **副作用（如实记）**：E1 覆写了主检出的 `state/notify-dedup`（内容变成 `p399-dedup`，无空格 →
  扩展解析时跳过，等同"首次运行"）。我已把该文件删掉，让它回到首次运行状态；`docs/team/inbox/dev2.md`
  与 `state/notify.log` 里我追加的探针行都已按字节还原，`grep -c 'p399 负对照'` 为 0。
- 守卫实现原来是**两份**（`key-replies.sh` 一份、`reply-fixture.sh` 一份），本轮合成一份 —— 否则"比对范围"
