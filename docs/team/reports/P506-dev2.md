## 用户实际怎么操作

```text
项目设置 / Project settings
  …现有项目命令、模型记录保留…
  任务标签 / Task labels                         ›

任务标签 / Task labels
  新增标签 / Add label                          ›
  用户反馈                  ● 蓝色 / Blue       3
  文档                      ● 自定义颜色         0

编辑标签 / Edit label
  名称 / Name                   用户反馈
  颜色 / Color                  ● 蓝色 / Blue
  权重 / Weight                 3
  保存 / Save                   取消 / Cancel
  删除标签 / Delete label
```

- 第一次打开显示「暂无标签 / No labels yet」和「新增标签」；例如填「用户反馈」，在有文字名称的色板中选「蓝色」，权重填 `3`，保存后在列表看到这条定义。没有预置标签；新建权重默认 `0`。权重是一个整数输入框，允许 `-2`，不要求写配置表达式；只在这个字段需要说明时用「按优先级排序时，任务的标签权重相加。/ Priority uses the sum of a task’s label weights.」
- 颜色用现有选项列表的交互，提供少量具名色，不新增专用取色器或复用主题角色色。若从命令建立的「文档」当前是 `#7856ad`，颜色栏显示「自定义颜色 / Custom color」及色样，选项保留「保留当前颜色 / Keep current color」。只改名称或权重时不发送颜色字段；打开色板再取消也不改值。取舍：这一版可保留任意现有色，常用新增/改色用色板；不额外做任意 RGB 输入界面。名称和数值不靠颜色辨认。
- 进入编辑不写；改完各字段再按一次「保存」，取消丢弃草稿。「删除标签」单独确认并显示名称，如「删除“文档”？/ Delete “文档”?」。如果仍有关联，显示「标签仍在使用，无法删除。/ This label is in use and can’t be deleted.」并列出命令返回的任务；不自动解除任何关联，不把给单项任务贴标签的操作加进来。重名显示「此名称已存在。/ This name already exists.」，小数权重显示「请输入整数。/ Enter a whole number.」。拒绝保留草稿，不把命令或配置文件路径当作正常操作步骤。
