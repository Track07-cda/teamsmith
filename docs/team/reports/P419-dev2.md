# P419 · 指令类消息用 steer 投递，通知类保持 followUp

agent: dev2   status: delivered   time: 2026-11-05T07:45:00Z
branch: `task/P419-say-steer`   PR/MR: -

## 结论（先说答案）

`team say` 的消息（spool 行 `kind=say`）现在走 `deliverAs: 'steer'`：本次工具调用结束后、下一次模型请求之前
落地，插得进正在跑的那一轮。通知类（`notify` / `nudge` / `knock` / `draft` 回执，以及任何其它类别）保持
`followUp`。判定只看这一批携带的类别，不看批量大小：混批仍然只投一次，用 `steer`。`triggerTurn: true` 不变，
输入框仍然一个键都不碰。两种模式在同一条通道上可观察：夹具看到 `sendMessage` 的 `opts.deliverAs`，生产现场
看到账本 `state/inbox-watch.log` 的 `wake … deliver=<steer|followUp>`。

**已知极限（brief 要求写进报告）**：`steer` 也只能落在两次工具调用之间。席位正卡在一个长工具调用里时，
指令仍要等那次调用返回才轮得到它 —— 这比 `followUp`（等整轮没有更多工具调用）早，但不是「立即中断」。
