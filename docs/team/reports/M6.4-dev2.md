## 每个 finding 怎么修的

### F4（medium）「未 push」量错了 ref

- 旧：`team_git_cols` 只算 `rev-list --count main..HEAD`，digest §[4] 的抬头写「未 push」——分支 push 过、
  被 squash 合并后，这个数永远 ≥1，PM 就会永远收到「收尾：提交并 push」。
- 新：`team_git_upstream_ahead <worktree>` 用 `git rev-parse --abbrev-ref --symbolic-full-name '@{upstream}'`
  + `git rev-list --count '@{upstream}..HEAD'`；三种取值写进注释并被测试钉住：`<n>` / `-`（没有 upstream：
  push 状态**无法判定**）/ `?`（配了 upstream 但解析不到）。roster 多一列 `未push`，并把「领先=相对 main」
  与「未push=相对 @{upstream}」分开写在页脚；§[4] 抬头改成「相对 upstream 未 push 的提交；领先按 main 另计」，
  只有**真的**有未 push 提交才给 `say ... "收尾：提交并 push"`；没有 upstream 时明说
  「无 upstream（未 push 无法判定）」并单独给「领先 main N」（local 模式补一句「PM 合并，不需要 push」）。
- 与 M6.1 的 `TEAM_TASK_BRANCH_RESET` 无交互（那条只管 close 后把 worktree 切回保护分支，不涉及 ref 选择）。

### F6（medium）id 含 `-` 的任务被切错

- 旧：`id="${base%%-*}"`（三处：common 的待复验/忽略清单、cmd-status 的覆盖版）→ `reports/API-2-dev.md`
  变成 id=`API`，标题校验必然失败 → 真报告落进「忽略的非任务报告」。
- 新：`team_report_task_id <报告>` 把文件名 stem 按 `-` 拆成**由长到短**的前缀（`API-2-dev` → `API-2-dev` /
  `API-2` / `API`），第一个「已知任务 id」胜出（已知 = BOARD 有这一行，或 `tasks/<id>-*.md` / `tasks/<id>.md`
  存在）；都不认识则回退到旧的「首个 `-`」，因此非任务报告（如 `P2-closure.md`）的行为**没变**，仍然
  「被忽略但可见」。digest §[3] 现在直接用派生出的 id 生成复验命令，显示名照旧是文件名。

### F21（medium）`version --check` 用 141 说「你是旧的」

- 旧：`sed -n '/^## /,$p' CHANGELOG.md | head -14 | sed 's/^/    /'`——`head` 读够就退出，上游 `sed` 收到
  SIGPIPE（141），主脚本 `set -euo pipefail` 把这个状态传给调用方，`&&` 链把「你是旧的」当成崩溃。
  实测地基：`bash -c 'set -euo pipefail; sed -n "/^## /,\$p" CHANGELOG.md | head -14 | sed "s/^/    /" >/dev/null'`
  → rc=141。
- 新：同一段摘要改成**单个 awk**（`/^## /{show=1} show && n<14 {print ...}`），读完整个文件、只打印前 14 行，
  没有下游早退就没有 SIGPIPE。smoke 断言「旧会话 → 退出码 0 且仍然打印『本会话是旧的』/『最新变更』」。
- 审计（未改）：`cmd-update.sh` 里其余 `sed … | head -1` 都在命令替换赋值里（赋值状态为 0，SIGPIPE 传不出去），
  `team_loaded_version/hash` 的 `grep … | head -1 | cut` 输出极小且不构成语句级管道；`CHANGELOG` 32KB /
  `SKILL.md` 24KB，写出量都在管道缓冲之内。真正会以 141 收尾的只有 F21 这一处语句级管道。

### F23（medium）`team reload` 承诺了一个不存在的 watchdog 行为

**选择 (b)：删掉承诺，只说实际会发生什么**（选项 (a) 要把「读 marker → 重启 PM」做进 `cmd-watch.sh`，
那不在本任务的边界内，也不该为一个记账文件引入重启路径）。

- 旧文案：「若你有 watchdog：它看到 marker 后会重启 PM 会话（pi -c 保留历史）」——`scripts/**` 里没有任何组件读
  `state/reload-requested`（watchdog 不读），扩展只在 `session_start(reason=reload)` 时把它删掉。
- 新文案：①在 Pi 会话里输入 `/reload`（或 `/teamsmith-reload`、或 `reload_skills` 工具）才能生效；
  ②marker 仅用于记账，`/reload` 完成后扩展会删掉它；③**没有任何组件会因为 marker 重启会话**（要重启用 `team up`）。
- 测试把「两边一致」钉住：`scripts/` 里除 `cmd-update.sh` 外没有文件提到 `reload-requested`，
  扩展侧仍然只有 `rmSync(marker, { force: true })` 那一句清理。

### F19（low）会议 TTL 接受垃圾值 → 永生

- 旧：`open` 不校验（`--ttl 0/-5/abc` 原样写进 `state.env`），`is_expired` 把 0/负数/非数字当「永不过期」，
  `read` 印出 `TTL abch`；把 `OPENED_EPOCH` 回拨到 1000 后，54 年后仍然能 `say`。
- 新：
  - `team_meeting_ttl_default`（文档默认值，环境变量非法也回退 72）、`team_meeting_ttl_hours`（有效 TTL）、
    `team_meeting_ttl_note`（登记值不可用时 read 的说明）；
  - `open` 先校验：非数字或 ≤0 → `team_usage_die`（**拒绝**，不写任何文件）；>8760（一年）→ 告警并夹到 8760；
    不传 `--ttl` 用文档默认值；
  - `is_expired` 用有效 TTL；`OPENED_EPOCH` 不可用时按 0 处理（比任何 TTL 都早 → 判过期，不给永生后门）；
  - `read` 打印 `TTL <有效值>h`，并在登记值非法时附「登记值 abc 不可用：按文档默认 72h 计，不会永生」；
    `meeting require_open` 的过期报错也用有效 TTL。
