## 结论（先看这里）

两处改动都在 `skills/teamsmith/tests/smoke.sh`，分支 `task/P334-anchor-lifetime`，代码提交 `185b81fc`：

1. **锚点 pane 的命令不再是无主的 `sleep 100000`**：换成只看本轮的 `while kill -0 <本轮 $$>; do sleep 2; done`
   （纯 bash + sleep，无新脚本/守护进程）。本轮没了 → pane 退 → 最后一个 session 走 → 私有 server 自己散。
2. **socket 目录清理的前缀早就对不上**：清理认 `.tm-*`，实际目录是 `.t-<uid>.<6 位>`（创建模板在别的提交里换过），
   所以**连正常跑完**也每轮漏一个目录。改成按实际形状逐字匹配，不用前缀通配。

同一实验、同一形态（从 tmux 里起、带 `--keep` 的选段、从**外部** `kill -9` 跑套件的那个进程）：

| 改动后 | `185b81fc`（`kill -0` 轮询） | 2528635 | 2528852 | **1s** | 锚点消失，`ps` 为空 |

正向（正常跑完）与不误伤也都对上了：跑完 `ps` 里没有锚点、socket 目录被收掉，运行期间既有断言

## 改了什么

### ① 锚点 pane 的命令：从「无主 sleep」改成「看本轮还在不在」（`smoke.sh` 锚点建立处）

```diff
   if [ "${SMOKE_CALLER_HAD_TMUX:-0}" = "1" ]; then
-    SMOKE_TMUX_ANCHOR="teamsmith-smoke-anchor-$$"
-    tmux new-session -d -s "$SMOKE_TMUX_ANCHOR" -n anchor "sleep 100000" 2>/dev/null || true
+    SMOKE_TMUX_ANCHOR_PID="$$"
+    SMOKE_TMUX_ANCHOR="teamsmith-smoke-anchor-$SMOKE_TMUX_ANCHOR_PID"
+    tmux new-session -d -s "$SMOKE_TMUX_ANCHOR" -n anchor \
+      "while kill -0 $SMOKE_TMUX_ANCHOR_PID 2>/dev/null; do sleep 2; done" 2>/dev/null || true
```

- `cleanup()` 里那条 `kill-server` **一字未动**：正常退出/可捕获信号仍走它，立刻收。补的是**不可捕获**的那一半。
- pid 用 `$$`（外层 shell = 本轮跑套件的那个进程），不是子 shell 的 `$BASHPID`：判据是「这一轮没了才收」。
  实测确认 `$$` 落在**真正跑套件**的那个进程上：`--select` 模式下是选段子进程（外层启动器只是它的父进程），
  锚点名 `teamsmith-smoke-anchor-<该 pid>`；杀它（不杀启动器）就是 PM 复现的「这一轮被掐死」的形态。
- 不收 pid 文件、不查进程表、不发信号给别的进程；`sleep 2` 的轮询对机器成本可忽略。

### ② socket 目录的清理判据：`.tm-*` → 实际形状（`cleanup()` 里 socket 目录那段）

```diff
   if [ -n "${SMOKE_TMUX_TMPDIR:-}" ]; then
     case "$(basename "$SMOKE_TMUX_TMPDIR")" in
-      .tm-*)
+      .t-"$(id -u)".[A-Za-z0-9][A-Za-z0-9][A-Za-z0-9][A-Za-z0-9][A-Za-z0-9][A-Za-z0-9])
```

**先说核实（任务书要求先自己验，不猜）**：

- 实际形状：本机跑 `tmp_root_socket_dir tmux "tmux-$(id -u)/default"` 得到
  `/var/tmp/teamsmith-<ns>/.t-1000.AfRy34` —— 模板在 `tests/lib/tmp-root.sh`：
  `mktemp -d "$base/.${kind:0:1}-$(id -u).XXXXXX"`，`kind=tmux` → `.t-<uid>.<6 位 [A-Za-z0-9]>`。
  本轮实验里也如实出现：`…/tmp/.t-1000.SUnevw`、`.t-1000.HE4X2M`、`.t-1000.7JALAk`。
- 为什么旧前缀对不上（溯源）：P310（`57efe1cb`）当时是**内联**模板 `.tm-<uid>.XXXXXX`（该提交里的
  `smoke.sh:1024`），清理写 `.tm-*` 是对的；之后 `9453e9e3` 把创建搬进 `tmp_root_socket_dir` 并换成
  `.${kind:0:1}-…`，清理那一行没跟着改 —— 从此永不命中。
- 现场旁证：本机 `/tmp` 上积了 **1233 个 `.t-1000.*`**（另有 46 个更老的 `.tm-*`，属于 P310 那一代）。
  改动前我用**正常跑完**（非 kill）的一轮验过：`--select 0c --keep` 结束后
  `/var/tmp/p334-dev3/before/tmp/.t-1000.SUnevw` **仍在**；`--keep` 也不是原因（改动后非 KEEP 的轮次目录被删、KEEP 的轮次打印保留行）。
- 改法：逐字匹配 uid + 恰好 6 位（mktemp 的模板长度），**不用前缀通配**。本脚本只有两处给
  `SMOKE_TMUX_TMPDIR` 赋值，另一处是夹具/兜底的 `$TMP/tmux`（basename 是 `tmux`，不匹配这个形状，归临时根回收）。
  依据写进了代码注释。

## 已知边界（如实写，没做的没写成做了）

- **`kill -9` 之后 socket 目录仍会留下**（里面只剩死 socket 文件）：目录回收在 `cleanup()` 里，不可捕获的终止
  跑不到它。任务书要的是「锚点 server 不被留下」，这条已对上；目录这一半超出本次写集，实测里
  `after-final` 留了 `.t-1000.7JALAk`。
- **本机历史的残留目录没有清**（1200 多个）：它们在 `/tmp` 与 `/var/tmp` 的项目根上，可能有别人的
  在飞运行，不属于本任务写集，也不该由席位扫。
- **僵尸进程形态没验**：`kill -0` 对一个未被回收的僵尸仍为真。本仓的终止形态（`timeout` 预算、后台车道）
  父进程都会 `wait`，实测两条腿都对上；我没有构造「父进程永不 reap」的反例，也就不声称它被覆盖。
- 任务书提到的那两个 4 天前 `shim/tmux` 空转进程不属本任务（不是本仓代码），我没动它们。
- 没跑整套门禁，没跑容器门禁；选段只覆盖了前导 + §0c/§2/§0h 与 `flip-p310-socket`。
