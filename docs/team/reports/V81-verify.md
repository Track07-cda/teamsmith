## 一、③ 的「锁已持有」与「等待者已排队」各自靠什么

现场没变（真 flock 持有者 + 真入口等待者），只有夹具的放行条件换了（16678–16684）：

```bash
p66_hold_until_released "$P66D"                  # 拿到锁 → 写 hold-ready；持到 hold-release 出现
p66_run "$P66D/queued.log" 20 0 & P66_WPID=$!    # 真入口等待者，私有锁 / 私有 TMPDIR
p66_wait_queued "$P66D/queued.log" 120           # 等它自己的日志里出现排队行
: > "$P66_RELEASE"                               # 等待者已经在排队：现在才放行
```

- **锁已持有的证据**（16597–16599）：
  `flock --close -x "$P66_LOCK" bash -c ': > "$2"; for i in $(seq 1 1200); do [ -e "$1" ] && break; sleep 0.1; done'`。
  `--close` 让 flock 在 exec 前关掉锁 fd，锁只由 flock 进程持有，所以子进程的第一句 `: > hold-ready` 只在
  **父进程已经拿到锁**之后才可能执行。这条语义 P340 已用四个探针证过（V80 §1.2），本处沿用同一手法，⑨ 在
  16935 行用的是同一句。
- **等待者已排队的证据**（`p66_wait_queued`，16608–16616）：用 `grep -aq '另一套全量 smoke 正在跑'` 轮询等待者
  自己的日志。这不是「N 秒内到达」，而是「这个行为事实出现了没有」；前导多慢只把放行整体后移。
- **上界不参与任何断言**：`P66_READY`/`P66_RELEASE`/`P66_HPID` 只出现在 16594–16602（助手）与
  16680/16682/16683/16684（③ 正文），没有任何 `assert_*` 读它们；两个秒数只出现在两条 `bad` 的文案里，耗尽时
  打一行「没等到 X（…上限）→ 下面的读数无效（这是「挂住」，不是「慢」）」，段子继续跑完后面的读数
  （`bad()` 只 `FAIL=$((FAIL+1))`，不 abort，`smoke.sh:800–806`）。实测这条行是**按需出现**的：绿侧
  `ticks 102`、它触发时 `ticks 103`（§四 H2）。
- **`p66_hold 2` 与 `sleep 0.4` 的去向**：③ 只调 `p66_hold_until_released`（16679）；`p66_hold` 的调用点只剩
  ①（16631）与 ⑤（16700），`sleep 0.4` 只剩在 `p66_hold` 体内（16586）。③ 的五条行为断言（16685–16689）
  一个字未改。
- **一处真实的取舍**：`p66_run` 现在放在后台（16680），否则本段没法在等待者阻塞期间观察它的日志。

## 二、⑦ 的判据是字段关系，不是十秒带

- 旧判据在 `main:16730`：`assert_match "$P281D/w-green.log" '已跑 3[0-9]s' …` —— 那条带的两端等于把夹具的
  起跑时刻当常数（登记 30 s 前、描述 32 s 后），前导一慢就滑出带外。
- 新判据（16767–16789）：`p281_elapsed_of` 从 `；` 分段里取出 `kind=nested` 那一条的 `已跑 Ns`；
  `p281_elapsed_verdict` 用 `lo = P281_T0 − P281_NESTED_STARTED`、`hi = P281_T1 − P281_NESTED_STARTED` 判
  `ok`/`小`/`大`/`读不到`；断言（16788–16789）比对 `ok/ok`，失败时把**读到的值与端点**一起打印。
- 为什么慢前导只整体平移：`已跑` 由 `gate_lock_describe_one` 产生（`gate-lock.sh:371–386`），
  `age = gate_lock_now() − started`，而 `gate_lock_now()` 就是 `date +%s`（`gate-lock.sh:34`；全文件唯一的覆写
  是 §34d/P338 在子 shell 里临时钉住的 16835，与 ⑦ 无关）。两行都写于 `[P281_T0, P281_T1]` 之间（16781 在调用
  `p281_waiter` 之前、16782 在它返回之后），于是 `N = 描述时刻 − started ∈ [lo, hi]` 对任何前导长度都成立；
  前导变慢时描述时刻与 `T1` 一起后移，端点跟着后移，判据不换面。
- `P281_NESTED_STARTED`（16738–16742）就是写进记录的那个整数，红侧还原（16803）复用它 —— 端点与记录同源
