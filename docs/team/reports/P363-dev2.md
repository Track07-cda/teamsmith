| D 软链/硬链让 `pm.md` 指向发送者文件 | 行内 `agent:<seat>` 指向错席位，`--ack` 基线成共享行号，硬链还让「逐字节不变」不成立 |
| E 只把跳过日志从 `/tmp` 搬到 `state/` | 修第二个后果、不修第一个：一个没人主动查的日志不能替代「打开收件箱就看得见」 |

必须由提案定下来的两处（都给了判据与红侧）：

1. **数哪一份**：选「数指针行、记录不计数」。理由是未读计数回答「**我要处理什么**」，而今天的 `dev3 · 8 条新` 正是
   把记录当流量的产物；`--ack` 因此不需要跨文件发明语义，一次交付仍然让待办 +1（今天加在 `dev3.md`，之后加在 `pm.md`，
   巡检的 `未读通知 N` 大小不变、归属变真）。代价写明：升级后历史 `[auto]` 行不再计数，**不回填**历史指针行
   （补写等于伪造一个从未发生过的落点与一个没观测过的 `knock=`）。
2. **`knock=` 写在哪**：选「写在指针行的字段里」而不是「只进账本、digest 自己做身份匹配」。这样 digest 的「未敲门」
   只需数 PM 未 ack 的行（读一次就归零，不需要第二个已读通道），账本保留为跨 ack、跨轮转后的取证，两者职责不重叠。

## 3 · 设计里最容易出错的三处，与它们的防线（`design.md` §2/§4/§5）

- **`knock=` 必须是 run 级字段**：叫醒只发生在 run 的第一个事件（`state=new`），合并时若取扩展事件的值，一个
  `enqueued` 的 run 会变成 `skipped:merged`。防线：合并器只对 `knock=` 加一条「取已存在那一行」的规则，而记录行不带该
  字段 → 记录行输出逐字节不变（既有 `§13` 字节断言即证）。
- **指针行不能是第二条记录**：它不写明细，否则 `×N` 与 `state/notify.log` 的记录数分家。防线：写入侧拆成
  「明细腿 / 合并追加腿」，指针只走后者（`detail=-`）。
- **叫醒结果必须在决定之后才知道，而账本又必须能记下指针失败**：顺序固定为「先写指针、后写账本」，账本因此才带得上
  `pointer=failed`；两次写之间崩掉只丢「一次成功指针的账本记录」，而 `pm.md` 里的行本身就是成功证据。反序只能记一个
  `pending` 假值。
