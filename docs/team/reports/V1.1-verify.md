### 2 · 不变量 B（`team review <ID> --dir <checkout>`）

#### 2.1 只读性：**有效**（实证）

```
$ bash verify.sh …（B.1：detached checkout of task/B1-demo，门禁 true）
  [review exit=0]  ✓ 复验记录：docs/team/reviews/B1.md（PASS）
-- git status --porcelain 前后对照
  diff 无输出；前：[]  后：[]
-- worktree 注册 / reflog 前后
  worktree 条目数：前 2 → 后 2        reflog 条目数：前 1 → 后 1
-- 前后指纹 diff（期望：两个都空）
  git 元数据内容哈希 + checkout 文件清单：无差异
  status / HEAD / 分支 / worktree 注册 / reflog：无差异
-- review 期间真实执行过的 git 子命令（git shim 记录）
        6 rev-parse
        2 diff
        1 log
        1 for-each-ref
  写型子命令检查 ^(fetch|worktree|checkout|switch|add|commit|reset|update-ref|merge|push|rm|mv|stash|clean|remote|config|branch|tag|gc|prune|repack)$：
  → 未出现任何写型子命令（review 只读 git）
-- 复验记录的落点
  $ ls repo/docs/team/reviews/ → B1.md / B1-verify.log（写在主仓库）
  checkout 里有没有被写东西：（目录不存在）
  FETCH_HEAD 是否被创建：无（临时仓库的 origin 指向死路径，任何 fetch 都会失败/留痕）
```

方法说明（可复现）：把 checkout 的 `.git` 公共目录与 worktree admin 目录里**每个文件的内容 sha1** 前后各算一次
（纯哈希、中间不插任何 git 命令），再把 `status/HEAD/分支/worktree 注册/reflog` 快照前后 diff；
同时用一个记录 argv 的 `git` shim 把 review 实际调过的 git 子命令全量截获。
**结论：不新建 worktree、不 fetch、不改 index/reflog/HEAD、不写 checkout 里任何文件。**

> 唯一会写 checkout 的是**门禁本身**（`( cd "$revdir" && <timeout> bash -c "$TEAM_GATES" )`）——这是设计使然
> （门禁要在被验代码上跑），不是 bug；但 `pnpm install` 这类门禁会留下 `node_modules/`，PM 复验后要自己清理。

#### 2.2 错误路径：符合预期，且**不会写出半截证据**

| 场景 | 行为 | 判定 |
|---|---|---|
| `--dir` 不存在 | `✗ 目录不存在：…`，exit=1，**没有**写 `reviews/B1.md` | 可预期 ✓ |
| `--dir` 是普通目录（不是 git 仓库） | `✗ … 不是 git checkout`，exit=1，**没有**写记录 | 可预期 ✓ |
| `--dir` 是只读目录（`chmod a-w`） | gates=`true` → PASS；gates=`touch …` → FAIL（门禁日志里是 `touch: cannot touch 'gate-wrote-here': Permission denied`，被如实判成门禁失败）；无半截文件 | 可预期 ✓ |
| `--dir` 是 detached HEAD | 正常工作（这就是正路） | ✓ |
| 路径带空格 | 正常工作（`review checkout: …/space/my checkout @ df7a7810b`） | ✓ |

#### 2.3 误判面：3 种错 checkout 都会拿到 **PASS**

`cmd-review.sh` 只校验 `--dir` 是「一个 git worktree」，**从不校验它的 HEAD 是否包含该任务的工作**
（`team_resolve_branch` 解析出的分支名只写进记录抬头，没有和 checkout 的 HEAD 做任何比对）。

```
B.4 --dir = main 的 checkout（任务分支的活压根不在里面）
  [review exit=0]
  | ✓ review checkout: /tmp/v11-verify.M1THrL/wrong/checkout-main @ 6a18cc483
  | ✓ 复验记录：docs/team/reviews/B1.md（PASS）
  → 记录抬头：· 分支: `task/B1-demo` · HEAD: `6a18cc483` · 判定: **PASS**
  → 记录正文：- agent 报告：**缺失**（没有报告本身就是问题）
     变更概览：（空）
  → 期望分支与实际 HEAD：task/B1-demo = 86a44f37a…  /  checkout HEAD = 6a18cc483…   ← 完全不是一个提交
```

同族的还有：

- **B.6** `--dir` = **另一个任务分支** `task/B9-unrelated` 的 checkout → 同样 `判定: PASS`，抬头仍写 `分支: task/B1-demo`。
- **B.5** `--dir` = checkout 的**子目录**（`…/checkout/sub`）：`git rev-parse --is-inside-work-tree` 对子目录同样为真
  → 被接受，门禁在子目录里跑，记录里写的 checkout 路径也是子目录。
- **B.10** 分支已删（合并后）时 `review B1 --dir <好 checkout>` → `✗ 找不到 B1 的分支：用 --branch 指定`（exit=1）；
  加 `--branch HEAD` 能跑（exit=0），但那时 diff 基准变成 HEAD，**变更概览必然是空的**。
- **B.8** 陈旧证据：先跑出 PASS，再把 checkout 删掉重跑（exit=1）→ 旧的 `reviews/B1.md` **原样保留**（sha 未变），
  只看记录的人会以为复验通过过。

#### 2.4 B 节结论与最小修复建议（**只建议，未改实现**）

**判定：只读性有效；判定可信度部分有效。**

1. **校验 checkout 与任务分支的对应关系**（最重要的一条，能一次性堵住 B.4/B.5/B.6）：
   拿到 `branch` 后比较 `git -C "$revdir" rev-parse HEAD` 与 `git -C "$TEAM_MAIN_ROOT" rev-parse "$branch"`；
   不一致就 **die 并给出可复制的 `git worktree add` 命令**（或至少把判定降级成 `UNKNOWN` 并在记录里写明
   「checkout 与分支不匹配」）。顺带校验 `revdir` 就是仓库根（`rev-parse --show-toplevel` == `revdir`）。
2. `agent 报告缺失` + `变更概览为空` 时**不应给 PASS**（至少降级为 UNKNOWN）——
   这两件事同时出现，几乎必然意味着 checkout 拿错了。
3. 分支已被删除的复验场景：把 `branch_now`（checkout 自己的 HEAD/分支）作为 `team_resolve_branch` 的兜底，
   免得 `--dir` 已经给足了信息还要人工补 `--branch HEAD`；补的时候把 diff 基准写成 `--branch` 的实际 ref。
4. die 路径（B.8）也在 `reviews/<ID>.md` 里写一行「本次复验失败/未完成」，或把旧记录改名为 `-stale.md`，
   避免旧 PASS 记录被当成当前结论。
