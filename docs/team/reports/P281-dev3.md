## 四项修复：改法 / 绿侧 / 红侧

### F1 · 期限对齐改读**记录里公布**的 heartbeat

改法：嵌套运行的祖辈证明成功时手里就有那个 pid，于是沿它去读 `<lock>.holder` / `<lock>.runs/<pid>.run`
里公布的 `heartbeat=`，只认**活着的那一条**（pid 相符且 `starttime` 相符）。环境变量
`SMOKE_ANCESTOR_HEARTBEAT` 降级为旧写入者的兜底；两条都取不到时按自己的表预算走，但这件事必须**可见**
（`section-guard.sh` 把来源标成 `nested-fallback` / `fixture-nested-fallback`）。

绿侧（夹具 ⑧，命令见下面验收 D 的同一次运行）：持有者记录公布着可读心跳、而环境里**没有**那个变量
（调用处继续 `-u` 清掉它）→ 真嵌套运行仍按祖辈剩余设限期、开跑行注明来源，并且 `预算 60s` 不出现。
另有一条旧通道对照（环境变量单独给）仍然被接受。

红侧：把这条读法退回改动前（`SG_ANCESTOR_HEARTBEAT=""`，只认环境变量）→

```
  ✗ 34b⑧ 开跑行注明预算来自祖辈剩余（…/hb.log 中找不到 [（嵌套运行：对齐祖辈剩余预算）]）
  ✗ 34b⑧ 预算取自祖辈剩余（≤5s），不是自己的表预算（…/hb.log 中没有匹配 [超时：预算 [1-5]s]）
  ✗ 34b⑧ 表里的 60s 预算没有被用（对齐真的生效）（不该出现 [预算 60s]）
== 选段结果 ==  ✓ 150  ✗ 4        （rc=1）
```

夹具里另有一条直接钉**可见退回**的红侧：记录里没有可读心跳时仍按时结束，但开跑行必须点名
「没有可读的祖辈心跳」，并按自己的表预算收口，且不许声称「对齐祖辈剩余预算」。

### F2 · opt-out 的运行也落记录

### F4 · 写权用不可继承的证明（选②）

改法：写/删 `.holder` 之前先问 `gate_lock_holder_claimable` —— 记录不存在 / 空 / 缺 pid（旧形状）→ 允许写
（不把「读不到」当拒绝）；记录里就是我 → 允许（重入）；记录里是别人但**已经跑完**（pid 死了 / 僵尸 /
pid 复用后 `starttime` 不符）→ 陈旧，允许接管；记录里是**另一个活着的**进程 → 不许写、也不许删，并把这次
拒绝打出来。为什么选②而不是①「把 marker 从环境里移出」：marker 的路径同时出现在包装器的 `argv` 里、也能
从 `$TMPDIR` 猜出来，而「自述是持有者」本来就是自证；②把判据换成一件**继承不到**的事实 —— 记录里活着的
那个 pid 是不是我。（理由同 design.md §8。）

绿侧（夹具 ⑬）：继承 marker 的后代把 marker 改写成自己的 pid（`exec` 保住 pid）后再跑真入口 →

```
  ✓ 34b⑬ 继承 marker 的后代不许改写真持有者的记录（pid 还是它）
  ✓ 34b⑬ 记录一个字节没动（也没被删）
  ✓ 34b⑬ 它把这次拒绝打了出来（可见，不静默）
  ✓ 34b⑬ 拒绝的理由是「记录里另有一个活着的进程」
  ✓ 34b⑬ 正对照：陈旧记录（进程已跑完）→ 允许接管（不是一律拒绝）
  ✓ 34b⑬ 红侧：拆掉写权证明 → 真持有者的记录被改写（改为 …）—— 这一条断言分得出两者
```
