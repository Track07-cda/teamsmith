## 这个 change 做了什么（一句话版）

会议从「双方都看得见的共享区」变成「**一方能自己判断该不该动**」：每方有自己的读位（未读可数）、过期是可关闭的
只读派生态、敲门先过投递守卫（脏框排队而不是粘走草稿）且载荷点名「第几轮」、每方登记自己的 PM 窗口、身份按
**记录过的任一名字**（声明名 / session / 仓库名）判定，通知则带上 `task=<ID> tip=<短哈希>` 让接收方能凭自己的
账本判断「这条通知我是不是已经判过了」。

## Decisions and deviations

- **段 55 的夹具每家项目一个自己的 tmux session**（`…-meet` / `-meet-a` / `-meet-n` / `-meet-t`）。最初三家共用一个
  session：R1 起 session 是身份轴，共用会串台（未读计数互相看得见），而且 pane 的 cwd 会让「对方的 PM 窗口」被判成
  `foreign`（找不到窗口）。分开之后每个现场都是真的。
- **`tmux_has_bracket_paste_format` 从前导段可见**：它原来定义在段 6i 里，选段运行（`--select 55` / `12b-h0c`）时
  定义随未选中的段消失 → `command not found` 让整段**静默 SKIP**（假绿）。挪到 `tests/lib/tmux-cap.sh`（前导段 source），
  并让它**自带私有 socket**（`mktemp -d` + `env -u TMUX -u TMUX_PANE TMUX_TMPDIR=<dir>`），因为 M28 lint 按文件判定隔离、
  库文件拿不到 `smoke.sh` 的文件级白名单。
- **实现缺陷（本 change 的第三处）**：`team_meeting_say --knock` 调 `team_meeting_knock` 时**没传轮次** → 每次
  `say --knock` 都被「没有可指认的轮次」拒绝，什么都不入队（段 55 第一次跑就把它抓出来了）。修复：传
  `$((10#${seq:-0}))`，与 transcript 文件名的十进制同号（`0004 → #4`）。见 commit `8c1a859d`。
- **两处夹具断言口径修正**（不是放宽实现）：读完那拍不该断言「日志 +1 行」，而是断言**新增的行**里没有「叫醒 PM：」
  （写完的会议在下一拍变成「无待办：不叫醒 PM」，是正确行为）；`assert_not_echo` 的要找串从 `叫醒 PM` 收窄为
  `叫醒 PM：`（否则会命中「不叫醒 PM」这句话本身）。
- **`--select` 的段体 helper 陷阱**：段 54 定义的 `p139_*` helper 在只跑其它段时不存在；段 55 的断言只在
  `--select 54,55` / 全量下才有意义。两个新段因此在 `section-paths.tsv` 里声明 `needs`，并且把跨段 helper
  放进前导段可见的库（`tmux-cap.sh` 就是这么来的）。
- **测试隔离纪律**：段 55 与两个现场脚本的所有 tmux 调用都在**本轮私有 socket**（`TMUX_TMPDIR` 先 `mkdir -p`，
  再 `env -u TMUX -u TMUX_PANE`）与**自己创建的 session** 上；只 `kill-session` 自己的 session，从不 `kill-server`
  默认 server（这正是本仓库历史上付出过代价的那条线）。
- **`flip.sh` 的 harness 细节**：`set -u` 下 `local a="$1" b="x-$a"` 会因「同一命令先展开全部词」而报 unbound ——
  第一版基线因此静默失败；现在拆成两行，`--patches-only` 会在源码漂移时点名。
