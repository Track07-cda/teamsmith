## SUGGESTION

1. **`--json` 下 `bad-message` 拒绝不是 JSON。** `state-authority.mjs` 的 `remind-add` 在 stdin 正文校验失败时
   直接打印中文人读行（`remind-add` 分支，`if (message.error) { process.stdout.write(renderRemind(...)) … }`），
   即使调用方带了 `--json`。因此 PM 工具这条路径拿到的是
   `team_remind authority failed (rc=1): team remind add：message contains a NUL byte`（我的探针原样记录），
   而不是结构化 `{ok:false, refusal:'bad-message'}`；拒绝本身仍在任何写之前。该行在 `state-authority.mjs`，
   该文件在本分支与 main 无 diff（`git diff --stat main..HEAD -- skills/teamsmith/scripts/state-authority.mjs` 空），
   属既有 CLI 形态被新工具暴露，不阻塞本片。建议后续让 `--json` 在该分支也输出拒绝对象。
2. **`hide()` 不撤下能力证据，doctor 的 `ready` 最多可滞后一个 TTL（20 秒）。**
   `extension/team-remind.ts` 的 `session_before_switch`／`session_before_fork` 只调 `hide()`，而 `hide()`
   只重注册隐藏定义与从模型工具表移除，不发布撤下记录；`inspectRemindCapability` 的判据里没有
   `runtime.sessionId` 与当前会话的比对，只有 pane/window/进程/启动证明。所以在「进程、pane、window、
   launch nonce 都还匹配」的切换/分叉窗口内，doctor 仍会按上一条记录报 `ready`，直到 TTL 过期。
   这条是代码路径 + 常量（`REMIND_CAPABILITY_TTL_MS=20000`）的推断，**没有**端到端实测；影响有界（≤20 秒，
   下一次 `before_agent_start` 若身份有效会重新注册）。若要求 doctor 的 `ready` 与工具表严格同步，
   需要在 `hide()` 时发布撤下记录，并补一条「同一 pane 内切到无效会话后 doctor 立刻不再 ready」的夹具。
