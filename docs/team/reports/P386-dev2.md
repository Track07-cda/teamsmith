## 结论

外层横幅报的不是断言数，是**行数**：`grep -ac '✓'` / `grep -ac 'SKIP'` 把整份嵌套日志里含这两个字符的**每一行**
都数进去，而夹具自己的结果行 `== P234 key-replies-ui 结果 == ✓72 ✗0 SKIP0` 本身就带一个 ✓ 和一个 `SKIP0`
—— 于是每次绿跑都稳定多出一条断言、并把 SKIP0 报成「1 条可见跳过」。

候选把总数改为读夹具**自己的结果行**（`smoke_inner_summary()`，取最后一条带该夹具名字的 `== <名> 结果 ==`
行并要求它满足 `✓N ✗M SKIPK`）。§63 的两处（UI 快组、真 pty 面）已换；内层非零退出码照旧是红；结果行缺失、
畸形、或换成了别家夹具的结果行，都是**点名的红**，不再变成绿的 0。

## 改的是什么（原文）

旧口径（§63 两处一模一样）：

```bash
ok "62 key-replies 读数面快组全绿（…；$(grep -ac '✓' "$TMP/p234-key-replies-ui.log" || true) 条断言，
    $(grep -ac 'SKIP' "$TMP/p234-key-replies-ui.log" || true) 条可见跳过）"
```

新口径（`smoke.sh:smoke_inner_summary`，两个调用点共用）：

```bash
smoke_inner_summary() { # <日志> <夹具结果行里的名字> → 打印 "✓N ✗M SKIPK"
  local log="$1" want="$2" last
  [ -r "$log" ] || return 1                                                   # 读不到日志 → 红
  last="$(grep -a "^== ${want} 结果 ==" "$log" | tail -1)" || return 1        # 没有本夹具的结果行 → 红
  [ -n "$last" ] || return 1
  [[ "$last" =~ ^==\ .*\ 结果\ ==\ (✓[0-9]+\ ✗[0-9]+\ SKIP[0-9]+)$ ]] || return 1   # 畸形 → 红
  printf '%s\n' "${BASH_REMATCH[1]}"
}
```

调用点三态：`rc≠0` → 红（并附上能读到的结果行）；`rc=0` 但读不到结果行 → 点名红「数不出来就是红，不当 0」；
其余 → 绿，打印夹具结果行原文。**没有引入第二套框架或通用日志解析器**，契约就是夹具已有的那一行格式。
