## Decisions and deviations

- **"One actionable refusal" is implemented as one exhaustive refusal per attempt**, not one blocker surfaced per
  attempt: all pre-launch guards are judged in one pass, one report lists every blocker, each with its fix. The
  literal alternative reading is recorded in `design.md` D4 / Open Questions — if the PM wants it, only the report
  shape changes, not the guards. (The measured 5-attempt drip is exactly the reading this rejects.)
- **"The refusal's first line"** (item 2) is satisfied as the *field's own diagnosis line*, which is the output's
  first line whenever the field blocker is first (guard order makes it so) — no banner line above it. Recorded in
  `design.md` D3 with the composite-report caveat.
- **`--branch` is strict when declared**: the worktree must be on exactly the declared name (another same-task
  slug is refused, with the fixing command). Without `--branch`, any same-task branch is accepted and both names
  are printed. This keeps "another task's branch is still refused" while fixing the churn.
- **Scope beyond the brief's `specs:` list**: the delta also modifies the routes requirement (for the pasteable
  fixes) and the stack requirement (its refusal joins the one report). Neither loosens a guard; both are needed by
  item 4.
- **The hint's second leg is a round record, not a JSONL parse**: `sid` + `sid_bytes` in `state/<agent>.env` keep
  the tool's existing "stat the session file, never parse it" discipline; the death classifier stays the only
  classifier. Alternatives (mtime, JSONL usage parsing, blocking) are rejected in `design.md` D6.
- **P70 accounting is in the apply plan** (tasks 4.4/5.3): whichever sections the new legs land in must be
  registered in `section-budgets.tsv` (measured band) and `section-paths.tsv`, with `--budget-check` and
  `select --check` green.
