## 1 · §42：夹具会话只剩 `dev` 一个窗口（夹具缺陷）

### 裁定与原始证据

九条红全是**级联**，首条是它，其余八条都在它下游：

```

✗ P67 生产路径：team_input_box_state 报 BUSY（[input_box_state=UNKNOWN
delivery_verdict=NOPANE
box_text=[]
... 里找不到 [input_box_state=BUSY]）
```

`UNKNOWN` / `NOPANE` / `box_text=[]` 三个读数一起出现，只有一种形状：**目标窗口不存在**。
纯帧半段（帧文件存在性、绿侧/红侧、两条路径同源、覆盖层优先权，共 36 条）**全绿**——所以问题不在帧、
不在判据、也不在 Pi 版本。

把它钉死的是同一次补跑里的下一段：§44 用**同一个** `$SESSION`、同一段构造（kill dev → new-window → 采帧），
它绿了，而且它多打了一行 §42 没有的行：

```
✓ 44·P80：夹具会话原本不在（选段运行没带上 §12b-h）→ 本节自建 teamsmith-smoke-1095736（真 pane 断言照跑）
```

也就是说：**§42 动手时会话还在（helper 判它存在、什么都没建），§42 收尾时会话没了**，于是 §44 只能重建。
`smoke_live_session_ensure` 只判「会话在不在」（`tmux has-session`），不判「会话里还有没有别的窗口」；
而 §42 的第一件事正是杀掉唯一那个窗口。

### 机理

```bash

team_tmux_starts_server() { case "$1" in new*|split*|respawn*|start*) return 0 ;; …
team_tmux_strip_identity() { for v in $(compgen -v TEAM_); do unset "$v"; done; }
```

而 `TEAM_ROUTES_*` 落在 `TEAM_` 命名空间里。容器内实测（stub tmux 打印它看到的变量）：

```

-- team_tmux respawn-pane（可能起 server）

-- team_tmux list-windows（不可能起 server）
verb=list-windows seen_TEAM_ROUTES_FAKE_LAUNCH=[1] seen_TEAM_ROUTES_WINDOWS=[/tmp/p319-d/winreg]
```

后果是自洽地断掉：`new-window` 不记账 → 窗口注册表空 → `list-windows` 说没有窗口 → shim 的
`respawn-pane` 分支看不到 `FAKE_LAUNCH=1` → 不写 `(nonce, pid)` 启动证据 → 派单如实报
「未能确认启动」。**产品没错，是夹具的载体被产品按设计清掉了。**
