## 实现要点（对照 delta 场景）

### `background-jobs#The lane's tool surface teaches suspend-and-wake as the default`

- 三个常量单一来源：`SUSPEND_DEFAULT`（起完默认结束回合；完成叫醒是正常收割点）、
  `INLINE_WAIT_EXCEPTION`（三条同时成立：预算 + 卡住下一步 + 没有别的可推进）、
  `INLINE_WAIT_BUDGET = '~2 minutes'`。它们喂给 `team_bg_run` 的 description / promptSnippet /
  promptGuidelines / 起作业回执，以及 `team_bg_wait` 的 description / promptSnippet（`team-bg.ts` 顶部）。
- 退休措辞零命中，且不再有「叫醒 = 损失」：夹具逐字搜
  `Harvest it with team_bg_wait before you end your turn`、`harvest every job with team_bg_wait before ending your turn`、
  `before you end your turn`、`before ending your turn`、`must not end with unharvested`、`costs a turn`，
  并按 `/\b(cost|penalt|loss|waste)/i` 扫一遍；命中即打印 offender 并判红。
- 完成叫醒的合并消息**逐字未动**（继续 `[team-bg] N background job(s) … Run team_bg_wait <id> …`），
  夹具钉住：两条同拍完成 → 恰好一条消息、点名两个 id、指 `team_bg_wait`。

### `background-jobs#The lane's ledger makes the wait pattern countable`

- `start id=<id> pid=<pid>`：与 `.job` 记录**同一点位**、返回 job id **之前**写；spawn 失败（pid=0）
  不记 start（只有既有的 `spawn-error …`）。
- `wait id=<id> outcome=<harvested|running|interrupted> waited_s=<秒>`：每次 `team_bg_wait` 返回一行，
  `waited_s` 只量**本次调用**自己等的时间（已完成作业的收割 ≈ 0；原地等 ≈ 实际等待段）。超时 = `running`，
  AbortSignal 中止 = `interrupted`；两者都撤销收割意图（作业完成时照常叫醒）。
- 既有行形状未动：`wake count=… ids=…`、`settled-with-unharvested=… jobs=…`、`spawn-error …` 逐字节不变
  （夹具钉住前两类 + 用空 PATH 夹具逼出真 spawn-error 行）；CLI 的 `stop …` 面（`cmd-bg.sh`）本轮未改，
  其形状由既有 §58 夹具（`team-bg-stop.sh`）把守。
- 「起了就等」与「挂起」只凭账本可区分：夹具同时跑 inline（`start` → `wait`，中间无 settled 点该 id，
  `waited_s=1.1`）与 suspend（`start` → `settled-with-unharvested=1 jobs=<id>:running` → `wake` →
  `wait waited_s=0.0`），断言两条真值不同。

### `background-jobs#A restart keeps the job's evidence but not the job table`

既有行为（`session_start` 清 job 表、作业 detached 照跑、记录/日志留盘）—— 本轮**首次**用夹具钉住：
第二个会话对旧 id 报 `unknown job … (this session started: (none))`、不收养、不剪记录，旧作业进程不受影响；
`team bg list` 读旧记录的路径由既有 `boundary` 规格与 §58 夹具覆盖。

### `notify-and-inbox`（MODIFIED）`A turn-end notification appends one inbox line and knocks once`

- 在跑集合从**车道自己写记录的目录**读：`laneStateDir(cwd)` 复刻 team-bg 的 `findRoot` + `stateDir`
  规则（显式 `TEAM_STATE_DIR` 优先；否则「cwd 的 worktree 带 `.pi/team/config.sh` → 它自己；`TEAM_ROOT`；
  最近的带 config 的祖先；git 主工作树」）；**不用** notify 自己的 root（`--git-common-dir`，落主工作树）
  顶替；两侧分歧时只记一行日志点名。
- 逐条 `(pid, start-time)` 活体验证（`/proc/<pid>/stat` 第 22 字段，`comm` 按最后一个 `)` 切）；死 pid、
  pid 复用、目录/记录读不了、软链-FIFO-目录记录、pid 非正整数、缺 `start=` 一律**跳过** —— fail-closed：
  判定的不确定方向永远是「不挂起」，绝不假造挂起。
- 完成 + 在跑非空 → `[auto·suspended]` + `awaiting=<id>[,<id>…]`，**省略** `⚠ 未提交 N 个文件 · ` 前缀
  （`uncommitted=<n>` 字段保留）；未完成 + 在跑非空 → 保持 `[auto·interrupted]` + `awaiting=`；其余形状
  逐字节不变。去重键含 tag + summary + revStamp，新形状与旧形状不互吞。

## 未解问题 / 局限（不隐藏）

1. **反向守卫的「真账本未动」以标记扫描为承重判据**：真项目是活着的（watchdog/其他席位会写
   `state/`），所以严格的整目录哈希会在并发写入时假红。入口对**夹具标记**（`bgl<pid>`，出现在夹具 job id /
   记录 / 账本行里）做硬断言；快照前后不一致时只打印 `·` note 并列出差异哈希。若 PM 要更严的形态，
   可在静态窗口里复跑同一条命令（标记扫描永远有效）。
2. **入口自己的 stdout 捕获日志**：用团队后台车道跑本入口时，它的 stdout 会落进真项目 `state/bg/`，
   里面含夹具 job id。入口按输出指纹 `[bg-ledger-run]` 把「自己捕获的输出」与真泄漏分开（前者是 note）。
3. **身份判据只做 `(pid, start-time)`**：与 design 决策 4 / delta 的文字一致；CLI 写侧多一条 `pgid` 实时
   复核（`team bg list/stop`），挂起判定不做 —— 方向是 fail-closed（少判在跑，不假造挂起）。
4. **Linux/`/proc` 依赖**：读不到 `/proc/<pid>/stat` 一律不算在跑（fail-closed）；这与 `team bg list`
   同源，非 Linux 平台没有额外分支。
5. **§58 的 `stop …` 行**：本轮没改 `cmd-bg.sh`，其形状由既有 `team-bg-stop.sh` 夹具把守（我在选段
   §13c 里只跑了 harness；§58 不在本次选段里）。
6. **未跑全套 smoke**（见上「额外回归」）；B 刀折回 §13/§13c 与 section-select 映射登记后，那种一致性
   由 B 刀的门禁承担。
7. **窗口期内口径半新不旧**：A 刀落地后工具面已是新口径，而工人提示词（B 刀）还是旧口径 —— 方向相同、
