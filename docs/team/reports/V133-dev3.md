## F1 · 缺席场地下 bounded 的独立检查失去唯一执行证据

**问题.** design `Goals` 第 2 条（`design.md:21`）与 key-replies delta 的 `Missing read-volume evidence is not a satisfied bound`（`specs/key-replies/spec.md:16–20`）都要求：观测器缺席时坏最新、不可枚举、正文不可读等独立断言仍照常执行并给原判定。改前这条唯一被执行的地方是强制缺席的整组 replay（`key-replies.sh:1025`）。改后正常 bounded 在 §62 里跑（观测器在），短样本只调「观测专属入口」三条路径（`design.md:31–40`）——「跳过之后继续跑权限/正文断言」这段在任何一次运行里都不再发生。

**源码反例.** `key-replies.sh:674–676` 的 skip 之后，718–751 的 0111 金丝雀、list/summary/show、0000 正文断言无条件继续执行；全仓带 `TEAM_REPLY_NO_PROC_IO=1` 跑这段的只有 1025（1034 是同一次失败后带 trace 的重跑）。

```
$ grep -rn 'TEAM_REPLY_NO_PROC_IO' skills/teamsmith/tests | grep -v 'lib/proc-io.sh'
key-replies.sh:1016:  if TEAM_REPLY_NO_PROC_IO=1 bash -c ...
key-replies.sh:1025:  TEAM_REPLY_NO_PROC_IO=1 ... --select bounded,flip ...
key-replies.sh:1034:  TEAM_REPLY_NO_PROC_IO=1 ... bash -x ... --select bounded,flip ...
```

**为什么是缺陷.** 这同时违反 `references/openspec.md` §4 第 2 条「每个场景都要能失败」：那条 AND 子句在改后没有任何执行能让它红，而它正是 PM 问题 2 要的答案。

**最小修法（推荐 a）.**
(a) 把 delta 的 AND 子句改成能证伪的写法：独立断言在**正常** bounded 中照常执行并给原判定；缺席样本证明观测入口在它们**之后**被调用、并在任何观测专属准备之前返回（配合 F2 的文件断言，这条子句重新有执行）。
(b) 让缺席样本同时跑 bounded 的非观测断言 —— 代价是 10 万槽准备回来，与「不为它准备正常大存储」冲突，不建议。

## F2 · 「先于观测专属准备」没有断言，缺大存储前提时也能绿

**问题.** `design.md:33` 要求 bounded 观测入口「能力检查发生在这条函数的任何 IO 专属准备之前」；delta 的 focused-sample 场景也要求 `before observer-specific large-store preparation`。样本只检查三条诊断、两条跳过、结果行与退出，没有任何一条检查「准备没发生」。

**源码反例.** `key-replies.sh:678–679` 的 `kr_new_proj bounded-mid` + `kr_make_big_store "$mid" 60`；full_scan 那边是 949–950（10 万槽）。把 945 的 `kr_io_supported || return 9` 挪到这两行之后，样本照样拿到 9、照样三条诊断、照样收口 `✓0 ✗0 SKIP2` —— 一次 400 MB 的准备对判定完全隐形。

**最小修法.** 样本调用 bounded 观测入口与 full_scan probe 之后，断言样本自己的项目里没有出现观测专属准备（`<proj>/.pi/team/state/key-replies/index.v1` 不存在、`$TMP` 下没有第二份 10 万槽索引）。一条断言，把「顺序」变成可证伪的。

## F3 · 「父级非零」这条证据不具区分力

**问题.** `tasks.md:9` 与 `design.md:65` 用「scratch 副本 … 父级非零」证明样本失败会传到父级退出码。但三类反例（tasks 2.1/2.2）与样本判定共用同一份处理函数，且都排在同一个 `--select skip-path` 里；共享处理被改坏时，每类反例「还原后绿」的半步读的是同一份坏代码 → 至少三条红。

**具体反例.** 副本里把 bounded 的缺席分支改成静默 `return 1`，同时把父级的消费改成 `out=$(kr_skip_sample_collect) || :`（吞掉失败）。该次运行的结果：

- 父级 exit 1，**因为**三类反例的还原侧红；
- 「诊断集合」那条具名断言不出现 —— 但「父级非零」这条证据照样满足。

所以 rc≠0 分不出「父级真的消费了样本失败」和「父级吞掉了它」。旧实现里 `key-replies.sh:1029–1031` 用的是「末行 ✗0」这种具名判据而不是 rc，正是同一个理由。

**最小修法.** `tasks 1.3` 把证据改成两件具名事实，并写明 rc 不算证据：
① 损坏共享处理的副本里，父级打出**具名的** `✗ skip-path：…`（点名缺的诊断/分类）；
② 再做「父亲吞掉样本失败」的副本：它仍因上面的反例红而 exit 1，但**不得**出现那条具名断言 —— 这才是「父级消费了样本失败」的证据。
两处都在同一 `--select skip-path` 里跑，成本一次运行。

## F4 · 三类反例的入口没定：现有唯一入口会自检递归

**问题.** `design.md:63` 写「只在 tests 的隔离函数/源码副本中变异」，并要求反例「只调用『收集短样本→原证据判定』，不重新进入整个 skip-path 组」。但脚本只有 `--select <组名>` 一个入口（`key-replies.sh:46–58`）；「源码副本 + `--select skip-path`」会在副本里再跑三类反例 → 递归；换新组名或新开关又违反 design 自己的「不建第二入口体系」「不新增产品开关」。

**最小修法（推荐）.** 用 subshell 里的函数覆盖做变异，不用副本：

```bash
( kr_bounded_observe() { return 0; }; out="$(kr_skip_sample_collect)"; ... )   # 反例只在子 shell 生效
```

正例仍跑真实函数（覆盖只作用于反例的 subshell），不需要副本、不需要新入口、不递归。把这一句写进 `design.md` §3 与 `tasks 2.1` 即可；若坚持用副本，必须同时写明副本用哪个入口只跑「样本+判定」。

附带一条实现约束：样本自己的结果行不要复用 `== P234 key-replies 结果 ==` 前缀 —— `smoke.sh:1124–1131` 的 `smoke_inner_summary` 按这个前缀 `tail -1` 取数，复用会让人和它都绑到错的行。
