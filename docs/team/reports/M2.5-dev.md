`memory.md` 的小节（对着任务书的 1–7 点逐条落）：

1. **Why the PM is the role that needs memory** —— 唯一跨任务/跨重启的角色；预防的三类失败：决策被反复重新讨论、
   约束静默消失、**"context says X, disk says Y" 漂移**（写明了那次真实事故：一份旧 skill 副本活在压缩后的上下文里）。
2. **The three layers, and who trusts each one** —— 表格：会话记忆（magic-context）/ 磁盘证据 / skill 版本状态；
   规则一句话写死：**结论落盘，"我记得"永远不是证据**（指向 creed #1、#6）。
3. **What belongs in project memory** —— 一条一个独立事实；三族：项目事实 / 工作规则（信条）/ 项目特有的坑；
   指向 `templates/memory-seed.md.tmpl` 作为起点；**不该进记忆的**用表格给出替代位置（当前任务状态→BOARD、
   秘密→不写、长日志→报告、证据→原件、明天就过期的→roadmap leftovers 或 note）。
4. **When to read, when to write** —— 对应 PM 提示词的两个时刻（开局先 search 再重新推导；收尾先落盘再写跨任务规则；
   "do later" → note/roadmap）；**记忆与磁盘冲突时：磁盘赢，然后修记忆**（并解释了为什么不取"折中"）。
5. **Lifecycles** —— 表格：`/compact`、重启（`pi -c`）、`/reload`、移动 worktree（session 按 cwd 归属 → 指向
   protocol §3 与 troubleshooting §2）、换机器；外加一份**诚实的"它不做这些"**清单（不是 stateless-safe、
   不跨机器同步、不与其他 agent 共享、不验证任何东西、session 被删记忆随之消失）。
6. **Working without it** —— `team doctor` 的「not detected」告警是什么（CLI 仍打中文，这里按语义描述、不引中文字面量，
   与 M4.1 的 no-CJK 不变量一致）；没有它时的阅读例程（`DECISIONS.md`、roadmap leftovers、最新 thread/review）；
   失去什么（对压缩历史的检索）与**不**失去什么（所有证据都在文件里）；顺带点了 `TEAM_PI_SETTINGS_FILE` /
   `TEAM_REQUIRE_MAGIC_CONTEXT=1` 两个键并链到 `config.md`。
7. **Keeping another PM (or a human) in sync** —— 记忆是 per session/per machine，所以别人需要的东西必须落盘或进
   `team meeting`；交接清单指向 BOARD/DECISIONS/最新 review/threads + memory seed。

## Decisions and deviations

1. **不重复信条与协议**：任务书要求"链而不是复述"，所以每处规则都写成「一句话 + 链接」；新文件里没有重新定义
   独立复验、status is a promise、容量底线等已有规则，只说明它们对**记忆**意味着什么。
2. **不写 magic-context 的工具语法与安装步骤**：安装属于 pi 的包管理/扩展自身文档，`ctx_*` 的参数形状随扩展版本
   变化（本机是 0.42.3）。技能只做两件事：检测它（`team doctor`）和定义**纪律**（什么进记忆、什么时候读写在文件里）。
   理由：把易变的外部工具用法抄进 skill，正是 M2.5 想避免的"上下文说 X、磁盘说 Y"的另一个来源。
3. **不引中文字面量**：`team doctor` 未检测到 magic-context 的那句提示目前是中文，我按语义描述并注明"CLI 输出仍是中文"
   （M4.2 才翻 CLI）。这样既不破坏 `references/**` 零 CJK 的验收，也没有把中文原文当成契约。
4. **未改 `references/config.md`**：两个键已在表里（第 74–75 行），任务书写明"可能已有"。
5. **未碰 `scripts/**`、`tests/**`、`templates/**` 逻辑**（任务书 note：V4.0 正对本分支基点 `cd8bdb9` 做对抗验证）。
   模板只加了一行文档句子，`git diff` 可核对（`templates/memory-seed.md.tmpl` 3 行）。
6. **本次没有给新文件加 smoke 断言**：一方面 `tests/**` 在并行验证期间不可动，另一方面现有 14b/CJK 不变量已经覆盖
   `references/**`（上面用注入证明了）。若 PM 想让它更硬，可另开一条"每个 references/*.md 都被 SKILL.md 的
   deeper-reading 表收录"的断言 —— 那属于测试任务，我没有越界。
7. **报告格式**：英文标题 + 中文正文（`docs/team/**` 仍是中文批次）。

## Not verified / risks

1. **没有在真机上验证 magic-context 的"未安装"路径**：本机装了 0.42.3（`team doctor` 报 `✓`），所以第 6 节的
   降级描述来自 doctor 的代码分支与既有文档，不是我实测卸载后的行为。要实测需卸载扩展，代价大且会动 PM 自己的记忆。
2. **`/reload` 后"旧 skill 文本仍可能留在上下文里"**这一条，我引用的是既有结论（SKILL.md 的版本检查机制与
   `team version --check` 的存在理由），没有在本会话里复现一次 `/reload` 漂移。
3. **记忆条目的"保质期"没有量化**（我只给了判断标准："明天就过期的不要进记忆"）。量化需要真实的使用数据，属于后面的
   观察项。
4. **没有覆盖多人/多机器同时用同一项目的场景**：第 7 节说了"必须落盘/走会议"，但没有展开"两个 PM 同机并行"的冲突处理
   （现有 SKILL.md 有 `TEAM_REPLACE_FOREIGN_PM` 之类的守卫，那是 PM 生命周期问题，不是记忆问题）。
5. **行数**：128 行落在任务书给的 120–180 区间内，但如果 PM 希望再压缩，最可裁的是第 5 节的表格细节（lifecycle 的
   "what to do" 列）而不是第 2/3 节。
