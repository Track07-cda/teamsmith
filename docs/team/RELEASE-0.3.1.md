## 二 · 门禁与 CI（写给仓库使用者）

- **普通推送不再跑整套**：`--floor` 跑产品地板，改动路径只加相关段；未知路径仍退回全量（安全方向）。
- **地板切片并行**（N=4，按段 key 的稳定哈希）：并集由 CI 里一个独立作业断言「恰好等于地板」，缺片/被收窄/被取消都判红。第 4 片估算 45.4 分（余量 11.5 分）。
- **门禁的私有锚点不再泄漏**：外部 `kill -9` 之后锚点 2 秒内自己消失；socket 目录回收形状修对（此前每轮留一个空目录，本机曾积 1233 个）。
- **两处「时红时绿」修根**：运行登记的 EXIT trap 武装得太晚（前七百行落 TERM 就没人删，等满 300 秒再红）；`§34b` 里最后两处墙钟窗口换成确定性条件。
- **一条死了两个版本的断言被救活**：`§36③` 的红标检查拿带 ANSI 的串比对已去色文本，永不命中；现在匹配串同样去色，并配正向对照——仪表坏了自己报红。

## 四 · 发布清单（每条都要有读数）

1. 版本号六处一致：`skills/teamsmith/scripts/lib/common.sh` 的 `TEAM_VERSION`、`package.json`、两个 `SKILL.md` 的 `metadata.version`、`CHANGELOG.md` 的标题、`install.sh`（如有）。`team version` 报 0.3.1。
2. `CHANGELOG.md` 新增 `## v0.3.1（2026-10-21）`：只写用户能感知的变化 + 升级须知（npm 用户重装即拿到四个入口）+ 内部卫生一段。
3. **最终组合验收**：合并后树上跑一次受影响选段的并集（不是整套），加 `openspec validate --all --strict`、账本禁令、`--loop-check`、`--check`。
4. **容器验收**：在固定镜像里跑 `--floor`（分片或全套），记录用时与红数；**不为此提高一小时上限**。
5. **发布工具自检**：`tools/release-check.sh`（版本、公开面泄漏扫描、三条安装路线）。
6. **npm 实装复核**（0.3.0 就是在这步抓出四个入口缺失）：从 registry 装一次，验 `team version`、`team help`、四个入口与信号闸门。
7. 推送：只推 `main` 与 `v0.3.1` 一个 tag；npm 走 stage + 用户在网页 2FA 批准。
8. 发版后：`git bundle --all` 备份、删已合并分支（合并即删已在规则里）。
