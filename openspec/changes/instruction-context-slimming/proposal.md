## Why

The shared AGENTS block currently repeats PM operations, worker dispatch instructions and reference procedures; P389 measured 60,297 bytes across the generic AGENTS template, PM template and daily SKILL source. That is not one seat's startup payload: roles receive different prompts and SKILL/references are read on demand. A shorter role-specific entry will reduce repeated material without dropping required duties, and existing projects need an accurate way to refresh it.

## What Changes

- Make the generated AGENTS block a short cross-seat constitution: roles, reading order, ownership/security/authorization boundaries, essential evidence and delivery rules, and short statements that existing specs require on this surface. Move operational detail to the existing skill/references, not to a new rule registry or generator.
- Keep the PM prompt independently usable at startup: immediate commands and decisions, verification/authorization boundaries, user-facing publication and writing duties, and the background-job contract. Keep the daily SKILL command index and point to detailed runbooks instead of retelling them.
- Keep worker dispatch self-contained on its worktree/branch/brief, security and cross-project boundaries, three legal turn endings, background-lane applicability, evidence, commits, report path and settled delivery. Correct contradictory prose about local/remote delivery and the report template without changing launch, notification, model/SID selection or lifecycle code.
- Align protocol/workflow/generated-PROTOCOL prose with the existing specifications and implementation: disclose selected versus full gate scope; distinguish local delivery from PM-directed remote delivery; report stopped workers without pulse auto-resume; describe task categories rather than seat models; name the actual capacity contract; treat performance measurements as non-blocking readings.
- Align the shipped reply duty with the accepted marker-capture contract (`key-replies` as modified by P395, D213–D216): the complete user-facing reply is the normal answer carrying one final control line, the directed PM extension publishes its sanitized body, the marker is removed from the final transcript and from Pulse, and `team reply post` stays manual backfill/recovery only. No default post-then-repeat, temporary-file or heredoc step survives. That requirement text is owned by P395/P396; this change consumes the landed wording and does not re-specify the obligation.
- Specify and test the explicit `team init` refresh of a well-formed managed AGENTS block without `--force`: the delimiter pair is the only update surface and every byte outside it — ordinary headings, project rules, marker-looking text quoted in prose or a fenced example, ordering, line endings and whitespace — is preserved. Legacy `pi-team` conversion is line-scoped for the same reason, so an outside legacy example survives. Ordinary quotes and indented examples are content, not errors, and LF/CRLF/mixed endings or a missing final newline are supported inputs rather than normalization targets; only a shape that is not one balanced pair, or a file that ends inside an unclosed fence with no pair, is refused loudly with the file byte-identical instead of being silently 'refreshed'. Cover legacy markers, append/create and idempotence, and plan the smallest correction inside the existing writer where today's code cannot keep that promise. Ship a short custom-placement rule on the AGENTS and PM surfaces with its detailed home in `references/migration.md`. Existing-config bootstrap is not the refresh route. Document init's other writes, render defaults and non-transactional behavior rather than promising an AGENTS-only operation.
- Reuse existing install-shape, smoke and task-model-routing fixtures. Strengthen marker/count-only re-init coverage with file/result comparisons and scratch mutations; use independent rule-by-rule reading, not a new prose guard, to decide whether required duties survived. Record before/after sizes as evidence, not a performance budget.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `init-skill`: role-specific organization of the instruction surfaces delivered by initialization, and observable explicit refresh of existing-project AGENTS through normal init. The delta adds these contracts; it does not relax dispatch, writing-discipline, key-replies, watchdog, verification or boundary obligations.

## Impact

Intended apply surfaces are `skills/teamsmith/templates/{AGENTS.section.md.tmpl,pm-prompt.md.tmpl,PROTOCOL.md.tmpl}`, the text produced by `team_build_prompt` in `scripts/lib/cmd-agents.sh`, daily `SKILL.md`, `references/{protocol,workflows}.md`, and the existing install-shape/smoke/task-model-routing fixtures. `design.md` maps each source to its retained summary and detailed destination. The existing init writer is corrected in place (a pre-scan plus anchored scanning in `team_write_section` and the legacy marker conversion inside `skills/teamsmith/scripts/lib/cmd-project.sh`) so that the outside-text promise holds; no new CLI mode, config key, dependency, migration command, marker framework or gate section is proposed. Shared instruction edits are serialized with P393 and P396: the reply section consumes P396's landed `key-replies` text, and this change neither restores the post-then-repeat default nor re-specifies that obligation.

This proposal does not update this repository's live AGENTS, config, skill installs, ledger or running sessions. Its 28-line / 1,988-byte project-only discipline currently inside the managed block must later be preserved outside the markers under a separately previewed and authorized adoption diff; it must not be copied into the generic template. Source verification, shared-source landing, explicit project refresh and PM reload remain distinct decisions. Apply is blocked until formal PM proposal ACCEPTED and independent substantive proposal review; archive remains the PM's action after independent implementation verification and user confirmation.
