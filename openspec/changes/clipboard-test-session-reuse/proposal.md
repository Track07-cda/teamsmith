# Proposal

## Why

`panel-b2.sh` 的 clipboard 场景有四次重起面板只为切换假工具输出和重置下一条草稿，而非验证冷启动。限定的两条件实跑已证明同一面板可经真实按键重置并分别取得 Wayland/X11 的不同数据；只值得减这处准备，不据此承诺总时间收益。

## What Changes

- 在同一 `scenario_clipboard` 中先将三处图像等待改为观察真实图片及对应草稿/理由状态，再替换第一至第五子例之间的四次准备：两个假工具读取本次私有目录的普通模式输入文件，面板不因这四次切换而重启。两项在同一次 apply 完成。
- 八个子例及原具名断言均保留：七个主动粘贴子例各执行真实 C-v 和相应工具/文件/草稿验证；未按键子例保持零 C-v、写信关/开两段观察。下一例草稿用真实写信键操作重置，不能只写磁盘文件。
- 静态目标为八次 bundle 启动降到四次；保留首次、理由模式、不同 team-cli 接口、未按键冷启动。只替换三处等待的观察条件，原等待引擎/稳定性/上限、键节奏、挂起及两段五秒观察、其它场景和恢复覆盖均不缩减。
- 不增加产品开关、缓存、服务、runner 或永久检查段。模式输入和实际状态等待替代四次原重启准备，不把本次样本的调试断言加成新门禁配额。
- 后续由非作者跑一次正常完整 clipboard 和必要 C-v no-op 短坏腿/失败接线；实现者只实现/静态，合并后核字节与必要短检，不重复完整 b2/§38。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `verification`：剪贴板条件切换共享活面板，同时保留逐例真实证据、失败返回和不同冷启动接口。

## Impact

- 未来实现路径只涉及 `skills/teamsmith/tests/panel-b2.sh` 的 `scenario_clipboard`；它已经由原 `38` 路径表登记，调用入口与选段语义不变。
- 产品、bundle、隔离/等待库、其它面板/设置场景、正式 spec、配置和 CI 均不在本规划的实现写集；临时坏腿仅在非作者的自有副本里构建。
- 本次只有一个两条件旧/候选样本，不是原八条件全验。候选两个屏幕 token 等待被路径换行误伤且被随后断言覆盖；正常默认磁盘路径也能跨同一 token，不仅是样本嵌套问题。保留 16.812s/84.018s 及两次等待错误，不称全绿或提速。未来唯一一次非作者完整 clipboard 走已确认的默认长路径，同时覆盖三处观察替换和四次准备复用；不先跑短路径再补一轮。
- 先独立方案审阅并由 PM 记录接受，再另派 apply；本提案不授权实施或操作真实团队。
