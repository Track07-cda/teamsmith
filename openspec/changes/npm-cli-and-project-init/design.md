# Design: `npm-cli-and-project-init` — a global npm CLI, and `team init` installs the project skills

## 1. Context

Read-only recon against this checkout (`.worktrees/dev2`), measured 2026-09-22.

- **The package has skills, no CLI.** `package.json`: `name: teamsmith`, `version: 1.42.0`,
  `pi: { skills: ["./skills"] }`, `files: ["skills/", "install.sh"]`, **no `bin`**. `npm pack --dry-run --json`
  → 162 entries / 1 489 392 B packed / 4 756 517 B unpacked (skills + install.sh + LICENSE/README/package.json);
  nothing named `bin`. So `npm i -g teamsmith` installs a package that offers no command, and the three install
  routes (`pi install git:…@tag`, `pi install -l <checkout>`, `./install.sh` → `~/.agents/skills`) are all
  machine-global — none of them is an `openspec init`-like per-project step.
- **What npm does with a `bin` entry (measured with a private npm probe; the recipe is in
  `docs/team/reports/P37-dev2.md` §3).** `npm pack` keeps the file's own
  mode (644 in the tarball for both a `#!/usr/bin/env node` ESM file and a `#!/usr/bin/env bash` script);
  `npm install -g --prefix <T> ./pkg.tgz` makes `<T>/bin/<name>` a **symlink** to
  `<T>/lib/node_modules/<pkg>/<target>` and **chmods the target 755**; both shebangs then execute. Package mode
  and the shim are npm's job — the choice between the two shapes is not about POSIX permissions.
- **Pi's skill search paths** (`pi` `docs/skills.md`): global `~/.pi/agent/skills/`, `~/.agents/skills/`;
  project (after trust) `.pi/skills/` and `.agents/skills/`; packages via `skills/` or `pi.skills`; settings
  `skills`; CLI `--skill`. `.pi/skills/` is already in use in this very repository — ten tracked `openspec-*`
  skills generated by `openspec init --tools pi`.
- **The CLI's own locations.** `team_skill_dir()` (`common.sh:28`) resolves the symlink chain around
  `BASH_SOURCE` and prints the skill root; `team` exports it as `TEAM_SKILL_DIR`, so the sibling init skill is
  `$(dirname "$TEAM_SKILL_DIR")/teamsmith-init` and the package root is `$TEAM_SKILL_DIR/../..`. That resolves
  for an npm install, a checkout, a symlinked `~/.agents/skills/teamsmith`, and a copied one.
- **Team windows do not need the project copy.** `team_pi_args` (`cmd-agents.sh:71`) injects
  `--skill "$TEAM_SKILL_DIR"` (the running CLI's own skill directory) plus the three `-e` extensions; smoke §18b
  R6 pins that rendered command and that it never names `teamsmith-init`. The project-local `.pi/skills/` entry
  exists for **the user's own session** in that project (the `openspec init` model), not for dispatch.
- **The panel does not go through a bin.** `panel/src/data.ts:231` spawns `bash <cli>` directly, so a wrapper
  adds a process only to shell invocations of `npm i -g`'s `team`.
- **`team doctor` already checks bash** (`cmd-project.sh:331`, `BASH_VERSINFO[0] -ge 4`) and prints
  `skill: $TEAM_SKILL_DIR ($TEAM_VERSION)` in its header; `team version --check` has an 安装方式 row
  (`team_skill_install_kind`: `git` | `copy`) for the skill directory.
- **`team init` today** = config + docs skeleton + AGENTS section + `.gitignore` (flags `--session --agents
  --vcs --gates --docs --pm-window --model --force`; unknown flags die). `bootstrap` calls it **only when
  `.pi/team/config.sh` is absent** (`cmd-bootstrap.sh:243`) and `--print` returns before that call.
- **Size of the source tree.** `skills/teamsmith` is 46 MB in a developer checkout, of which 43 MB is
  `scripts/panel/node_modules` (ignored by `skills/teamsmith/scripts/panel/.gitignore`); the tracked payload is
  159 files / 4.9 MB. An npm install carries the packed payload only (no `node_modules`). This matters for
  `--copy`, which must not clone a developer's build directory into a project.

## 2. Decision 1 — the bin shape: a thin Node wrapper (`bin/team.mjs`)

| | `bin: {"team": "skills/teamsmith/scripts/team"}` (bash directly) | `bin: {"team": "bin/team.mjs"}` (wrapper) |
|---|---|---|
| POSIX install + run | works (measured: npm chmods the target 755 and symlinks it) | works (same mechanism; measured) |
| Windows `npm i -g` | npm writes `team.cmd`/`team.ps1` that cannot execute a `.sh` target — the failure is a Windows `CreateProcess` error with no hint | the shims run `node bin/team.mjs`; the wrapper can print the fix (bash ≥ 4 from Git for Windows / WSL, or the Pi `shellPath`) and exit non-zero |
| Missing/old `bash` | `#!/usr/bin/env bash` → `env`'s own error; bash 3.2 (macOS `/bin/bash`) dies somewhere inside `common.sh` | one check before any work, naming the found shell/version and the minimum |
| `files` whitelist | already covered by `skills/` | `bin/` must be added (one line) |
| Cost | none | one extra process per shell invocation (probe + CLI); the panel is unaffected |
| `npx`/`bunx` | same as POSIX | same as POSIX |

**Verdict: the wrapper.** Pi ships a Windows story (`docs/windows.md`: Git Bash by default, `shellPath`
override); a bash-only bin would make `teamsmith` uninstallable-by-accident there, and the readable
missing-shell failure is the same class of promise `team doctor` already makes. The wrapper is deliberately
**transparent**: it resolves `../skills/teamsmith/scripts/team` from its own realpath, probes `bash`
(`bash -c 'printf %s "${BASH_VERSINFO[0]:-0}"'`), then `spawnSync('bash', [cli, ...argv], { stdio: 'inherit' })`
and exits with the child's `status` (a signal → `128 + signo`; `EPERM`/`ENOENT` → the missing-shell message).
It implements no subcommand and rewrites no argument, so `team help`/`team version`/exit codes are byte-identical
to the bash entry (asserted).

## 3. Decision 2 — what `team init` installs, and how

**Target.** `<main worktree>/.pi/skills/<name>` — `$TEAM_MAIN_ROOT`, like every other init write, so running
init inside a linked worktree still installs for the project (asserted). Pi's project search path; the
per-project, version-lockable location, not the machine-global `~/.agents/skills`.

**Source, by name, never by sweep.** `teamsmith` = `$TEAM_SKILL_DIR`; `teamsmith-init` =
`$(dirname "$TEAM_SKILL_DIR")/teamsmith-init`. A source layout that carries only one of the two (e.g. a copied
`~/.agents/skills/teamsmith`) installs only that one and says so — a "every directory under `skills/`" sweep
would install whatever else happens to sit next to it, which in a copied layout includes other people's skills.

**Modes.** Default `link` (`ln -s "$src" "$dest"`): the project entry follows the package, so a package update
is live and there is exactly one copy of the code. `--copy`: for an ephemeral source (an `npx` cache) — copy
everything except `.git/` and `node_modules/`, nothing else (no magic list). `--no-skills`: skip the step and
say so (config/docs only). No `--target`: the location is Pi's project path, not a preference.

**Idempotence / conflicts.** The table the fixture walks:

| `dest` state | default | `--force` |
|---|---|---|
| absent | install (link/copy) | install |
| symlink → this source | `skip` (exit 0) | `skip` |
| symlink → another source | conflict: name it, exit non-zero, routes: `--force` / remove by hand / `--no-skills` | repoint to this source |
| directory (or file) with a `SKILL.md` whose frontmatter `name` is this skill, bytes equal to the source (copy mode) | `skip` (exit 0) | `skip` |
| directory with that `SKILL.md`, bytes differ (hand-edited vendored copy, older copy) | conflict: exit non-zero, untouched, routes as above | replaced |
| anything else | conflict: exit non-zero, untouched | **still refuses** — never delete an unrecognised directory |

**`.gitignore`.** The install directory joins the existing teamsmith block (`.pi/skills/`). An absolute symlink
must not be committed (it breaks on the next machine) and a copy is re-creatable; adding a line never untracks
anything already committed (this repository's tracked `openspec-*` entries stay tracked). Asserted
non-duplicating.

**bootstrap.** `team bootstrap` runs the same function through the same code path — including when
`.pi/team/config.sh` already exists, which today is the branch where init is skipped entirely. That makes
"re-run bootstrap" the upgrade route for an existing project, and it is one implementation with two call sites,
not a second semantics. `bootstrap --print` names the step and writes nothing.

**Output.** One line per skill — `link <dest> → <src>`, `copy <dest>`, `skip <dest>（…reason）` — so the result
is auditable from the command's own output; conflicts print the path, what was found and the routes.

## 4. Decision 3 — the package shape (`init-skill`)

`"bin": { "team": "./bin/team.mjs" }` (one entry — a second name would be a second CLI identity) and
`files: ["skills/", "bin/", "install.sh"]`. `pi.skills` is unchanged: the package still installs as a Pi package,
and the two routes compose (a Pi-package user needs no global CLI; a global-CLI user needs `team init` for
discovery). The tarball contract is observable: `npm pack --dry-run --json` must list `bin/team.mjs`, both
`SKILL.md`s and `install.sh`, and no path under `docs/team/`, `.pi/`, `openspec/` or `node_modules/`.

## 5. Decision 4 — the shell check, and where it lives (`memory-and-deps`)

The check lives **in the wrapper only**. A guard inside `scripts/team` cannot be tested (by the time a real bash
runs the file, `BASH_VERSINFO` is the truth on that machine) and would fire after `common.sh` is sourced — too
late on bash 3.2. The wrapper resolves the same `bash` the CLI would (`PATH`), so the report names the shell that
would actually run the tool; the fix text names `bash` 4 and the README's `Requirements` row. `team doctor` keeps
its existing row (already correct); no `TEAM_REQUIRE_*` knob is added — a missing shell has no degraded mode.

## 6. Decision 5 — visibility and repair (`init-skill`)

The install is only auditable if a drifted one is visible. `team doctor` gains one row, computed from
`$TEAM_MAIN_ROOT/.pi/skills`: **silent** when there is no `teamsmith` entry (a project using the Pi package, a
`~/.agents/skills` link or a settings `skills` entry must not be nagged); `pass` when the entry is a symlink to
`$TEAM_SKILL_DIR` or a directory whose `SKILL.md` version equals `TEAM_VERSION`; `warn` (never `fail`) when the
entry is a copy from another version, a symlink to another source, or carries no readable `SKILL.md` — naming
the found version/target and the repair `team init --force`. This is the same warn-don't-fail line `team doctor`
draws for a stale session version.

## 8. Risks and open questions

- **Open change on the same deltas.** P34 (`pi-only-scope`, dev3) declares
  `deltas: agent-adapters, init-skill, memory-and-deps`; its committed `init-skill` delta is **ADDED-only**
  (checked: `git show 75782af:openspec/changes/pi-only-scope/specs/init-skill/spec.md` — one ADDED requirement
  about the questionnaire's Pi version/plugins, no `## MODIFIED` block), so the two changes do not fight over a
  requirement block: this change's MODIFIED block stays valid on its own and the archive order does not matter
  for the spec. What the two changes do share is the **file** `skills/teamsmith-init/SKILL.md` (its questionnaire
  vs its opening beat), so their applies must land one after the other and the second one re-reads the file
  rather than replaying a stale copy. The PM should still sequence the two archives.
- **Windows is reasoned, not measured.** No Windows host here; the wrapper's advantage there follows from npm's
  shim behaviour and Pi's `docs/windows.md`. The fixture proves the *missing/old shell* path on POSIX, which is
  the same code path Windows would take; the proposal does not claim a Windows test.
- **Ephemeral sources.** `npx teamsmith init` would symlink into the npx cache. `--copy` is the answer, stated
  in `team help`/README; no auto-detection, because guessing "is this path ephemeral" is not falsifiable.
- **`team update` is not changed.** It reports and reloads; the repair route is `team init`/`team bootstrap`,
  which the workspace already treats as idempotent. Adding a third call site is out of scope here.
- **The stray tracked `tests/__pycache__/fake-tui.cpython-313.pyc`** is pre-existing; this change neither
  ships nor excludes it in copy mode (the exclusions are `.git/` and `node_modules/` only). If the PM wants it
  gone, that is a separate task.

## 9. How the change is verified

- A new headless fixture, `skills/teamsmith/tests/install-shape.sh`, wired into the FAST smoke like
  `tests/config-cli.sh` is (smoke §33): every fixture is a fresh git repo under `$TMPDIR`, the caller's `TEAM_*`
  and tmux identity are stripped first, and no tmux/pi process is started. It walks the install matrix, the
  wrap/permission modes, the pack contract, the shell checks and the three doctor states, and it carries its own
  flip pairs (a scratch CLI tree whose `files` lost `bin/`; a scratch `bash` shim reporting 3; a scratch
  install-step variant without the conflict check) so a red side exists for each promise.
- Smoke §2 (the main fixture's `team init`) gains the install assertions: both entries, the `.gitignore` line,
  the second run's `skip`, and `bootstrap` on the already-initialised fixture.
- The flips the PM can reproduce by hand are in the proposal's "What flips" (they are the same scratch-tree
  edits the fixture performs).
- Anything that needs a real npm prefix (`npm i -g --prefix <T> ./teamsmith-*.tgz`) is asserted **when `npm` is
  resolvable** and otherwise prints a visible `SKIP` — never silently.

## 10. What this change does not do

- No change to any other subcommand, to the extension injection (`--skill`/`-e` rendering stays byte-identical),
  to `install.sh`, to the gates, or to the `pi.skills` manifest entry.
- No npm publish, no tag, no repository-visibility change (PUBLISH.md gains the rehearsal step only).
- No second spec system: the promises are the four requirements in this change's delta files, and the reasoning
  stays here.
