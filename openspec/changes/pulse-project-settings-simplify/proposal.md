# Proposal

## Why

项目设置把完整配置清单当成日常操作页：已接受的同输入观察有127个可选行，120×30首帧23行全部不能编辑，任务模型反而排在118个键之后。普通用户应先选模型和调整自动检查，不必先读项目路径、进程参数和配置语法。

## What Changes

- **BREAKING（仅显示约定）**：用精选用途页替代全键、未知键自动出现及schema分组原样呈现；完整CLI、用户文件和值不删除。
- 默认页先显示全部实际任务类别，再显示PM模型、模型同时运行任务数、自动检查间隔、PM每小时自动恢复次数及启动时检查新版本；不固定类别数。
- 只留两个按需入口：“项目命令”保留安装命令、验收命令及验收最长时间；“模型记录”复用现有派单/PM启动数据，准确标为记录而非正在运行。两者在现有设置内返回，不增加顶层页面。
- 不新增“资源下限”子页：四个阈值和其余运行参数退出设置，继续由完整CLI维护；容量不足、配置读取及迁移错误仍在原有错误位置可见。
- “模型同时运行任务数”用适用模型和数量字段编辑现有规则，普通编辑不再手写`pattern=N`；保持单个`TEAM_MODEL_LIMITS`值、原有匹配/优先级、完整映射写入及校验。
- 精简中英文标签和编辑反馈；常态不重复原始键、默认标记、逐行生效徽章及CLI教学。保留必要生效提示、真实失败与危险值确认；保存不表示已换模或已重启。
- 替换现有UI场景内的全表/新增键必显示/schema组绑定断言；作者只做实现与静态检查，由非作者一次执行受影响UI验收，不再增加平台、截图矩阵或重复CLI验收。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `panel`：精选设置行集、用途分组、两处返回式入口、规则表单、标签化确认、按当前视图计数；退休全表及磁盘阈值必须显示的承诺，保留写入和模型身份边界。
- `memory-and-deps`：删除schema新增键必须自动进入UI的跨层承诺；完整机器读的group来源、字段、顺序和校验全部不变。
- `verification`：只为本次已点名的展示断言退休/替换补覆盖保留规则的窄例外；其余覆盖和此前例外不变，不普遍豁免UI或增加运行。

## Impact

- 同一代表输入C=3/A=5/L=1/U=0：默认可选行127→10（8编辑+2入口），整个设置的配置编辑入口80→11；模型记录6条仍可按需查看。一般默认C+7，所有配置编辑入口C+8；并非项目或类别上限。
- 未来实现涉及`skills/teamsmith/scripts/panel/src/{layout.ts,App.tsx,types.ts,strings/*}`、钉住工具链生成的`panel.js`及现有说明；在原`panel-p21.sh`、字符串和布局检查内替换相关断言，不增加检查段。
- 不改schema、CLI完整输出/分组、默认值/choices/值域、writer/CAS/actor、危险确认、模型身份/运行逻辑、真实配置、项目版本或团队状态；不新增后台操作、重启按钮、通用高级页或配置系统。
- 本变更仍是规划。正式接受及独立实施/验证派单之前不授权Apply；设计中的画面均未实现。
