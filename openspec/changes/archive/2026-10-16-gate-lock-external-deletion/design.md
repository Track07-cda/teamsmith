## 1 事实（决定做法的那几条）

### 1.1 事件的两半，既有防线只盖住了一半 [引用 + 读码]

2026-10-15 18:07:21 另一个项目的清理命令里带了一条 `rm -rf /tmp/teamsmith-smoke.*`（D184）。两条后果：

1. **可承受的一半**：被删的那次 `--paths` 门禁按哨兵设计**响亮地停**（一条点名红 + exit 2，不是假红）。
   这条防线是 2026-09-18 bg6 那次之后专门为「$TMP 在运行途中消失」建的：金丝雀文件 `$TMP/.smoke-alive`
   （`smoke.sh:744`–`:767`）、0.2s 轮询的后台哨兵（`:831`–`:845`，`:861` 双重 fork 起）、一条点名红 + 证据 +
   `exit 2`（`:804`–`:822`）、段落边界与每条红之前都过一遍（`:496`、`:825`）。
2. **危险的一半**：**锁文件被删会静默破坏互斥**。今天没有任何一条防线看这件事：`SMOKE_LOCK_HELD=1` 是从
   **环境标记**推出来的（`:396`–`:400`），一整轮里再也没有回过头去核对「路径上那个文件还是我持有的那个 inode 吗」；
   收尾只删自己的 `<lock>.holder`（`:881`）。

### 1.3 锁被删就静默分裂：flock 锁的是 inode，路径只是名字 [实测 B]

```bash
D=/tmp/p287-exp-$$; mkdir -p $D; L=$D/teamsmith-smoke.lock; : > $L
flock -x "$L" sleep 6 & HP=$!
sleep 0.3; echo "  持有者 pid=$HP 握着 inode $(stat -c '%d:%i' "$L")"
rm -f "$L"; : > "$L"
echo "  外部删除后重建：路径现在指向 inode $(stat -c '%d:%i' "$L")"
flock -n "$L" true && echo "  新运行 flock -n = 成功（两套「顶层」同时认为自己独占）"
```

```
  持有者 pid=1171458 握着 inode 29:34717904
  外部删除后重建：路径现在指向 inode 29:34717906
  新运行 flock -n = 成功（两套「顶层」同时认为自己独占）
```

这就是 D184 第二条后果的现场：持有者握着**已被 unlink 的 inode**（内核不会通知它），新运行在**新 inode** 上

## 2 D1 · 锁的归属：机器级伴生锁（推荐）

**结论：互斥留在机器级，但离开「按 kind 命名的平铺家族」—— 改成一个点开头的**伴生锁**（machine lock），
由它承担互斥；发布路径（published path）保留为兼容声明。**

- 为什么互斥必须留在机器级：这把锁保护的是**机器**（一套全量门禁自己就能把 32 核压到 loadavg 20+，
  P255 §2.2；协议 §9b-2 与 perf/panel 的负载前提都建立在这条上）。它的**名字**也必须说清范围：机器级的东西
  不叫任何项目的名字。
- 落地形状：伴生锁 = 发布路径的**同行同目录、basename 加 `.machine`、点开头**：
  `…/teamsmith-smoke.lock` ⇒ `…/.teamsmith-smoke.lock.machine`（公式在合同里，不是这里）。注册与持有者记录
  放在伴生锁边上（`<companion>.runs/*`、`<companion>.holder`）—— 点开头目录天然不是 `--sweep` 的候选（842 的既有规则）。
- 为什么这样够：实测 A 说事件那条命令够不着点开头的名字；实测 C 说**够不着就等于互斥保持**。发布路径被删只
  丢「与旧版本串行」（§3），不丢互斥。
- **被否掉的备选**：
  ① **锁放进本项目自己的状态目录**（brief 的括号里那支，`<主检出>/.pi/team/state/…`）：它把锁搬出共享临时面，
  也**顺手把机器级串行交了出去** —— 两个项目（以及同一个项目的两个检出）各自持一把锁，可以并发跑全量，正是
  M23/P255 量过的形状（§36 超时、ENOSPC 假红那一族），而 P281 的 `nested` 纪律正建立在「锁串行化**顶层**运行」上。
  代价（跨项目并发）比收益（名字干净）大，不取。
  ② **`$XDG_RUNTIME_DIR/teamsmith/…`**（机器级、且不受 `TMPDIR` 覆盖的影响）：位置更「正确」，但它**可能不存在**
  （容器/CI/非 systemd 会话），于是要么退化、要么两处并存 —— 两处并存 = 两把锁 = 静默并发。不新增第二个
  解析规则，等有需求再单独改（§10 第 4 条）。
  ③ **只保留发布路径、只加察觉**：最省事，但事件那条命令仍然**删得掉互斥**（只是被察觉），而 brief 第 1 条要的
  正是名字这一半。不取。

## 3 D2 · 兼容声明与「持有者不许删自己的锁」

- **为什么保留发布路径上的一把声明**：机器上一定有 P287 之前的写入者（其它项目按自己的节奏升级；npm 包是逐项目装的）。
  它们只取发布路径。没有这把声明，升级窗口里**机器的互斥会与它们静默分裂** —— 一个以「终结静默并发」为目的的
  变更不能自己开一个静默窗口。
- **顺序固定：先发布路径、后伴生锁**。旧写入者只取发布路径（前缀），本版本的运行取两把（全长）。顺序是全序，
  不存在环，因此不可能死锁；旧写入者持有时我们排队，我们持有时旧写入者排队。
- **兼容声明按需创建、绝不 unlink**：文件不存在就建（旧写入者也是这么建的），**持有者永远不许删除或改名自己持有的锁文件**。
  理由不是洁癖：删掉一个还有等待者阻塞在它 inode 上的锁文件，**正好就是事件那条机制**（等待者拿到一个没人看得见的锁），
  所以这条要写成合同，而不是留给下次「清理」的好意。
- **账要如实记**：发布路径因此是**活运行仍在创建的唯一一个平铺家族形状的文件**（命名规则的一个例外，写进文档与测试），
  它被删只影响与旧版本的串行；那条 guard 会**点名 + 留证据、但不停止运行**（互斥完好）。残留窗口：删除之后、下一次取锁
  之前启动的旧写入者可以与我们并发 —— 会被点名、会被记录，窗口由下一次取锁封住。
- **被否掉的备选**：`teamsmith-smoke.lock.machine` 这类「家族里加后缀」的名字（点仍是那个点，实测 A/C：照样被命中）；
  退出时把发布路径删掉（违反上面的 no-unlink，且会自己制造分裂）；「文件存在才声明」（在检查与取锁之间有竞态：
  旧写入者可以在这中间创建并拿锁 → 双方都跑，且静默）。

## 4 D3 · 身份：什么可证、什么不可证

- **可证的**：持锁进程自己的描述符身份（`stat -L /proc/self/fd/<n>` 的 `dev:ino`）—— 只有**持有那个 fd 的进程**
  读得到。P281 的形状里，真跑套件的是 `flock --close` 的**子**进程（拿不到 fd），所以两种落法都合规：
  ① 取锁助手自己就是持有者（自己开 fd、加锁、从自己的 fd 记 `dev:ino`、再以「子进程关掉那个 fd」的方式跑套件）——
  首选，因为记的是**真持有**的那个 inode，取锁瞬间的替换窗口（`flock` 开文件与我们 `stat` 之间）也关掉；
  ② 记录 `source=path` + 路径身份 —— 窗口留着，由 §6 的入场登记核对兜住。合同只依赖「记下身份 + 守卫比对路径」，
  不依赖是哪一种。
- **不可证的**：内核不提供「我持有的 inode 被 unlink 了」的通知，flock 会一直挂在那个孤儿 inode 上。所以察觉是
  **有界时间**（轮询节奏）而不是即时 —— 这条写进 §10，不许声称即时。
- **被否掉的备选**：锁一个**目录**（`rm -rf` 删空目录一样删得掉；Linux 上没有任何路径能免疫 unlink）；
  给同一个 inode 加**第二条硬链接**当「幸存锚」（它确实活过 unlink，但新来者锁的是**路径上的新 inode**，互斥并不会
  因此恢复，只是多一个要同步的名字）；**自动重取/修复**（在旧持有者还活着时在新 inode 上重新加锁，正是要消灭的
  静默分裂；本变更的选择是**停止 + 留证据 + 运维重跑**）。

## 5 守卫：复用哨兵，两条前提 [读码 `smoke.sh:744`–`:861`]

- **一个进程、两条前提**，不建第二个看守：既有的后台哨兵已经在 0.2s 轮询金丝雀（`:843`），P287 让它**同时**核对伴生锁
  （路径不存在 ⇒「已不在」；路径上是另一个文件 ⇒「已被替换」并印两个身份）。理由：这两件事是**同一个场景家族**
  （现场被抽走），出事时的动作（一条点名行 + 证据 + 停跑）也应当只有一套。
- **动作与既有形状逐条对齐**：证据文件仍是 `$TMP` 之外那个点开头的诊断路径（`:760`–`:767`，删 TMP 也带不走），
  追加一节 lock 现场（时刻、期望/实测身份、最后经过的段落、锁路径上的实测持有者、本轮的 ns/工作树/席位）；
  一条点名行由主 shell 印（`smoke_tmp_fire`，`:804`）；`KEEP=1` 留下能留的现场；退出码仍是**约定的 2**
  （协议 §9b-2 已把 1/2/3/4 四个码的含义钉死，不新增码）；段落边界与结果行之前照旧过守卫（`:496`、`:825`），
  于是「跑到一半被抽走」不会走到结果行、更不会给出对代码的判定。
- **两条前提的处置不同**：伴生锁 —— 停跑（互斥是这套运行的全部依据）；发布路径 —— 只点名 + 记录（互斥完好，
  丢的只是与旧版本串行）。文案区分「已不在」/「已被替换」/「兼容声明丢失」，便于事后一眼归因。
- **`team review` 侧同一份实现**：review 的门禁子进程同样带这条前提；记录里写「门禁没有跑完（锁在运行中丢失）」，
  判定不为 `PASS`（token 闭集不变），排队记账的三个键不变。

## 6 等待者与入场检查

- **等待者**：把「一次 `flock --close -w` 阻塞」换成**有界轮询**（短 `flock -n` 尝试），每一轮重新解析路径并与
  它第一次解析到的身份比对；变了就印一行（两个身份）再继续等。上限算式仍是 P281 冻结的那条
  （`clamp(remaining + margin, …)`），marker 语义（「真的跑起来了」的唯一证据，P66）与超限/加锁失败的文案、
  退出码**一字不改**；取锁顺序同样是「发布路径 → 伴生锁」。
- **入场检查（acquire-time cross-check）**：拿到锁之后、跑套件之前，读 `<companion>.runs/*`，按 P281 的
  pid+starttime 规则过滤出**活着的 `top` 登记**；若有一条记的**身份与我这把不同**，就证明「互斥已经断了」：
  印一行点名那个运行、席位、工作树与两个身份，**不跑套件**（「本套没有运行」，退出码 2）。
  这是**新来者**侧唯一的保护 —— 旧持有者那边只有它自己的守卫。
- **为什么不是排队**：「别人持着锁」才是排队的事；「同一把锁上有一个活运行记着另一个 inode」是**锁坏了**，
  排队等于假装没事。这一条与 §5 的守卫**互补**：守卫保证持有者在有界时间内停，入场检查保证新来者不加入。
- **旧版本的记录**：只有 `<published>.holder` 存在时（P287 之前的写入者持有发布路径），按 P281 对旧写入者的
  既有口径打印 —— 有多少字段打多少，缺的写 `?`，并标 `version=legacy`；绝不印 `holder unknown`。

## 7 命名空间（`ns`）的推导与影响面

- **推导**：`ns = <slug>-<hash8>`。`slug` 取 `TEAM_PROJECT`（有则用，与 `team notify`/会议的发送者同源），否则取
  主检出目录名；只保留 `[A-Za-z0-9_]`、截断到 24 字符。`hash8` = 主检出 realpath 的 sha256 前 8 位十六进制。
  主检出 = `dirname "$(git rev-parse --path-format=absolute --git-common-dir)"`（**所有 worktree 落在同一个 ns**），
  git 不可用（无 git 的检出）时退到 skill 自己的仓库根 —— 与 P122 已经写进台账头的 `repo=` 是**同一条解析**
  （`tmp-root.sh:102`），两处不会各说各话。
- **一处定义、两个调用面**：夹具的唯一创建者仍是 `tests/lib/tmp-root.sh`（764 的「一处声明」不破），但产品侧也有
  直接在平铺面上写文件的模板（`cmd-review.sh:1071`、`common.sh:1198`、`cmd-watch.sh:244`、`cmd-review.sh:372`），
  它们拿不到 `tests/` 的库 —— 所以推导定义在 `scripts/lib/common.sh` 里做一个**纯函数**（不读配置、不依赖检出），
  `tests/lib/tmp-root.sh` 调它。仍然只有一份实现。
- **标记与台账**：`.teamsmith-tmp` 与 run 台账头各加一个 `ns=`（与 `repo=` 并列）；`--status` 多一列 ns，
  于是「按名字归因」与「按台账归因」两条信号都在，而**权威仍是台账的 `repo=`**（P122 的规则不动：外来仓库的根
  列出来但不碰）。
- **迁移**：新代码不再在平铺面上创建任何根；历史平铺根照旧靠自己的 `run=` → 台账归因（`tmp-hygiene.sh:298`–`:317`
  既有路径），可被同一个 `--sweep` 回收；`--status` 把它们标 `legacy`（一行显示细节，不新增判据）。
- **`review-<ID>` 不改**：它是检出、由 git 记录归因，名字写在 SKILL.md/`references/workflows.md`/`references/migration.md`
  三处；本变只在设计里记一条 finding：`review-*` 仍在别人的 `rm -rf /tmp/review-*` 射程里（它是检出、不是活运行，
  且 P122 已拒绝未证明的候选）。

## 8 静态闸与清扫面

- **`--lint` 的规则扩到「整条临时根模板」**：今天只扫 `mktemp -d`（本树 15 个）、只认前缀，另外 7 个直接落在
  临时根上的模板（§1.5 表里那两行）全在静态闸之外。P287 要的规则是**点开头或带 ns**，于是顺带把它们拉进视野：直接落在解析后临时根
  上的每一个模板，要么点开头（台账/pid/诊断），要么带 ns（根/队列标记/过滤副本）；根还要在 owned 家族里。
  finding 仍是 `<file>:<line>`，退出码仍是 1，`--dir` 仍可指向副本（红侧用）。
- **`--sweep` 不需要新判据**：根仍是 `teamsmith-` 前缀（候选谓词不动）；伴生锁与它的记录目录是点开头 ⇒ 本来就不是候选；
  发布路径是**文件** ⇒ 本来就不是候选。新增的只有 842 的一句「三样都要在 `--status` 里带角色报出来」。

## 9 红侧的设计（brief 第 3 条）

全部只用**私有 `TMPDIR` + 私有 `TEAM_SMOKE_LOCK` + `TEAM_SMOKE_FIXTURE=1`**，绝不碰机器锁；身份清洗与既有夹具同形。
新增两个翻转夹具（`tests/flip-p287-name.sh`、`tests/flip-p287-lock.sh`）与两个新段（`34c` 命名面、`34d` 身份面），
不扩 `34`/`34b`（那两段是 P281 的写集，避让）。

| 场景 | 造现场 | 断言 | 红侧（翻转） |
|---|---|---|---|
| ① 锁被删 | 持有者（真入口 smoke，私有锁、私有 TMPDIR，一段永不返回的夹具段）起来后，从外面 `rm` 伴生锁 | 有界时间内**一行**点名「锁已不在」；证据文件在 `$TMP` 之外且带期望/实测身份；安全点停跑、退出码 2；**没有**结果行 | `--break=no-lock-guard` → 同场景不印那一行且继续跑 → 断言红；还原后绿 |
| ② 锁被换 | 同上，但用「unlink + 新建」与「`mv` 覆盖」两种形状替换伴生锁 | 一行点名「已被替换」并带两个身份（与①的文案可区分）；同样停跑；证据记两个身份 | 同上 shadow |
| ③ 入场检查 | 持有者（身份 A）在跑；把伴生锁换成身份 B；起第二套（同一个私有锁路径） | 第二套印一行（点名那个活运行 + 席位 + 工作树 + 两个身份）且**不跑套件**（无结果行、无 marker、退出码 2） | `--break=no-entry-check` → 第二套照跑 → 断言红；还原后绿 |
| ④ 反向对照（不许误报） | 正常一套跑完；再跑第二套（第一套退出后） | 两套都**没有**锁身份行，都有正常结果行与原退出码；伴生锁 inode 前后不变（持有者没删/改名自己持有的锁）；发布路径仍在 | —— |
| ⑤ 等待者 | 第二套在等待中，从外面删/换伴生锁 | 等待者印两个身份 + 「我等的那把已经变了」，然后按同一个上限重新解析继续等；旧版本记录（只有 `<published>.holder`）印 `version=legacy` + `?` | —— |
| ⑥ 命名面 | 私有 TMPDIR 下起一套夹具运行，列它**为自己**在临时根里创建的条目 | 每个条目点开头或带 ns（根、队列标记、过滤副本、台账、pid、诊断）；根的名字带 ns；标记与台账带 `ns=`；这些条目**都不匹配**平铺家族模式。唯一的例外是发布锁路径（§3，锁要求管它，它的丢失只印不停） | `--break=flat-name` → 根回到平铺名 → 模式命中 → 断言红；还原后绿 |

时间要有界但不脆：①/②/③ 的「有界」判据取**守卫节奏 + 安全点等待**的上界（建议 ≤5s，夹具用轮询到上限再判红，
不用固定 `sleep`）。⑥ 的「平铺模式」用**契约里点名的那一族形状**（不是某一条具体命令）在测试里写死，红侧证明它
判的是命名规则。

## 10 诚实边界（不许声称的东西）

1. **没有不可删的锁**：外部把两把锁（或整个临时根）一起删掉，只能在**有界时间内被发现**，不会被阻止。窗口由守卫节奏
   封住；窗口内到达的第三套由 §6 的入场检查拒绝。**两者合起来**才让「静默并发」不成立 —— 单独一条都不够。
   另外，发布锁路径仍是活运行创建的**唯一**平铺形状文件（§3：兼容声明的代价），所以「事件那条命令一个字节都碰不到我」
   这句话的准确版本是：**它碰不到互斥、碰不到工作根与标记，只能删掉一个删了会被点名、被记录、且不影响互斥的兼容声明文件**。
2. **`source=path` 那种落法**留着取锁瞬间的替换窗口（§4）；记录里如实写用了哪一种身份来源，窗口由入场检查兜。
3. **升级过渡期**：P287 之前的写入者只经发布路径串行；发布路径被删时守卫只**印**不**停**，此时一个旧写入者可以加入。
   窗口由下一次取锁封住。
4. **`TMPDIR` 覆盖的残留**（P255 r4/r5）本变更不关：换了 `TMPDIR` 的运行取的是另一对文件，彼此**不可见**（连察觉都没有）。
   最便宜的将来修法是把家族基址钉在一个不随 `TMPDIR` 漂的位置 —— 不在本变更范围。
5. 守卫证明的是「路径上那个文件不是我所持有的那个」；它**不能**证明是谁换的，也**不能**证明有人读了那一行。
   门禁与文档都不能证明「人跑的是安全的那条清理入口」。
6. 容器里的运行（P162 的临时纪律）拿到的是容器本地的临时根 ⇒ 它的互斥是容器本地的；本变更不改变这一点。
7. 非 git 检出退到「skill 自己所在仓库根」的 ns：同一个项目的两份拷贝在不同路径 ⇒ 两个 ns ⇒ 彼此的陈旧根互不回收
   （各扫各的）。可接受（本来就是两份安装），但写在这里。
8. §1.6 的 111 个平铺条目**不会**被本变更改名或回收：历史残留照旧靠 `--sweep`（本项目归因）与运维手工处理；
   本变更只保证**新**的活运行不再长在那个形状上。
