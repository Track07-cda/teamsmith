### 3b. The managed boundary: outside text is preserved byte-for-byte

The user's 2026-10-30 requirement is stronger than what the current writer does, so this plan amends the earlier “text-only, no algorithm change” boundary for exactly one function and the legacy conversion beside it. Probes run against the shipped functions on `main` (`/var/tmp`, scratch copies; log in the report):

| Probe | Shipped behavior today | Consequence |
|---|---|---|
| AGENTS whose prose mentions the delimiter inline, no standalone pair | Detection is `grep -qF` (substring) while the replacement scan enters only at an exact full-line match, so the rewrite is a no-op and init still prints `update …（协议段落已刷新）` | A silent non-refresh reported as success; the quoted prose survives only by accident |
| Outside fenced example quoting both delimiter lines, then a real block | The exact-line scan is fence-blind, so the fenced example is taken as the managed pair | The rendered block is injected into the outside example; its original bytes are destroyed |
| Outside fenced example quoting the legacy delimiter plus a real legacy pair | Legacy migration is a global `sed` substitution | The quoted example is rewritten too (`pi-team` → `teamsmith`), i.e. outside text changes |
| CRLF file with a proper pair | Line equality fails on the trailing `\r`, so the exact-line scan matches nothing while `grep -qF` still detects the block | `update …（协议段落已刷新）` with the body unchanged (86 → 86 bytes): a silent non-refresh again |
| Managed block whose last line has no final newline | The `awk` rewrite terminates the last line | One byte is added beyond the managed range (70 → 75 bytes with the replacement body) |
| Unclosed fenced example quoting the delimiters, no real pair | The fence-blind scan treats the fenced lines as the pair | The example is rewritten instead of receiving a block outside it |

Minimal correction, inside the existing writer: one pre-scan reads the whole file, collects **every** eligible delimiter candidate, and only then decides — refresh one balanced pair, append when there is none, refuse otherwise; there is no first-match shortcut, so "the scanner stopped at the first pair" cannot be read as a defensible implementation. A candidate is an exact standalone line **outside** a fenced code region, where a region opens on a line with at most three leading spaces followed by at least three backticks or tildes and closes only on the same character with at least the opener's length and a whitespace-only suffix, and a backtick-opened fence's info string may not itself contain a backtick (unclosed regions run to EOF). This is the same narrow lexical rule the accepted `key-replies` parser states for its protected regions, restated with its info-string condition in one comment for the writer — not shared code and not a Markdown parser. Everything else is ordinary content: a marker quoted in prose, indented, sharing a line with text or inside a closed fenced example is never a candidate and never an error, so the append path handles a file with no candidate and the pair path preserves those examples untouched.

The update is a byte-range replacement between the two recognised delimiter lines, and the replacement body's terminator is the **existing begin delimiter line's own terminator** (LF or CRLF), used for every inserted line — including in a mixed-ending file, where that begin line is the only authority. The scan writes only the bytes between the begin line's end and the end marker's start, so a CRLF block receives CRLF body lines, other endings and a final line without a newline are carried over unchanged, and no normalization or trailing newline is added: preserving the user's outside bytes is the contract, not restricting the document's format. Both delimiter lines themselves are kept byte-identical. The legacy conversion is the same range edit on the two delimiter lines only, so an outside `pi-team` example stays byte-identical.

The scan refuses rather than guesses in exactly two situations: an eligible-candidate set that is not one balanced pair (two or more pairs, a begin without its end, an end without its begin, or current and legacy delimiter lines mixed), and a file with no eligible pair that ends inside an unclosed fence — there an appended block would land inside the fence and be appended again on every run, so the smallest honest handling is a named failure with the file untouched until the project closes the fence. Every refusal leaves the bytes identical and names the file and reason; that replaces today's silent “refreshed” success, and refusing means no pair is refreshed on the way out. No repair heuristic, no separate migration command, no new flag; `--force`/bootstrap/install-conflict semantics and init's non-transactional ordering are unchanged.
