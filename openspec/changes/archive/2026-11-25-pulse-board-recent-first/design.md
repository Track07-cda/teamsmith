## Context

D269 接受 P501 的来源结论：Git 提交、整份文件的 mtime、交付报告、办结日志和刷新时刻都不能证明某一行何时改变。没有可从旧数据补齐的历史；本单使用原任务表，不建立另一份索引。

## Goals / Non-Goals

让看板页按栏先看到最近实际更新的任务，保留旧表可读可写、每栏的折叠与滚动、以及刷新前后同一行的选中身份。本单不迁移任何活看板，不改变工作页、打印/JSON 输出或命令行顺序，不引入持久行 ID、配置、轮询、排程或标签实现。

## Decisions

### 1. 原任务表是唯一时间来源

末列名固定为 `Teamsmith Updated UTC`，去除表头单元格首尾空白后精确匹配，所有语言共用；不识别项目自定的日期列。值用现有 `team_timestamp` 的秒级 UTC 格式 `YYYY-MM-DDTHH:MM:SSZ`，读时验证实际日期与时间，不接受偏移、小数或自动归整后的日期。一次操作需要记时才取一次时钟；同次改动多行允许同秒。

读写共用一个**仅用于时间**的位置判断：沿用看板现有业务列名及别名，结合相邻分隔行和原有连续表边界，判断原读者/写入者已选的物理行及业务格是否与任务表对齐；不按同 ID 借用另一行的值。它不替换 `team_board_cols_direct` 的原列位与缺列处理、`team_board_add` 的原插入位置、或原业务字段寻址、判重和诊断。比如仅有 `编号` 表头且下方另有风险表，即使能辨出任务表，若原新增落在风险表尾附近，仍在原位置写，不记时间；重排列头的旧写入若格位不一致，同样照旧、不记时。表外同 ID 行保留既有匹配行为，但不取、不写时间。

首次在对齐的任务行上发生实际新增或修改时，才一并补末列表头和分隔格，不碰其余旧行。旧行只缺这个末格仍可读，且仅实际变化的那行补末格。读时跳过表头、分隔行、占位和其它表；保留名必须唯一且在末位，否则不读、不另加同名列。无法辨明任务表、实际落点或格位不吻合，或加列会把旧行未声明的格误当时间时，保持旧业务写法，不记时。空、缺、非法时间为无时间，不因读取或重复操作修复；人工改表不自动记时。有效值须符合规范形状且经 UTC 日期解析后能原样往返。

### 2. 两处原写入口，同笔替换

| 调用 | 记时点 |
|---|---|
| `cmd-docs.sh:team_cmd_task`、`team_cmd_board add` | `common.sh:team_board_add` 追加表内新行，含明确允许的重复；不给既有行补时间。只为已有行写任务书不算。 |
| `team_cmd_board set`、`cmd-agents.sh:team_dispatch_execute` | `team_board_set → team_board_write → team_board_write_col`，只在某行状态实际改变时记时。成功派单登记的 `wip` 若原来就是 `wip`，不重新记；运行记录不算看板变化。 |
| `cmd-review.sh:team_cmd_close` | 直接走 `team_board_write → team_board_write_col`；沿用 close 的前置检查与审计，不在 `team_board_set` 才补时间。 |
| `team_cmd_board assign` | `team_board_assign → team_board_write_col`，按行比较去首尾空白后的负责人值。 |

同 ID 的匹配行分别比较旧格与原写入逻辑**实际将写出的格值**，两边都去首尾空白；不拿裸参数比较、不改原值的解释或接受范围。例如负责人参数多了尾空白，实际有效值相同仍不记时。按旧语义写业务格，表外同 ID 不记时。除原目标业务格、可写的时间格和首次需要的表头/分隔格外，保留其它格及原行序。找得到 ID 但有效值相同仍是成功；只写任务书、报告、日志或标签不更新行。保留 `done` 准入、显式重复新增成功审计、未知 ID/缺参等原拒绝和诊断。

`team_board_add` 和 `team_board_write_col` 都可能用同一个 `BOARD.md.tmp`；即使用两个临时文件，两笔写入读同一旧板也可能让后替换的一笔覆盖前一笔的业务值和时间。复用 `team_with_lock`，按同一实际替换路径取相同资源名，不因计算锁键改变原替换目标。在锁内直读（可用现有 `TEAM_SCAN_CACHE=0`），按原条件新增判重、解析插入落点和列位、逐行比较、取时，在同目录一次替换；成功后由锁外的原调用进程执行 `team_scan_invalidate board`，不能只清锁函数子进程的缓存。未取到锁、生成失败或替换失败要显式返回非零，不依赖 `set -e`，不退回无锁写，不清缓存、不记新增成功审计；成功替换的显式重复仍记一笔。

`dispatch` 持 seat → admission → config 后才进入原板写口；`close` 在 seat/admission 收尾锁释放后写板，板锁中不回取这些上层锁，不锁整个命令或改原准入。写失败时，派单仍按原分支警告、保留已提交派单及 pending，办结仍按原分支提示板未更新、不撤销收尾；不能把写失败当板状态已更新或作办结成功审计。保留原成功路径的 `done` 证据与审计。只在两写口复用现有锁，不改锁目录规则、不增通用写入层；手改、旧版写入者及不同锁目录不受此锁保证。

### 3. 只投影页面顺序，不改原始行

`cmd-watch.sh:team_panel_board_json` 在原 `board` 块的批量扫描附带行级可选字段 `updated_at`，读不出就不当作有效时间。继续按文件顺序发原行、维持计数和交付摘要，不加第二个块、额外子进程或更新时间轮询。只在消费时验证规范/真实 UTC 值，原 `board` 读取及刷新周期不变。`team board ls` 仍原样打印 Markdown 表行（新列自然可见），`team board row` 仍按原方式返回原始行；`team monitor --json` 的 `buildJson` 输出 `panel/activity`、不序列化内部 `board` 块，不增加字段。`--print` 即使用 `--page 4` 也仍用原来的机器布局投影和历史窗口；纯文字的 `--once`/循环及工作页 `boardBlock` 的排序、历史保留与计数不变。`--snapshot` 走交互布局，随看板页显示新次序。

以原数组生成 ID + 原文件中同 ID 的出现序号，再给看板页按栏生成一份可复用的行投影：有效时间降序、并列按文件顺序；缺时间在末尾，普通栏按文件顺序，`done/dropped` 的无时间行由文件尾向前。宽档历史栏从零偏移显示，故没时间的旧板仍先显示原末窗那批行，但不声称这就是历史的真实先后。宽档各栏保留独立偏移，轮滚可有意把焦点滚出窗口；刷新时只有原先可见的选中行因换序或换栏离窗，才对受影响的窗口补偿，不重置其它栏或撤销主动偏移。窄档各栏仍在一个跟随焦点的整体窗口内，保持 `kanbanGrouped` 按当前焦点限制滚动位置的规则，不新增可将焦点完全滚出屏幕的行为。上下计数取实际绘制范围，折叠规则不变。

`layout.ts` 的并排车道和分组绘制、窗口、命中范围，与 `App.tsx` 的方向键及键盘 Enter 共用投影和原行引用；跨栏取目标栏显示首行。鼠标仍是先定位，点击已选卡才打开；仅看板页的该打开动作携带对应帧的原行引用，不能点击时按新位置重新解释，也不改工作页动作。原行寻址仍是 ID 加出现次序，不承诺跟踪人工交换完全同编号行或在之前插入同编号行；选中行不再可寻址时保持现有同 ID、同栏、首个非空栏回退规则。详情文件仍按 ID 寻找，同 ID 两行可分别选中但共用文件。

### 4. 标签由它自己的变更衔接

`task-labels` 候选的 `projectBoard` 已有展示投影，接入时应把这里的默认顺序与历史首窗合入该投影，而非串两次排序。承接点是其 `panel` 草案的两个要求（“Board labels and priority are optional read-only views” 及同名看板 MODIFIED 块）；届时才把候选的默认文字换成「最近更新 / Recently updated」。显式优先级仍按分数、同分按文件顺序；标签不可用也保留看板的最近更新默认。CLI 的显式筛选/优先级和文件序同分不变。不改 P497 或 V196 的暂停状态，也不把未接受的标签草案当本单基准。

## Risks / Trade-offs

- **原表会多一个可见列。** 这是不用两份数据同步的代价；并列用文件序以避免发明精度，原行不随显示移动。停用此显示规则时旧读者仍可容忍末列，不需删除原表数据；不承诺反向迁移。
- **最容易错的是画对了、操作却开错了。** 时间排序用原行引用，测试必须从真实刷新后的画面走键和点卡，并查文件正文，而不只比 JSON 次序或光标的 ID。
- **最容易误改其它测试的是全局替换 CLI 替身。** `panel-b3.sh` 的 `board` selector 只命中 `scn_board`；其它场景各有 `server_up` 根但共用 `start_panel`、替身及 pty 驱动。仅在该场景把 `board/detail` 委托真实 CLI，余块维持替身；不用全局改默认调用。其内原有工作页重复 ID 断言保留，用同一真实表证明仍按原顺序；其它场景（含 `workdetail`、`detail`）不换源。独立的 `fold` 场景仍使用原替身，其展开历史栏头的滚轮动作从首窗向较旧行应改用向下，仍断言只滚该栏；折叠栏的负对照保留。不增一轮折叠测试。
