## Context

The help fixture already initializes a scratch project for `perf --host`, records its six project fingerprints and has a way to select just this command. Its current whole-suite branch also handles `smoke --select 0`; the latter still does real selected correctness work and is not part of this change. See the accepted P481 report and review for the original call chain and why historical section timing is not a baseline for this call.

## Decisions

1. **Replace only the measurement target.** After the normal fixture initialization, stage a private copy of the CLI's `scripts/` tree under the help fixture's existing temporary root, with sibling `tests/perf.sh` containing only the recorder. Run the copied, otherwise unmodified `scripts/team` as `team perf --host` from the original `p-perf` project. Use the existing isolated invocation context and status capture; scope the copied CLI path to this call. Never overwrite the source under test or fall back to running its real `perf.sh`. Keep the invocation inside the ordinary fixture's existing timeout handling; there is no longer a `perf` arm of the 300-second whole-suite measurement wrapper. Keep that wrapper unchanged for `smoke`.
2. **Use one receipt and one verdict.** Append one unambiguous record per recorder invocation to a fresh test-owned file outside the project. Record the actual argument vector, physical working directory and a fixed nonzero test status (for example, 23); exit with that status only after the write succeeds. The help test compares the recorded argv with the literal one-element `--host` vector, the directory with the physical project root, and the real CLI's observed status with the recorder's expected status. An expected nonzero status distinguishes successful handoff from a generic return of 0; it is not a new public exit code. Require exactly one complete receipt and compare the same `state`, `docs`, `config`, `worktree`, `skills` and `meetings` fingerprints before and after. Missing or wrong receipt, a timeout, wrong status or a changed face is a named `claims: perf` failure; report which face changed. Count the combined result once through existing help accounting. The pass line says it checked handoff and the six faces, not that it measured or exercised repeated real runs.
3. **Validate only the changed path.** An independent verifier uses the existing `claims` selector on a frozen candidate and two disposable copies, with faults in the actual CLI route rather than the recorder or assertions. In one copy return 0 before handoff; in the other write a new state file inside the scratch calling project immediately before invoking the unchanged recorder. Keep exit status, receipt and changed faces distinct in the evidence so a setup error or missing receipt cannot stand in for the second fault. Discard both damaged copies. No enduring fault harness or extra author runtime pass is needed.

## Alternatives and Boundaries

- A shorter timeout still attempts the impossible frame observation and does not prove handoff. Checking just the help line or reading the dispatcher cannot prove a real call reached its target with the right arguments and directory.
- The removed attempt could observe setup and partial execution of the real performance program when reached, but not a completed measurement in that fixture. The recorder does not preserve observation of those real paths or prove that they never write to the calling project. The existing independent measurement remains responsible for real readings; it is not a substitute for the six-face observation during real execution. Do not rerun or alter it to accept this change. If new evidence of that property is required, record what is missing and refer it to the PM outside this scope.
